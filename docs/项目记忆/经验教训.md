## Flutter 界面与性能

### 设置内容列与懒列表搜索状态（2026-09-16）

- 设置分组的水平边距只能由一层负责；外层页面 padding 与分组隐式 margin 叠加会让卡片变窄，全部清零又会使宽屏卡片铺满。设置二三级页统一使用 `MoeSettingsContent`，以所在面板的局部约束计算宽度，不能用全窗 `MediaQuery` 替代；尺寸与材质规范见客户端《公共组件总览》的 `MoeSettingsGroup` 章节。
- 搜索栏进入懒构建的 Sliver 后，筛选状态与输入框必须共用由列表 State 持有的 controller。不能让输入框自有 controller 随滚出卸载而丢失、却继续保留外层查询条件；回归须覆盖输入、滚出卸载、回顶重建、继续筛选。正例：`apps/aicove_flutter/lib/src/ui/features/plugins/widgets/voice_preset_list.dart`；回归：`apps/aicove_flutter/test/ui/features/plugins/settings_surface_layout_test.dart`。

### 可空模型配置的清除语义（2026-09-16）

- 界面传入 `null` 不等于配置实际被清除；`copyWith` 若使用 `value ?? this.value`，显式清除会被当成保留。失效 embedding 配置使用 sentinel 区分未传参与显式 null，只修改已确认需清除的字段，不能顺带改变其他模型字段的语义。
- 回归同时检查点击入口、Provider 当前值、持久化 JSON，以及未传参数时其余配置完整保留。正例：`apps/aicove_flutter/lib/src/features/plugins/memory/memory_config.dart`；回归：`apps/aicove_flutter/test/ui/features/plugins/pages/memory_plugin_detail_page_test.dart` 与 `settings_surface_layout_test.dart`。

### 底部弹窗的末项安全点击区

移动端底部弹窗中的最后一个可点击选项不得与屏幕底边重合。全面屏手势导航可能让视觉上可见的末项落入系统手势竞争区，导致人工点击不稳定。

1. 自定义 `showModalBottomSheet` 内容必须使用 `SafeArea`，并为底部提供至少 24px 的 `minimum` 或等价内边距。
2. 选择类弹窗应在选项自己的 `onTap` 中直接更新上层选择状态，再关闭弹窗；不得仅依赖弹窗 route 的返回值完成唯一一次状态写入。
3. Widget 回归测试需固定窄屏尺寸，并断言最后一个可点击项的底边与屏幕底边至少相隔 24px，同时验证点击后页面主标签立即变化。

### 长列表滚动性能（聊天消息列表等）

以下为 2026-07-13 排查聊天列表滑动卡顿后沉淀的硬约束，违反会直接导致掉帧：

1. **滚动派生状态禁止进 `setState`。** 滚动通知（`ScrollUpdateNotification` 等）每个拖动帧触发一次；若在其中 `setState`，整个列表 widget 每帧全量 rebuild（重算分段、重建 sliver delegate、重绘所有可见气泡）。仅服务局部 UI（如「回到底部」按钮显隐）的派生状态，必须用 `ValueNotifier` + `ValueListenableBuilder` 局部消费，让滚动帧只重建那一个小部件。
   - 反例：`_manualDetachedDistanceToBottom` 曾是每帧 `setState` 的 double 字段（已废除）。
   - 正例：`_showJumpToBottom`（`ValueNotifier<bool>`），滚动回调只写布尔、不 `setState`。见 [chat_message_list_viewport.dart](../../apps/aicove_flutter/lib/src/ui/features/chat/widgets/chat_message_list_viewport.dart) 的 `_syncJumpToBottomVisibility`。
   - 在 build/layout/animation 帧阶段（`persistentCallbacks`/`transientCallbacks`/`midFrameMicrotasks`）写 notifier 值，要推迟到 `addPostFrameCallback`，避免 markNeedsBuild during build；同一帧多个通知用一个 scheduled 标志合并，只注册一次回调。
   - 程序化滚动若用 `_isProgrammaticScroll` 守卫吞掉同步，结束时（清标志处）必须补一次同步，否则局部状态可能永久残留。

2. **列表内图片必须按显示尺寸降采样解码。** 原图直接解码会把数百万像素 bitmap 塞进 ImageCache，滚动进入新缓存区时产生解码/纹理上传尖峰。
   - 照片：`Image.file(cacheWidth:)` / `CachedNetworkImage(memCacheWidth:)` / `ResizeImage.resizeIfNeeded(width, null, provider)`，宽度 = 实际显示宽 × `MediaQuery.devicePixelRatioOf(context)`。
   - 头像：按固定显示尺寸（如 42px）× dpr 限制。
   - **全屏预览 / 画廊 / Hero 用的 `ImageProvider` 必须保持原图**，只对列表内显示的 `Image` widget 降采样，否则放大后模糊。

3. `CachedNetworkImage` 的 `memCacheWidth` 只控内存解码，不改磁盘缓存；不要顺手设 `maxWidthDiskCache`/`maxHeightDiskCache`。

4. **删 `setState` 前先确认没有隐式依赖它的"顺带稳定化"。** 长列表里一次 `setState` 除了刷新它名义上的状态，还会顺带触发整棵列表 rebuild——某些滚动/流式对齐逻辑（如 element 复用、`findChildIndexCallback` 对齐）可能**隐式依赖**这次 rebuild 才能正确收敛。把逐帧 `setState` 改成局部 `ValueNotifier` 时，必须区分：
   - **高频路径（拖动逐帧）**：这是卡顿主因，切断 setState 改走 notifier。
   - **低频路径（ScrollEnd、方向切换、流式内容稳定化）**：保留 setState，维持旧的稳定化 build 语义。
   本项目 `_updateManualDetachedDistanceToBottom({bool isDragFrame})` 就是这样分流的。
   - **务必跑 widget 测试验证**：这类隐式契约静态审查（自查 + 外部模型双审）都抓不到，只有真实 widget 测试能暴露。本次两个回归（`轻微手势脱离`、`流式气泡锚点 identical`）都是 `flutter test` 才发现的。

5. **滚动派生的显隐阈值用"手势时刻采样值"，不要用任意时刻的实时几何值。** `reverse:true` + `center` 双 sliver 列表的 `position.pixels - minScrollExtent` 在内容被动变化（如新消息撑高）时会算出很大的几何值，若据此实时判断按钮显隐会误触发。正确做法是保留一个仅由用户滚动事件更新、带去重的采样字段（本项目 `_manualDetachedDistanceToBottom`）作为显隐输入。

### 首屏加载与缓存后台维护（时间线缓存等）

以下为 2026-07-19 排查「进入聊天页记录要等一会儿才显示」后沉淀的硬约束（根因：时间线缓存的图片尺寸升级在主 isolate 整图解码、失败永不收敛且自激循环、慢任务与首屏读取共用串行队列）。完整契约与修复设计原在 Trellis 任务 07-19-chat-first-paint-cache（已随 Trellis 退役归档至备份包）。

1. **主 isolate 禁止整图解码。** 纯 Dart `image` 包的 `decodeImage` 对数百万像素图要几百毫秒到几秒，放在主 isolate 会直接卡首帧/掉帧。需要图片元数据（宽高等）时：原生平台用 `Isolate.run` 包裹的后台探测（头信息优先、整图回退、字节上限在**大块分配前**预检）；Web 无 isolate，用条件导入的桩静默降级，绝不能退回主线程解码。正例：[image_dimension_probe/](../../apps/aicove_flutter/lib/src/features/chat/services/image_dimension_probe/)。

2. **后台维护任务必须收敛，通知必须以实际变化为条件。** 「缺元数据→补一次」类维护若失败后无终态标记，会每次读缓存都重跑；若完成后无条件广播变更，会触发「通知→重读→再调度」自激循环。硬规则：
   - 失败来源记终态（attempted，按**稳定来源身份**如 raw id＋内容指纹标识，不能用会漂移的投影 UUID）；
   - 无实际变化的维护轮**静默结束**：不替换缓存、不写库、不发通知；
   - 派生成功的结果写回持久层（本项目：宽高 CAS 写回 `message_blocks.data`），否则重启后重复付费；
   - 淘汰终态记录时不得逐出「当前数据中仍缺元数据的活跃来源」，否则逐出-重探测死循环。

3. **读路径必须纯读。** `peek`/`watch` 首值这类读接口不得顺带调度维护任务，也不得排入与写库/维护共用的串行队列——热缓存命中就直接返回。订阅型接口要**先建立（缓冲）订阅、再取首值**，否则「首值与监听建立之间」完成的变更会丢通知，UI 停在旧值。

4. **CAS 写回防并发污染。** 后台任务把探测结果写回 DB 时，探测期间行可能已被外部写路径替换。写回必须带乐观锁（where 含 data 原文全等）并校验受影响行数；全部 stale 时重读行按来源精确比较——来源未变（仅其他字段变了）就用新原文重试一次，来源已变才丢弃，否则同来源会被终态标记永久压死。

### 全局设置 Provider 的订阅粒度（2026-07-20 沉淀）

`appSettingsProvider` 是全应用共享的大对象；页面/大型列表整颗 `ref.watch(appSettingsProvider)` 会让任何一个设置字段变化（音量、TTS 开关…）重建整页/整列表。硬规则：

1. **热区 widget（聊天页、消息列表等）只允许字段级订阅**：`ref.watch(appSettingsProvider.select((s) => s.valueOrNull?.某字段))`；一个 widget 用几个字段就写几个 select。正例：[chat_message_list.dart](../../apps/aicove_flutter/lib/src/ui/features/chat/widgets/chat_message_list.dart) 的 `uiScaleFactor` / `messageFormatConfig`，[chat_page.dart](../../apps/aicove_flutter/lib/src/ui/features/chat/pages/chat_page.dart) 的 `chatBackgroundColor`。
2. **select 的字段类型必须有值相等性**。配置类（如 `MessageFormatConfig`）若不实现 `==`/`hashCode`，settings 每次重建新实例时 select 照样触发重建，粒度优化失效。新增配置类必须实现值相等（含 List 字段逐项比较）。
3. 守卫测试模式：用 `ChatMessageList.onDebugListItemCountChanged` 之类的 build 计数钩子断言「无关字段变化 build 计数不增长、相关字段变化必须增长」。正例：`test/ui/features/chat/widgets/chat_message_list_settings_select_test.dart`。

### 流式投影双通道契约（2026-07-21 沉淀，任务 07-20-stream-active-bubble）

流式期间 UI 投影分两条通道，禁止回退到「每 flush 全量替换时间线」的旧模式：

1. **结构转移走时间线**（增量 diff 写：removed=id 差集、upsert=新 id/视觉变化；空 diff 不触 cache）：占位出现/钉底、壳出现/换 id、chunk seal、揭示放行、pendingAudio、finalize、reset/interrupt。窗口通知数必须与结构转移数同阶（守卫：characterization 载荷 spy 与 100 delta 用例）。
2. **活跃尾文本增长走瞬态通道**（`activeStreamProjectionsProvider`，单 owner map）：`(generationSeq=runId, writeEpoch)` 字典序 CAS，旧流 publish/clear 均不得影响新流；`tailText` 只能取自物化管线的 active descriptor（已 sanitize），禁止另建第二套解析；顺序契约＝先写时间线后 publish、reset/remove 先 clear 再撤壳。
3. **消费端**：气泡在列表 presentation 层包 Consumer select 按 (conversationId, tailMessageId) 命中；列表用 `listenManual` 长驻窄信号（仅同尾同相位文本增长触发）只调度视口稳底——纯 delta 期间不 rebuild widget 的场景**禁止依赖 build 期 `ref.listen`** 做旁路副作用（首个变化后可能失联，实测踩坑）。
4. **首次出现 vs 增长的分工**：壳首次出现是结构事件，由 didUpdateWidget 稳底路径负责；窄信号只管增长步。窄信号稳底必须带多帧＋长尾（260ms）重试——布局下一帧生效且流末尾无后续信号，实测单次调度留 ~14px 残差。
5. **开关语义**：`streamProjectionPolicyProvider` off＝严格回滚面——机制分流、气泡 Consumer、列表订阅整组关闭，off 子树与旧实现一致（守卫：settings_select「off 下通道发布不重建/不上屏」）。基线测试必须显式钉 policy，不得依赖全局默认。
6. **用户滚动时必须冻结活跃气泡的流式 UI 投影。** `detached` 和 `_isUserScrollActive` 只阻止自动贴底及列表结构重投影，并不会自动停止活跃气泡 Consumer 随每次通道发布重新排版；手指拖动/惯性滚动期间若仍排版增长文本，依然会与滚动布局抢帧。接管滚动时先保存当前可见投影再暂停消费，禁止退回较短的壳文本；滚动结束后先让延迟的结构更新落位，下一帧再一次性追平最新投影。守卫测试必须在手势未 `up()` 时发布新投影，并分别验证窄屏与宽屏。正例：[chat_message_list.dart](../../apps/aicove_flutter/lib/src/ui/features/chat/widgets/chat_message_list.dart) 的 `_chatVisibleStreamProjectionProvider`、[chat_message_list_viewport.dart](../../apps/aicove_flutter/lib/src/ui/features/chat/widgets/chat_message_list_viewport.dart) 的 `_markUserScrollActive` / `_markUserScrollEnded`。

### 纯渲染层长高与入场收敛窗（2026-07-21 沉淀，任务 07-20-chat-entry-bottom-anchor）

进入会话后表情/图片异步解码长高、字体加载、视口尺寸变化等**纯渲染层 extent 变化不产生 didUpdateWidget**，follow-latest 的稳定化收不到信号，列表会停在「差一段」的位置。修复契约：

1. **唯一正统信号是 `ScrollMetricsNotification`**：它**不是** `ScrollNotification` 子类，必须独立挂 `NotificationListener`；框架在帧后 microtask 合并派发，此时挂普通 post-frame **不保证有下一帧**——处理器须当场 `jumpTo`（自会请求新帧），不做 debounce（latest state wins＋距离阈值幂等短路；jumpTo 只改 pixels 不改内容尺寸，不自激）。
2. **消息追加与纯渲染层长高在 metrics 层完全同构，不可无差别重锚。** 贴底时新 AI 消息不拉底是既有产品裁决（auto_scroll_guard 锁定；只有同尾可行动布局变化、输入区高度变化、pinLatestTail 才稳底）。重锚必须收窄到**入场收敛窗**：初始置底开窗；首次实质性结构变化/用户手势/历史分页锁一次性关窗；切会话复位重开。窗内位移定义上只能来自纯渲染层。
3. **关窗判据＝有序消息 ID 全序列逐位比较**（codex 审查 R1：只比 length/首尾 id 会漏判等长中间替换/重排）；**列表实例变化但 ID 结构等同的刷新不得关窗**——真机上入库回流常发同内容新实例列表，误关则修复失效。contextStart 类 nullable 锚点先 trim 规范化再比较。
4. **动画期的结构性长高用生命周期事实静默，禁止用帧时间戳猜时长**（codex 审查 R2：`currentSystemFrameTimeStamp` 是引擎裸时间戳——warm-up 帧跳变、不随 `timeDilation` 缩放、长帧穿透固定余量）。正例：`AnimatedMessageItem.onFinished`＋serial 对账；完成回调须经 post-frame＋`scheduleMicrotask` 延迟失效，才能存活过完成帧自身的 metrics 通知（通知的 microtask 在布局期入队，早于 post-frame 里再入队的 microtask）。
5. 实现与测试全貌见 [chat_message_list_viewport.dart](../../apps/aicove_flutter/lib/src/ui/features/chat/widgets/chat_message_list_viewport.dart) 的 `_handleScrollMetricsNotification` 与 `test/ui/features/chat/widgets/chat_message_list_metrics_reanchor_test.dart`（10 用例：核心重锚/多次长高/脱离/分页/视口/负向锁裁决/R1 正反判据/空时间线动画/programmatic follow-up）。

### 流式多模态语音占位与并发就绪（2026-09-04 沉淀）

表面原因：模型生成长文本时，虽然 `<tts>` 很早就已输出完毕，但语音条一直显示「加载中」无法点击播放，直到模型把全部文字打完才变可播。

真实原因：
1. 语音占位在流中出现后并未启动合成，原实现将 TTS 解析压到流式全部完成后的收尾阶段；
2. 即使流中提前触发合成并拿到 URL，每帧 text delta 仍由 `_rebuildMessage` 硬编码重建物化为 pending 态（清空 URL），把已就绪状态冲刷回加载态；
3. 流式收尾时若语音已提前就绪，`pendingStreamTts` 变空会导致后补多模态误判为「流中无 TTS」而重复插入一条新语音消息；
4. 流中提前就绪的投影消息其 `sourceMessageId` 最初为临时 ID，在 `rawMessage` 真正入库后若未执行 `syncRawSupplementsFromTimeline`，SQLite 无法落盘已就绪的音频 payload；
5. TTS Future 可能跨越流式收尾、中断、重试或删除边界；若没有明确交接态和 raw 源存活检查，迟到结果会覆盖终态或复活已删语音；
6. TTS 失败回退成 `TextBlock` 后仍是受管理的原 TTS 段；若将它误当普通流式文本锚点，后续表情/图片的插入位置会错位。

硬约束：
1. **流中即时触发异步合成**：流式阶段解析到闭合的 `</tts>` 后立即调度后台解析，并按 `message.id` 单飞防重；
2. **流式物化必须保留就绪状态**：`_rebuildMessage` 与 `_isPersistableProjectedTimelineMessage` 必须保留已有 `AudioBlock` 的就绪 URL、durationSeconds 与 `BlockStatus.success`，禁止被后续 text delta 刷回 pending；
3. **后补交付防重复判据**：后补多模态必须按「流中是否存在 TTS 占位」（`streamDelivery.hasAudioPlaceholders` / `hasStreamTts`）而不是「当前是否仍为 pending」决定是否后补，已就绪的流中语音绝不能重复补发；
4. **收尾时显式回写持久层**：流式收尾 `rawMessage` 落库后必须立即触发 `syncRawSupplementsFromTimeline`，保证提前就绪的多模态数据正确落入 SQLite `rawPayload`；
5. **异步结果必须经生命周期门控**：用 streaming → committing → committed / discarded 显式交接；commit 后的迟到回写前后均校验 raw 源仍未删除/替换，中断/reset 则立即作废 token；
6. **多模态锚点要按语义分类**：`streamTextMessageIds` 必须排除全部受管理 TTS ID，包括已成功音频和失败回退文本，避免后补表情/图片把 TTS 段当成普通文本锚点。

正例：[chat_actions_stream_placeholder.dart](../../apps/aicove_flutter/lib/src/features/chat/chat_actions_stream_placeholder.dart) 的 `updateResolvedAudio` / `_enqueueCommittedTtsResolution` / `_rebuildMessage`，[chat_actions.dart](../../apps/aicove_flutter/lib/src/features/chat/chat_actions.dart) 的 `_scheduleStreamPendingTtsResolution` 与 `_commitStreamDelivery`，[chat_history_store.dart](../../apps/aicove_flutter/lib/src/features/chat/services/chat_history_store.dart) 的 `isRawMessageActive`。

### 视口跟随的补位必须在布局期完成，禁止靠帖后 jumpTo（2026-09-04 沉淀）

表面原因：流式生成时气泡「一卡一卡」、历史消息加载「卡」，直觉归因于 build 开销（07-13 已切掉拖动逐帧 setState 却没根治）。

真实原因：`reverse: true` + `center` 双 sliver 列表里，活跃区在 center 之前（GrowthDirection.reverse）。内容长高时 `minScrollExtent` 变小而 `pixels` 不变，这一帧先把新内容画到视口底部之外，再由 post-frame 的 `jumpTo(minScrollExtent)`（外加 3 帧 + 260ms 重试链）补位。每次长高都是「错一帧→跳一下」，帧率再高也是抖的——这是**画面错位**问题，不是耗时问题，profile 里看不出来。

硬约束：

1. **贴底跟随的位移修正走 sliver 的 `scrollOffsetCorrection`**（`RenderViewport` 会在同一帧内重新布局），帖后 `jumpTo` 只能作兜底，不能作主路径。正例：[chat_end_anchored_sliver.dart](../../apps/aicove_flutter/lib/src/ui/features/chat/widgets/chat_end_anchored_sliver.dart)。修正量以本 sliver 自身 scroll 空间表达，center 前的 sliver 由 viewport 自行取反——符号写反会触发「30 次布局循环无共识」断言。
2. **修正 sliver 必须包在 `SliverPadding` 外面**，否则只把列表末端贴到视口底、不含 bottom padding（首次接线漏掉 70px 就是这个原因）。
3. **「该不该跟随」的裁决留在 widget 层**：sliver 只在 `arm()` 后修正；在原本调度帖后稳底的位置 arm，在用户手势 / 历史分页 / 切 detached / 不跟随的结构变化处 disarm；一帧内无修正自动解除，入场动画期用生命周期事实延长保持（不用时间猜）。
4. **守卫测试要只 pump 一帧后读渲染树位置**（`tester.getBottomLeft`），而不是读 `controller.position`——帖后 jumpTo 已改 offset 但渲染要下一帧才生效，只有渲染树读数能暴露错帧；且单轮增量必须明显超过 bottom padding，否则测试没有区分力（正例 `chat_message_list_stream_follow_test.dart` S1b）。
5. **配套项**：`Decoration` 子类默认引用比较，父组件每次 rebuild 新建实例就会让 `RenderDecoratedBox` 丢 painter 重画——自定义装饰必须实现值相等（`MoeG2Decoration` 已补）；纯函数的重计算（分段正则、时间线合并排序）按输入身份/内容记忆化，不要每次结构变化对全部消息重跑。

### Android 后台生成必须由真实任务持有守护（2026-09-05 沉淀）

表面原因：前台守护服务显示正在运行，但切到后台后聊天生成仍会中断。

真实原因：旧实现只把守护绑在「主动回复」开关上，与正在运行的 Dart SSE 生成没有生命周期关系；原生服务既不持有 CPU 唤醒锁，又使用有后台时长配额的 `dataSync` 类型；主回复结束后继续运行的 TTS/生图也没有独立保活。

硬约束：

1. **守护所有权跟随任务，不跟随页面或功能开关。** 聊天发送、重试、重生成、延迟 TTS/生图都必须在开始时获取生成租约，在成功、失败或中断后释放。正例：[android_keep_alive_manager.dart](../../apps/aicove_flutter/lib/src/core/services/android_keep_alive_manager.dart)、[chat_actions.dart](../../apps/aicove_flutter/lib/src/features/chat/chat_actions.dart)、[chat_tts_handler.dart](../../apps/aicove_flutter/lib/src/features/chat/services/chat_tts_handler.dart)。
2. **并发任务用引用计数，禁止单个 `bool` 相互覆盖。** 只有最后一个租约释放后才能结束生成守护；主动回复的长期守护与生成临时守护必须独立。
3. **前台服务类型必须符合真实用途与 target SDK 限制。** 长耗时 AI 生成不得冒用 `dataSync`；使用 `specialUse` 时必须同时声明权限、service type 和 subtype property，发布到应用商店前另行核对政策申报。正例：[AndroidManifest.xml](../../apps/aicove_flutter/android/app/src/main/AndroidManifest.xml)。
4. **CPU 唤醒锁必须有界且可回收。** 正常结束主动释放，原生服务还必须有超时兜底，防止 Dart 引擎异常退出后永久占电。正例：[PersistentGuardService.kt](../../apps/aicove_flutter/android/app/src/main/kotlin/com/example/aicove_flutter/PersistentGuardService.kt)。
5. **验收看真实后台运行，不只看服务“存活”。** 真机测试必须同时记录 Home 后的前台应用、进程 PID、FGS type、唤醒锁、流式终态和回到页面后的完整消息；国产 ROM 仍可以代理未加白名单应用的唤醒锁，这是必须显式验证的系统前置条件。

## 测试相关

### widget 测试中的真实 IO 必须包 `tester.runAsync`（2026-07-20 沉淀）

`testWidgets` 运行在 FakeAsync zone：真实的文件/网络 IO Future **永远不会完成**，`await` 它会让单个用例挂满超时（本项目曾有测试因此每次挂约 10 分钟拖慢全套）。硬规则：

1. 测试体里凡是真实 IO（`Directory.createTemp`、读写文件、`clearPersistent` 之类的持久化清理），必须包在 `await tester.runAsync(() async { ... })` 里。
2. 被测 widget 内部 fire-and-forget 的 IO 不受影响（没人 await 它），无需处理。
3. 跑测试统一带 `--timeout 60s`（或按需更短），让挂起用例快速失败而不是拖满默认超时。
4. 无断言、纯 print 的调试测试不允许提交；调试完即删。

### finder 默认 skipOffstage 会漏掉「已构建未上台」的组件（2026-07-21 沉淀）

`find.byType`/`find.byWidgetPredicate` 默认 `skipOffstage: true`，沿 `debugVisitOnstageChildren` 遍历——**滚动列表 cacheExtent 区（已构建未绘制）的子项与高度为 0 的子项（如入场动画 `SizeTransition` 卡在第 0 帧）都会被判为 offstage 而「隐身」**，finder 返回 0 但组件和其中的图片解码链路其实全程健在。曾造成两个测试用例被误判为「组件消失」并长时间排障。硬规则：

1. 断言「组件是否存在/尺寸如何」而非「是否可见」时，finder 显式传 `skipOffstage: false`。
2. 诊断输出（dump 树内组件清单）同样要 `skipOffstage: false`，否则 dump 本身也会漏报。
3. `tester.drag` 松手带惯性速度（bouncing 物理会 fling 出 cacheExtent 使组件真被回收）；需要精确位移时用手工手势：分步 `moveBy`＋静置超过速度采样窗（>100ms）再 `up()`，抬手速度≈0。

### 首批历史恢复必须区别于新消息入场（2026-09-05）

表面现象是历史加载慢、进入后停在最后一条用户消息附近。复现确认：异步历史首次到达时，`_latestAnimatedAt == null` 会把全部历史误认为新增消息，统一从零高展开；首次贴底测到的是展开前尺寸，动画期又屏蔽尺寸变化重锚。联系人原有“预热”仅包含头像，并未准备聊天记录。用户数据上的实际秒级耗时仍需真机测量，不可把动画问题当作全部耗时的唯一原因。

1. **明确传递首批加载状态**：`ChatPage` → `ChatMessageList.isInitialLoading`，首次历史返回跳过新增动画；不能仅凭“旧列表为空”判定，否则已加载空会话中的真正新消息也会丢失入场行为。
2. **历史首屏在布局期贴末尾**：复用 `ChatEndAnchoredSliver`，不依赖帧后 `jumpTo` 才显示正确位置；手势/分页守卫仍优先。
3. **预读必须有界、只复用正式缓存**：`ChatPageQueries.warmEntryMessages` 每容器只执行一轮，最多三个候选会话，每场最近 20 条 raw 消息；串行、热命中跳过、失败不阻断实际打开。不再创建第二份持久化消息源。
4. **测试检查第一帧的渲染位置**：同时覆盖冷历史返回与热缓存首帧，360px/1000px 各验；断言历史无 `AnimatedMessageItem`，最后一条 AI 消息底部已在输入区上方，再断言稳定后没有偏移。

正例：[chat_message_list_timeline.dart](../../apps/aicove_flutter/lib/src/ui/features/chat/widgets/chat_message_list_timeline.dart)、[chat_message_list_viewport.dart](../../apps/aicove_flutter/lib/src/ui/features/chat/widgets/chat_message_list_viewport.dart)；测试：[contacts_list_content_warmup_test.dart](../../apps/aicove_flutter/test/features/chat/presentation/widgets/contacts_list_content_warmup_test.dart)、[chat_entry_warmup_test.dart](../../apps/aicove_flutter/test/features/chat/application/chat_entry_warmup_test.dart)。

### 生成不停与手势优先：控制争抢和排版耗时分开修（2026-09-05）

本条覆盖上文“用户滚动必须冻结投影”及“每个增量必须多帧＋260ms 重试”的旧约束。用户明确要求正文继续增长，只有视窗不自动跟随；冻结正文不是这个需求的解法。

1. **所有代码滚动让位于按住、拖动和惯性。** `Listener` 从 PointerDown 即使旧补位与动画完成回调失效，多指用集合追踪；真正方向/位移事件才进入 detached。`ScrollStart` 可能在没有位移时发生，不能据它永久脱离；`ScrollEnd` 也可能由布局/程序产生，不能无条件重新贴底。滚轮接管不依赖触摸事件。正例：`chat_message_list_viewport.dart` 的 `_canFollowLatest` 守卫、交互序号和主视口 depth 过滤。
2. **接管时保存“上次真正画出的分区”，不能按最新控制器状态重新计算。** `pinLatestTail` 改变未必触发列表重建；重算会在下一次结构事件把用户消息搬到另一 sliver，画面跳一个气泡高度。固定 center 后尾段/尾图向下长高天然保持已有内容坐标；按 minExtent 差额 `jumpTo` 反而推走画面。守卫复现曾测得尾图变化把阅读位置错误移动 241.5px。正文、新分段和就绪媒体均可正常更新，不需要滚动结束后的 220ms 延迟刷新链。
3. **同帧多次 arm 只能合并回调，不能让新序号失去清理。** `ChatEndAnchorController` 原先先递增序号再跳过重复注册，旧回调因序号不同直接退出，armed 永久残留；现读最新状态清理。测试：`chat_end_anchored_sliver_test.dart`“同一帧重复 arm”。
4. **几何正确不代表耗时合格。** 超长单个 `Text` 每次追加会重排整段；含硬换行的长消息用 `IncrementalMessageText` 复用稳定段落，保留短文本/无硬换行的原路径。空行不能直接用空 Text 替代：放大字体时行高不同，须保持正常字形度量；原始全文与读屏语义不变。样式变化、替换/缩短、空行/CRLF、混合双向文本及窄宽屏缩放均须验证。
5. **真机性能按刷新率算预算，并拒绝无效采样。** 120Hz 是约 8.33ms，不是 16.67ms；锁屏后台 `FrameTiming` 可能为 0，不能报成零掉帧。`tool/chat_scroll_probe.dart` 校验有效帧数、实际移动次数和 detached 次数；同机合成流中，段落复用前后拖动 UI P95 11.138ms → 3.798ms，超预算 124/836 → 0/949，拖动整列表重建均为 0。该对照只证明长文本排版优化，不代表真实供应商解析与多模态解码全部链路。

主要回归入口：`test/ui/features/chat/widgets/chat_message_list_stream_follow_test.dart`（360/1000px 实际视口、首帧几何、连续增量与换尾、惯性基线轨迹、回底中断、多指和滚轮、图片长高）；`test/features/chat/presentation/widgets/incremental_message_text_test.dart`。


### 流中媒体回填不能提前持久化投影映射；测试必须开启真机外键（2026-09-05）

表面现象：几千字回复期间第一条语音一直加载，整轮结束才可播放，容易误判为 TTS 没及时发请求。实际复现：`updateResolvedAudio` / `updateFallbackText` 调用持久路径 `replaceMessages`，写入引用尚未落库 `_pendingRawSourceId` 的 `message_projection_mappings`；真机 `foreign_keys=ON` 抛 SQLite 787，缓存安装与通知因此没有执行。内部时间线却已变为 success，后续增量也不会再补通知，直至 commit 才恢复。旧测试 `NativeDatabase.memory()` 没开启外键，造成假通过。

1. **流中原始消息未落库时，媒体成功/失败回填统一用 `replaceMessagesTransient`**；不得提前写投影映射，不得为绕过外键而提前持久化半条 raw 或关闭外键。正式 commit 和已提交后的迟到结果仍走原持久路径。
2. **涉及 raw/投影交接的测试显式 `PRAGMA foreign_keys = ON`**，并检查流中无该 raw 的投影记录、结束后 `foreign_key_check` 为空；测试连接不能比真机更宽松。
3. **区分请求、回填和可点击三件事**：在 HTTP 边界拦截外网但保留真实 TtsService，请求须在模型结束前发出；用闩锁保持模型未完成并输入约 8800 字，检查音频原位 success；组件另测 pending→success 后可点击播放，390px/1200px 各验。

正例：[chat_actions_stream_placeholder.dart](../../apps/aicove_flutter/lib/src/features/chat/chat_actions_stream_placeholder.dart)；回归：[chat_actions_test.dart](../../apps/aicove_flutter/test/features/chat/chat_actions_test.dart)、[audio_player_widget_test.dart](../../apps/aicove_flutter/test/features/chat/presentation/widgets/audio_player_widget_test.dart)。

### 角色隔离不止是文件分目录，页面和工具也必须固定 owner（2026-09-05）

角色 MD 文件正确分开后，新增复现测试仍抓到“页面复用为角色 B，但草稿还是 A”的泄露：State 只在 initState 读取，owner 参数更新不会自动清空旧内容。

1. **有 owner 的页面处理 didUpdateWidget**：owner 变化即清空旧草稿，并用 generation 校验异步读写、弹窗返回结果，禁止迟到结果回填另一角色。
2. **工具在请求装配时绑定 owner**：schema 与绑定 handler 同时保存，不用全局插件上的最近角色字段，也不从工具参数或当前页面反推 owner。
3. **隔离测试覆盖界面与执行链**：除了 A/B 文件独立，还要测同名角色、跨角色事件 ID、A 请求后创建 B 工具、删除/关闭后的旧闭包、页面 owner 复用。真实工具循环测试只替换网络边界，验证正文确实回传给模型。

正例：[contact_memory_page.dart](../../apps/aicove_flutter/lib/src/ui/features/character/pages/contact_memory_page.dart)、[contact_memory_tools.dart](../../apps/aicove_flutter/lib/src/features/memory/application/contact_memory_tools.dart)；回归：[contact_memory_page_test.dart](../../apps/aicove_flutter/test/ui/features/character/pages/contact_memory_page_test.dart)、[contact_memory_plugin_test.dart](../../apps/aicove_flutter/test/features/memory/contact_memory_plugin_test.dart)。

### 日志筛选与导出必须覆盖真实数据入口（2026-09-05）

1. **异常过滤不能只过滤 AppLogger。** 网络记录必须先按 `ok` 映射级别，再应用同一过滤器；否则界面写“只看异常”，仍显示成功请求。正例：`apps/aicove_flutter/lib/src/ui/features/settings/pages/log_formatters.dart`；回归 `log_frontend_summary_test.dart`。
2. **导出服务存在不代表按钮已接入。** 原 TraceExportService 没有 UI 调用者；单轮导出必须用真实按钮联测验证通过 Port 传入所选 traceId，而不是继续导出当前内存 API 列表。重复请求复用 turnId 时，显式 traceId 必须优先，不能再用 turnId 的 OR 条件把其他 retry 合并。正例：`trace_export_service.dart`、`log_viewer_page.dart`；回归 `trace_export_service_test.dart`、`log_viewer_page_scroll_test.dart`。
3. **需要等待 widget 内部真实文件读取完成的测试，启动该读取的 pump/tap 也放入 tester.runAsync。** 只在旁边 runAsync 等待 30ms，不会解开此前在 FakeAsync 中启动的 IO；会误报“对话未选中/导出没调用”。这补充上方 IO 规则：不等待的 fire-and-forget 可不处理，断言依赖其结果则必须处理。
4. **可见性验收用实际小屏宽度。** 390px 测试通过，仍可能在约 347dp 的手机上把最常用的异常筛选挤到屏幕外；前端筛选保留水平滚动，但“全部/只看异常”放在前两项，并用 320px 的按钮几何断言守卫。
5. **号码兜底脱敏不得破坏诊断结构。** 原电话号码正则将 `tr_1772424000000000` 变成 `tr_***`，还会遮掉日期，导致导出后无法可靠对齐。只对严格匹配系统 Trace/operationId 格式和标准 ISO 时间字段开例外；不是所有名为 id/time 的任意值都可信，授权头、电话号码和错误正文仍必须脱敏。回归：`trace_export_service_test.dart` 同时断言密钥被遮盖、关联编号与时间保持不变。

### 单气泡流畅不能代表分段流畅；跳过动画不是延期播放（2026-09-05）

1. **分段验收走真实生成投递链。** 单个 ActiveStreamProjection 长高不会覆盖反复封段、新增气泡、生成占位及最终交接。使用内存数据库（开启外键）和模型输入替身驱动 ChatActions；同次回复的各气泡应共享 sourceMessageId，拖动及惯性期间确实继续新增。
2. **入场资格在消息到达时裁决。** 跟随状态跳过动画必须同时放弃 pending ID，不能留待后续重建。否则手势接管改变 pinLatestTail 后，第二段出现会给第一段补播 AnimatedMessageItem，实测额外跳动 43.7px。正例：`chat_message_list_timeline.dart` 只登记 `_shouldAnimatePendingMessage` 为真的新增消息。
3. **pixels 对齐不等于速度归零。** 布局期修正可能把位置放到底部，但旧回弹仍活动，继续将画面带离底部。仅在 `_canFollowLatest` 且非用户拥有视口时允许同位置 jumpTo 停止残余物理活动；真实拖动/惯性必须与无生成基线同轨迹，不能顺手截断。
4. **待展示分段也算 dirty。** `_flushNow` 会清 dirty；有已完成但仍在等展示延迟的分段时，仅排定时器不够，下一次回调会被提前退出。必须保留待提交状态，不能依赖下一个模型 delta 来唤醒展示。正例：`chat_actions_stream_placeholder.dart` 的 hasHiddenSealed 分支。
5. **真机几何读数等布局，不猜时钟。** 手势识别/启动阈值通过后再采“已接管”误差；每步等 endOfFrame 再读 RenderBox。只等 16ms 会读到旧画面而误报 3px，单看 ScrollPosition 则会漏掉动画造成的位移。`valid` 表示采样充分，`behaviorPassed` 才表示几何合格；新气泡引起的列表重建不是逐拖动帧重建。

回归：`apps/aicove_flutter/test/ui/features/chat/widgets/chat_message_list_segmented_delivery_test.dart`（360/1000px、0/0.3s、连续新增 15 段、回底中断/恢复、12 段增长时惯性基线）；真机入口：`apps/aicove_flutter/tool/chat_scroll_probe.dart`。

### 压缩不只是写摘要：边界、空输出和旧轮次都可能让内容丢失或回流（2026-09-05）

1. **边界等于最后一条，也必须切出空列表。** 原判断 `markerIndex + 1 < length` 会回流整个旧话题；真实 SQLite 复现后，两个历史读取器均改为找到 marker 就切片，允许结果为空。

3. **压缩提交与记忆写入分开报告。** 摘要和边界同事务，MD 使用 pending 可补写；撤销同时取消未完成归档，不让稍后重试把已撤销的操作补回来。摘要内容参与版本 ID，不同修订不能覆盖成同一条记录。

5. **预算截断不代表请求仍完整。** 原 token 裁切器在 system 超预算时只返回 system；新增摘要可能触发这一分支。压缩请求装配必须检查预算与用户输入仍存在，不能拿没有当前问题的请求继续调用模型。

### 导入导出成功不等于完整、安全或原子提交（2026-09-06）

1. scope 必须同时约束实际导出的字段/文件与导入写入，不能只写 manifest；本地当前不支持的范围明确拒绝，不允许“勾选记忆但只有聊天和卡”。旧包可能标签与内容不一致，导入仍使用请求范围和包声明的交集及字段白名单。
2. ZIP 条目和 JSON 中的附件引用是两条独立路径边界，都要检查；不能只阻止解压的 `../`。archive 3.6.1 的 Archive 会合并同名条目，必须在原始中央目录/本地头上查重复、模式、声明大小与路径一致性；路径预检先于 verify:true 引发的解压。声明大小限制不是强制流式内存上限。
3. DB message/block 主键全局唯一，不能因为 conversation 不冲突就直接 upsert。新建副本重映射全部相关ID；其它跨owner冲突拒绝整批，不能偷走另一角色的记录。三个仓库必须使用同一AppDatabase事务；附件按任务独立目录，失败清理仅该目录，派生图片缓存不在事务里异步启动。
4. UI进度是观察者，不能以销毁后ref异常打断数据提交，尤其done事件已经在提交后。组件加mounted守卫，服务隔离观察者异常；清理临时目录失败也不能把已生成有效备份标成数据失败。
5. 每次导出使用独立临时目录、UUID输出名与独占目标保留，写partial并flush后rename；不依赖角色名+日期或毫秒时间碰运气。测试必须实际比较旧文件字节、两个并发包可读性，以及带已复制附件的失败回滚，不能只看结果计数。

### 绘图配置快照不能只改入口名称（2026-09-06）

### 气泡补写失败不能破坏原始消息块（2026-09-06）

1. 更新messages、删除旧message_blocks、插入新blocks必须在同一事务内；不能假定每个调用方都有外层事务。否则投影补写报错时，会从“显示更新失败”扩大为原始正文/工具块被删空，或payload先改、blocks未改。
2. 在统一单消息写入函数保证原子性，已有父事务时允许嵌套，父事务失败仍须撤销子写入。UI缓存/映射/预览不因此自动具备同一事务保障，不将单消息原子性宣称为整轮完全一致。
3. 回滚测试必须注入首块、后续工具块、DELETE及外层摘要失败；校验原DB行/blocks/模型上下文都保留，再去掉故障重试验证不是跳过写入。SQLite测试开启外键。

正例：`apps/aicove_flutter/lib/src/features/chat/services/chat_history_store.dart` 的 `_upsertSingleMessage`；`test/features/chat/chat_history_truth_audit_test.dart` 的 A10（三故障点）和 A11（父事务失败），先红后绿。并行开发时用冻结副本对照修复前后，不原地回退别人正在修改的文件。

### 聊天媒体备份与导入来源不是气泡操作目标（2026-09-06）

1. DB媒体可能保存在多种raw_payload形态；导出提取必须和真实还原优先级一致，避免漏图/语音或恢复已被高优先级保存形态覆盖的旧媒体；覆盖也约束原message_blocks，不能简单求并集。用户消息不消费assistant专用补充材料。复用标准附件块时原始message.content和源DB不得改变，也不得把缓存气泡文本导成新raw消息。
2. 加附件块后渲染会走blocks，需补原正文TextBlock避免正文消失；同时保留重复媒体的出现次数，但同一个文件只打包一次。只停止拷贝文件不算排除图片，base64也必须受选项约束。
3. DB sourceMessageId记录导入来源；passthrough气泡的sourceMessageId则是后续操作要定位的当前raw.id。这两个语义不能混用，否则新建副本的语音气泡仍指原角色。data.id与外层DB block.id也必须同步重映射，不能只查外层ID就宣布副本正确。
4. 媒体还原验收必须经消息行+blocks的真实DB converter再进projector，断言文件字节、原正文、时间、归属与源数据不变；只用MessageConverter.fromDb(row)而不加载blocks，会把正确恢复的标准附件误报成丢失。保留导出前实际存在媒体的断言，不能靠降低期望让测试变绿。

### 编辑草稿不能提前改变raw历史（2026-09-06）

### 聊天块写库成功不代表聊天可读取（2026-09-06）

### 文件与表情不能只按图片和语音的路径字段处理（2026-09-06）

### 备份索引的字符串唯一性不等于落库唯一性（2026-09-06）

1. 实测两个不同孤立UTF-16代理项ID，Dart集合认为不同，SQLite UTF-8绑定却替换为同一字符，导致2角色变1角色、聊天混合。角色/消息/块及非空来源ID必须能无损UTF-8往返；不能自动替换后继续写。正常中文/合法代理对须有正向回归。
2. 可选source_message_id为空白表示未知，不是所有消息共用的去重键。空来源按缺省回退该条原ID；非空非法来源拒绝，避免两条新消息在merge中只剩一条。DB来源标识不要求存在于当前包的角色清单，它与message.conversation_id语义不同。
3. 预览和导入必须共用基础索引校验。读取聊天时，角色/消息ID和归属、明确给出的总数必须自洽；不能where过滤掉孤立消息后假报成功。统计缺省/null仍可兼容，统计一致不是签名或真实性证明；只选合法A时不验证未选B的具体坏块内容，但基础索引损坏不承诺部分抢救。
4. 原生unknown占位与不支持的具名内容类型必须区分。不能把translation/citation/video/未来类型静默变成占位并宣称完成；工具/代码/错误记录只做领域解码，不执行内容。测试数据要补真实工具字段和正确统计，防止测试在错误的层提前失败。

### SQLite能存的时间不一定能显示（2026-09-06）

SQLite整数范围大于Dart DateTime的毫秒范围；导入不能只做`as int`就宣称恢复成功。基础角色/消息时间在写入之前检查整数及±8640000000000000毫秒边界，预览与实际导入共用验证。负数/零和合法边界须正向覆盖；不要把越界值夹到边界或改成现在。旧包缺省时间的已有回退不等于恢复原始时间，需明确证据边界。同毫秒排序验证必须经真实导出→副本ID重建→raw稳定读取，不能只断言数组或ID字典序。

### 2026-09-06：压缩失败不一定是模型窗口不足

手动压缩曾只用模型窗口做最小值检查，却固定 2400 tokens/32 批，导致 200K/1M 配置也在模型调用前失败。整理预算必须来自所选模型配置，包含系统提示、上一摘要的 JSON 转义、响应/推理预留与估算余量；不能用固定小分块总数拒绝长历史。尽量整批整理，装不下才分批，任何拆分都必须覆盖所有来源文字并保护 Unicode 边界。供应商明确上下文超限才缩小重试，次数有界；摘要格式错误与普通网络/鉴权失败不能触发这种重试。输入预算的响应预留必须与真正发出的输出上限一致，不能只在本地减预算。

正例：`apps/aicove_flutter/lib/src/features/chat/data/background_topic_summary_adapter.dart`、`features/background_agent/background_agent_service.dart`；`test/features/chat/topic_compaction_test.dart` 覆盖 200K/1M 一次压缩、超过 32 批、转义摘要预算、完整尾部、取消及有界重试。确认前仍只生成草稿，不提交上下文或记忆。

### 2026-09-06：摘要请求HTTP成功不代表压缩成功

真实模型会在提示要求纯JSON时仍返回完整Markdown代码框，或输出正文引号未转义的JSON。不能只用HTTP 200/TURN_COMPLETED宣称压缩完成；还须检查输出归一化、所有批次完成、草稿与提交边界。归一化可去除整段外层代码框，但不能从混杂指令里捞JSON；仅语法错误且外形为JSON的摘要可增加一次有预算的格式修复请求，不重发历史、不增加工具权限、不把拒绝文字变成事实，继续执行原结构/长度校验和取消守卫。网关502是另一类失败，不应误称为上下文超长。正例：`BackgroundTopicSummaryAdapter._normalizeOrRepair` 与 `topic_compaction_test.dart` 四项真实结构回归；不把用户真实摘要写入项目文档或测试夹具。

同日真实保存发现，来源校验不能对含读取时重建字段的领域对象直接全量toJson散列。MessageBlock.fromJson未恢复块createdAt，基类每次赋DateTime.now；即使数据库没变，两次读取的摘要revision也不同。`topicSourceDigest`现只排除块的派生createdAt/updatedAt，仍绑定消息原始时间、块身份/顺序/状态/内容；真实块编辑仍拒绝过期提交。回归必须经过真实SQLite和正式raw loader，不能只在没有内容块的消息夹具上验证压缩事务。已失效旧摘要不批量回填校验值，避免把真正编辑过的内容冒充未变化。

### 2026-09-06：合并成功不代表顺序和可见性正确

1. SQLite同毫秒稳定顺序依赖插入次序：包中缺失前驱追加到已有后继之后会倒序。不能只断言数量，应检查相对次序；不改rowid/时间的导入器遇到可证明的矛盾应拒绝并引导新副本，而不是假称安全合并。合法追加、不同时间补历史和分页都要有正向控制。
2. 原生消息可能没有source_message_id，副本的来源ID仍能指向它；合并索引须同时认识当前ID和来源ID。仍保留本地同身份记录，不擅自将合并升级为编辑版本同步。
3. 回收站角色仍能被getById查到，写入成功后却不在联系人列表。合并/替换明确拒绝、允许新副本；不自动撤销用户软删除意图。
4. 勾选基本卡片必须实际应用包中明确字段；不能仅复制头像后丢弃映射。白名单局部更新，缺省字段保留，插件绑定/角色设置不借此覆盖，后续聊天失败也要回滚卡片。仅卡片导入不得重算本地聊天摘要。

### 2026-09-12：导航模糊不能在主体内提前淡出

- **2026-09-23 修订**：标题栏滚动边缘按用户要求改为渐进模糊（顶边全模糊、到悬浮组件中线清晰，ADR0039），本条“主体内保持完整”不再适用于标题栏；仍适用的是：不能用单层模糊加渐变蒙版把清晰底图混进来（会出现清晰与模糊叠影），渐进效果须靠多层递增模糊各自淡出实现。
- 原条款：顶部导航的高斯模糊在整个导航主体内保持完整，只在额外的 fadeExtent 内淡出；从顶部开始混合清晰底图会让主体残留清晰纹理，不能以条纹对比度逐步增大就判定材质正确。像素回归须断言主体底部仍无清晰条纹。正例：`apps/aicove_flutter/lib/src/ui/shared/widgets/moe_navigation_backdrop.dart`。

### 2026-09-12：液态不可用与用户关闭材质必须分开处理

- `isLiquidEnabled == false` 既可能表示液态能力不可用，也可能表示用户选择纯色或无障碍要求不透明。不能统一回退带模糊的半透明表面；先判断玻璃是否允许启用，再选择液态或毛玻璃。正例：`apps/aicove_flutter/lib/src/ui/shared/widgets/moe_liquid_glass.dart`；回归：`test/ui/shared/widgets/moe_liquid_glass_test.dart`、`moe_material_surfaces_test.dart`。

### 2026-09-12：同级替换必须同步真实路由栈

- 宽屏左侧打开二级页是同级替换，不能只隐藏返回图标，也不能因为存在 PopScope 保护而改成压栈；阻止离开时保留编辑并提示。右侧下级跳转仍保留父子返回，窄宽切换只改变返回入口展示。
- 混用 go_router 声明式聊天页与 Navigator 临时详情页时，替换需先正常退到占位根页，使 go_router 同步清除旧 match，再进入目标。直接 remove 页面会留下旧聊天配置；只 go 到新路径也可能保留根页上的临时详情。回归必须覆盖聊天→设置→聊天，以及设置→下级聊天→返回。
- 导航层级通知仅刷新需要它的标题栏，避免通过整个工作区的继承通知重建详情背景和业务页；退出背景仍保持到 TransitionRoute.completed。正例：`apps/aicove_flutter/lib/src/ui/shared/widgets/moe_adaptive_shell.dart`、`moe_app_bar.dart`；回归：`apps/aicove_flutter/test/ui/shared/widgets/moe_adaptive_shell_test.dart`。

### 2026-09-12：长流分段的解析成本与收尾副作用

- 操作其它页面时卡顿也可能来自主 isolate 的全文解析。引号保护/还原不能按每个引号反复扫描全文、或让每个分段遍历全部引号；用按匹配替换，定时揭示时复用原文未变的解析结果。缓存必须包含尾段是否封口的状态，并随流生命周期清理。正例：`apps/aicove_flutter/lib/src/core/utils/message_formatter.dart`、`apps/aicove_flutter/lib/src/features/chat/chat_actions_stream_placeholder.dart`。
- `canFinalizeWith` 等资格查询不得修改可见分段计数或触发定时器。收尾要把“输入已结束，尾段可以封口”与“全部气泡已显示”分开，否则会一次涌入剩余气泡，或在无标点尾段时永远排不完。回归须覆盖每次至多新增一段、无结束标点与排空期间中断；不能用允许收尾+N的断言锁住错误行为。正例回归：`apps/aicove_flutter/test/features/chat/stream_segment_backlog_test.dart`。


### 2026-09-12：可展开资料中的选择文本须隔离页面存储标识

- ExpansionTile、外层滚动区与其内的 SelectableText 使用各自带角色 ID 的 PageStorageKey。选择文本内部也有滚动位置；仅给展开项与外层滚动区不同 key 仍不够，内部文本可能把展开状态 bool 当成滚动偏移 double 读取。回归必须实际展开包含选择文本的资料区，不能只验证首帧。正例：`apps/aicove_flutter/lib/src/ui/features/character/pages/character_detail_page.dart`；回归：`test/ui/features/character/pages/character_showcase_test.dart`。

### 2026-09-12：渐隐蒙版须覆盖滤镜裁剪区的小数像素

- BackdropFilter内用dstIn混合渐隐蒙版时，用canvas.drawPaint覆盖整个裁剪区，不用逻辑bounds大小的drawRect；小数像素边缘会留下未被完整蒙版处理的模糊采样，出现细接缝。整数坐标测试不足以覆盖此问题。正例：`apps/aicove_flutter/lib/src/ui/shared/widgets/moe_navigation_backdrop.dart`；回归：`test/ui/shared/widgets/moe_navigation_backdrop_test.dart`的向上渐隐测试使用120.3逻辑位置，修前透明边缘白色通道216，修后>253。

## 2026-09-12：同步成功必须落到同一份协议与持久化事实

- 同步进度必须依据已提交变更序号，不能拿消息创建时间同时承担分页与删除/恢复传播；同毫秒分页和旧消息状态变化都要测。正例：`cloud_backend/sync_v3/service.py`、`tests/test_sync_v3.py`。
- 回执、版本和变更必须同事务提交；禁止逐操作捕获异常后把残留修改一起提交并返回成功。重试必须返回原回执，并按账号隔离操作编号。
- 冲突快照须保留双方附件引用。只保留待提交一方的附件时，原对象后续变化会让冲突的另一方附件漏出备份。已用复现失败测试后修复，见 `test_conflict_snapshot_retains_both_versions_attachments`。
- 认证测试必须经过真实密码校验与实际签发Token后访问业务接口；伪造可用Token会掩盖密码库兼容和JWT subject类型问题。本轮真实注册测试先失败后修复，见 `test_real_registration_login_token_can_access_sync`。
- 账号生命周期必须覆盖新版同步表；旧账号删除接口不能绕过归属保护，SQLite也需显式启用外键，避免删除后ID复用使新账号继承旧同步记录。


### 2026-09-12 · 毛玻璃底色与厚度联动

- 毛玻璃过厚先查底色来源和重复合成，不单独增大模糊：不能直接以页面背景（尤其深蓝灰色或自定义壁纸底色）作高不透明度染色。共用面板内的搜索框不得再次叠加 70% 页面底色。
- 材质厚度同时驱动模糊、底色与默认边缘装饰；0 时毛玻璃应显露原背景。配方与数值唯一入口见 `apps/aicove_flutter/docs/公共组件总览.md`「玻璃材质系统」，实现见 `MoeColors.glassTintForSigma`、`MoeFloatingSurface`，像素验收见 `moe_glass_thickness_test.dart`。

### 2026-09-12：玻璃菜单与淡入合成

- 液态玻璃菜单外不能包整层 `Opacity`／`FadeTransition`：Android 原生着色器在中间透明度下会采到临时合成缓冲，出现错位黑块；静止帧和 widget 测试无异常不足以验收。用同机有／无 Opacity、保留／取消缩放的对照区分根因，验收必须包含实际展开中间帧。
- 当前全部操作菜单走 `MoePopupMenu` 和 `MoeMenuTransition` 的锚点缩放展开，玻璃直接采样原页面；保留选择回调等待路由退出、勾选语义、系统返回和减少动画。正例：`apps/aicove_flutter/lib/src/ui/shared/animations/moe_menu_transition.dart`；回归：`test/ui/shared/widgets/moe_menu_transition_test.dart`。

### 2026-09-12：消息菜单关闭不能恢复输入框焦点

- Android 收起软键盘不一定清除 Flutter 输入焦点；消息菜单路由退出会恢复此前焦点，从而再次弹出键盘。文字与媒体菜单在打开前统一 `unfocus()`，清除旧焦点历史；不要在菜单退出后强制取消焦点，以免覆盖编辑等操作主动请求的焦点。正例：`apps/aicove_flutter/lib/src/features/chat/presentation/widgets/message_action_sheet.dart`。
- 回归须模拟“键盘隐藏但输入框仍聚焦”，覆盖点外部（包括输入区）、系统返回和 Escape；确认没有新的 `TextInput.show`、草稿保留且再次点击输入框可正常输入。菜单动作的断言须等待退出动画完成。回归：`apps/aicove_flutter/test/ui/features/chat/message_menu_focus_test.dart`。

### 2026-09-13 · 多选控件贴合气泡边界
- 选择按钮应在消息气泡的内容约束内布局，不包在整条消息行外侧；否则头像占位和右对齐留白会叠加为过大的按钮间距。按钮到气泡复用 `MessageBubble.avatarBubbleGap`，可选项与气泡渲染共用可见性判定，内部空块不生成选择按钮。正例：`apps/aicove_flutter/lib/src/features/chat/presentation/widgets/message_bubble.dart`、`apps/aicove_flutter/lib/src/ui/features/chat/widgets/chat_selection_region.dart`。

### 2026-09-13 · 无边框输入仍会继承主题填充
- `InputBorder.none` 只取消边框，不关闭 `InputDecorationTheme.filled`。行内输入和外层自绘表面的输入统一使用 `MoeInputDecoration`，显式禁用填充与各状态边框；独立表单保留自身填充设计，不全局关闭。
- 正例：`apps/aicove_flutter/lib/src/ui/shared/widgets/form/moe_input_decoration.dart`、`moe_text_field.dart`；回归：`test/ui/shared/widgets/moe_input_decoration_test.dart`。

### 2026-09-13 · Mac连续缩放不能延迟校正原生按钮

- AppKit在`setFrame`内会重排已移入自定义宿主的标准按钮；`didResize`延迟到下一轮主线程只能修正静止结果，拖动过程仍会显示系统坐标与自定义坐标交替。须在`super.setFrame`后同步恢复三个按钮及宿主位置。
- Flutter帧后对齐请求可能晚于下一次原生缩放；按当前原生内容宽度确定边距，不能信任旧帧传回的inset。全屏／恢复等延迟校正仍保留。
- 回归在让出run loop前测量三个按钮的位置，覆盖连续缩放及899／900／901；不能等异步校正完成才断言。正例：`apps/aicove_flutter/macos/Runner/MainFlutterWindow.swift`；原生离屏回归：`apps/aicove_flutter/tool/test_mac_window_chrome.py`。离屏几何通过不替代实际应用手动拖动／全屏验收。

### 2026-09-13 · 搜索提示与光标共用输入排版

- 可编辑搜索框的提示须由同一个InputDecoration绘制，不用透明原生hint加独立Text覆盖；覆盖文字与RenderEditable的内置排版偏移会让光标压进首字。居中展开时使用同一个动画值驱动图标位置和输入内边距，提示、光标及输入文字一起移动。正例：`apps/aicove_flutter/lib/src/ui/shared/widgets/moe_search_field.dart`；回归检查原生提示可见且与RenderEditable起点一致，覆盖宽度、主题和字号。


### 2026-09-13 · 菜单悬停规则与自动焦点

- `Button.styleFrom(foregroundColor: ...)` 会生成局部 overlay，覆盖全局禁止悬停反馈的主题；新增局部按钮样式必须使用 `withoutHoverFeedback`，纯文字浮层菜单显式使用透明 overlay，避免首项 autofocus 与鼠标悬停同时产生两块底色。保留方向键、Enter 与 Escape 操作。正例：`apps/aicove_flutter/lib/src/ui/shared/widgets/menus/moe_popup_menu.dart`、`apps/aicove_flutter/lib/src/ui/features/chat/pages/chat_page.dart`。


### 内容材质的可读性底线（2026-09-13）
- 弹层、搜索与列表的灰暗／白板割裂不能靠局部实心底色补救：公共内容材质须以主题surface统一色相，但必须按组件独立配置保底：文字面板默认10%模糊／10%底色，聊天悬浮组件0／0，不能把高遮盖全局套在所有浮层上；厚度在组件保底与原材质上限之间调节，纯色与无障碍分支保持实心。

### 弹窗标题居中与内容收缩（2026-09-13）
- 导航栏不能用不等宽的左右操作直接夹住标题；两侧保留相同宽度，长标题省略，关闭保持44触控区域。
- 短选择列表使用可收缩的滚动内容，不用Expanded强制撑满弹窗；底部确认交给公共footer。搜索与列表在极短可用高度下一起滚动，避免大字号与键盘组合造成固定搜索栏挤出内容。
- 正例：`apps/aicove_flutter/lib/src/ui/shared/widgets/sheets/moe_bottom_sheet.dart`、`apps/aicove_flutter/lib/src/ui/features/settings/widgets/model_picker_sheet.dart`；边界回归见 `moe_bottom_sheet_layout_test.dart` 与 `model_picker_material_test.dart`。


### 2026-09-13：同步媒体身份必须穿过真实模型上下文构建链

只在 HTTP 发出前增加原图解析器仍可能丢图：更早的历史消息构建器可能已把本地媒体 ID 当失败路径剔除。结构化图片 ID 必须在 `ChatRequestMessageBuilder` 与历史序列化阶段保留，最终按原始能力/插件规则解析原图；缩略图不可当模型原图，缺失原图明确失败。正例：`apps/aicove_flutter/lib/src/features/chat/services/chat_request_message_builder.dart`、`lib/src/core/media/media_resolver.dart`，回归包含真实构建器→原图解析。

### 2026-09-13：Mac 本地签名与账号安全存储

本地临时签名的 Mac 构建曾因 Data Protection 钥匙串签名授权不足报 `-34018`，当时改为系统登录钥匙串。该存储选择已被用户 2026-09-13 的明确要求取代，当前按 [ADR0032](决策记录/0032-Mac本地凭据与自动同步唤醒.md) 使用应用私有文件。服务器登录成功仍不等于本机持久化成功；必须验证写入及应用重启后的账号恢复，不能用 HTTP 200 替代。正例：`features/account/data/account_repository.dart` 与 `test/features/account/secure_account_storage_test.dart`。


### 2026-09-13：异步串行锁的清理回调不要返回正在清理的Future

`future.whenComplete(() => running.remove(owner))`可能返回包装后的同一个Future，使完成回调等待自己，表现为数据库/压缩测试超时。清理回调用无返回值语句块；空队列完成与下一作业可继续必须测试。正例：`apps/aicove_flutter/lib/src/features/memory/application/compaction_memory_service.dart`及`test/features/memory/compaction_memory_test.dart`。文件补写完成状态与对话摘要事务分开，避免文件故障卡住已保存的聊天。

### 2026-09-13：上传变慢不只取决于字节数

- 首次同步包含逐条整理消息、完整大图解码和逐文件往返；仅压缩网络数据不能消除本地处理瓶颈。先区分业务记录、附件个数与实际字节量，再分别测量。
- 图片/音频本身已压缩，采用有限 ZIP STORE 批量请求，JSON 使用 gzip；缩略图由引擎直接缩小解码。单张 2048×3072 样图本机实验 350 ms→33 ms 仅代表该实验，不能宣称整库提速十倍。
- 多端解码器可能产出不同缩略图。服务端合并保留既有缩略图摘要时，客户端必须同步换取对应文件，不能只改元数据；真实服务契约测试已先复现再修复。


### 2026-09-13：同步结构升级不能只改出站打包

- 聚合父消息之后，首次快照和后续增量必须有一致的旧子实体替代规则；客户端收到后丢弃旧行只能减少应用操作，不能减少网络请求。迁移验收同时统计服务端返回记录、实际字节和接收端可用时间，不用唯一媒体ID数量替代手机文件现场。证据入口：客户端文档《云同步开源数据结构调研》与 `tool/audit_cloud_sync_structure.py`。
- 接收端路径整理、内嵌媒体外置属于表现形式变化；只有已确认基线未变、没有用户编辑时，才能刷新比较摘要并清除自动产生的脏标记。先迁移旧JSON基线再捕获外部设置，保留真实编辑。正例：`features/sync/data/cloud_local_store.dart`，回归：`test/features/sync/cloud_local_storage_test.dart`。
- SQLite默认回滚日志下，长读事务也会令同步提交争锁。缩短读取事务，并在启动阶段启用WAL及有界等待；不以降低提交持久性掩盖锁问题。正例：`cloud_backend/database.py`、真实双连接复现 `test_sync_v3_process.py::test_read_snapshot_does_not_block_sync_commit`。

## 2026-09-13：近期可用与同步完成必须分别测量

- 不能把消息块、投影映射、媒体身份和物理文件统称附件；改为消息快照后，服务端也必须过滤被覆盖的旧子实体，客户端收到后再丢弃不节省传输。
- 文件下载、图片解码不能堵住消息/设置入库；附件身份、稳定目标路径与持久传输队列分开，下载失败保留队列。预留路径在文件到达前编辑也必须反查同一媒体 ID。
- 有版本确认不等于可以跳过中间所有序号；只有连续已确认前缀才能推进 cursor，其他设备夹在中间的变更必须拉取。
- 按近期窗口读取要按原始创建时间，不能按上传顺序；固定水位必须同时约束主文档和依赖，分页途中新增不改变首轮窗口。
- 压测使用相同数据、实际压缩传输字节、磁盘数据库及原文校验；首批数据就绪、全历史、文件就绪、UI 绘制和真实手机网络分别报告。查询中逐子项相关 EXISTS 可造成整页超线性开销，应检查执行计划与实际索引。
- 正例：`cloud_backend/sync_v3/reads.py`、`cloud_sync_engine.dart`、`cloud_sync_contract_test.dart`、`cloud_sync_benchmark_test.dart`（完整路径见 ADR0029）。


## 2026-09-13：已初始化设备也要验证同步协议升级路径

- 业务初始化标记不能代替新增协议阶段标记；旧接收端必须按独立、可恢复的 head/history 状态补跑近期读取，不能永久停留在旧 cursor 路径。正例：`features/sync/data/cloud_sync_engine.dart::_readInitialState`，回归 `an initialized legacy receiver enters the recent window and keeps edits`。

### 2026-09-13：旧缩略图路径不能当作角色编辑

### 假时钟测试里 await provider.future 会饿死全局串行写队列（2026-09-15，已根修）

- `testWidgets` 同一文件里第二个用例起，`await container.read(appSettingsProvider.future)` 永久挂起的真实原因不在页面也不在 pumpAndSettle：设置存储链（`ui_models_store_local_data_source._loadStore`）里的 `cloudLocalWrite` 是全局 `_cloudWriteTail` 串行链，其 `.then` 续体的完成依赖真实事件循环的微任务冲刷；假时钟区里的裸 await 冲不到这条链，provider 一直停在 AsyncLoading。

- 不要把写链执行挪到 `Zone.root`：那会让 `prefs.setString` 等操作逃出 fake zone，`pumpAndSettle` 冲刷不到，「点击→断言持久化」类断言会拿到旧值（实测 `getString` 返回 null）。
- 同类隐患仍在：`markdown_contact_memory_store._writes`（`Map<String, Future>` 静态链）同构未改，若其测试出现同样的跨用例卡死，按同一模式处理。

- 诊断套路：对疑似假时钟饿死的挂起，用 `tester.runAsync` + `Future.any([future, 5s真实延迟])` 竞速，并直接读 provider.state 区分「build 没跑完」还是「.future 没派发」。正例：`test/ui/features/settings/pages/frontend_ui_settings_audit_test.dart`。

### Xcode 27 构建 macOS 的两个坑（2026-09-18）

- **deployment target**：Xcode 27 支持下限 12.0，工程里 10.15 全报 `range of supported deployment target versions is 12.0 to 27.0.x`。已统一 `macos/Podfile`（platform + post_install 强制覆写各 pod target）与 `Runner.xcodeproj` 三处 `MACOSX_DEPLOYMENT_TARGET = 12.0`；pod 升级后再报同类错先查 Podfile.lock 是否重新生成。

### 2026-09-22 · 异步媒体回填必须保留当前投影的排序位置

### 2026-09-23 · 安卓返回键状态必须合并详情嵌套导航栈

现象是"二三级页面按返回直接回桌面"，看似宽屏改了层级，真实原因是 targetSdk 36 在 Android 16 默认启用预测性返回：系统只在 Flutter 声明"框架接管返回"时才把返回交给应用。详情页在 ShellRoute 嵌套导航器里，而 `showDialog`／菜单等默认进根导航器；它们关闭时根导航器单独上报 `canHandlePop: false`，覆盖掉详情栈的 true，下一次返回就被系统拿去退出应用。

上报给平台的值必须是 `notification.canHandlePop || router.canPop()`（go_router 的 canPop 会逐层检查 Shell 导航器）。正例：`apps/aicove_flutter/lib/src/ui/shared/widgets/moe_adaptive_shell.dart` 的 `moeNavigationNotification`，接入于 `app.dart` 的 `MaterialApp.router`；回归：`test/ui/shared/widgets/moe_adaptive_shell_back_test.dart`（需把生命周期置为 resumed 才会上报）。

### 2026-09-23 · 后台 Agent 的输出上限要给思考模型留余量

辅助回答"完全生成失败"，日志里请求却全是 200：真实原因是 deepseek-reasoner 先思考再回答，思考 1–3k token 就把 `maxOutputTokens: 512` 用光（finish_reason=length），正文为空，JSON 解析失败。给后台 Agent 定输出上限时按"思考＋正文"算，不按正文长度算；空正文要单独报错，别混成"格式不对"。正例：`apps/aicove_flutter/lib/src/features/smart_reply/infrastructure/smart_reply_adapter.dart`（4096）与 `domain/smart_reply.dart` 的 `parseSmartReplies`。

### 2026-09-23 · 公开安装包不能在本机仓库路径下构建

Release APK 的 `libapp.so` 会写入构建目录的绝对路径（如 `file:///home/<用户名>/…/dart_plugin_registrant.dart`），在本机仓库构建会把用户名带进公开包。上传 GitHub Release 的安装包必须在不含用户名的隔离脱敏工作树（如 `/private/tmp/aicove-release-*/publish`）里构建，上传前用 `unzip -p <apk> 'lib/*/libapp.so' | strings | grep /home/` 确认 0 命中。给自己手机装的包不受此限。


### 2026-09-28：预设兼容先确定运行架构

- 用户不需要前端，不代表可以删除脚本中的上下文处理。先划清 JS 语言运行时、酒馆宿主 API、浏览器 DOM 的边界，再决定可兼容范围。
- 不用逐预设文本降级或自制 JS 语法子集代替原始脚本语义。此前 ADR0041 对应实现已按用户要求撤回；新路线仍是研究方案，不能作为已实现能力宣传。

### 2026-09-28：工具清单 null 与空列表不能互换

聊天运行时中，`boundTools/availableTools == null` 允许从有效插件查找工具，空列表表示明确没有工具。接入额外 JS 工具时仅在确实需要合并时构造新列表，禁止用无条件空集合替换 null，否则原有生图等工具会变成 Tool not found。正例：`chat_send_api_runner.dart`；回归：原有 fast_async_image / non_vision / stable_vision_image 测试。

### 2026-09-29：正文传输解包后必须保留业务调用的结构

- 不能仅用 tool call ID 删除已消费的正文传输调用：Gemini 允许多个调用 ID 为空，应以请求内数组位置区分，避免误吞同轮业务工具。
- 解包后不回用旧 provider response，也不能只删 rawResponse 就继续工具循环；必须从解包正文和剩余业务调用重建后续 assistant 消息，保留 Gemini parts／业务签名，并在进入预设运行时前归一 model 角色。否则症状是下一轮 Invalid message from preset，真实原因是上轮工具结构已丢失。
- 正例：`quickjs_preset_runtime.dart`、`chat_send_api_runner.dart`、`chat_send_api_runner_tool_support.dart`；回归：`kemini_transport_pipeline_test.dart` 的两种供应商流式／非流式混合业务工具用例。

### 2026-09-29：语义标签扫描不能让“顺口提到的开标签”吞掉后文

- 症状是图片、语音整轮失效；真实原因是预设思维链里写了“这轮要用<tts>”这类未闭合的标签名，扫描器按“未闭合＝流式尚未写完”把其后全文当成一个元素，真正的 `<tts>…</tts>`、`<image>…</image>` 都被吞进去。
- 硬约束：到结尾仍未闭合的开标签，只有其后没有任何完整标签（或孤立闭标签）时才算流式尾巴；否则按普通文字处理并继续扫描。
- 正例：`content_tags/domain/content_tag_scanner.dart` 的未闭合回退；回归：`test/features/content_tags/first_party_tag_consumers_test.dart`。

### 2026-09-29：暗色纯色组件不能拿页面底色当填充

- 现象是暗色下大块组件变成纯黑色块，表面像“去掉液态玻璃”造成，真实原因是 `moePanelDark` 被设成与 `moeSurfaceDark` 同值（纯黑），而 `MoeFloatingSurface`／`MoeLiquidGlass` 在纯色模式和移动表面回退时填的是 `colors.surface`。玻璃／模糊材质靠半透明底色与模糊区分层级，纯色没有这层，容器就和页面融成一片。
- 硬约束：暗色容器色必须比页面底色浅；纯色填充默认取 `componentBackground`，只有整页承载面才显式用 `surface`。回归：`apps/aicove_flutter/test/ui/theme/dark_surface_layering_test.dart`。
- 窄屏全屏的页面外壳背后没有可模糊的内容，不能接浮层材质：模糊材质的固定底色 `0xCC2D2D2D` 会把整页刷成 #242424，反而比卡片更浅。正例：`main_page.dart` 窄屏 `blurEnabled: false`，只有宽屏悬浮卡保留材质。
- 模糊材质暗色底色（`MoeFrostedMaterial.surfaceTint`）按各档不透明度从容器色反推（`_darkContainerLevel`），叠纯黑正好等于 `moePanelDark`；改容器色时必须同步改该常量，回归见同一测试文件。


## 2026-10-01：整卡冲突可阻止单项壁纸同步

- 登录恢复、云端游标追平及壁纸原图存在不能证明目标角色已应用。先检查该角色的冲突版本；本次云端有壁纸、电脑候选为空，但还同时不同于置顶与音色设置，整卡冲突保护会阻止替换。不得自动处理账户全部冲突。
- 整卡更新时间不能代表壁纸修改时间；初始空值与主动清空必须通过修改记录或共同基线区分。更改自动合并契约前需明确字段及删除语义，不能用“非空优先”吞掉用户删除。正例入口：`cloud_backend/sync_v3/service.py` 的 `conflicts/resolve`，客户端 `lib/src/features/sync/data/cloud_sync_engine.dart` 的 `_applyInbox`。
- 用户选择目标版本后，验收媒体实际下载、哈希及目标页面显示；凭据落盘或账号 HTTP 200 不能替代。

### 2026-10-01：设置的值相同不代表修改时间相同

- 同值提交不应无故递增版本、让另一个设备产生冲突；但 A→B→A 的较新编辑时间必须保留并上传，不能被“内容未变”扫描/dirty 修订裁剪丢弃，否则旧离线 B 会覆盖用户最后选择的 A。时间比较与内容比较须共同参与设置变化判断。
- 合并上传回执的比较基线只记录服务器确认内容，不能记录叠加上传途中新编辑后的本机内容；否则接收端后续裁剪会把尚未上传的新编辑当作已同步。
- 恢复备份/显式冲突选择须作为当前的新设置编辑记时，不能沿用旧快照的旧时间；云端接收继承时间，不能反过来伪造本机编辑时间。
- 正例：`cloud_backend/sync_v3/setting_merge.py`、`apps/aicove_flutter/lib/src/features/sync/data/cloud_local_store.dart`、`cloud_sync_engine.dart`；回归：`cloud_backend/tests/test_sync_v3.py`、`apps/aicove_flutter/test/features/sync/cloud_sync_contract_test.dart`。

## 2026-10-01：聊天列表不要为读一个会话字段去监听整个会话列表

- 聊天消息列表等高频组件需要会话上的某个字段（如聊天样式覆盖）时，由聊天页把字段作为参数传入，不在列表里 `watch(conversationsProvider…)`。表面症状是与之无关的语音气泡、重新生成测试卡死十分钟；真实原因是列表一监听会话列表就触发真实的会话加载，在测试的模拟时钟下永远完成不了，页面无法稳定。
- 正例：`chat_page.dart` 传 `chatDisplayStyle: conv.chatDisplayStyle`，`chat_message_list.dart` 取 `chatDisplayPolicyProvider(widget.chatDisplayStyle)`（只监听全局设置）。回归：`test/ui/features/chat/chat_audio_regeneration_gesture_test.dart`、`test/ui/features/chat/pages/chat_page_regenerate_test.dart`。

## 2026-10-01：设备直连的删除和附件必须按接收端约束处理

- 服务器顺序不能代替离线设备的因果关系。角色删除必须等待消息墓碑；离线端仍有保留的聊天时保留角色与删除请求，显式恢复必须继承删除请求的版本，不能靠较晚到达把历史清掉。
- 附件传输只接受媒体身份，拒绝远端传入本机绝对附件路径或 file URI；否则后续正常本机编辑可能把该路径注册成附件。检查 JSON 字段时不能把路径校验异常当作 JSON 解码失败吞掉；普通文本中的路径保持原样。
- LAN 与云端共享同一个 MediaStore 及到达通知，不能各建索引实例让实际到达的附件缺少界面刷新。

### 2026-10-02：批量采集与显示回退不能绕过数据保护

- LAN 接收远端修订前，必须优先采集该实体本机状态，不能假设前 500 条覆盖了它。应用事务仍须拒绝未知但已存在、或扫描后发生的新修改。正例：`LanRepository.receive` 与 `public_release_lan_http_repro_test.dart`（1600 条历史、真实配对加密 HTTP）。
- `deleted_at` 软删除也是删除。并发删除与编辑不得按设置字段时间静默合并，必须保留冲突。附件重试批次须轮转，前八个不可用对象不能永久堵住后面的可用对象。
- 非空显式话题边界找不到原文时阻止发送；边界在最后一条时窗口为空。主聊天、历史读取、增强回复和后台主动回复统一使用 `sliceConversationContext`。

### 2026-10-02：迟到的界面回调必须校验归属与草稿版本

- 发送检查结束后仍须确认页面挂载、页面会话 ID 与当前发送目标一致；最终派发前再核对一次，不能把检查开始时角色 A 的内容发给后来打开的 B。文字和图片共用归属保护。正例：`ChatPage._isCurrentSendOwner`、`_submitPlainTextSend`、`_submitImageSend`。

### 2026-10-02：公开提交必须检查 Git 身份元数据

- 工作区文件脱敏与提交身份脱敏是两个独立检查。新克隆未配置身份时 Git 会从本机用户名、主机名生成作者邮箱；源码扫描零命中不能证明提交对象没有隐私。

- 若漏检后已公开，不用新增提交宣称已清除旧身份；先准备代码树完全相同的脱敏提交并核验 tree diff，明确缓存与旧克隆仍可能保留对象。重写已公开历史按授权边界确认，仅使用绑定已知远端 SHA 的精确 lease，远端变化则停止。
