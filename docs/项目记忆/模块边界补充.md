# 模块边界补充（按需读取）

> 各功能批次交付后沉淀的"当前有效边界"。入口页 `README.md` 只保留一行速查；改动对应模块前再读这里的对应小节。新增边界时在这里加小节，并在 `README.md`「模块边界速查」补一行。

## 联系人记忆补充边界（2026-09-05）

新 MD 模式以稳定联系人 ID 隔离，每个角色独立 `MEMORY.md`；常驻笔记直接注入，往事通过绑定该请求 owner 的工具读取。不得用当前活动页面替代请求 owner；`ApiConfig.boundTools` 与 schema 同时保存。旧向量库保留回滚，第一批仅手动维护，自动整理/备份同步未接入。参见 `决策记录/0004-联系人独立Markdown记忆.md` 与客户端 `docs/04_功能模块规范/记忆系统/联系人Markdown记忆.md`。

### 手动压缩补充（2026-09-05）

上述手工 MD 之后已接通“压缩并开启新话题”：纯内容摘要立即注入新话题，最新角色卡决定表达，旧原文不带入；确认后可归档本角色 MD 往事。SQLite v16 的 topic_handoffs 保存派生摘要/来源/边界/待写状态，与 raw 消息真相源分开。支持撤销与补写，生成锁固定目标 owner。2026-09-13 已接入发送前自动压缩：默认 272k 窗口、80% 触发线与 16% 近期原文预算，不移动新话题边界、不产生 UI 话题分隔；压缩同时返回有来源的记忆增量，经校验写该角色 MEMORY.md，文件失败留队列补写。现行决策为 [ADR0027](决策记录/0027-压缩与持久记忆联动.md)（触发、保留与记忆联动），[ADR0007](决策记录/0007-手动压缩继承内容重置格式.md) 仍约束手动新话题，ADR0024 仅保留移除条数限制的首批记录。参见客户端《上下文压缩与记忆联动方案.md》。

## 插件预设补充边界（2026-09-06）

插件配置统一预设化，角色卡按插件绑定预设；复杂的多渠道、多供应商配置由预设集中管理，“默认设置”改为“默认预设”。音色预设包含渠道、模型、TTS 基本参数、音色 ID／文件等完整配置。未绑定时使用对应插件默认预设，明确绑定不随默认选择改变。绘图和音色正在改造，其他插件逐步接入；这是已确认目标，不是全量实现声明。

正式架构权威文档：[插件预设与角色卡绑定规范](../../apps/aicove_flutter/docs/02_前后端分离与架构规范/插件预设与角色卡绑定规范.md)；决策：[ADR 0008](决策记录/0008-插件配置统一预设化与角色绑定.md)。后续改插件、角色绑定与预设导入导出时必读，不继续以旧模块的全局散项配置为目标。

### 绘图配置包实施（2026-09-06）

绘图已接入独立版本目录、角色稳定 ID 单绑定、旧配置保留与渐进转换；请求工具闭包和快速生图事件固定本轮配置，参数可合理覆盖而不回写。辅助提示词高级折叠；跨设备预设定义/渠道映射尚未接入，不宣称分享一个 ID 即可恢复。详见 `决策记录/0009-绘图预设存储与请求快照.md` 与客户端《绘图预设实现与迁移》。

## 酒馆兼容补充边界（2026-09-06）

组合预设沿用recipeId及本地预设信封，在compatibilityData保存附加资源和条目开关，不迁移聊天数据库。`TavernCompatibilityPort.resolvePreset`按请求owner一次性读取总开关、显式绑定／默认预设；明确绑定缺失不静默回退。世界书只扫描有效近期raw派生请求副本，经WORLD_INFO正则后由现有装配器注入，不能改raw或喂UI气泡。此批不扩大后台专业Agent权限，云同步/备份携带组合资源另批处理。参见 [ADR 0010](决策记录/0010-酒馆兼容组合预设与上下文接入.md)。

## 编辑提交保护（2026-09-06）

编辑入口只创建按owner隔离的草稿，不再立即软删历史；确认发送时通过 ChatEditPort 校验raw版本，将旧后缀失效和新消息/blocks落库放进同一事务。输入框等本地受理后清草稿，AI随后失败保留新分支重试。旧话题编辑暂拒绝；重生成语义不变，未升级schema。详见 `决策记录/0012-编辑草稿与分支提交分离.md` 和聊天上下文规范第13节；真机验收状态见需求日志，不将代码完成等同发布完成。

## 音色预设实施补充（2026-09-06）

语音插件已改为完整预设库，角色voiceFile引用预设；请求准备时固定owner与供应商快照，生产播放器不回退全局服务。旧JSON先原样备份，再转换可确认绑定，剩余显示待完善。已完成分组搜索/编辑/试听/角色绑定与范围验证，实际付费合成未调用。最新实现及回滚见[音色预设实现与迁移](../../apps/aicove_flutter/docs/04_功能模块规范/语音插件系统/音色预设实现与迁移.md)；由于有并行工作树变更，最终手机安装的是验证过的固定快照buildId `896a5cb4…`，不是任意后续工作树的运行证明。

## 插件上下文边界补充（2026-09-11）

标签说明由各有效插件提供，主聊天不注入统一标签前导；绘图/语音关闭后，请求副本屏蔽对应Image/TTS标签正文、生成上下文及工具调用对，原始历史保留，用户上传附件保留。酒馆组装后也需过滤，纯标签最新输入过滤为空时拒绝误发旧问题。参见[ADR0017](决策记录/0017-插件拥有标签说明与请求上下文过滤.md)。

## 全端共用界面架构（2026-09-11，当前规范）

用户明确制定新架构并授权清理冲突规则：以 Mac 为设计、开发与首轮验收基准。窄屏即手机模式；宽屏左侧悬浮完整手机一级界面（含标题、内容与底栏），右侧展开同一份二级及更深页面。宽屏包含全部窄屏页面与入口，不复制手机／桌面整页、导航或业务链路。

统一壳集中管理900逻辑像素断点、面板局部约束、页面身份及详情栈；跨断点保留搜索、滚动、草稿和任务归属。Mac大窗口左侧360宽面板仍按手机宽度排版；平台差异集中在窗口、系统安全区及输入适配。联系人保持单列，无全部／未读。

规范全文：[全端共用界面架构与布局规范](../../apps/aicove_flutter/docs/界面布局说明.md)；决定：[ADR0019](决策记录/0019-Mac基准与全端共用界面架构.md)。ADR0018改为历史实现记录；现有MainPage、MoeAdaptiveShell与MoeWorkspace可复用，桌面样式分支及全端覆盖仍待收口验收。本次仅修改规范，不把既有安装与测试视为全端重写已完成。
