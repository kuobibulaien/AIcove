# ADR0050：设置修改时间与通用本地化

- 状态：accepted；本地实现与隔离验证，云端尚未部署。
- 日期：2026-10-01
- 授权：用户要求“记录一下修改设置的时间，优先按时间线靠后的那个来。同时在同步的过程中，‘通用’设置不用同步。”

## 背景与决定

整张角色卡的版本冲突会阻止壁纸等单项设置合流。整卡更新时间、导入时间和上传先后不能代表各设置的实际修改时间；空的初始值也不能等同于用户主动清空。

对会话/角色、渠道行与 preference 设置记录字段修改时间，按实际编辑的毫秒时间优先；同一毫秒以持久设备编号确定顺序。SQLite 行修改与时间记录同事务，preference 写入在本地写锁内保存带值摘要的时间日志；接收云端数据继承时间，不伪造本机新编辑。初始/历史无时间字段以未知基线处理，两个未知但不同的值保留冲突。消息、预设文件、实体删除继续受文档版本保护。

设置对象按顶层字段合并，嵌套对象/列表作为单项整体；较新的清空同样优先。上传返回合并后的文档，客户端继承其时钟并保留上传过程中产生的更晚编辑；比较基线必须是服务器确认的内容。恢复快照和手动选择冲突版本算新的显式设置修改。相同值的较新修改时间仍须发布，避免 A→B→A 被旧的离线 B 覆盖。

“通用”页面及其个人资料入口的设置仅保存在当前设备，客户端上传和应用时、服务器新写入和历史读取时均过滤。模型、渠道、插件配置仍同步。具体字段集合与协议唯一说明见 [云同步协议](../../../cloud_backend/sync_v3/README.md)，不复制到本 ADR。

## 代价、验证与回滚

设备时钟相差过大仍会影响跨设备编辑顺序；单设备时间倒退采用该字段上一时间加一。历史修改时间无法补造，已有生产冲突不自动清空。服务器通过 `setting_times_version=1` 声明能力，新客户端遇旧服务器保持原文档版本协议。上线需同步部署后端与客户端并另做真实双端验收；隔离测试不能代称运行中的设备已生效。

验证覆盖离线不同字段合并、晚上传的旧编辑、主动清空、同毫秒顺序、未知时间冲突、同值时间更新、上传途中编辑/删除、回执丢失重试、备份恢复、General 双向过滤及消息/附件现有契约；后台75项、客户端52项相关测试通过，改动范围 Dart 静态检查无问题。回滚切回原代码，保留附加时间表、日志和不可变云端历史，禁止清空 outbox 或业务数据。
