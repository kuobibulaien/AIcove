# 联系人独立 Markdown 记忆

> **已被取代（2026-09-23）**：由 [ADR0038](0038-记忆与上下文重构为短期长期两层.md) 取代，以下仅保留原始记录。

## 背景

用户要求重做联系人记忆，暂不依赖向量；保留常驻知识及可翻阅往事，并明确每个角色的记忆分离、各有 MD 文档。用户已同意按此方向开始实现。

原提案的 SQLite 文本记忆被这次用户要求具体化为独立 Markdown 文档；不是删除已有聊天数据库，也不是把 raw messages 搬入文件。

## 备选

- SQLite 文本 + MD 导出：沿用现有存储便利，但 MD 不是真正独立的记忆文档。
- 角色独立 MD + 全文/目录工具：可检查、无需向量，适合本期；较大文档需要后续优化本地索引。
- 继续四层向量记忆：现有能力保留回滚，不作为新模式依赖。

## 决定

1. 新模式用 `ApplicationSupport/contact_memories/<SHA256(ownerId)>/MEMORY.md` 为唯一记忆真相源，按稳定联系人 ID 隔离。当前 owner 映射 Conversation.id，不使用昵称、模板 ID 或当前活动页面。
2. 首批一份文档容纳常驻笔记与事件记录；目录从正文元数据派生，向模型按预算提供，不全量注入往事。聊天 raw message 真相源仍在数据库。
3. 通过 `ContactMemoryPort` 分隔 UI/运行时与文件实现。`memory_search` / `memory_read` 闭包在请求装配时绑定 owner，与 schema 一起保存在 `ApiConfig.boundTools`，工具参数不能指定其他 owner/path。
4. 新旧模式由每个角色文档开关选择，默认保留旧模式。新模式跳过旧召回和写入，旧数据库不删除、不迁移，切回旧模式可回滚；文档损坏必须失败关闭，不隐式回退旧记忆。
5. 分批交付。首批手动编辑和真实工具读取；自动整理、原始来源、锁定/敏感候选、备份同步、自动遗忘均不冒充已完成。

## 代价

- 增加文件格式、原子写、并发版本及角色生命周期边界管理。
- 当前关键词搜索不是语义检索，无法保证隐晦线索都能命中。先用实际样本验证，再决定是否需要向量。
- 当前读取单文档，没有另建索引；大库性能未测。设置了大小保护，不自动裁掉旧事。
- 新 MD 未接旧备份/同步与物理删除清理；仅本地保存有丢失风险，需明确告知。
- 开关切换不强制取消已在执行的旧后台请求，但旧请求无权写新 MD。

## 验收门

- 角色 A/B 同名和同事件 id 不串库；缺 owner、越权参数、切角色后的旧闭包均安全。
- 无 Embedding/总结配置时，手写记忆仍可持久化和进入模型上下文。
- 真实工具执行循环把本角色事件返回模型；不只展示工具描述。
- 并发/外部编辑冲突不覆盖；损坏文件不变空库；页面复用和迟到结果不污染其他角色。
- 原始聊天与旧记忆未迁移；窄/宽屏操作、相关测试、静态检查和 Android 编译运行通过。
