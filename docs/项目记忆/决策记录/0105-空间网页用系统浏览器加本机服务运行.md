# 0105 空间网页用系统浏览器加本机服务运行

- 状态：accepted（2026-10-22 用户确认：重点适配安卓和 Windows；不自写 WebView、不依赖 `flutter_inappwebview`；用默认浏览器打开、AIcove 起本机端口；端口固定；手机上用系统小窗和 AIcove酱 边玩边聊，不另写悬浮窗；IndexedDB 存档由 AIcove酱 提醒用户；实施前须经 Codex 审查；Codex 两轮审查的必须修已并入）
- 日期：2026-10-22
- 关联：ADR0089（本文取代其第 1、2、3、5 条；第 4 条存档格式与第 6 条导入保留）、ADR0087（空间存储、条件提交、撤销）、ADR0098（工作区工具）、ADR0086（应用数据目录）
- 实施方案：[空间网页运行实施方案](../../../apps/aicove_flutter/docs/02_前后端分离与架构规范/空间网页运行实施方案.md)

## 背景

ADR0089 定的是 App 内嵌 WebView。2026-10-22 复查选型：

- `flutter_inappwebview` 主仓库最后提交在 2026-02-10，223 个未关闭 issue，基本一人维护；稳定版 6.1.5 是 2024 年的，项目要求 Flutter ≥3.44.6 只能用 6.2 beta。
- 官方 `webview_flutter` 不支持 Windows；`webview_windows` 2024-02 后停更；`webview_flutter_windows`、`webview_win_floating` 没有请求拦截。
- 自写薄插件（安卓 Activity＋Windows WebView2 窗口）可行，但要长期维护 Kotlin 与 C++。

下载量最多的是安卓和 Windows。两端都有完整的系统浏览器，Dart 自带 HTTP 服务器，项目已有 `url_launcher`。插件只是胶水，网页引擎本来就是系统的；直接用浏览器，兼容性最好、原生代码为零。

用户的目标是「借 AIcove酱 的能力保持游玩体验」：AIcove酱 能读改存档，玩到一半能叫她改。不需要读浏览器自己的数据（安卓读不到，Windows 读浏览器目录会被当成盗号行为），让页面把存档交回 AIcove 即可。

## 决定

### 1. 用默认浏览器打开，AIcove 起本机服务

- 空间里的 `.html`／`.htm` 文件多一个「运行」入口：AIcove 启动本机服务，用系统默认浏览器打开对应地址。聊天里仍不渲染 HTML（ADR0046／0071 不变）。
- 服务在第一次运行时启动，App 进程存活期间一直开着。
- 只监听回环地址：同一端口同时绑 `127.0.0.1` 和 `::1`。`::1` 因「端口被占」失败时整个端口作废、换下一个（否则浏览器会连到别人的服务）；因系统不支持 IPv6 失败时只用 IPv4。
- **端口固定**：候选 47823 起共 20 个，优先用上次成功的那个（记在应用数据目录），不行再按顺序试。换了端口时浏览器视为另一个网站，IndexedDB 进度不会跟过去，启动时提示一次。

### 2. 每个空间一个子域名

- 地址形如 `http://<空间 ID>.localhost:<端口>/<路径>`。Chrome（含安卓）、Edge、Firefox 都把 `*.localhost` 指回本机，并视为独立的安全来源：不同空间的 IndexedDB、Cookie 互不干扰。
- 只供「本次 App 运行期间用户点过运行」的空间；其他一律 404。
- 资源从该空间读出，路径过 ADR0087 的规则：不能越出空间、不能读 `.aicove/`（按不区分大小写判断）。
- 第一版不做 `127.0.0.1` 退路地址。H0 若发现主流国产浏览器不认 `*.localhost`，再另行决定。

### 3. 只做必要的安全检查

用户对自己的设备负责，不做随机口令、随机端口这类打扰性的防护。只防用户在浏览器里打开的**其他网站**借这个端口读文件或改存档，全部是响应头和请求头检查，对用户无感：

- `Host` 必须是本服务的地址（防 DNS 重绑定）；
- 有副作用的接口只走 POST，要求 `Origin` 与本空间地址一致、`Sec-Fetch-Site: same-origin`；GET 接口一律没有副作用；
- 所有响应带 `Cross-Origin-Resource-Policy: same-origin`，不返回任何 CORS 放行头（防其他网站用 `<script>`／`<img>` 跨站引用）；
- 只供已运行过的空间。

所有响应都带同一条 CSP（Worker、SVG 等独立执行环境不继承页面的 CSP，所以不只加在 HTML 上）：只允许本空间地址、`data:`、`blob:`，允许内联脚本和 `eval`，禁止页面资源和接口访问外网，`frame-ancestors 'self'` 防止被别的网站套进 iframe。第一版拒绝 Service Worker 脚本。这限制的是页面加载资源和发请求，**不是完整的断网沙盒**：用户点链接跳到外网、浏览器本身联网都不受限。依赖 CDN 的网页要先由 Agent 把依赖下载到空间里。

### 4. 存档：localStorage 替身＋双向同步

- 存档在 HTML 同目录的 `<文件名>.save.json`，格式 `aicove.webapp.save.v1`，规则沿用 ADR0089 第 4 条：值满足 `JSON.stringify(JSON.parse(v)) === v` 且是对象或数组时展开，其余原样字符串。**编解码只在浏览器里用 JavaScript 做**，服务端只校验 `format` 字段、原样落盘，不用 Dart 重新序列化（Dart 与 JS 对数字、键顺序的处理不同，会改坏存档）。
- **容量**：每条 `JSON.stringify(键)` 加 `JSON.stringify(值)` 的 UTF-8 字节数之和不超过 5 MiB，超出时 `setItem` 抛 `QuotaExceededError`、数据不变。这比浏览器（500 万个 UTF-16 字符）略严，中文多的存档能存的字数少一些。存档文件按两格缩进写出；超过 16 MiB 时改为紧凑格式。服务端请求上限 16 MiB，与之对齐，所以客户端接受的数据服务端一定收得下。
- 服务返回 HTML 时，在文档最前面（开头的注释和 `<!doctype>` 之后）插入一个同步加载的替身脚本，先于页面任何脚本执行，替换 `window.localStorage`，游戏代码不用改。替换失败或被页面自带 CSP 拦住时，页面上明确提示「本次进度不会保存到 AIcove」。只支持 UTF-8 等 ASCII 兼容编码，UTF-16 的页面在点「运行」时就拒绝并说明。
- **写盘**：停止改动约 2 秒后写一次，持续改动时最长 10 秒也写一次；页面隐藏时立即写。待写的快照按页面分别存一份在浏览器原生 localStorage 里，服务端确认后删除（原生存储不可用时页面提示「关闭后未保存的进度无法找回」）；下次打开时发现未提交的快照，基准没变就补写，基准变了就按冲突处理。所以「关闭时保存」是尽力而为，没送达的进度在下次打开时补上。
- 经 ADR0087 的条件提交，带 revision。一段连续游玩的写入归同一个 run，可在「修改记录」整次撤销；页面发现存档被外部改过（AIcove酱 修改、撤销、同步入站）之后继续写，就另开一个 run。撤销时服务先暂停该空间的网页写入、等在途写入结束再撤销，撤销完再放开。撤销遵循 ADR0087 的保护规则：中途被别处改过的部分不会被撤掉。
- **AIcove酱 改存档后页面自动重载**：替身每 2 秒检查一次存档 revision。替身有明确的状态（正常、写入中、冲突、存档损坏），写入中不做判断；发现被别处改过时：
  - 本页没有未写盘的改动 → 重新载入页面，游戏读到新存档；
  - 本页有未写盘的改动 → 页面里弹出两个选项：「放弃本页进度，载入新存档」或「保留本页进度并覆盖」（覆盖前的版本在修改记录里能撤回）。
- 存档文件格式有误（比如被手改坏了）时，替身停止写盘并在页面上提示，文件修好后自动恢复。
- 只接管 localStorage。用 IndexedDB 的游戏进度留在浏览器里，AIcove酱 看不到。RPG Maker MV 的存档是压缩过的字符串，能同步但要先解码才能改。`workspace_open` 的说明里写明这两点。

### 5. 手机与电脑上的使用方式

- 安卓：浏览器全屏玩，或用系统小窗把 AIcove 放在旁边边玩边聊。不申请悬浮窗权限、不另写悬浮窗。
- **安卓保活**：浏览器全屏时 AIcove 在后台，新版安卓几秒内就会冻结后台进程，存档就送不回来，AIcove酱 看到的是旧存档。所以点「运行」时（AIcove 还在前台）就让现有前台服务进入「网页运行中」状态，通知显示「网页游戏运行中」；连续 2 分钟没有页面请求才退出。这个状态与「正在回复」分开计数，没有 30 分钟超时，不持有唤醒锁。需要改少量 Kotlin。
- Windows：浏览器窗口与 AIcove 窗口并排，不需要保活。
- 横屏、全屏由浏览器和用户决定，ADR0089 的 `aicove-orientation` 不再需要。
- AIcove 界面需要在系统小窗（高约 400dp）下检查输入框与键盘，另行处理。
- ADR0089 第 6 条的导入（单文件、多文件、ZIP）不在本期，另行交付。

## 代价

- 体验取决于用户的默认浏览器：地址栏、横屏、全屏都不由我们控制；不认 `*.localhost` 的浏览器第一版打不开。
- 本机任何程序都能连这个端口。上述检查挡住了网页，挡不住本机恶意程序；按用户意见接受。
- 安卓玩游戏期间常驻一条「网页游戏运行中」通知。
- 「关闭时保存」是尽力而为：浏览器被直接杀掉时，最后几秒的进度要等下次打开同一页面才补写。
- 「放弃本页进度」一旦选了就找不回。
- 只接管 localStorage，IndexedDB 存档 AIcove酱 看不到；容量口径比浏览器略严。
- iOS 不能在后台维持服务，本方案不覆盖 iOS。

## 验收门

1. **H0**：Mac 与安卓上，默认浏览器打开 `http://<id>.localhost:<端口>/game.html`，带相对路径的 CSS／JS／图片能加载，替身先于游戏脚本生效；记录安卓 Chrome 与一款国产浏览器是否认 `*.localhost`。
2. **边界**：`../`、`%2e%2e`、`.aicove/`（含大小写变体）、未运行过的空间、错误的 `Host`、跨站 `Origin` 的写入全部被拒；跨站网页用 `<script>` 引用 `shim.js`、用 `fetch` 读文件都拿不到内容；页面和 Worker 里 `fetch('https://…')` 都被 CSP 拦下；Service Worker 注册失败。
3. **存档往返**：字符串、数字字符串、`{"n":1.0}`、`{"2":2,"1":1}`、`{"n":9007199254740993}`、JSON 对象和数组、带空格的 JSON 文本、中文、空字符串，经「浏览器 → 存档文件 → 浏览器」后逐字节一致；AIcove酱 手写的数字、布尔能读成字符串；超过容量抛 `QuotaExceededError`；`localStorage.foo = 'x'`、`localStorage['foo']`、`key()`、`length`、`clear()`、`Object.keys` 行为与浏览器一致。
4. **写盘**：停止改动后写一次；持续改动 10 秒内必写；页面隐藏时写；浏览器在写出前被杀，下次打开补写；一段游玩一个 run，无外部修改时撤销回到打开前。
5. **AIcove酱 改存档**：游戏开着时用 `workspace_edit` 改存档，几秒内页面自动重载并读到新值；有未写盘改动时弹出两个选项，选「覆盖」后旧版本能在修改记录里撤回；自己的写入不会被误判为外部修改；把存档改坏后页面提示且不覆盖，修好后恢复。
6. **安卓**：浏览器全屏玩 40 分钟（超过原 30 分钟超时），中途切回 AIcove 让 AIcove酱 读存档，读到的是最新进度；小窗模式同样可用；停止游玩 2 分钟后通知消失。
7. **Windows**：默认浏览器（Edge）打开同一游戏并完成第 3～5 条（在用户的 Windows 电脑上验）。
