# 0063 插件请求前提醒钩子

- 状态：accepted（代码未实施）
- 日期：2026-10-07
- 关联：ADR0017（插件上下文过滤）、ADR0054（插件标签说明全局一份）、ADR0060（统一装配）、ADR0064（微内核钩子体系：本钩子迁入其“请求前”钩子）；参考 Pi `context` 事件

## 背景

插件接口 `features/plugins/domain/plugin.dart` 已有三个被发送链路统一调用、实际生效的钩子：`getSystemPrompt`（贡献提示词）、`getTools`（贡献工具）、`processResponse`（回复后处理）。

另有通用钩子 `LLMHook`（`features/plugins/domain/handlers/llm_hook.dart`，类型 beforeRequest／afterResponse）与触发器 `LLMHookManager`（`features/ai_tools/llm_hook_manager.dart`）：没有插件实现 `getHooks()`，全项目也没有调用 `triggerBeforeRequest`／`triggerAfterResponse`。afterResponse 的用途已被 `processResponse` 覆盖。

缺少“每次请求前向上下文加入内容”的口子，于是两处插件逻辑写死在 `features/chat/services/chat_send_backend_service.dart`：

- 时间感知：按 `plugin is TimeAwarenessPlugin` 找到插件，生成当前时间／距上次发言的提醒；
- 画图：`imagePlugin.buildImageFailureReminderContent(history)` 在上次画图失败时提醒模型。

二者合并为系统提醒，无绑定预设时插在最后一条用户消息之前（`insertReminderBeforeLastUser`），有绑定预设时走预设路径放置。发送核心因此需要认识具体插件类型，新增同类插件必须修改核心。

## 备选

1. 维持写死。
2. 删除全部未用钩子，插件视为内部模块。缺的口子已有两个真实使用者，删掉后问题仍在。
3. 补一个真实的请求前钩子，迁移两处写死逻辑，删除多余的 afterResponse。

## 决定

采用 3。

- **新增请求前提醒钩子**：插件在每次请求前按只读输入（本轮时间、历史原文、插件配置）返回零或多条提醒内容；权力仅为“贡献提醒文字”，不能直接改写消息列表、系统提示词或工具。
- **放置由核心决定**：核心收集各插件提醒，按固定顺序合并，沿用现有放置规则（无预设插在最后一条用户消息之前；有预设走预设路径），保持请求开头稳定、不破坏前缀缓存（第 2 课约定：会变的内容放后面）。
- **迁移**：时间感知提醒、画图失败提醒改由各自插件经此钩子提供；发送核心删除对 `TimeAwarenessPlugin` 的类型判断与对画图失败提醒的直接调用。`buildOutputTagReminder` 中按画图／语音启用状态拼出的标签提醒，可在同一批迁移或保留在核心，实施时评估。
- **清理**：删除无人使用的 afterResponse 类型及其触发方法；`LLMHook`／`LLMHookManager` 若改造承载新钩子则保留并更名对齐，否则删除。不保留没有使用者的通用钩子。
- **出错策略**：提醒类插件出错时只记录并跳过该插件提醒，本轮请求照常发送（装饰性插件放行，见第 5 课）。
- 统一装配（ADR0060）落地后，此钩子归入装配流水线的一个固定步骤。

## 验收项

1. 迁移前后，同样输入下的请求副本逐字一致（时间固定的单元测试，覆盖有／无绑定预设两条路径）。
2. 发送核心代码不再出现具体插件类型判断（`TimeAwarenessPlugin`、画图失败提醒的直接调用）。
3. 新增一个测试用假插件，只在插件侧实现钩子即可让提醒出现在请求中，无需修改核心。
4. 某插件钩子抛错时，其余提醒与请求不受影响，有测试。
5. afterResponse 相关死代码已删除，静态分析通过。

## 代价

- 改动触及聊天发送主链路，需完整回归时间感知、画图失败提醒与预设路径。
- 多个插件提醒的合并顺序成为新约定，后续插件需遵守。
- 回滚：还原发送服务与插件相关文件，不涉及数据。
