# 0061 旧工具结果按时间清理（参考 Anthropic context editing）

- 状态：accepted（代码未实施）
- 日期：2026-10-07
- 关联：修订 ADR0038 “先截短超长工具结果”一步；参考 Anthropic `clear_tool_uses_20250919`（https://platform.claude.com/docs/en/build-with-claude/context-editing）

## 背景

工具结果在一次 run 成功结束后，随助手消息以 `ToolBlock.result` 原文落库（`chat_send_service.dart` 构造 ToolBlock）；循环进行中只在内存追加，run 失败或中断时本轮工具结果不落库（见 ADR0064 第一批说明）。裁剪只作用于请求副本，这一点保持。现行裁剪 `RuntimeContextService.pruneToolResults`（`features/context/application/runtime_context_service.dart`）在用量达到 80% 触发线后，把**所有**超过 8192 字符的工具结果截为“头 4096＋尾 1024”，不分新旧。

问题：模型刚拿到、正要使用的工具结果（如本轮搜索）也会被截成半份；中间截断仍保留大量旧内容，腾出的空间有限；没有不可清理的工具名单。

外部做法：Anthropic API 与 opencode（`SessionCompaction.prune`，2026-04 起默认开启）均从最旧的工具结果开始整条替换为占位文字，保留最近若干次完整，并设最低清理量以避免白白破坏前缀缓存。

## 备选

1. 维持现状（全部按长度截断）。
2. 直接启用 Anthropic API 的 `clear_tool_uses`。只对 Anthropic 模型有效，AIcove 为多供应商，不可行。
3. 在自有装配流水线中按同样规则实现。

## 决定

采用 3，仍只改请求副本，raw message 不变。

- **触发**：沿用 `ContextWindowPolicy.trigger`（窗口 80%，不足时扣除输出预留）。
- **保留**：最近 3 次工具调用（以闭合的调用与结果为一组）完整保留，不截断。
- **清理**：更早的工具结果按时间从旧到新整条替换为占位文字，形如 `[旧工具结果已清理，需要可重新调用 <工具名>]`；工具调用及参数保留，tool_call_id 配对不破坏。
- **保护名单**：可配置不清理的工具名，默认为空。
- **最低清理量**：本步可腾出的 token 低于阈值时跳过，直接进入摘要压缩，避免为少量空间破坏缓存；阈值实施时按窗口比例定，并写入测试。
- **单条上限**：工具执行时的单次输出上限与“已截断”提示属于工具产生端，保持独立，不由本步承担。
- 顺序不变：先清理旧工具结果，仍超线再做闭合工具组摘要（ADR0038）。

## 验收项

1. 触发线以下请求副本与原文一致。
2. 触发后最近 3 次工具结果逐字不变；更早的按时间顺序替换为占位，调用与 id 配对完整。
3. 保护名单内工具不被清理。
4. 可腾空间低于阈值时本步不改动请求副本。
5. raw message 始终不变。

## 代价

- 旧结果整条清掉后，模型若需原文要重新调用工具；搜索类可能结果不同且产生费用，必要时加入保护名单。
- 实施前现行截断逻辑仍在运行，ADR0038 与记忆系统说明中的对应描述已加注待改。
