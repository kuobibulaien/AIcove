# 0037 短上下文辅助回答

日期：2026-09-22。状态：implemented，离线验证通过，真实供应商与运行设备未验。

## 需求与边界

用户要求把界面设置改为通用设置，在其中开关辅助回答并指定便宜快速的模型；回到底部旁显示同尺寸气泡，点击展示三个候选。沿用 07-13 方案已确认的“填入输入框，再手动发送”。

## 决定

- 复用 AppSettings 的增量键值存储，新增 `smart_reply_enabled`（默认 false）、`smart_reply_model`（默认空）；无数据库 schema 迁移。模型必须独立明确选择，禁用或失效不回退主模型。
- UI → SmartReplyController → SmartReplyPort → SmartReplyAdapter → BackgroundAgentService，继续复用供应商适配。AgentDefinition 显式声明近期会话权限、JSON 输出、无工具、单轮运行及候选投递通道；候选只在页面会话内存中缓存，不入消息历史。
- 上下文取 DB canonical raw 最近 10 条记录并尊重新话题边界；独立短提示词加 user/assistant 文本或语音转写。排除完整角色/酒馆提示词、长期记忆、思考、工具、附件及 rawPayload。每条最多 1200 Unicode 字符，总计最多 6000 字符；不把字符上限称为精确 token 上限。
- 单次生成三个有差异的回复，每条最多 120 字、输出最多 512 tokens；错误或数量不正确允许手动重试，不以硬编码内容假装模型结果。
- 按需调用，不自动预生成；按会话、模型和裁剪后原始文本缓存，同模型并发去重。对话改变时拒绝迟到结果，选用前再次检查；生成中的会话暂不调用。
- 选中后通过会话隔离的草稿通道填入；已有草稿追加换行保留，编辑历史消息时拒绝填入，不自动发送。
- 设置根入口为「通用」，子页标题为「通用设置」。气泡复用回到底部尺寸，使用 MoeIconButton；两个入口由同一右下角 Row 布局，回到底部隐藏时辅助回答占据右端，回到底部出现时辅助回答位于其左侧、间距 10；加载使用 MoeLoadingIndicator；三个候选使用 MoePopupMenu/MoePopupMenuItem 锚定气泡展开，共用菜单材质、边界避让和键盘操作，在所属详情 Navigator 内打开。业务不自建 Dialog、菜单行或候选按钮。

## 调研依据与代价

[Google ML Kit Smart Reply](https://developers.google.com/ml-kit/language/smart-reply) 使用最多最近 10 条消息生成最多 3 个候选；[Smart Reply 论文](https://arxiv.org/abs/1606.04870) 强调候选语义多样性。这里借鉴近期窗口与多样性策略，实际调用用户选择的多语言聊天模型，不接入仅支持英语的 ML Kit 模型。

按需首次点击需要等待网络；短窗口不会理解久远事实，因此提示词禁止替用户编造经历。现有 canonical loader 会读取本地原始记录后切片，传出给辅助模型的仅是裁剪副本；本批没有修改共享历史加载器。
