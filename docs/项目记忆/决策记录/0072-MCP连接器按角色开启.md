# 0072 MCP 连接器：远程 HTTP、每个连接器一个插件、按角色显式开启

- 状态：accepted（2026-10-10 用户确认「按角色绑定，先做 MCP 客户端」；第一批已实施，离线测试与公开 MCP 服务冒烟通过，真实模型对话与实机未验）
- 日期：2026-10-10
- 关联：ADR0064（微内核与全插件化，MCP 为唯一生态兼容口）、ADR0008（插件按角色绑定）、ADR0017／0044（插件关闭后工具调用对移出请求副本）、ADR0031（旧云端服务下线）

## 背景

Agent 能力已在代码里，但用户无法自己扩展工具。用户要的是像 Claude／ChatGPT 手机端「连接器」那样，把自己或第三方暴露的 MCP 地址接进来，给角色少量操作外部的能力（查天气、查新闻、接外部记忆库）。仓库里原有一套 MCP 代码指向已删除的云端 `/mcp/*`，每次发消息还会去拉一次配置，属于死代码。

## 备选

- 连接器作为一个「MCP 插件」，角色再绑定连接器列表（存人设标记或新列）：多一层绑定结构，要么改人设编解码要么迁移数据库。
- 每个连接器注册为独立插件 `mcp:<id>`，复用会话已有 `enabledPlugins`：采用，无数据库迁移，前台聊天、主动关怀等所有走 `getEffectivePlugins` 的链路自动按角色生效。
- 借用 pub 上的 MCP 客户端包：现有包下载量小、维护不确定，本期只需 initialize／tools/list／tools/call，自写约 300 行不新增依赖。

## 决定

1. 传输只做 Streamable HTTP（含 SSE 响应），全平台可用；不做本地进程（stdio）与旧版 HTTP+SSE 传输。
2. 每个连接器是一个插件，id `mcp:<连接器id>`；工具名 `mcp__<连接器id>__<工具名>`（≤64 字符，超长截断加哈希），可从工具名反查连接器。
3. 角色 `enabledPlugins == null`（全部插件）不包含连接器；连接器能改动外部服务，必须在角色「管理开启的插件」里显式开启。新角色默认不开。
4. 工具清单在「测试连接／刷新」时拉取并随配置保存，请求时不联网列举；服务端 inputSchema 原样作为参数 schema，只去掉 `$schema`、`additionalProperties` 等部分供应商不认的字段。
5. 连接器配置存 `aicove.plugins.mcp.connectors.v1`，与其它插件配置一样随用户自建云同步／局域网同步（含令牌，与联网搜索密钥同口径）。
6. 角色未开启某连接器时，请求副本里该连接器的历史工具调用与结果成对移除（ADR0017 口径），原始历史不动。
7. 删除旧云端 MCP 客户端、`toolPrefs` 参数链与走云端 `/api/chat` 的发送方法。

## 代价与缺口

- 不支持 OAuth 授权流程，只支持 Bearer 令牌与自定义请求头；需要 OAuth 的官方连接器（如部分 SaaS）暂不可接。
- 工具结果只回文本，图片／音频块以占位文字告知模型；单次结果截断到 2 万字符。
- 仍挂在旧 `PluginManager` 上，ADR0064 第二批迁内置插件时一起迁到内核 `PluginHost`。
- 未做调用前确认弹窗（「是否允许角色调用此工具」）；当前靠连接器级、工具级开关与角色显式开启控制范围。
- Gemini 对 JSON Schema 子集较严，含 `$ref` 等写法的工具可能被拒，未实测。
