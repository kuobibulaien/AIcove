# 0015 连续中断转场的位置衔接

- 日期：2026-09-10
- 状态：superseded（2026-09-14，由 [0033](0033-页面转场统一使用官方Cupertino.md) 替代；下文仅保留历史）
- 用户要求：修复供应商渠道错拍，排查全应用，并支持连续打断仍流畅。

## 原因

Flutter 的 secondaryAnimation 在旧页退出、新页进入重叠时通过 TrainHoppingAnimation 等待进度相遇。CurvedAnimation 随后仍可能保留旧返回曲线。真实供应商行点击实验已确认：返回160ms后重入，新页覆盖83%时底层仅偏移3.9px。仅等待Navigator.push返回也无法解决，因为返回的是popped而非视觉退出完成的completed。

## 决定

ParallaxSlidePageRoute 与 ParallaxSlidePage 共用 _ContinuousParallax（continuous_parallax_transition.dart）。原生前景转场、阴影、边缘返回、Page/PopScope语义以及已有提前返回Simulation保留。底层位移不再消费Flutter的换轨secondaryAnimation，而是跟踪直接相邻路由的真实controller，以当前可见比例为新段起点；路由更换和方向反转时重新确定起点/目标。手势阶段跟随线性进度。非滑动弹窗覆盖期间保留正在退出的归位动画，归位完成即解绑；所有监听在换源/销毁时解绑。

不排队等待动画、不吞点击、不用固定延迟、不新增计时器或逐帧写盘。普通子页统一加入公共路由；裁剪、图片预览、卡片展开和框架组件演示保持其语义。

设置侧栏另修复关闭中重开被_isOpen拦截的问题：open始终允许控制器正向运行，仅在实际dismissed时隐藏面板，不使用过期的关闭Future隐藏新一轮面板。

## 代价与边界

新增每个路由一个轻量位移通知器，刷新FractionalTranslation，页面内容作为缓存child。接续保证位置连续、下一帧响应；没有承诺速度/加速度数学连续或所有业务负载下零掉帧。原生路由offstage测量帧不能当真实动画终点。

全应用普通横向入口已统一；框架原生演示仍是原生组件对照，并不把它的原生行为当生产路由验收。特殊展开/媒体/裁剪没有同一底层换轨机制。本轮不重做这些效果。

## 验证与回滚

55项相关测试通过：真实渠道行、六次连续进退、360/1000px、LTR/RTL、多层退栈、手势取消、Page更新/禁止返回、设置侧栏反复开关、记忆编辑、日志详情和组件演示。Release已安装PKX110；构建指纹、真机操作及限制见需求日志和scratch/transition-fix/交付报告.md。

回滚仅撤销本轮part/mixin接入、8个普通入口路由变更和侧栏改动；保留此前_InterruptedCupertinoPop及无关工作树修改。原始文件快照与增量在scratch/transition-fix/。不涉及schema、账户、生产请求或全局系统设置。
