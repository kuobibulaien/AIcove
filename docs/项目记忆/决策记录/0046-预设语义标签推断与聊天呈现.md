# 0046：预设语义标签推断与聊天呈现

## 背景

ADR0044 建立了统一的标签注册表，但预设自带的标签（`<think_nya~>`、`<thinking>`、`<tuiyan>`、`<zw>`、`<branches>` 等）还没有进入聊天。酒馆显示正则会在落库前把这些标签改写成整页 HTML，而气泡不渲染 HTML，用户只能看到源码。用户确认：前端只做三种呈现，即**正文、折叠、选项**；“隐藏”由后端照常执行预设中替换为空的正则。

## 决定

- **从正则推断，不按名字逐个适配**：`preset_tag_mapping.dart` 读取预设显示正则，从中推断每个标签的呈现方式。
  - 分类依据有三类：标签名词根（think/思考/思维 为折叠；option/branch/选项 为选项；zw/正文/content 为正文）；替换结果是否生成 `<details>`；是否生成至少两个按钮（按钮数量达到这个门槛才判为选项）。
  - 标签名提取时会还原转义、展开可选前缀，并跳过正则语法本身。
  - 用户的手动修改存在 `compatibilityData['tagDisplay']`，不需要数据迁移。
  - 在酒馆插件「标签」页签中逐行查看和修改。
- **美化正则让位**：凡是输出 HTML 的显示美化正则，一律不再执行（界面渲染不了 HTML）；替换为空、纯文本替换以及请求侧的正则照常执行。结果是落库文本保留原始标签。
  - 2026-10-04 修订（ADR0059 后续，用户确认）：识别范围补上 ```html 代码块及 `<body>`、`<script>`、`<iframe>` 等写法；其中「只把占位符换成网页」的规则（查找规则无捕获组、无成对标签，替换结果不引用原文）显示时改为替换成空，避免露出占位符；用到原文的照旧交给标签组件。
- **聊天投影**：
  - 聊天页把会话的 `recipeId` 传给消息列表，由 `tagPresentationForRecipeProvider` 算出本会话的映射：绑定预设的推断结果叠加用户修改，内置常用名打底。
  - `buildChatMessageListItems` 把文本切成正文段和折叠段：折叠段用带 `title` 的 `ThinkingBlock` 承载，`MessageBubble` 将其渲染为独立的 `MoeCollapsibleBubble`；正文标签去掉外壳后照常分段；流式中尚未闭合的折叠段也会显示。
  - 选项类标签交给对话选项气泡解析（ADR0045 可传入同义标签名）。
- **流式过滤**：`<think>` 的隐藏规则改为要求标签名完整匹配，不再误吞 `<think_nya~>`、`<thinking>`。
- **按当前映射解释，不保存快照**：旧消息按会话当前的映射显示。修改映射后立即生效；代价是解绑或更换预设后，旧消息的呈现也会随之改变。

## 代价与后续

- 生成 HTML 小部件的美化（状态栏卡片、播放器、时间流光等）一律退化为折叠或纯文本，不复刻预设前端（沿用 ADR0041）。
- 方括号语法（`[CAST]`、`[STATUS]`）尚未识别。
- ADR0044 中“QuickJS `prepare` 之后缺少最终请求过滤”的缺口仍然存在。

## 验证与回滚

- 离线验证：推断规则用三份真实预设样例与一份自拟的小猫之神样例验证；另有列表切段、流式未闭合、折叠气泡渲染、流式过滤、`branches` 选项解析的专项测试。
- 全量测试：失败集合与此前基线相比没有新增失败。
- 源码渲染预览：`scratch/tag-fold/`（360 与 1000 宽度）。
- 未验证：真机与真实模型均未验收。
- 回滚：撤回列表投影、气泡分支、后端对正则的过滤以及 provider 即可；`ThinkingBlock.title` 是可选字段，旧数据兼容。
