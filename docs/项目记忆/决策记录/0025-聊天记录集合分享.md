# ADR0025：聊天记录集合分享

- 状态：accepted
- 日期：2026-09-13
- 用户明确要求：联系人头像多选；使用专用聊天记录集合气泡；AI上下文标记用户与哪位联系人的聊天；留言可空但发送后仍触发回复。

## 决定

`ChatRecordBlock` 复用 `TextBlock` 类型与原有消息JSON，附加 `chatRecord` 快照（来源名称、发送者、时间、内容与原消息块）。UI优先渲染集合卡片，可打开共享记录详情页；`content` 提供带来源和引用边界的完整文本，既供现有模型适配器读取，也让旧客户端保留可读回退。原始会话不改写，新的集合是接收会话的一条用户消息；不做DB/schema迁移，不把来源消息的raw工具载荷转为当前会话指令。嵌套图片/音频保留在详情快照中，目前模型读取集合的文本及媒体文字占位。

发送经 `ChatActions.forwardMessages` → 现有 `_sendText` 投递链，显式绑定接收会话及已构造的消息，不修改活跃会话全局值。留言非空时追加文本块，为空仍以集合的完整内容触发回复。正在回复的接收方暂拒绝新分享；本地受理即完成该接收方发送，后续模型错误沿用已提交消息的失败/重试路径，不重新转发。多接收方按本地受理顺序处理，保留未成功项，避免重发已成功项。

分享弹窗按联系人实际行数收缩，最高占屏幕85%，超出仅联系人区滚动，底部紧贴并排「导出为图片」「直接分享」。选好联系人点击「直接分享」才打开独立留言悬浮窗，发送或取消；半屏面板不放留言框。取消保留联系人选择且不发送，键盘下留言窗可滚动，输入及提示文字水平居中并使用对称内距。图片导出沿用会话背景参数；按宽度等比铺图，重复完整背景并裁切末张。顶部导航与保存按钮跟随预览滚动，不烧入PNG。

## 取舍与回滚

不新增独立数据库实体或模型协议类型；代价是模型读取文本引用，集合内部媒体不会展开为新一轮原生多模态输入。结构化快照增加消息JSON体积。回滚仅撤回本批源码接入，保留已有消息；旧解析器仍能显示带来源的文本，不删除数据。实现和验收证据见需求日志及 `scratch/chat-share-sheet/`。
