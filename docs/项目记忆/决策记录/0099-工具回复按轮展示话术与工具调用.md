# 0099：工具回复按轮展示话术与工具调用

关联：ADR0064（Agent 运行时）、ADR0077（模型思考）。

## 背景

一次回复里可能有好几轮工具调用：模型先说一句「我查一下」并调工具，拿到结果再说一句、再调工具，最后给出正文。原来各轮话术合并成一段文字，工具调用块统一挂在回复上，列表只能把全部思考和工具折叠段堆在正文前或正文后，看不出真实先后。

## 决定

1. 内核执行器每轮工具调用前记下这一轮的话术、模型思考和工具调用 id；收尾时生成 `ApiCallResult.replyRounds`（最后一轮是正文，不带工具；工具产出的图片、语音与工具事件归最后一轮）。
2. 调过工具时，预设正则与回复插件**按轮分别处理**（空轮不跑插件），再拼回合并字段。合并字段 `rawReplyText`／`replyText`／`processedText`／`pluginEvents` 的含义不变，上下文回放、语音等其他使用方照旧。旧执行器也走同一套按轮处理，两边结果保持一致。
3. `replyRounds` 存进原始消息的 `rawPayload`（键 `replyRounds`），从存档重建投影时读回。
4. 投影逐轮生成：思考 → 话术 → 这轮的工具调用，最后是正文轮。工具调用单独成一条消息，不与话术合在一条里（列表会把同一条消息里的过程折叠段提到正文前）。
5. 没有轮次信息时（没调工具、旧消息）按合并文字展示：思考与工具调用排在整段回复最前。

## 代价

- 回复插件的处理单位从「整段回复」变成「一轮话术」。现有插件（提醒、表情、生图、语音）都只处理各自的标签，结果不变；以后若有插件要看整段回复（比如在末尾追加内容），需要另行处理。
- 跨轮的预设正则（一条规则同时匹配两轮的文字）不再生效。
- 走工具语音输出（`hasToolAudio`）的回复仍按合并文字展示，没有逐轮穿插。
- 已存的旧消息没有 `replyRounds`，不迁移。
