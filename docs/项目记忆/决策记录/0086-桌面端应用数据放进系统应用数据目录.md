# 0086 Windows／Linux 应用数据放进系统应用数据目录，旧数据启动时搬家

- 状态：accepted（2026-10-16 用户同意：安装到系统规范位置，数据随之规范）
- 日期：2026-10-16
- 关联：发布安装包改为 DMG／Windows 安装程序（`tool/DIAGNOSTICS.md`「公开发布」）

## 背景

数据库 `aicove.db`、日志、壁纸、生成图、音色、酒馆预设等 20 处代码都用 `getApplicationDocumentsDirectory()`。手机和 macOS 上它是沙盒里的私有目录；Windows／Linux 上却是用户看得见的「文档」根目录，数据库直接摊在 `C:\Users\<用户>\Documents\aicove.db`，常被 OneDrive 同步（同步正在写的 SQLite 可能锁文件或损坏）。媒体、表情包、记忆等另一半数据早已在 `getApplicationSupportDirectory()`（Windows 为 `%APPDATA%\com.example\aicove_flutter`）。

## 决定

1. **统一入口**：`core/storage/app_data_directory.dart` 的 `appDataDirectory()`：Windows／Linux 返回应用数据目录，其他平台仍返回文档目录（行为不变）。应用自己的数据一律经它取根目录；用户主动导出的文件（对话导出、日志导出默认位置）仍放「文档」。
2. **启动搬家**：`main()` 最先调用 `AppDataMigration.run()`，把旧版写在「文档」下的已知条目（`aicove.db*` 与 `aicove`、`logs`、`wallpapers` 等 11 个目录，清单在代码里）搬到新目录；用户自己的文件不碰。数据库作为一个整体先复制、再改名、最后删旧，失败则本次继续用旧位置、下次再试；目录同卷直接改名，跨卷逐个复制；新位置已有同名文件时新位置为准、旧文件原地保留。
3. **改写绝对路径**：壁纸、生成图、参考音频等在偏好设置和数据库里存的是绝对路径。搬家后把旧前缀（原样、JSON 转义、正斜杠三种写法，且必须是已知条目名＋分隔符）改成新前缀：偏好设置在启动时改，数据库在打开时（`beforeOpen`）改，跳过 `cloud_*`／`lan_*` 同步簿记表并暂停同步触发器，改完恢复，不会当成用户编辑上传。各有一次性标记（偏好 `aicove.storage.data_dir_paths_v1`、库内 `local_storage_migrations` 表），只跑一次。
4. **不改 `Runner.rc` 的公司名／产品名**：应用数据目录路径由它们决定，改了会让已在 `%APPDATA%\com.example\aicove_flutter` 的媒体等数据失联。

## 代价

- 新增一张本地表 `local_storage_migrations`（不同步、不改 schemaVersion）。
- 路径改写只覆盖偏好设置与数据库文本列；若有别的文件里存了旧绝对路径，不会改到（目前未发现）。
- 目录路径里仍带 `com.example`，要改得另做一次搬家。

## 验收门

Windows 实机：用旧版（数据在「文档」）跑出聊天记录、自定义壁纸、生成图、参考音频后，装新版启动：数据都在、图片与音频能打开、「文档」里只剩用户自己的文件、云同步／局域网同步没有多出待上传记录。
