# 手动压缩：继承内容、重置格式

> **已被取代（2026-09-23）**：由 [ADR0038](0038-记忆与上下文重构为短期长期两层.md) 取代，以下仅保留原始记录。

## 背景

用户常在更改角色卡后点击新话题，希望旧回复样式不再影响模型，但此前的重要内容仍能继承。仅移动上下文边界会失去内容；仅把摘要存入记忆目录而不注入，也依赖模型主动查找，不能稳定接续。用户已确认“内容继承、格式重置”并要求开始实现直到完成。

## 决定

1. 第一批只交付手动压缩和确认后记忆归档。新请求装配最新角色卡/预设、有效角色记忆、纯内容摘要和新话题消息，不带旧原文尾巴。自动压缩在2026-09-13由ADR0024独立实现（其触发、保留与记忆策略同日由[ADR0027](0027-压缩与持久记忆联动.md)修订）；不能把手动操作当自动续聊。
2. 会话交接与长期记忆分存：SQLite v16 新增 `topic_handoffs`，保存派生摘要、raw 来源、版本、前后边界与待归档状态；角色长期记忆仍以独立 MD 为真相源。原始聊天不删除、不迁移，不复用旧 summarized 标记。
3. 通过 `TopicCompactionPort` / `TopicSummaryPort` / `TopicHandoffStorePort` 跨层调用。模型仅生成 JSON 草稿，无工具、角色卡装配或文件写权限；以 `local.topic_content_handoff` 定义其 ContextProfile、OutputContract 和后台 trace 投递边界，复用现有 BackgroundAgentService 运行壳，不另建一套调度器。
4. 用户预览/可编辑摘要后，摘要和话题边界同事务提交；归档 MD 失败保留 pending，不误报整体未保存。执行及生成锁固定目标 owner，不跟随 activeConversation。相同归档 ID 与相同事实行不重复追加，不覆盖手写常驻笔记。
5. 支持应用内撤销，恢复前一边界并取消尚未完成的归档；不撤回已写 MD。源消息改变后摘要失效，旧轮次重放不带之后生成的交接材料。摘要挤掉当前用户输入或超预算时拒绝残缺请求。

## 备选与代价

- 拒绝“仅清窗口”：用户需重讲重要内容。
- 拒绝“保留近期旧原文”：旧回复格式仍作为示例干扰新角色卡。
- 拒绝“全摘要放进常驻 MD”：临时上下文与长期记忆混在一起，容量和更新职责不清。
- 当前采用模型有损整理与用户预览，会增加模型调用、费用和等待；不承诺零格式残留或原文全部细节保留。长输入分块与摘要有上限，详见模块文档。
- SQLite 内部表采用专用 Adapter 的参数化 SQL，沿用本项目内部认领表做法；无新增业务实体/代码生成，但迁移必须覆盖新建与 v15 升级。
- 来源验证偏保守：raw 状态/blocks 改变也可能要求重整。精细事实纠错、语义去重、自动常驻更新、完整遗忘及新 MD 备份均未纳入本批。

## 验收门

- 真实 DB/文件验证 owner 隔离、原文保留、事务回滚、升级、重启待写恢复、撤销和源变更；不只测 fake repository。
- 真实普通/酒馆请求装配中有最新角色卡与内容摘要，没有旧原文；模型网络边界替换，语义质量需真实模型另验。
- 360/1000px 预览、编辑、开关、保存、取消及页面 owner 复用通过；生成状态按目标 owner 检查。
- Flutter 相关/全量测试、静态检查、编译运行。回滚不降级数据库 schema，保留 v16 表支持。
