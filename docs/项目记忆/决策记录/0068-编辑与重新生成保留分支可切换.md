# 0068 编辑与重新生成保留分支，可切换

- 状态：accepted（方向）；数据模型与界面方案待设计，涉及 schema 与同步契约，实施前需用户确认方案
- 日期：2026-10-07
- 关联：ADR0012（编辑草稿与分支提交分离）、ADR0038（摘要来源校验）、ADR0050（设置字段合并）、ADR0060（统一装配）

## 背景

用户心智模型：从当时那句话派生出一条新分叉，原分叉保留，形成一棵会话树（与 Pi 的会话树一致）。

现状：
- 重新生成调用 `truncateAfterMessage`，撤回编辑调用 `truncateFromMessage`（`features/chat/services/chat_history_store.dart:1110` 起），把后续消息全部软删除。
- 编辑提交（ADR0012）在同一事务软删旧后缀、插入新消息，“原记录不物理删除”，但界面无法回到旧分支，模型也看不到。

旧分支数据仍在库中，改为分支树不会丢历史。

## 决定

- 编辑与重新生成都产生新分支，原分支保留；会话有一条**当前分支**，上下文组装、摘要、记忆整理只沿当前分支进行（与 Pi “模型上下文由当前分支重建”一致）。
- 用户可在分叉点查看并切换分支。
- 被软删除的现有旧后缀，在迁移时可识别为非当前分支（具体能否可靠还原分叉点，设计时核实）。

## 待设计（实施前确认）

1. 数据表达：消息增加父消息引用，或增加分支／当前分支指针；schema 迁移与备份。
2. 同步：分支与当前分支指针如何跨设备合并，两端同时在不同分支续聊时的处理（ADR0050 字段合并能否覆盖）。
3. 摘要与记忆：摘要来源校验（ADR0038）改为按分支；切换分支时自动摘要、记忆 Agent 书签如何处理，避免把非当前分支内容整理进长期记忆。
4. 界面：分叉点的切换入口、宽窄屏一致（ADR0019）。
5. 重新生成与编辑的语义统一，`truncate*` 接口退役。
6. 消息发送设备归属：2026-10-07 进程死亡后的残留 sending 恢复暂用 30 分钟时间门槛避免跨设备误判（无设备归属字段，云端与 LAN 同步整行 status）；数据模型设计时一并增加发送设备或租约，使恢复只作用于本机发出的消息。

## 代价

- 触及聊天真相源的数据模型、同步契约与上下文组装，是难回头的改动，需分批实施并逐批验收。
- 会话数据量随分支增长，需考虑非当前分支的显示与清理策略。
