# ADR0028：消息整体同步与媒体单份存储

- 状态：accepted（当前过渡实现），服务器与 Android 已更新；用户要求转向成熟开源方案调研后，Mac 同步暂停保留队列，手机已拔线，完整对齐未验收。候选替代引擎尚未确定，见[开源数据结构调研](../../../apps/aicove_flutter/docs/02_前后端分离与架构规范/云同步开源数据结构调研.md)。
- 日期：2026-09-13
- 授权：用户要求先优化数据架构，纠正“3 万个附件”的同步设计与计数；只有聊天记录中超过 30 天的图片可以仅同步缩略图，其他用途传原图。

## 已有证据

手机存储盘点记录 9,591 条消息、7,287 个消息块、20,057 条投影映射。原同步实现将每行作为独立文档/事务。消息 raw_payload 约 702 MB，音频内容被嵌入多个字段；另有按字节验证的重复图片副本。同步媒体索引又按资产/源路径生成多个 JSON 小文件。以上分别是同步粒度、媒体载荷重复和索引碎片问题，不能只调整上传并发或计数文案。

## 决定

1. 一条原消息、所属消息块与投影映射组成一个版本化消息快照；原始行和所有字段保留，整体原子应用。孩子记录改动标记所属消息。既有独立文档保留为历史兼容数据，不物理清理服务端历史。
2. 媒体内容按摘要只保存一份，已知媒体字段中的内嵌音频/图片改为持久文件引用；正文、工具参数与生成参数保持原值。同步比较基线保存摘要，避免额外复制完整 raw_payload。
3. 媒体与来源索引集中到 SQLite；旧 JSON 索引只作一次导入，原文件和原索引保留用于回退，不自动清理唯一原图。
4. 用途与原始创建日期分离：非聊天用途标记必须传原图；聊天按最近一次引用日期决定。仅确认超过 30 天且仅用于聊天的图片可推迟原图。共享图片以要求原图的用途优先，未知日期保守传原图。头像、背景、插件配置、预设引用图和其他非聊天文件不受 30 天限制。
5. 进度分别报告消息/配置、唯一媒体文件与字节数，不用数据库行数表示附件数。

## 迁移与回滚边界

先暂停当前两端传输；既有冻结 outbox 保持原操作编号完成后再切消息快照。源端重发完整快照，接收端保留待上传编辑，不能把不完整接收数据反向发布为完整源。内嵌媒体必须先原子写文件并校验，再以比较条件替换数据库引用；失败保持旧载荷。保留升级前数据库、媒体文件、旧镜像与 compose，回滚不得清空附件或同步序号。

## 验收

真实服务契约覆盖：消息整体恢复、子记录删除与并发冲突、旧队列重试、旧独立文档不覆盖新快照、单份媒体字节校验、非聊天原图、旧图近期重用、跨用途合并、索引导入/重开与存储体积。实际手机与 Mac 在保留回退副本的前提下恢复同步并验收，不能以构建或测试代称实机通过。
