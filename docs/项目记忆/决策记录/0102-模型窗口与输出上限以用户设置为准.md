# 0102：模型窗口与输出上限以用户设置为准

关联：ADR0038（记忆与上下文）、ADR0062（陪伴压缩）。

## 背景

用户反馈：现在的模型普遍支持百万级上下文、128k 输出，软件写死的默认值把能力压住了。核对代码有四处：

- 没单独配置窗口的模型，先查写死的模型表（gpt-4o、deepseek-chat 等多为 128k），查不到再用 128k 兜底，再与全局「上下文窗口」（默认 272k）取小，全局设置等于白设。
- 压缩输出上限曾为窗口 1/8、最多 8192，记忆整理为 1/8、最多 4096；推理模型的思考计入输出，DeepSeek Flash 在 32k 窗口下思考吃光额度、正文为空（见经验教训 2026-10-22）。
- Claude 渠道未配置时 `max_tokens` 默认 4096，长回复和思考都会被截断。

## 决定

1. 模型窗口：模型配置 > 渠道配置 > 全局「上下文窗口」设置。删除写死的模型窗口表与 128k 兜底；真超出模型上限时由服务商报错，发送链路已按超限压缩重试。
2. 后台模型（压缩、记忆整理）输出上限：窗口的 1/4，最少 2048、最多 128000（`context_window_policy.dart` 的 `backgroundOutputTokens`）。服务商拒绝时逐次减半重试，不低于 8192，实例内沿用减半后的值。
3. Claude 渠道未配置 `max_tokens` 时默认 32000（当前 Claude 4.x 各模型都接受）；渠道或预设配置的值优先。
4. 聊天思考档默认仍是「最低」（2026-10-13 用户裁决），本 ADR 不改。

## 代价

- 未单独配置窗口、真实窗口又小于全局设置的老模型，会先收到服务商超限错误再压缩重试，多一次请求。
- 输出上限变大后，按窗口预留给输出的部分变多，压缩每批能装的原文相应变少。
