# 0115 上下文 Raw 与确定性消息投影

- 状态：accepted，2026-10-25 按用户提供的总架构师审定方案实施后端部分。
- 关联：0038、0104、0108。前端流式与列表切段器由后续任务接续。

## 决定

1. DB Raw 仍是模型上下文唯一真相源。`ReplyRound.rawText` 保存清理后的轮次原文，`replyText`／`processedText` 只服务展示；旧轮次无 `rawText` 时回退 `replyText`。单轮与多轮回放都剥离行内 think。
2. `PluginRequestContext.rawHistory` 传递本次话题／重生成锚点裁切后的 Raw 历史。记忆查询只取该列表最近四条有效对话，不重新读取最新时间线；assistant 优先 `rawReplyText ?? content`，排除思考、系统注入和插件控制载荷。
3. 展示前先提取 think（原生 reasoning 优先），用第一方标签扫描器保护插件标签，再运行第三方展示正则并还原标签，最后运行插件。占位符被删除不复活，被复制只还原一次。普通回复、缓存主动回复与 TTS／背景分段共享口径。
4. 有语义字段时直接重算投影，连旧快照解码都不执行。仅完全没有可重算语义的历史消息回退 `projectedMessages`，其既有 ID 保留以兼容旧操作引用。版本仍为 1，无 schema 或同步数据迁移。
5. 新气泡 ID 以 Raw ID、轮次、槽位／类型构造，块 ID 以所属气泡 ID、块序号／类型构造。后补媒体用 Raw ID＋补插序号。创建时间沿用 Raw；Block 解码及副本不再刷新时间。生成新回复时 Raw 与投影共用一次创建时间。
6. 媒体继续使用 `pluginContents`、`toolAudioResults`、`supplementInsertOps`；不新增 media／unreadAudioIds 结构。补插锚点落在合并正文中间时，仅在语义锚点拆开正文。后台准备完成的失败文字回退写回现有展示字段，原始文本不变。
7. 有语义的 Raw 停写投影快照；新自定位 ID 停写映射，历史／流式旧 ID 兼容映射保留。首屏与翻页走相同投影。部分文字气泡删除使用现有本机隐藏记录，不修改模型历史；显式展示文字更新保存在既有展示字段。
8. `runStatus`／`stopReason` 经 displayOnly、气泡编码和重建保留，只附在最后一个 assistant 气泡。过程 Raw 保留尚未完成的调用意图供安全回放，历史卡片只投出已有结果的步骤。

## 验证与交接

已覆盖 Raw／Display 隔离、记忆裁切、标签保护、TTS／主动缓存、重启状态、重复投影 JSON 字节相等、媒体位置／失败回退／重生成及快照停写；命令、日志和剩余检查见 `scratch/context-projection/RESULTS.md`。

后续前端只消费纯投影和独立的流式状态，不用气泡反向拼 Prompt，不恢复快照写入；应用内与真实多端仍需后续验收。

## 前端流式收尾（2026-10-25 第二棒）

9. 流式收尾时，Raw 有语义字段、流式中没有语音占位、没有 `tts_convert`／`image_generate` 事件，且构建结果只含文字／工具／思考块，就直接把 `projectMessage(raw)` 写进时间线。这样不在数据层预切文字、不留随机 ID、不写别名映射，与冷启动重算逐字节一致，分段交给列表层。Raw 创建时间沿用第一个流式气泡的时间，位置不变，也不重播入场动画。投影收尾后不再进入旧的后补交付，否则同一气泡里思考旁边的正文会被剥掉。取消时保存的部分回复同样处理。
10. 带语音占位或生图／TTS 后补的回复，后补媒体仍按流式分段锚点插入，暂时保留旧收尾路径（流式 ID＋别名映射）。这部分与 pendingAudio 存储改造重叠，等那边合并后再收口。

## 生成与交付的响应处理收口（2026-10-26）

11. 主动回复（含 WorkManager headless 生成）与任务回执转述共用 `ProactiveReplyGenerator`：准备时清空 `responseProcessors`，缓存／返回清理后的 Raw，不触发响应插件；显式空 Raw 不回退展示／处理后文本，省略 Raw 的旧调用仍由 ApiCallResult 构造器兼容。`generateDraft(allowCall: true)` 只另加只读 `call_user` 工具，保留 yield 和开场白语义。
12. 内核最终回复和缓存／后台文字交付共用 `chat_reply_display_transform.dart` 的语义源与展示阶段：提取思考、规范文本、保护标签并运行展示正则、按顺序运行响应插件。内核使用请求快照，按工具轮逐轮投影、跳过空轮；中间工具快照不运行响应插件。缓存交付仍读取实时预设、角色音色和插件配置。临时注册 scope 在安装、工厂或执行成功／失败后统一释放，不销毁共享插件实例。
13. 前台主动交付先检查会话／触发器／设备归属，再成功 `beginDelivery`，之后才运行响应插件；已认领来电回落消息不重复认领，表单试发仍允许无持久化 claim。插件开始后失败不重试，维持至多一次副作用。构建出 Raw 后用 token 绑定交付锚点，绑定仅允许已完成认领且尚无锚点的同一持有者；随后及每次落库仍执行原有删除／暂停／锚点门禁。
14. 后台保持先投 Raw、来源设备回前台补媒体的路径，原 ID／时间、尝试预算与并发编辑守卫不变；本轮不扩大纯文本后台补处理范围，不改 schema／同步载荷版本。

离线验证：主动回复、task_agent、插件响应和展示投影共 51 个测试文件、408 项通过（含真实 provider 转述＋假 HTTP、失去认领零响应处理、处理前认领和失败后不重试、每轮一次）。日志：`/tmp/aicove-step3-regression-final.log`、`/tmp/aicove-step3-transform-final.log`；应用内、真实媒体／跨设备竞争与进程崩溃演练未验。
