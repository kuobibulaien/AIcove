# 0074 语音通话：级联流水线复用音色预设，通话轮次独立存储

- 状态：accepted（2026-10-11 用户确认路线与界面形态；10-12 用户同意通话记录的数据库迁移，第一批流程、存档与气泡已实现；同日用户确认通话按「子 Agent」处理上下文，摘要回流已实现）
- 日期：2026-10-11
- 关联：ADR0008（插件／音色预设按角色绑定）、ADR0038（原文唯一真相、摘要与记忆 Agent）、ADR0047（分段规则）、ADR0064（Agent 运行时 ContextProfile）

## 背景

用户要给角色加实时语音通话，硬约束是通话与语音条必须同一个音色。用户也明确指出，通话上下文不能直接塞进聊天上下文。

## 备选

- 端到端语音模型（OpenAI Realtime、Gemini Live、豆包实时语音等）：延迟最低，但只能用模型自带音色，带不走用户的音色预设；还要另起一个“大脑”，绕开人设、预设、世界书和记忆链路。不采用。
- 级联：VAD → 流式 ASR → 现有聊天链路流式输出 → 切句 → 流式 TTS（复用角色音色预设）→ 边收边播：采用。
- 通话逐句写进 messages 表：会快速挤占聊天上下文，口语体会污染文字聊天，ASR 错字也会混入原文。不采用。

## 决定

1. 通话走级联流水线，TTS 用角色当前音色预设对应供应商的流式接口，音色与语音条一致。
2. 通话像一个子 Agent（2026-10-12 用户确认）：接通时调用主聊天唯一的装配入口 `prepareApiConfig`，拿一份上下文快照，人设、预设、世界书、长期记忆和话题交接摘要与打字聊天一致；文字聊天不整段带上（2026-10-12 用户确认）：只带最近 8 条原文，更早的部分用自动压缩 Agent 压成一份「接通前摘要」，合并已有的自动摘要。这份摘要只缓存在内存里，不写 `context_summaries`。它在后台整理，接通不等它，整理好后从下一轮起带上。只保留记忆和时间感知两个插件，去掉工具，关闭思考。之后每轮只在快照尾部接上本次通话轮次，并在用户最新一句前插一条通话约束提醒：口语短句、先给短反应、不出 Markdown 和插件标签。通话期间文字聊天不会变，所以快照只做一次，首字延迟不增加。快照不落任何副作用（`persistSideEffects: false`）：不写预设变量，超出窗口时只做运行时压缩、不写 `context_summaries`。模型和打字聊天一样取默认聊天模型（`defaultChatModels.first`，没有时用 `defaultModelName`）；通话一律流式请求，预设关掉流式时也一样，没流出来的部分用最终回复补齐。摘要和通话轮次以两条 assistant 角色占位接在历史尾部，`{{lastusermessage}}` 和附加到最后一条用户消息的内容仍指向真实的用户原文；替换时按「整条相等 > 首尾相接 > 包含」找槽位，保留占位前后被合并进来的文字（如相邻回复、预填），其它消息里由宏复制出的占位只删占位本身（2026-10-12 审查修复）。
3. 通话轮次不进 messages 表，不当正式消息。聊天界面只落一条带时长的通话气泡（`CallRecordBlock`），点开查看逐句记录。~~逐句记录单独存储在 `call_sessions`／`call_turns`（数据库 v22，只存本机、不同步）~~（2026-10-12 用户修订）：逐句记录是气泡的附属数据，存在块 JSON 的 `callRecord.turns` 里，随聊天走云同步和局域网同步；块的文字内容不变，模型仍只看到标签和摘要。之前的通话气泡里没有记录，记录页回退读本机两张旧表（只读，不再写入，不做回填迁移）；别的设备点开这类旧气泡会提示记录不在本机。
4. 之后的文字聊天只看到通话摘要，不看逐句记录。挂断后，后台的通话摘要 Agent（`local.voice_call_summary`）会整理一份摘要。它复用后台运行壳和压缩模型，输入只有本次逐句转写。摘要写进气泡块的 `callRecord.summary`，模型看到的是 `[语音通话 mm:ss]` 加上「通话摘要：……」。摘要随聊天同步，不需要新的数据库迁移；删掉气泡，摘要也就不在上下文里了。摘要失败只记日志，气泡保持原样。写入走 `ChatHistoryStore.attachCallSummary`：在事务里确认气泡仍有效、仍是这通电话才写，不改会话预览和时间；气泡已删除或被改动就放弃（2026-10-12 审查修复）。逐句原文交给记忆 Agent 整理（ADR0038 口径），目前还没接入。
5. 被打断时，只把实际播出去的部分记为角色说过的话。Fish 没有逐段完成信号，轮次结束以「收到的音频不短于按字数估算的最短时长」（中日韩字 110 ms、英文字母和数字 35 ms）为下限；超过 8 秒没有新进展就打断合成，只记估算听到的前缀。挂断时先停播放，再等麦克风和识别收尾。
6. 跨供应商先定义统一的流式 TTS 端口（输入文字片段、输出音频块）和流式 ASR 端口，各家各写一个 Adapter；通话逻辑只依赖端口。
7. 语音识别来源由用户选择（2026-10-12 用户确认）。选项在「语音 · 语音通话」页，分自动、本地、阿里云三种，只存本机、不同步，因为本地模型装在哪台设备上不一定。可选来源有：本地离线（应用内下载模型，默认采用 Silero VAD＋SenseVoice）、云端（用户自填密钥，首个接入阿里云 Paraformer 实时识别）、系统语音识别（兜底，待实现）。不 hook 第三方输入法。（2026-10-14 ADR0082 扩展：云端来源改为渠道商里配置的识别模型，逐家接流式协议。）
8. 通话属于语音插件，不单独做插件（2026-10-12 用户确认）。设置入口在语音插件页的「语音通话」子页面；全局或角色关掉语音时，聊天页不显示通话按钮。`sherpa_onnx` 锁定 1.13.8，并 override `web ^1.1`（Web 不是目标平台；1.13.4 的 Apple 原生库签名损坏，不可用）。
9. 通话中可以改用打字（2026-10-12 用户提出）：通话页「打字」把通话收成聊天页上的悬浮窗，输入从识别换成聊天输入框，话筒同时暂停，不让语音和文字同时输入。打的字只进这通电话：走和识别结果同一条回复链路（角色照常念出来），写进同一份逐句记录，挂断后随通话收进同一条通话气泡；不写 messages 表、不进主对话上下文。通话进行中，聊天列表把逐句记录投影成普通样子的临时气泡（`voice_call_live_` 前缀），长按只有复制和删除；删除只是不再显示，不改通话记录和摘要（2026-10-12 用户确认）。挂断存档后撤掉。为此通话的生命周期从通话页移到全局的 `ActiveVoiceCall`（`activeVoiceCallProvider`，同一时间一通），页面和悬浮窗都只是视图；直接离开通话页仍是挂断，收成悬浮窗后关掉聊天页或切到别的角色也挂断，不留看不见的电话。

## 代价与缺口

- 首句延迟高于端到端模型：实测从说完话到听见第一块音频约 2.5～3.1 秒（数据见[语音通话实测](../../../apps/aicove_flutter/docs/04_功能模块规范/语音通话/README.md)）。
- 逐句记录随气泡一起同步，长通话会让这条消息的块数据变大（每句几十字，几十句也只有几 KB）。2026-10-12 之前的通话记录仍只在原设备上。
- 回声消除、打断判定、真机网络下的延迟都还没有验证。
- 桌面端没有可用的回声消除：macOS 上 `record` 开启系统语音处理后输入全零（2026-10-12 实测），桌面通话只能半双工。以后做全双工要换方案，前置条件和可选方向见[语音通话 README「全双工前置条件」](../../../apps/aicove_flutter/docs/04_功能模块规范/语音通话/README.md)。
- 上下文快照只在接通时做一次，通话中记忆检索不会跟着用户的话更新。
- 挂断后、摘要写完之前，如果应用被杀，这通电话就不会有摘要。气泡和逐句记录都在，不会卡在中间状态。
