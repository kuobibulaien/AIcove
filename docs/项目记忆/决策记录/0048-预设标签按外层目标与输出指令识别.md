# 0048：预设标签按外层目标与输出指令识别

## 背景

ADR0046 只从预设正则推断标签，用户在小猫之神上发现两个漏识别：

- `<summary>`：预设把它当独立的「摘要」标签用，但我们把它列进了 HTML 结构的忽略名单。
- `<game>`：这是正文标签，只在提示词里写了「正文要用 `<game></game>` 标签包上」，没有任何正则会处理它。

另外，推断时把正则里出现的所有标签名都收集进来，导致播放器正则内层的 `<诗词意境>` 等被误当成独立标签。

方案经 Claude 与 Codex 分别统计真实预设后确定。用于统计的真实预设是本地第三方资料，不入库。

## 被否决的做法

- **扫描提示词里所有成对标签**：两边统计的误判率都在一半左右。`user`、`writing_style`、`output_method`、各类「××规范」都是写给模型看的输入结构，不是模型的输出。
- **未识别的标签一律自动折叠**：可能把正文或一段对白折起来，用户会以为内容丢了。

## 决定

识别证据的优先级：用户覆盖 > 正则的外层目标 > 提示词中明确的输出指令 > 内置常用名 > 聊天中发现（只提示，不自动生效）。

1. **正则只认外层目标**：
   - 先去掉前后查找断言（lookaround），再按顶层 `|` 拆成多个分支；同一个可选前缀在开、闭标签里同时取舍。
   - 成对出现、且不被另一对标签包住的标签算外层目标。
   - 如果前面有一个没写闭标签的开标签，它就是外壳。
   - 只有闭标签时，属于预填充写法，闭标签就是外壳。
   - `*?<tag>` 里的 `?` 是懒惰量词，不能当成命名分组跳过。
   - HTML 结构名单不再包含 `summary`、`details`：这两个名字两种用法都有，按它们在正则中所处的结构位置判断。
2. **正则名字是意图证据**：预设作者给正则起的名字里有「选项」，就判为选项；有「正文」，就判为正文。删除「至少 2 个按钮就算选项」的规则，因为播放器的按钮会造成误判。
3. **提示词只认包裹动作的宾语**：
   - 标签紧挨在「包裹 / 包上」之前，如 `由<Options>包裹`、`用<game></game>标签包上`、反引号写法 `` `<content>``</content>`进行包裹 ``。
   - 或标签紧跟在「放在 / 写在 / 输出到」之后。
   - 用同一句话里的关键词定呈现方式：选项 > 折叠类 > 正文。看不出来的列为「待确认」，不自动生效。
4. **聊天中发现**：
   - 统计范围：已生成完的回复里，出现在代码块之外、完整闭合、位于最外层、不在映射里、也不是 HTML 结构名的标签。
   - 模型回显的角色名（user、char 等）不提示。
   - 只记在内存里（`observedUnknownTagsProvider`，按会话绑定的预设分组），在标签页签中显示，用户归类后才写入 `tagDisplay`。
5. **无损兜底**：已生成完的回复里只剩一个未知外层标签、且它包着可见正文的一半以上时，去掉外壳按正文显示。其余情况保持原样，绝不自动折叠、隐藏或当成选项。流式过程中只使用发送前已确定的映射。
6. **代码块不识别**：围栏代码块和行内反引号中的 `<` 先换成占位符再扫描，示例代码不会被投影。

这一决定修订了 ADR0044 中「未知标签显示原样」的边界，只放开第 5 条的去壳情况。

## 验证与代价

- 本机 9 份以上真实预设回归：
  - 小猫之神：`think_nya~` 折叠、`summary` 摘要、`game` 正文、`options` 选项。
  - 云中梦：补出 `ztl`。
  - 双人成行：`content` 正文，播放器只认外层。
  - Kemini 的 `suot`、创世回廊的 `action`：判为选项。
  - `命运琥珀`、`诗词意境` 等误判已消除。
- 仓库测试使用自拟样例（`preset_tag_mapping_test.dart`、`tag_presentation_test.dart`、`tag_fold_bubble_test.dart`）。本机资料的回归测试在资料缺失时自动跳过。
- 代价：
  - 只靠提示词声明、又没有关键词的标签需要用户确认。
  - 「聊天中发现」重启后会清空。
  - 方括号语法（`[CAST]`）仍不识别。
- 回滚：撤回 `preset_tag_mapping.dart` 的外层与提示词识别、`tag_presentation.dart` 的代码屏蔽与兜底、列表与标签页的接入；没有数据迁移。
