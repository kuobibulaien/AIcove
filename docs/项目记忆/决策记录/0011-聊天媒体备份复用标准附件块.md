# 聊天媒体备份复用标准附件块

## 背景

用户要求在插件预设大改期间只修严重导入导出 bug，优先聊天记录和角色卡基本信息。真实 DB converter/projector 已复现：原本可还原的补图、语音，经过 `.aicove` 往返后消失。媒体可能在数据库 raw_payload 的多种保存形态中，而导出只读 message_blocks。

用户在获知“复用现有格式、原消息附件、可能不保留精确插入位置”的方案后回复“继续”，确认此次兼容修复。该决定只约束聊天媒体备份，不是插件预设架构或完整 raw 调用数据的迁移方案。

## 决定

1. 维持 `.aicove` v1 和 DB schema。只从 DB 已保存的原始材料读取图片/音频，白名单转换为现有标准 image/audio blocks，挂在原消息下并复用现有附件复制/导入逻辑。保留原消息 id、角色、正文、时间和会话归属，不修改源 DB。
2. 与正常聊天还原一致：非空 projectedMessages 优先，其次非空 supplementInsertOps，否则使用 pluginContents/toolAudioResults。这里只读取落库材料的媒体字段，不读当前 UI 列表，不导出缓存消息文本、整份 raw_payload、供应商配置、工具调用参数或预设。高优先级材料也约束既有 DB 媒体块，不能重新导出已被隐藏/替换的旧图；非 assistant 消息在无有效缓存表示时只使用自身标准块，不读取 assistant 专用补充材料。
3. 保留有意重复的媒体出现次数；对 message_blocks 已经表示的对应媒体按出现次数匹配，对相同源文件只复制一次。补充块 ID 在相同数据下稳定，内外 block id 与副本 messageId 都必须一致。
4. DB 的 sourceMessageId 保留导入来源用于合并；展示层 sourceMessageId 必须指向当前 raw 行，不可指回其它角色的原消息。补充文字块仅用原始 message.content，避免增加附件后遮掉正文。
5. 用户排除图片/音频时对应媒体块也排除，包括内嵌 base64；原始 message.content 不变。明确选中的媒体缺失或材料损坏则停止导出，不能默默丢掉后报成功。

## 备选与代价

- 不选整份 raw_payload 直出：包含与媒体无关或敏感的调用材料，也会扩大格式/安全/ID映射边界。
- 不选把 UI 气泡直接当新 raw 消息导出：会改变模型历史的唯一真相源及消息数量。
- 接受原始长回复的精确分段、媒体插入字符位置可能不保留；媒体作为原消息附件，通常位于正文之后。标准块并不等于完整还原思考、工具结果、话题摘要或所有插件文本。
- 不获取远端媒体，只保留已有远端地址；本地文件复制并校验字节，内嵌图片按原内容保存。旧版 v1 结构兼容，不代表所有历史发布版本均已实机验证。
- 读取和转换仍可能有大包内存/耗时成本，本次不是流式打包或性能改造。

## 验收门

真实 exporter → importer → DB converter → projector；四种落库形态的媒体存在、目标文件字节一致、正文/时间/角色不变、缺失文件失败、排除生效、来源敏感哨兵不出包、源 DB 不改、新建副本内外 ID 与展示引用一致、合并不重复。

代码：`apps/aicove_flutter/lib/src/features/backup/data/conversation_exporter.dart`、`conversation_importer.dart`、`features/chat/services/chat_frontend_message_projection_service.dart`。测试：`test/features/backup/chat_history_integrity_test.dart`。
