# 0079 主动回复：判断交给决策模型，代码编排固定流水线，聊天模型只写话

- 状态：accepted，2026-10-14 修订（暂不接入决策模型，见文末「修订」）。B1、B4 已实施，离线测试通过，DeepSeek 真实请求已验，实机未验
- 日期：2026-10-13
- 关联：ADR0060（后台收拢）、ADR0064（微内核）、Agent 运行时第二批 2f（前后台共用 `ProactiveReplyGenerator`）；方案见 `apps/aicove_flutter/docs/04_功能模块规范/主动关怀系统/12_判断与执行拆分方案_20261012.md`

## 背景

主动回复原来由一个「管家」后台 Agent 负责：多轮、带工具，自己判断要不要发、什么时候发，自己写旁白，调用预览工具让主聊天模型写候选，再自己审稿，最多重试 3 次。这样一来，判断和写作混在同一个循环里：工具里套着另一个模型，管家和写话的模型看到的上下文也不一样。每 5 分钟静默就要跑一次，大部分结论还是「不发」。提示词是早期由 GPT 写的，读起来不像人话。

## 备选

- **保持管家 Agent，只换提示词**：成本和结构问题都还在。
- **判断拆成能列出选项的题目，交给决策模型（jev）批量回答；代码编排固定步骤；只有要发的话由聊天模型写**：采用。
- **全部判断交给聊天模型，但不带工具**：作为没有配置决策模型时的兜底。

## 决定

1. **判断题目**：要不要发、哪一种（`stay_silent` / `continue_chat` / `check_in` / `new_topic`）、时间段（7 档）、用户是否要求提醒、深夜可否、是否和已有提醒重复。审稿是三道是非题。措辞只在 `ProactiveDecisionQuestions` 里写一份。
2. **谁来回答**：「判断模型」所选供应商的 `capabilities` 含 `decision` 时走 jev 原生接口（TypeSafe `/v1/systemone` 或 OpenRouter `/api/alpha/decisions`）；否则由聊天模型回答同一组题目，只回一行 JSON，并跳过审稿。
3. **拿不准就不打扰**：`kind` 低于 jev-use 默认阈值，或兜底 JSON 解析失败，都按沉默处理，安静 8 小时。用户一说话就提前唤醒。
4. **时间由代码换算**：时间段换成具体时刻，加随机偏移，再套免打扰时段。取消旁白，聊天模型只拿到发送时刻、间隔和开口方式的提示。
5. **预生成按发送时刻装配**：`prepareApiConfig(requestTime:)` 让时间感知插件描述发送那一刻。AI 触发器的 `preparedAt` 记为计划发送时刻，所以按时发送都算新鲜缓存。
6. **主动打电话**（方案 §4.8，B4 实施）：设置开关默认关闭；打开后由聊天模型结合人设，决定是否调用 `call_user` 工具。这是「判断归决策模型」原则的唯一例外，由用户在 2026-10-12 裁决。

## 代价

- 时间精度降到「档位加随机」，没法精确到「47 分钟后」。
- 使用 jev 时，最近 10 条聊天会发给所选的决策模型服务商，性质与选用聊天模型的服务商相同。
- 删除了「自定义判断提示词」设置，旧值不再读取。
- jev 对中文陪伴语境的判断准确度还没有用真实对话做过对照。

## 修订（2026-10-14）

用户裁决：决策模型目前只服务这一个功能，单独引入的成本（供应商类型、设置界面、未验证的请求路径、多一家服务商拿到聊天记录）大于收益。改为：

- 判断一律由「判断模型」选中的聊天模型回答同一组选择题。上面「决定 2」的 jev 分支、「决定 3」中的置信度阈值不再适用，解析失败仍按沉默处理。
- 审稿一步删除。预生成写完直接入库。
- 只保留 `ProactiveDecisionPort` 作为接口。决策模型有更多用途后再新增适配器接入，届时另写 ADR。
- 「代价」中关于 jev 的两条随之失效。

## B4 落地（2026-10-14）

「决定 6」按原样实施：打不打电话由聊天模型在预生成时结合人设决定，`call_user` 是请求里唯一的工具，调用只被记下，到点才响铃。三条底线护栏（免打扰除非 night_ok、同一时间一通、连续 2 通未接暂停）挡住时，开场白改作消息发出。没接留未接气泡、不补发消息。Android 后台用来电通知，iOS 不提供。真实请求验证了人设起作用（文静人设不打、古灵精怪人设打）。

Codex 审查首版后，来电状态改由本地 SQLite 账本 `proactive_calls` 统一管理：前台、后台、通知按钮三处共用，每步一条原子 SQL，保证全局只有一通在响、接听与未接只判一次、未接气泡只写一条；连续未接暂停由账本行推出，不存计数器。细节见方案 §13。
