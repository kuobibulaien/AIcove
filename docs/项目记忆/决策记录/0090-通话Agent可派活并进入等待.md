# 0090 通话 Agent 可以派活：先回话，再等结果，结果作为新一轮输入

- 状态：proposed（2026-10-17 用户提出方向；实现细节由 AI 拟定，待用户审阅；未施工）
- 日期：2026-10-17
- 关联：ADR0074（语音通话；本文修订其决定 2「去掉工具」）、ADR0088（聊天模型只派活）、ADR0084（按会话只由一台设备负责）、ADR0063（请求前提醒钩子）、ADR0044（语义标签注册表）

## 背景

ADR0074 让通话只保留记忆和时间感知两个插件，并去掉全部工具，所以通话里的角色说「我帮你查一下」只是嘴上说说，后台什么都没发生。挂断后的通话摘要也只看逐句转写，不知道有没有任务、做没做完。

用户的要求（2026-10-17）：通话 Agent 也要能唤起杂活 Agent。平常聊天不用；真要办事时，先回复用户，再把任务挂起等结果。等待期间用户照样可以接着聊；杂活 Agent 的返回值相当于又一轮输入，角色收到后接着聊。

## 备选

- **通话里同步等工具结果再开口**：一件杂活要几秒到几分钟，电话里干等不能接受。不采用。
- **通话不派活，挂断后交给文字聊天**：等于现状，用户已否决。
- **通话派活，结果作为新一轮输入**：采用。

## 决定

### 1. 工具面

- 通话请求只多一个工具：ADR0088 的 `delegate_task`（`start`／`reply`／`cancel`），定义、请求键和持久化规则与文字聊天相同。其他工具（提醒、生图等）仍不进通话。
- 启用条件与文字聊天一致：派活开关和杂活总开关开着、通话模型支持工具调用；角色授权给杂活 Agent 的能力照旧由角色决定，通话不另设一套权限。
- 通话约束提醒里加一条：只有用户明确要你办事、而且电话里答不了时才派活；派活前先用一句话告诉用户你去办了；结果没回来之前，不编造结果。

### 2. 先回话，再挂起

- 一次回复可以同时有台词和工具调用。台词照常流式切句、合成、播放；流结束时如果有 `delegate_task` 调用，宿主执行它（`start` 只做持久化，毫秒级），把调用和结果接进这通电话的请求历史。**不为工具结果再发一轮请求**，下一轮由用户说话或任务结果触发。
- 例外：这次回复只有工具调用、没有台词时，立即补发一轮，让角色说一句话，不让电话冷场。
- 派活失败（总开关关闭、持久化失败）时，工具结果如实写进历史，并立即补发一轮，让角色告诉用户没派成。

### 3. 等待状态

- 通话会话多一个「等待中的任务」集合，与听／想／说这几个音频阶段并列，不占用其中任何一个：等待期间照常听用户说话、照常回复。
- 每轮请求前，提醒钩子（ADR0063）把等待中的任务列给模型：任务说明的前几十个字、已等多久。用户问「好了没」时，模型能如实回答。
- 等待期间不自动催促，不自动说「还在查」。任务本身的超时和中断仍按 ADR0088 的状态机处理。
- 通话界面（含桌面小窗镜像）显示一个小的等待提示，可以点开查看任务；不阻止挂断。

### 4. 结果作为新一轮输入

- 通话进行期间，本会话的回执转告（ADR0088 第 6 条的 `relay`）**改为交给通话**，不写文字转告。范围是本会话所有需要转告的回执，包括通话前在文字聊天里派出的任务。
- 回执进入通话的输入队列。等到下一个轮次边界（角色说完、用户也没在说话），队列里的回执合成一轮输入，触发角色回复；这一轮用户没有说话，模型看到的是回执的简短系统事件（与文字聊天请求副本里的写法相同）。
- 用户正在说话时回执到达：等用户这一轮说完，回执和用户这句话一起作为同一轮输入（回执排在用户这句前面），只生成一次回复。
- 角色正在说话时回执到达：不打断，等这句说完再处理。
- 多个回执同时排队：合成一轮。
- `needs_input` 回执同样进入通话：角色在电话里转问用户，用户回答后由模型调用 `reply`。
- **转告完成的判定**：包含这条回执的那一轮开始生成，就算转告完成（`completeDelivery(delivered: true)`）。这一轮之后被用户打断，不重新转告：回执已经在这通电话的历史里，后面的轮次都看得到。

### 5. 挂断

- 挂断不取消任务。任务属于会话，不属于这通电话，继续在执行设备上跑。
- 挂断时还在输入队列里、没来得及进入生成的回执，**退回** ADR0088 的文字转告流程，由人设在文字聊天里发消息。
- 通话记录块新增 `callRecord.tasks`，记下这通电话里派出的每个任务和收到的每条回执，以及挂断时的状态（已在电话里转告／还在进行／已退回文字转告）。旧客户端不认识这个字段，会直接忽略，逐句记录照常显示。
- 气泡给模型看的文字里，由代码（不是摘要模型）追加一行确定的任务状态，例如「电话里派出的任务：查明天的天气（挂断时还没完成，结果会另行转告）」。这样文字聊天的角色一定知道有任务没做完，不依赖摘要模型有没有写进去。
- 通话摘要 Agent 的输入也带上任务事件，让摘要的叙述与这一行一致。

### 6. 多设备

- 接通即把本机登记为该会话的负责设备（ADR0084 的 `claim`），与用户发一条消息同等。这样通话期间到达的回执一定由正在通话的设备认领。
- 执行权仍在派活的设备上（ADR0088 第 6 条），通话派的活就在通话设备上跑。

## 代价

- 通话请求带上工具定义，提示词变长，首字延迟可能增加，要实测。思考仍关闭。
- 部分模型或预设不支持工具调用，这些情况下通话里仍然不能派活。
- 任务说明由模型根据语音识别的转写来写，识别错字会带进任务说明。
- 回执在用户沉默时触发角色主动开口，可能打断用户的思路；等待期间用户挂断，结果只能回到文字聊天。
- 只回话、不补轮的做法要求模型把台词放在工具调用之前或同一回复里；只给工具调用的模型每次派活都会多一轮延迟。

## 验收门

1. 用户在电话里提出要查的事：角色先说一句话，同一轮里任务已持久化；没有额外的请求轮次（只有工具调用、没有台词的情况除外）。
2. 等待期间用户继续聊天，回复正常，不受任务影响；问「好了没」时，角色能说出在等什么。
3. 回执在用户沉默、用户正在说话、角色正在说话三种时机到达，行为分别符合第 4 条；两条回执同时到达只生成一轮。
4. 通话期间到达的回执不生成文字转告；挂断前没来得及进入生成的回执，挂断后在文字聊天里转告一次，不重复、不丢。
5. 挂断时有任务没完成：通话气泡给模型看的文字里，有代码写入的任务状态行；任务之后完成，按 ADR0088 在文字聊天里转告。
6. 旧客户端读取带 `callRecord.tasks` 的通话气泡，不报错，逐句记录正常显示。
7. 通话模型不支持工具调用时，通话行为与现在一致。
