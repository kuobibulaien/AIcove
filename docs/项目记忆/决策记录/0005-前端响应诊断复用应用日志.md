# 前端响应诊断复用应用日志

## 背景

用户确认补齐手机聊天前端响应日志，并要求日志中心更自然易读。已有 AppLogger、ApiLogger、TraceStore，不需要再造日志数据库。原来的 MESSAGE_DELIVERED 只证明业务投递完成；滚动诊断仅在 debugPrint，无法从手机日志中心追踪页面、气泡与播放器状态。

## 决定

1. 低频前端事件通过 `FrontendDiagnosticsPort` 进入 `FrontendDiagnosticsService`，使用既有 AppLogger 的内存、文件、历史清理路径；不变更聊天 DB、不上传遥测、不引入新依赖。单轮导出通过 `TraceExportPort` 调用已有 TraceExportService。
2. 页面实例/发送操作有独立 operationId 与 Stopwatch，关联既有 conversationId、turnId、traceId、messageId；不改变原 sessionId 代表联系人会话的语义。发送时绑定本轮 Trace，流式消息创建时固定关联，旧气泡不跟随“最近会话”漂移。AppLogger.startTrace 可接收既有 traceId，模型直连与主发送链路统一编号。
3. 只采集关键状态切换：页面打开/数据到达/布局/离开、提交发送/本轮结束或失败/中断、首段文字布局、手势接管与回底请求、语音资源/播放器就绪与播放。`firstTextLayout` 校验当前路由、生命周期及视口相交，按操作去重；postFrame 是布局证据，绝不宣称 GPU 已出帧、用户已读或已听到声音。发送耗时从页面正式提交开始，不含前置确认弹窗。
4. 写入先排微任务，防止 build 中同步通知 UI；队列上限 128、待绑定发送 32、轮次 128、消息关联 512、去重键 2048。队列丢弃量有提示，采集异常不得阻断业务。事件不接受任意正文或 URL 字段，错误仅记录类型与 package/dart 代码位置，不记录 error.toString()；原框架/平台错误处理继续执行。
5. 日志中心保留现有分类索引，新“前端”枚举追加；中文摘要、较大字号、按需展开完整技术详情。“只看异常”同样过滤成功网络请求，并在窄屏优先露出。对话页导出选中 Trace 的 events/apiLogs/payload/appLogs；应用日志优先按显式 traceId 匹配，再用 operationId 找回绑定前的提交事件，禁止同一原消息的另一次 retry 混入。原无 traceId 的 API 日志仍按 sessionId/turnId 兼容读取，无法追溯补齐过去不存在的前端事件。

## 代价与边界

- 这是低频响应日志，不是逐帧 FrameTiming 性能系统。帧指标留在原性能观测任务，不逐帧/逐 token 写 AppLogger 或 TraceStore。
- 关联缓存只在当前进程有界保留；历史音频无本轮映射时创建独立播放操作，不猜测属于哪一轮。普通“全部/前端/网络/应用”页显示当前内存窗口，旧记录在历史日志；对话 Trace 读取最近七天。
- AppLogger 原有异步落盘仍不是崩溃零丢失保证，本批未改成事务日志，也没有原生进程崩溃/系统 ANR 采集。未开启诊断时不补记缺失事件。
- 顶部更多菜单可关闭“记录前端响应（本次运行）”；撤回本批增量即可回滚，无数据迁移或删除。

## 验收门

- 单测覆盖异步通知、绑定与重试隔离、去重/有界队列、开关、错误隐私、全局处理器转发、关联应用日志导出。
- Widget 测试覆盖首段文字与视口外不误报、320/390/1200px 中文筛选与折叠、导出按钮真实调用端口。
- 已在 PKX110 真机打开空会话再返回：四个前端事件已进入手机文件和日志中心，首值 137ms、布局 174ms；仅用于证明采集路径，不当作性能基准。真实模型生成、流式音频和性能开销仍需对应场景实测。
