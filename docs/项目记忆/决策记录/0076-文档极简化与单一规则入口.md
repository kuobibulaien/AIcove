# 0076：文档极简化，AGENTS.md 为唯一规则入口

## 背景

每次会话固定加载 AGENTS.md（13KB）和 hook 注入的项目记忆 README（16KB）。README 的「当前重点」写成了按日期追加的流水账；同一条规则分散在多处（全端界面 4 处、文档分工 3 处、项目记忆写入规则 2 处），而且口径不一致；发布脚本的内部细节放在 AGENTS.md 里，每个会话都要读一遍。

## 决定

- 规则只有一个入口：根 `AGENTS.md`，负责执行方式、授权和文档地图，并写明「什么不写文档」。架构约束和验证流程归 `DEVELOPMENT.md`，命令和发布流程归 `tool/DIAGNOSTICS.md`，其他地方只放链接。
- 项目记忆 README 只放当前状态：状态变化时原地改写对应行，过程写进 ADR、需求日志或模块文档。hook 在页面超过 6000 字时注入警告（机械门禁，不靠自觉）。
- hook 只注入已写结果的最近需求，不再注入「（待补）」条目。
- 完成使命的方案和一次性排查一律移入 `05_历史归档/<日期>_<主题>/`；`文档治理规则.md` 并入 AGENTS「文档地图」后删除。

## 备选

- 照搬 write-notes-like-deepseek 技能（按状态和类别分目录、SHA-256 封印、校验脚本、看板）：约束最强，但这是给多人、多分支、高 PR 量的仓库设计的，单人开发用不上；它本身的体量（约 45KB）还超过了要删掉的部分，而且需要迁移 76 篇 ADR。只借用了其中「事实原地改、不追加流水账」「明确不写什么」「能机械检查的就别写成散文」三条原则。
- 只删冗余、不改结构：成本最低，但规则分散的问题会再长回来。

## 代价

- 每次会话固定上下文从约 29.5KB 降到约 11KB。
- 被移动的文档链接已用脚本批量重写；归档目录里的历史文档不再维护链接。
