# 0100：表情看图打标，AI 只说情绪、应用挑图

关联：ADR0078（表情包库）、ADR0095（表情语义标签）、ADR0096（表情导入，第 6 条「不做看图打标」由本 ADR 接续）、ADR0098（工作区读图）。

## 背景

表情只靠文件名起标签。微信导出的素材大多是纯数字文件名，492 张里只有 36 张有名字，其余都是「未标注」，AI 用不上。即使有标签，`StickerRegistry.getByTag` 也是在同一标签下随机挑图，挑出来的不一定贴切。

另外，提示词里的 `{tags}` 列的是库里全部标签。如果放任模型随便起标签，库越大，这个列表越长，同一种情绪还会冒出「开心／高兴／乐」好几种写法。

用户 2026-10-22 定下方向：看图打标，标签收敛到固定词表，不搭向量数据库，不做人工标注评测集，打完标交给用户过目。

## 决定

1. **固定情绪词表（50 个）**，是 `tags` 唯一的取值范围：
   - 问候：早安、晚安、打招呼、再见
   - 回应：好的、收到、拒绝、谢谢、道歉、点赞
   - 正向：开心、大笑、得意、兴奋、期待、喜欢、害羞、撒娇、感动、庆祝
   - 负向：委屈、难过、大哭、失落、生气、怨念、无语、嫌弃、鄙视、无奈
   - 惊疑：震惊、疑惑、尴尬、害怕、紧张、着急
   - 互动：安慰、抱抱、夸夸、加油、求助、调皮
   - 状态：累了、困了、摸鱼、忙碌、饿了、发呆、思考、等待

   现有 `_synonymGroups` 里有几组会把词表词合并掉（如「委屈」归入「难过」组，「困了」归入「晚安」组），实施时改为每个词表词各自为一组，同义词只映射到词表词。
2. **每张表情存五个字段**：
   - `tags`：从词表选 1～2 个，进提示词。
   - `usage`：适合什么时候发。
   - `text`：图上的配字，没有就留空。
   - `description`：一句话描述画面，动图写出动作。
   - `keywords`：自由补的特色词，0～3 个。

   后四项只用来挑图，不进提示词，也不进 `_tagIndex`。`library.json` 增加 `usage`、`text`、`keywords` 三个可选字段，旧清单读取时缺省为空，不需要迁移。
3. **打标流程**：
   - 动图抽首、中、尾 3 帧，拼成一条横图；静图缩到 384px 以内。
   - 每次请求放多张独立的图，不拼九宫格，避免缩小后配字看不清、编号对错格。
   - 结果按图片内容哈希（`sha256` 前 32 位，与 `StickerLibrary` 一致）缓存，同一张图只标一次。
   - 有文件名的图，把文件名作为提示一起给模型；模型拿不准时写 `confidence: low`，由用户在界面上复核。
4. **AI 侧语法**：`<sticker tag="词表词" hint="想表达的画面"/>`，`hint` 可省。提示词 `{tags}` 只列词表里库中实际有图的词。
5. **应用挑图**：先在 `tag` 对应的那一类里，按 `hint` 和 `usage`／`text`／`description`／`keywords` 的字面重合度（中文二元分词）挑分数最高的一张，同分时随机，并避开最近发过的几张。`tag` 不在词表里时，对全库做同样的打分兜底。
6. **不上向量数据库**。字面匹配效果不够时，再把向量存成本地文件、在内存里算余弦相似度，另立决定。
7. **素材分发**（用户 2026-10-22 定）：
   - 静图 291 张（5 个套组，约 18MB，原像素）随应用内置在 `assets/stickers/builtin/`。首次加载时 `StickerLibrary.seedBuiltin` 把它们导入成普通套组，并在清单里记 `builtinSeeded`；之后用户删改都不会再放回来。
   - 动图 201 张（约 42MB）不进安装包，同一个 ZIP 放在两处，都是 v1 发行版，内容一致：GitHub `kuobibulaien/AIcove-stickers` 和 Gitee `koubibulaien/AIcove-stickers`。不用网盘，不承担费用。在表情包设置页「可选下载」一键下载并导入。
   - 下载前同时探测两个源（`sticker_pack_download.dart`）：能连上的排前面；设备在东八区时 Gitee 优先，否则按延迟排序。下载失败、超时，或者拿到的不是 ZIP（比如被跳到登录页），就自动换另一个源，两个都失败时把两边的错误一起报出来。
   - 套组文件夹带 `labels.json`（套组名、原作者、每张图的标签与描述）。ZIP 导入同样认这个文件。
   - 套组新增可选的 `author` 字段，显示在套组列表和套组页。页面底部附声明：「所有表情包来源于微信公众号公开表情，已标注原作者，如有侵权请联系删除。」
   - 素材未获授权。用户已知情，并要求随应用分发，这一条覆盖 AGENTS.md「第三方抓取资料只存本地」的默认做法；收到侵权投诉时删除对应套组和 Release。

## 代价

- 50 个词可能覆盖不全，比如反话梗、地域梗只能放进 `keywords`，AI 没法直接点名要这类图。
- 打标依赖用户配置的视觉模型和 Key；没有视觉模型的用户仍只有文件名标签。
- 不做人工标注评测集，打标质量由用户抽查判断，不能给出准确率数字。
- 安装包增加约 18MB。
- 「在国内」只靠时区判断，港澳台和新加坡等东八区地区也会先走 Gitee，靠兜底换源。Gitee 新建的仓库默认是私有的，已通过接口改为公开；以后 Gitee 如果审核下架，就只剩 GitHub 可用。
- 换版本时两处都要上传，并改 `gifStickerPackMirrors` 里的地址。
- 内置套组目前只把 `tags` 和 `description` 写进库；`usage`／`text`／`keywords` 留在 `labels.json` 里，等挑图实现后再读。

## 验收门

1. 内置素材（492 张）全部打标，结果交用户过目；`tags` 全部落在词表内。
2. 挑图打分有离线测试：同一标签下 `hint` 能命中对应的图；`tag` 不在词表时有兜底。
3. 真实模型下，AI 输出的 `tag` 都落在词表内。
