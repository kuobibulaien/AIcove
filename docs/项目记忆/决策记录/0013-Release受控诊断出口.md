# 0013 · Release 受控诊断出口

日期：2026-09-10。用户要求补齐正式版导出与电脑 Agent 读取，保留 Release 性能。

决定：新增 DiagnosticAccessPort，手机文件导出与限时本机HTTP读取共用同一过滤快照。服务默认关闭、只监听IPv4 loopback、随机256位凭证、30分钟到期；电脑经已授权ADB建立临时端口转发，复用现有collect_diagnostics.py的关联闭包、构建映射与摘要，并支持离线手机JSON包。

边界：不改变应用可调试标志，不依赖root/run-as，不读数据库、聊天全文、附件或payload；不新增系统权限、不持久化凭证、不部署云端、不增加后台保活。扫描仅在请求时在工作isolate执行。旧完整对话导出保留，不能混同受控诊断包。

备选：持续镜像至外部存储会增加写盘和外泄面；公共网络日志服务需要额外授权/配对治理；只做手动导出无法满足电脑自动抓取。因此采用限时loopback通道。

代价：手机每次会话需开启一次并给电脑临时命令；进程重启/到期后重新开启。ADB仍用于传输但不截图、不访问私有目录。系统暂停应用时不可保证实时可达。快照有界且非原子，覆盖限制保留在summary的sourceCoverage；不把未写盘事件视作不存在。

回滚：关闭读取开关立即释放服务；撤回入口、端口实现及脚本新增分支，旧日志与生成业务不受影响。无数据/schema迁移。操作与验收见客户端tool/DIAGNOSTICS.md及需求日志。

## 2026-09-10 用户变更：自动持续开启

用户明确要求“允许电脑读取，直接自动开启，不需要关闭”。本节替代上文默认关闭、30分钟到期和不持久化凭证的旧决定：应用主入口在runApp后自动启动服务，不等待诊断页面；移除到期计时与页面开关，改为状态显示。随机凭证通过已有FlutterSecureStorage保存，使重启后原电脑命令继续有效；安全存储或端口暂不可用时每5秒重试，不阻塞首屏。loopback、凭证校验、过滤字段和按需快照边界保留。进程被系统终止时服务自然结束，再次打开应用自动恢复，不额外增加后台保活。
