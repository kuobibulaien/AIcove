# 0107：Agent 工具默认无需审批

## 背景

用户要求内置 Agent 像 Pi 一样默认直接执行，不再为每条 shell 命令手动审批。原「修改前每次问我」关闭后，review 仍走审核模型，major 仍找用户；shell 与扩展安装还通过工具标记和 handler 强制真人批准，导致关掉开关也不能直接执行。

## 决定

- AIcove酱默认允许本轮已装配的所有工具，不走审核模型、不弹审批卡；包含 shell、JavaScript、设置／角色修改、删除、表情导入、本地扩展安装、读取可见角色的聊天和记忆。
- 保留本机「修改前每次问我」作为用户主动开启的模式，默认关闭；既有显式开启值保留，运行中切换下一次调用即生效。该模式下非只读调用逐次确认，其他角色正文仍沿用原按角色授权机制。
- shell 和扩展安装不再声明 `requiresHumanApproval`，handler 接受当前工具策略的 `allowed`；人工模式的 `approved` 仍须真人批准标记。未经过工具策略的直接 handler 调用不能启动 shell 或安装。
- 默认策略在当前 `ToolCallScope` 标明免审批，正文读取和开启外部插件遵循该策略，不把自动放行伪装为真人授权，也不写入永久正文读取授权；插件修改仍检查快照与写入冲突。
- 工具装配范围、工作区授权、隐私空间隔离、系统沙盒、Key 输入卡片、参数校验、脱敏、取消／超时、文件锁及撤销规则保持原契约。普通角色与后台任务不会因此新获得 shell。
- 同步工具描述、助手系统指引、设置资料库及技能返回提示，避免模型继续按旧文案停下来索要确认。

本决定取代 0073、0093 中默认分级审核与逐次确认的规则，以及 0096 的表情导入确认、0098 的 shell 逐条确认、0103 的安装逐次真人确认条款；其余能力与授权边界不变。

## 代价

默认模式下，删除、shell 和扩展安装也直接执行；其中原本不可撤销的操作仍不可撤销。需要逐次确认的用户可主动开启原开关。

## 验证

- 修复前先复现默认风险档仍 ask、无审批通道 shell 不执行两项失败。
- 225 项相关离线回归通过：默认 shell 实际执行并写入文件、扩展实际安装、可见聊天读取、外部插件开启、运行中切换手动模式，以及拒绝／取消／超时／工作区和隐私边界。
- DeepSeek Flash 真实请求修改角色称呼通过，工具实际写入，审核模型调用与用户审批均为 0。
- 改动范围静态检查无 error／warning，17 条既有 info；技能提示相关静态检查无问题。
- Mac Debug 管理器发现旧会话 PID 启动时间／命令／目录不匹配，拒绝接管；未绕过管理器，应用内热加载及端到端、手机与 Windows 未验。
