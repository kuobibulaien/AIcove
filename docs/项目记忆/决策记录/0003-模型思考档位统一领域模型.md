# 模型思考档位：统一 canonical 档位 + 按模型查表翻译

## 背景

选模型时无法设置思考强度（reasoning effort / thinking budget），只能吃上游默认。三家供应商的参数形态互不兼容：

| 方案 | 字段 | 取值 |
|---|---|---|
| OpenAI 兼容 | `reasoning_effort` | 枚举字符串，各代可用档不同（gpt-5 有 `minimal` 无 `off`；gpt-5.1 起有 `none`；gpt-5.2+ 多 `xhigh`；o 系只有 low/medium/high） |
| Claude 4.6+ | `output_config.effort` | 枚举，另需 `thinking.type=adaptive` |
| Claude 4.5 及更早 | `thinking.budget_tokens` | 整数 token 预算，须 < `max_tokens` |
| Gemini 3.x | `thinkingConfig.thinkingLevel` | 大写枚举 |
| Gemini 2.5 | `thinkingConfig.thinkingBudget` | 整数，0 表示关 |

同时用户要求：档位按会话隔离，切模型时沿用「该会话上次对这个模型的设置」；档位口径以上游为准，上游没有再用自研四档。

## 备选

1. 每个 adapter 各自存各自的字段（UI 直接写 `reasoning_effort` / `budget_tokens`）。持久层被上游形态绑死，换模型即失配。
2. 只做自研四档（低/中/高/关），统一映射到三家。gpt-5.2 的 `xhigh`、gemini 的 `MINIMAL` 等上游真实能力被抹平，与用户口径相反。
3. 统一 canonical 枚举 + 按「供应商 × 模型 id」查表决定可用档与翻译方案。

## 决定

采用方案 3：

- **canonical 枚举** `ThinkingLevel`：`auto/off/minimal/low/medium/high/xhigh/max`，序号即强弱序；`auto` 表示不发任何 thinking 参数。持久层与 UI 只认这套值。
  实现：[thinking_level.dart](../../apps/aicove_flutter/lib/src/core/api/thinking/thinking_level.dart)
- **查表** `resolveThinkingOptions(providerType, modelId)` 返回该模型的可用档集合 + `ThinkingScheme`（openaiEffort / claudeEffort / claudeBudget / geminiLevel / geminiBudget / generic）。未命中退到该供应商兜底方案，宁可保守也不报错。
  实现：[thinking_level_catalog.dart](../../apps/aicove_flutter/lib/src/core/api/thinking/thinking_level_catalog.dart)
- **翻译在 adapter 边界**：各 `ProviderAdapter` 按 scheme 写请求体（Claude effort 方案同时写 `thinking.type=adaptive`；budget 方案在 `max_tokens` 不够时整体跳过；Gemini 的 `thinkingLevel` 与 `thinkingBudget` 互斥，不同时出现）。
- **优先级**：会话覆盖 > 模型默认（`ModelConfig.thinkingLevel`）> ST 预设 `reasoning_effort` > 软件默认。显式来源先经 `coerce` 收敛到该模型可用集合（`off` 不可用取最低档；其余取序号最近、同距取高档）。
  实现：[thinking_level_resolver.dart](../../apps/aicove_flutter/lib/src/core/api/thinking/thinking_level_resolver.dart)
- **软件默认档位 = 能关就关，不能关取最低档**（用户 2026-09-04 裁决）。例外：`generic`（未识别的 OpenAI 兼容模型）无法确认上游是否接受 `none`，保持 `auto` 不发参数，避免第三方中转站 400。
- **会话隔离**：会话覆盖存 `conversations.thinkingLevels`，结构是 `模型 key → 档位` 的 map（DB schema v15，nullable text，空 map 存 null）。因此同一会话内换模型自动沿用该模型上次的设置，跨会话互不影响；云同步走 `thinking_levels` 字段。

## 代价

- 查表是静态正则匹配模型 id，新模型发布后需要手动补表；补表前落到该供应商兜底档位，功能不坏但档位可能少。
- canonical 八档与上游档位并非一一对应，`coerce` 的降级是有损的（xhigh → high 等），UI 需显示实际生效档位与来源。
- 会话级 map 随模型数量增长，但只存被显式改过的模型，量级可忽略。
