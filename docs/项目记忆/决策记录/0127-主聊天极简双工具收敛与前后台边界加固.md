# 0127：主聊天极简双工具收敛与前后台边界加固

补充升级 [0124](0124-聊天模式三合一为统一路由层与后台执行架构.md)。

## 背景

ADR0124 将角色工作模式三合一为主对话路由层＋后台执行架构，并参考 DeepSeek Super Agent 理念做前后台分层，但在陪伴聊天场景与最小表面约束上仍存在四类设计冗余与隐患：

1. **伴侣提醒被误归入后台办事且拆成 4 个工具**：`trigger` 被列入 `isTaskBackendPluginId`，导致普通陪聊角色一旦开启 AI 设提醒就被迫挂上后台路由 `delegate_task`／`steer_task`，而提醒本身拆成 `create_reminder` / `list_reminders` / `search_reminders` / `delete_reminder` 4 个碎片工具。
2. **后台管理存在双工具歧义与 `needsInput` 唤醒黑洞**：前台同时暴露 `delegate_task` 和 `steer_task`，模型容易混淆 `reply` 与 `steer_task`；且 `TaskAgentService.steer()` 在 `needsInput` 状态下仅追加写入 checkpoint，未消费 open question、未迁移回 `queued` 也未触发 `pump()`，导致追问挂起卡死。
3. **非管家角色前台被注入大段 UI 组件与设置键说明**：开启 `aicove_assistant` 的自定义或剧情角色（如内置漫画家 `preset_mangaka`）在前台系统提示中被 `AssistantRouterRequestScope` 无差别塞入完整的交互组件目录与 40+ 个 `settings` 键清单，严重分散聊天注意力并抬高误调工具倾向。
4. **后台任务控制工具在工作区脚本开启时被误隐藏**：`assembleCodemodeTools` 未把运行时内置的 `ask_user` 与 `submit_reference_material` 列入 `direct`，开启工作区脚本时它们被降级进 `codemode`。

## 决定

对齐 DeepSeek Harness 极简模式「合并多工具＋剔除系统噪音」思路，划清主对话只服务于**直接陪伴聊天**与**管理后台**的极简边界：

1. **主聊天固定为最多 2 个多动作聚合工具（非必要不调用）**：
   - **伴侣提醒工具 `reminder`**：将 `TriggerPlugin` 4 个工具合并为单一 `reminder`（`action: create | list | delete`），并从 `isTaskBackendPluginId` 迁回主对话直出（仅在当前会话 `enabledForConversation` 为真且模型允许工具调用时挂载）。纯陪聊角色未开其他后台能力时不再因提醒开关挂载 `delegate_task`。
   - **后台路由工具 `delegate_task`**：移除独立 `steer_task` 工具，将其能力收编进 `delegate_task(action: start | reply | cancel)`（兼容 `steer` / `follow_up` 别名与 `instruction` / `answer` 兜底）；在长对话中仅当当前会话存在 `queued` / `running` / `needs_input` 活跃任务时注入单行 `<system-reminder>` 状态摘要（空闲时 0 字符）。
   - **历史旧工具兼容隔离**：`ChatPluginContextPolicy.retiredTools` 新增 `steer_task` 与 4 个旧提醒工具名，`TriggerPlugin.contentTags` 声明 `reminder` 归属，`delegateTaskContentTags` 声明 `delegate_task` 归属，成对剥离未激活插件工具与历史残余工具。
2. **修复 `needsInput` 追问卡死并补齐只读契约锁**：
   - `DelegateTaskPort.reply` 对 `needsInput` 任务走 `service.reply`，对 `queued` / `running` 任务走 `service.steer`；`TaskAgentService.steer` 遇 `needsInput` 时消费等待态问题并迁移为 `queued` 后立即 `pump()` 唤醒。
   - `delegate_task(action=start)` 新增可选 `read_only` 布尔锁（通过 `TaskCheckpoint.read_only` 持久化），为 `true` 时后端强制剥离 `ToolEffect.write` 工具、关闭工作区 `bash`、使 `aicove_role` 退化为仅 `list` / `read`，防止查询/取材任务误改用户数据。
3. **前台系统提示词去噪与「非必要不调用」硬约束**：
   - `AssistantRouterRequestScope` 仅对 `kAicoveAssistantId`（AIcove酱）注入 `uiBlockPrompt()` 与快捷面板目录，非 AIcove酱角色（含内置漫画家）仅保留 2 行极简路由提示，并清理快捷面板示例里前台不存在的 `aicove_list_roles` 引用。
   - 收紧 `delegate_task`、`reminder`、`mangaka.md`、`aicove_assistant.md` 边界：日常闲聊、情绪倾诉、角色扮演、聊天中顺嘴提到的现实话题一律直接聊天，严禁自发搜索或派活；纯查资料／取材优先用 `read_only: true`。
4. **修复后台控制工具直出**：`assembleCodemodeTools` 的 `direct` 集合补全 `ask_user` 与 `submit_reference_material`。

## 代价

- 主聊天若同时开启提醒与后台能力，最多暴露 `reminder` 和 `delegate_task` 两个多动作工具（如开稳定模式生图则保留 `draw_image`）；部分弱指令遵循的小模型初次使用多动作参数时若漏传或混用字段，依赖工具描述与 handler 参数兜底提示纠偏，需结合常用模型实测几轮日常闲聊验证触发克制度。
