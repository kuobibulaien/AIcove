# 0125：酒馆预设统一单飞传输封套与宿主能力后置隔离

升级 [0043](0043-预设传输工具与业务工具作用域.md)、[0121](0121-统一长驻异步JS运行底座与开放预设外部脚本.md)。

## 背景

ADR0121 开放预设脚本直接运行后，旧兼容层仍保留按预设 ID 嗅探的宿主仿写壳与混合拼装路径，在实际运行「我即浪潮 1112」＋「漫画家」等组合时暴露出四类结构性错位：

1. **按预设写特例壳导致双轨冲突**：`WaveTransportConfig`、`KeminiTransportConfig`、`wave_context.js` 与 `transport.js` 内的 `prepareAte`／小说角色名硬编码按固定 UUID 分流；浪潮 1112 新脚本（`actual_content`）未命中旧 ID 后落入通用脚本分支，而宿主把 `prepare` 与 `response` 拆成两次独立的假 `fetch('/api/backends/chat-completions/generate')` 调用，导致脚本挂在当次 `fetch` 闭包上的流式重写器（`actual_content -> delta.content`）在回复阶段丢失，协议工具泄漏进 `AgentLoop` 触发报错重试循环。
2. **宿主能力与提醒混进聊天楼层（`chatHistory`）**：`SillyTavernPresetAssembler` 把 `runtime.system` 插在 `chatHistory` 头部，`SystemReminderService.normalizeReminderPlacement` 又把 `<system-reminder>` 挪进最后一条用户楼层，导致预设脚本调 `getChatMessages()` 搬运历史时把 AIcove 工具／绘图说明与本轮提醒一并搬走或污染预设提示词锚点。
3. **预设传输工具与宿主业务工具权限耦合**：导出自酒馆的抗截断预设（如 `Kemini_Dramatron_v3.1`、`kunlun_linux_1.6`）普遍保存 `function_calling = false`（在酒馆中仅关闭内置 `ToolManager`，不拦截脚本改写 `window.fetch`），而部分隐身正文承载工具（`stealth: true`）亦不应进入主对话 `AgentLoop` 落库。

## 决定

1. **删除按预设嗅探的仿写壳，统一执行预设原生脚本**：
   - 删除 `wave_transport_config.dart`、`kemini_transport_config.dart`、`assets/preset_runtime/wave_context.js`，并清除 `transport.js` 中按脚本特征硬编码的 `prepareAte`、特定小说角色名与本地路径字面量。
   - 所有酒馆预设的 `tavern_helper.scripts` 与 `SPreset` 统一在 `QuickJsPresetRuntime` 内按原生脚本执行，不再维护预设名／脚本 UUID 白名单或宿主克隆版协议。
2. **单飞挂起式 `fetch` 传输封套（Single-Flight Wire Envelope）**：
   - `prepare` 阶段触发 `GENERATION_STARTED -> GENERATION_AFTER_COMMANDS -> GENERATE_AFTER_DATA -> CHAT_COMPLETION_PROMPT_READY -> CHAT_COMPLETION_SETTINGS_READY` 后发起唯一一次内部 `window.fetch('/api/backends/chat-completions/generate')`，在 `baseFetch` 捕获最终 wire 请求体后挂起该 Promise。
   - 模型流式分片（`preview`）与完整回包（`response`）统一作为 SSE／JSON 响应流喂回**同一个**挂起的 `fetch` Promise，使预设脚本在 `window.fetch` 闭包内挂载的流式重写器（如浪潮 1112 `actual_content`、Kemini `emit_complete_response_*`、昆仑 `dispatch_stream_payload_*`）原样运行并吐出解包后的 `delta.content` 与剩余业务 `tool_calls`。
   - 请求改写期间通过 `PresetImageReferences.preserveImages` 保护多模态图片引用不被纯文本脚本投影丢弃；`GeminiAdapter` 将请求级 `toolChoice == 'required'` 映射为 `functionCallingConfig.mode = 'ANY'`。
3. **传输封套工具与业务工具严格分层及权限解耦**：
   - 凡由 `window.fetch` 拦截层注入的仅存在于 wire 请求体的工具、或经 `ToolManager` 注册且 `stealth: true`／无业务 `action` 的工具，统一归入 `transportTools`：仅用于单轮正文传输与流式预览，在 `response` 阶段按调用下标消费，永不进入 `AgentLoop`、不写 `ToolBlock`、不落库。
   - 宿主业务工具（`delegate_task`、`steer_task`、`draw_image`）与 `SPreset`／非隐身 `ToolManager` 动作工具归入业务工具链。
   - 对齐酒馆原生语义与 ADR0043：`preset.function_calling === false` 仅关闭 `ToolManager`、`canPerformToolCalls()` 与业务工具，不剥离预设脚本通过 `window.fetch` 自行注入的抗截断传输工具；仅当模型本身不支持或禁用工具（`!modelSupportsTools`）时才剥离全部 wire 工具并回退纯文本。
4. **AIcove 宿主能力后置区与内部楼层溯源隔离**：
   - 绑定酒馆预设时，`SillyTavernPresetAssembler` 将 `runtime.system`、未显式占位的兜底 `runtime.drawingPrompt` 及 `protectedRuntimeMessages`（`<system-reminder>`）统一放置在预设全部条目之后、`assistantPrefill` 之前的**宿主后置区**，且 `ChatSendBackendService` 不再对绑定预设的请求执行 `normalizeReminderPlacement` 把提醒塞回用户消息。
   - 组装器通过内部溯源标记 `__isHistory`（`presetHistoryMarker`）精确标识真实聊天历史楼层供 `getChatMessages()` 提取，在脚本进入前及 `ToolMedia.wire`、`ToolMedia.log`、`buildContextPreview`、`renderedContextTokens` 中统一剥离，确保绝不外泄至供应商接口、界面预览或虚增 token 估算。

## 代价

- 预设脚本在单轮请求期间持有一个挂起的内部 `fetch` 流上下文，流式回退非流式（`reset(false)`）时需取消旧单飞流并在快照监听器上重放当轮准备阶段，换取所有闭包型 `window.fetch` 预设脚本的零特例兼容。
