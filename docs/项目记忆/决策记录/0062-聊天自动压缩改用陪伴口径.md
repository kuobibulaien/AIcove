# 0062 聊天自动压缩改用陪伴口径

- 状态：accepted（代码未实施）
- 日期：2026-10-07
- 关联：ADR0038（记忆与上下文两层）、ADR0061（旧工具结果按时间清理）

## 背景

`features/context/data/background_context_summarizer.dart` 中，自动压缩 Agent `local.automatic_context` 的目标是“保留当前目标、已完成步骤、未完成事项、关键结论……工具执行结果”，输出契约固定五栏 `background／preferences／progress／pending／details`，并要求“自动续聊时保留任务状态和下一步”。这是编码 harness 的任务口径。

同一 Agent 同时服务两处：发送前的聊天自动压缩，以及工具循环中的运行时压缩（`RuntimeContextService` 以 `ContextSummaryKind.auto` 调用）。陪伴聊天最需要保住的关系与情绪近况、当前场景／剧情位置、正在聊的话题、角色答应过的事，没有专门栏目，只能挤进“当前进展”或被漏掉。手动压缩（`local.topic_content_handoff`）已有剧情与事实来源区分，口径更贴合。

摘要落库前已被 `normalize` 转成 Markdown 文本，`previous_facts` 也按文本合并，栏目变化不涉及数据迁移。

## 备选

1. 维持统一任务口径。
2. 全部改成陪伴口径。工具循环中的任务型对话会丢失目标、进度与待办。
3. 按场景拆分：聊天自动压缩用陪伴口径，运行时压缩保留任务口径。

## 决定

采用 3。

- 新增区分聊天自动压缩与运行时压缩的类别或参数；运行时压缩继续使用现有 Agent 与五栏契约。
- 聊天自动压缩使用新 Agent 定义与输出契约，栏目大致为：重要背景与人物关系、约定偏好与称呼、关系与情绪近况、当前场景与话题、答应过或未聊完的事、准确细节与日期；最终栏目名与提示词在实施时定稿，沿用手动压缩已有的约束（区分用户确认事实与助手说法、剧情写成“在剧情中…”、后来更正优先、附件无内容不猜）。
- 能由数据库直接取得的硬信息（提醒与约定日期等）不依赖摘要保存，后续另行设计取用方式，不在本 ADR 范围。

## 验收项

1. 聊天自动压缩与运行时压缩分别使用各自模板，有单元测试断言。
2. 新输出契约的结构校验有测试（缺栏、类型错误时报错）。
3. 旧格式摘要作为 `previous_facts` 仍能被合并。
4. 用默认测试模型 DeepSeek Flash 对一段真实长聊天跑一次自动压缩，人工核对情绪、约定、场景是否保留。

## 代价

- 多维护一套提示词与契约；两套口径需各自回归。
- 回滚只需还原 `background_context_summarizer.dart` 及其测试，不涉及数据。
