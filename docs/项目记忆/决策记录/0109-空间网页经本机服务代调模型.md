# 0109 空间网页经本机服务代调模型

- 状态：accepted（2026-10-22 用户确认：按「本机服务代调模型、游戏不碰 Key」实施，不用环境变量）
- 日期：2026-10-22
- 关联：ADR0105（空间网页运行、CSP 与安全检查）、ADR0093／0107（AIcove酱 权限与凭据脱敏）、ADR0074（按模型引用解析接口与密钥）

## 背景

用户想让 AIcove酱 写的空间小游戏调用 AI（比如 NPC 对话）。现状有两道墙：

1. 渠道 Key 由脱敏器挡住，AIcove酱 看不到，也就没法写进游戏配置。这是有意的（ADR0093）。
2. 即使 Key 写进游戏，ADR0105 的 CSP 是 `connect-src 'self'`，页面连不上外部模型接口。

曾考虑把 Key 存成环境变量供 AIcove酱 引用，否决：从启动台打开的 Mac 应用读不到 shell 配置；Key 会明文落进空间文件、跟着云同步和分享出去；第 2 道墙仍在。

## 决定

### 1. 本机服务提供代调接口，Key 不离开 AIcove

- 新增 `POST /__aicove/ai/chat?page=<页面路径>`，沿用 ADR0105 对 POST 的全部检查（`Host`、`Origin` 同源、`Sec-Fetch-Site: same-origin`、只供已运行过的空间、页面须存在）。CSP 不变，页面仍只能连本机服务。
- 请求体：`{"messages":[{"role":"system|user|assistant","content":"…"}],"temperature":可选 0～2,"max_tokens":可选正整数}`。上限：请求体 1 MiB、最多 200 条消息、`content` 必须是字符串、至少一条非 system 消息。
- 成功返回 `{"text":"…"}`，只含模型最终正文，不含思考。
- 失败返回 `{"error":代码,"message":说明}`：`bad_request`（400）、`too_large`（413）、`busy`（429，同一空间同时最多 2 个请求）、`no_model`（503，没配好模型或 Key）、`model_failed`（502，上游出错或超时）。所有说明文字经凭据脱敏器处理后才返回。

### 2. 模型与调用方式

- 用用户的默认聊天模型（默认模型列表第一个，否则 `defaultModelName`），按 ADR0074 的 `resolveRequestConfig` 取接口地址与 Key。页面不能指定模型、渠道或接口地址。
- 单次调用，不带工具、不流式、不写聊天记录；超时取设置里的模型超时。

### 3. 页面写法

- 替身脚本额外提供 `window.aicove.chat(messages, options)`，返回 `Promise<string>`；`messages` 也可以直接传一个字符串（当作一条 user 消息）。失败时抛出 `Error`，`error.code` 是上面的错误代码。
- 替身注入不了的页面（UTF-16 等）没有这个函数，但可以直接 `fetch` 上面的接口。
- `workspace_open` 返回的网页说明写明这个函数、只能在 AIcove 运行时用、费用记在用户自己的额度上，并要求 AIcove酱 不要在游戏里写任何 Key 或外部模型地址。

## 代价

- 游戏只在 AIcove 运行着、且用户点过「运行」时能用 AI；离开 AIcove 单独打开 HTML 文件没有这个能力。
- 空间里的任何网页（包括用户导入的第三方网页）都能花用户的模型额度。同时请求数有上限，但不限总量；按 ADR0105「用户对自己设备负责」的口径接受。
- 本机其他程序同样挡不住（与 ADR0105 一致）。
- 第一版不流式、不能选模型；需要时再扩展。

## 验收门

1. 离线：合法请求返回 `text`；非同源、错误 `Host`、未运行空间被拒；格式错、超限、并发超限、未配模型、上游失败各返回对应代码；上游错误里出现的 Key 被脱敏。
2. 替身：`window.aicove.chat` 字符串与消息数组两种写法都能用，失败时 `error.code` 正确。
3. 真实模型：DeepSeek 下经本机服务完成一次调用，返回正文；Key 不出现在响应与页面里。

## 补充（2026-10-22）：第三方网页与 Agent 自己运行

起因：用户让 AIcove酱 跑一个下载来的单文件网页游戏（自带「OpenAI 兼容 API」设置）并「直接走 AIcove 内置的服务商」。AIcove酱 没调 `workspace_open`，不知道本机服务和 `window.aicove.chat`，自己用 bash 起服务器（命令结束即被回收），最后让用户手填 Key。即使知道，这类游戏也只会请求 `{API 地址}/chat/completions`，接不上第 1 条的接口。

1. **OpenAI 兼容入口**：本机服务另提供 `GET /__aicove/v1/models`（只列一个 `aicove-default`）和 `POST /__aicove/v1/chat/completions`。检查与第 1 条相同（`Host`、POST 同源、只供已运行的空间），但不要求 `page` 参数——第三方网页只会在地址后面拼路径。请求里的 `model` 忽略，`developer` 当 `system`，`content` 可以是文字片段数组，其他片段拒绝；`max_completion_tokens` 优先于 `max_tokens`。`stream: true` 时整段回复作为一个 SSE 块返回，再跟结束块和 `[DONE]`。错误用 OpenAI 格式 `{"error":{"message","type","code"}}`，代码与状态码同第 1 条。同一空间的并发上限与原接口共用。
2. **`workspace_run` 工具**：有工作区的 Agent（AIcove酱、杂活 Agent）可以像用户点「运行」一样运行当前工作区的 `.html`，返回网页地址和 `ai_base_url`（`http://<空间>.localhost:<端口>/__aicove/v1`）。ADR0105「只供用户点过运行的空间」相应放宽为「本次 App 运行期间用户或 Agent 运行过的空间」；Agent 本来就有 bash 全权限，不新增风险。
3. **提示**：工作区系统提示里加一句「网页用 workspace_run，不要自己起服务器，能调用 AIcove 的默认模型」；`webapp_guide` 写明第三方网页把 API 地址设成 `ai_base_url`、Key 随意、模型填 `aicove-default`，并可以直接改 `.save.json` 里的 localStorage 设置免得用户手填。

验收：离线（模型列表、非流式、流式、片段数组、错误格式、跨站拒绝、`workspace_run` 与提示）通过；DeepSeek 下经 `/__aicove/v1/chat/completions` 流式调用返回正文，响应不含 Key。真实浏览器里跑第三方游戏未验。

## 补充二（2026-10-22）：网页可连外网，AIcove酱 的 shell 里有渠道 Key

起因：用户让 AIcove酱 给网站新版 MyRaidRealms 配生图（游戏自带「本地 ComfyUI／NovelAI 兼容接口」设置，网页直接请求 `{地址}/prompt` 或 `{地址}/ai/generate-image`）。AIcove酱 看不到 Key，CSP 也挡住了页面连外部服务和本机其他端口。用户决定（原话要点）：允许连外网，否则外部资源下不了；云同步数据只在自己设备上，不会把整个游戏文件分享出去；AIcove酱 有 shell 权限，把 Key 放进环境变量让它直接填进网页设置。本节推翻「背景」里否决环境变量的结论，以及 ADR0105 的「禁止页面访问外网」。

1. **CSP 放开外网**：`default／script／style／img／media／font／frame-src` 增加 `http: https:`，`connect-src` 增加 `http: https: ws: wss:`（含本机其他端口，如 ComfyUI 的 `127.0.0.1:8188`）。`worker-src`、`form-action`、`base-uri`、`frame-ancestors` 不变。本机服务自身的写入检查（`Host`、同源、`Sec-Fetch-Site`）不变。
2. **渠道 Key 进环境变量**：只给 AIcove酱 的 `bash`。每条命令启动前按当前设置把每个填了 Key 的渠道写成 `AICOVE_KEY_<ID>`、`AICOVE_URL_<ID>`（ID 为渠道 id 转大写、其他字符换成 `_`），`AICOVE_KEYS` 列出「ID:渠道名」。实现是启动子进程前用 `setenv`／`SetEnvironmentVariableW` 改应用进程环境、子进程继承；其他角色的 shell 启动前会清掉这些变量。从启动台打开也能用，不依赖 shell 配置文件。
3. **脱敏不变**：工具输出仍经凭据脱敏器，AIcove酱 用脚本读环境变量写文件，不在输出里看到 Key。提示词要求它不打印 Key、不让用户在聊天里发 Key。

代价（用户已接受）：任何空间网页（含第三方）都能连外网、把页面数据发出去；Key 会明文写进 `.save.json`，随云同步到用户自己的设备；分享空间文件时要注意。验收：shell 能读到变量、其他角色读不到；Key 转换规则；CSP 头。真实浏览器里生图未验。
