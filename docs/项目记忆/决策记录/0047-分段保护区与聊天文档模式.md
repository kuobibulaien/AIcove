# 0047：分段保护区与聊天文档模式

## 背景

自动分段（`MessageFormatter.formatAndChunkText`）先按换行、再按标点切句，对文本里的结构一无所知。它在两层生效：流式交付层把一条 raw 回复切成多条前端投影（`_StreamPlaceholderDelivery`），列表层再对单条消息做显示期切分（`buildChatMessageListItems`）。因此：

- 模型写的围栏代码块（```` ``` ````）被切成一串气泡；项目里的 `CodeBlock` 数据类型从未被生成，代码一直按普通文字处理。
- 预设折叠、选项等语义标签（ADR0046）在流式层没有保护，开着分段时 `<thinking>…</thinking>` 会被拆进多条投影，列表层只能看到半个标签。
- 只想看长文的用户没有不分段、能渲染代码块与 Markdown 的显示方式。

## 决定

### 1. 分段保护区（两种显示样式共用）

**只有正文里的句子可以被自动分段；被划分为组件的文本，内部一律不切。** 组件整块成为一个分段，不参与换行切分、标点切分、短句合并与尾标点过滤，内部原样保留。

组件（保护区）包括：

| 组件 | 识别方式 | 说明 |
|---|---|---|
| 多模态标签 `<tts>`、`<image>` 等第一方内容标签 | 流式层 `_extractRawSegments` 先按标签位置拆成独立片段（多模态交付机制） | 已是独立片段，不进入标点分段 |
| 预设折叠、选项等语义标签 | 当前会话的标签呈现映射，经 `content_tags` 唯一扫描器识别（ADR0044／0046） | 正文类标签（如 `<zw>`）去壳后属于正文，可以分段 |
| 围栏代码块 | 行首 ≤3 空格后 ≥3 个 `` ` `` 或 `~` 开栏，可带语言名；同字符、长度不短于开栏的行闭栏 | 代码块内的 `<tag>` 只是代码文字，不按标签处理；标签内含代码块时随标签整体保护 |

- 只认已注册的标签，正文里的 `<3`、随手写的 HTML 文字不算组件。
- 流式中尚未闭合的组件保护到当前文本末尾，闭合后再按规则继续。
- 新增组件类型时，必须同时接入保护区，不能只在渲染侧识别。

### 2. 聊天文档模式

- 聊天样式分「气泡」与「文档」。全局设置为新会话默认值（本机设置 `chat_display_style`），会话可单独覆盖（`Conversations.chatDisplayStyle` 可空列，空值跟随全局；schema v19，云同步行版本 `kCloudRowSchema` 升到 18，旧客户端收到新行会提示更新应用）。入口：界面设置「聊天样式与分段」、聊天菜单「聊天界面」页的「聊天样式」（2026-10-03 由菜单项移入该页）。目前应用没有创建分支会话的功能，日后加分支时应继承父会话取值。
- 文档模式：不做自动分段，助手消息无气泡、占满宽度、按 Markdown 渲染（标题、列表、引用、表格、行内与围栏代码）；用户消息为右侧浅色块；操作沿用现有工具栏。
- 两层分段与显示缓存只读同一个派生显示策略 `ChatDisplayPolicy`（聊天页把会话的覆盖值传给列表，列表取 `chatDisplayPolicyProvider(覆盖值)`，只监听全局设置、不监听整个会话列表；流式交付用同一 `resolve` 规则按本轮设置快照计算），不各自判断。
- 只改显示与流式切分，不改 raw message、raw payload、投影格式与提示词；旧的分段历史不合并，按原投影逐条无气泡显示。
- Markdown 渲染用 `gpt_markdown`（10k 字流式样本热身后 P50 约 5.5ms，`flutter_markdown_plus` 约 18.5ms；代价是附带 `flutter_math_fork`），由公共组件 `MoeMarkdownView` 薄封装；代码块统一用 `MoeCodeBlock`（`re_highlight` 高亮）。
- 本期不做：数学公式、Mermaid、HTML 渲染、链接跳转、Markdown 图片加载。

## 代价

- 气泡模式下长的标签或代码块会成为一个很长的气泡。
- 流式层需要拿到会话的标签呈现映射，生成开始时读取并在本轮固定。
- 旧历史里已经被切碎的代码块与标签保持原样。
- 会话表新增一列（schema 迁移，用户 2026-10-01 确认）。

## 执行

方案与审查记录在 `scratch/document-mode/`。分三批：A 保护区与代码块组件；B 样式设置与会话覆盖；C 文档模式渲染。
