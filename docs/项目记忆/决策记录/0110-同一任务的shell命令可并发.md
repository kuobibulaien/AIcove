# 0110：同一任务的 shell 命令可并发

## 背景

用户实际使用时，AIcove酱在 codemode 里用 `Promise.allSettled` 同时跑几条命令，第二条立刻报 busy，只好改成串行。对照 Pi（pi-mono `packages/agent` 与 `coding-agent/src/core/tools/bash.ts`）：工具调用默认 `parallel`，单个工具可声明 `executionMode`；`bash` 直接起子进程，不加锁。

我们这边卡在两层：

1. 执行层：一批调用只有全是只读工具才并行，bash 算对外副作用，整批串行。
2. 工作区层：每条命令在 `shell_intents` 登记一份占住整个空间的租约，备份 `.aicove/`，结束时还原并整空间哈希扫描、把变化登记到本 run 以便撤销。第二条命令拿不到租约就报错，而且报错写成「这个文件正在写入」，与真实原因不符。

独占的原因是撤销归属：两条命令同时跑，扫描出的改动分不清是谁做的。

## 决定

- **同一 run、同一空间的命令共用一份租约**。第一条命令照旧登记意图、备份元数据；同 run 的后续命令加入这一组，不再另登记。组里最后一条结束时统一还原 `.aicove/`、扫描一次并登记全部改动；先结束的命令返回空扫描结果。组内改动统一记在这个 run 名下，撤销时一起处理（命令改动本来就按 0098 如实跳过）。
- **不同 run 仍互斥**：别的任务（另一会话、另一 isolate）的命令或文件写入在组存在期间照旧拿到 busy，撤销归属保持按 run 清楚。
- 组里任何一条进程没能在期限内收尾，整组留给启动恢复：最后一条离开时不扫描，报告空间保持锁定，`recoverCommands` 照旧完成。
- 命令运行期间文件工具写入、移动、删除和撤销仍被拦住，规则不变。
- 执行层：`AITool` 新增 `concurrent`（对应 Pi 的单工具 `executionMode: "parallel"`）。一批调用全部是 `concurrent` 或只读工具时并行，混入其他写工具仍串行；手动审批模式与逐步记录（杂活）仍强制串行。只有 `bash` 声明了 `concurrent`。
- 报错改为真实原因：同空间命令运行中写入 →「空间里有命令正在运行，结束前不能写入」；别的任务的命令 →「空间里有别的任务的命令正在运行」；命令开始时有文件写入 →「空间里有文件正在写入」。
- bash 工具描述同步写明同一任务的命令可同时运行。

本决定修订 0087 条件提交与 0098 第 4 条「命令占用整个工作区」的独占范围：从「每条命令独占」改为「每个 run 独占」。其他可靠性规则不变。

## 代价

- 同组命令的改动合在一起登记，撤销粒度从单条命令变成一组命令。
- 组内命令可能互相改同一个文件，结果由命令自己负责，和 Pi 一致。
- 组只在本 isolate 内存里；崩溃后由持久意图记录恢复，与原租约一致。

## 验证

- 修复前先复现：同一 run 并发两条互相等待的命令，第二条拿到 busy，第一条超时。
- 新增测试：同 run 三条命令并发成功、元数据被还原、改动一次登记且可按 run 撤销；组在最后一条离开前仍拦写入、别的 run 拿到新的 busy 文案；一条未收尾时整组留给恢复。shell 测试 48 项通过。
- 执行层新增测试：两个 `concurrent` 工具一批时交错执行，混入普通工具时串行；内核差分 32 项通过。
- 工作区与扩展相关测试通过；`workspace_image_real_model_test` 2 项失败为既有问题（仍断言 0108 改名前的 `workspace_read`），`workspace_pages_test` 一项在整批运行时偶发失败、单独运行通过。
- 应用内 AIcove酱 实际并发跑命令、Windows 未验。
