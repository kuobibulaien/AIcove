# 0082 语音识别来源来自渠道商：识别格式注册表，逐家接流式协议

- 状态：accepted（2026-10-14 用户确认：识别来源列表＝本地模型＋渠道商里配置的识别模型；不做「本机 VAD＋上传整句」的通用 OpenAI 转写，延迟不可接受，改为逐家适配主流流式识别）
- 日期：2026-10-14
- 关联：ADR0074（语音通话流水线，决定 7 识别来源）、ADR0081（语音合成格式注册表，同一思路）

## 背景

通话的云端识别只写死了一项「阿里云百炼」：固定读 id 为 `aliyun` 的渠道的 Key，固定调 Paraformer。渠道商里早有「语音识别」模型类型（`ModelType.stt`），但通话用不上，别家识别服务也接不进来。

## 备选

- OpenAI 兼容转写（`/audio/transcriptions`）＋本机 Silero VAD 切句：一个格式覆盖很多厂商，但每句要等说完再上传、再整句转写，多 0.5～1 秒。用户否决。
- 逐家接各自的流式 WebSocket 协议，服务端边听边判停：采用。

## 决定

1. **识别格式注册表**：`AsrRequestFormat`（`features/voice_call/domain/asr_request_format.dart`），格式存在渠道 `customConfig.asrRequestFormat`，与对话／合成的 `requestFormat` 分开，所以同一渠道（阿里云）可以同时有合成和识别模型。添加页、详情页、存储规整、识别器装配都从这里读，识别只认这个字段。首批七种：
   - 阿里云百炼：Fun-ASR／Paraformer 走 run-task 双工协议；`qwen3-asr*` 走 `/api-ws/v1/realtime`（OpenAI 风格事件），按模型名分流。
   - 火山引擎豆包（`bigmodel_async`，二进制帧＋gzip，模型名即 Resource-Id；新版控制台 X-Api-Key，旧版 App ID＋Access Token）。
   - 腾讯云（地址签名 HMAC-SHA1，模型名即 engine_model_type，凭证 AppID＋SecretId＋SecretKey）。
   - 讯飞实时语音转写标准版（signa＝HmacSHA1(MD5(appid+ts), apiKey)）。
   - OpenAI Realtime 转写会话（服务端 VAD，24 kHz，话筒 16 kHz 线性插值升采样）。
   - Deepgram（`is_final` 拼到 `speech_final`／`UtteranceEnd` 才定稿）。
   - ElevenLabs Scribe realtime（VAD 自动提交）。
2. **一个骨架**：`WebSocketSpeechRecognizer` 统一管建连、等就绪、句子状态、失败与断线判定、收尾；各家只写协议。判停静音统一 500 ms（300 ms 会在句中逗号处误切，阿里云实测）。
3. **保活**：通话里角色说话时话筒不送音频，超过 4 秒没音频就发保活（默认 100 ms 静音；Deepgram 用 KeepAlive 消息），避免腾讯 6 秒、Deepgram 10 秒、讯飞 15 秒无音频断开。阿里云 run-task 开 `heartbeat`。
4. **识别来源**：只存本机，键改为 `recognizer_source.v2`，值是 `auto`／`local`／`{provider, model}`。列表是自动、本地模型，加上所有启用渠道里的可见识别模型；缺凭证的照样列出并写明缺什么。「自动」＝本地模型优先，否则第一个凭证齐全的云端模型。旧 v1 的 `aliyun` 迁到阿里云渠道里第一个识别模型。
5. **存储规整**：有识别模型的渠道没写格式时按地址补一次；纯识别渠道里未手动设类型的模型一律定型为识别（`nova-3`、`16k_zh` 等名字推断不出）；语音合成渠道的「全部算语音」规则跳过推断为识别的模型。内置阿里云预置 `fun-asr-realtime`、`paraformer-realtime-v2`，老用户的阿里云渠道补一次（`asr_models_seeded` 标记，删掉不再加回）。模型名推断补上 `transcribe`、`scribe_v*`。
6. **渠道界面**：添加页新增「识别」类别，按格式显示额外凭证输入；详情页有识别格式的渠道多一个「语音识别」分组（切格式、填 AppID／SecretId 等）；纯识别渠道不显示对话的 API 格式。「测试模型」对识别模型真实建连一次、送 1 秒静音，验证地址、凭证、签名与模型名。

## 代价

- 七家协议都只按官方文档写、用本地假服务测过，没有一家用真实 Key 跑通（本机没有这些 Key）；字段名或事件名和文档不一致时要逐家修。
- 讯飞只接了标准版；讯飞大模型版、Azure、Google、AssemblyAI、Soniox 没接。
- OpenAI `gpt-live-transcribe` 不支持服务端 VAD，不能用于通话。
- 保活的静音在腾讯、讯飞等按时长计费的厂商会计入时长（每 4 秒 0.1 秒）。

## 验收门

- 离线：注册表规整与地址推导、存储规整（阿里云补模型只补一次、纯识别渠道定型）、来源编码与 v1 迁移、七家协议（握手地址／头、签名、开场消息、结果到事件、保活、收尾）、工厂路由与缺凭证提示、设置页列表，均有测试。
- 待实测：至少阿里云 Fun-ASR 在真机通话里跑通；其余厂商拿到 Key 后逐家验证。
