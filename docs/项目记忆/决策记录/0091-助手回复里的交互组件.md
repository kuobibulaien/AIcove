# 0091：助手回复里的交互组件（aicove-ui 代码块）

关联：ADR0073（AIcove 助手）、ADR0047（分段保护区与文档模式）、ADR0045（对话选项只填草稿）、ADR0063（请求前提醒）、ADR0089（聊天里不渲染 HTML，本 ADR 不改）。方案与分批：[交互组件方案](../../../apps/aicove_flutter/docs/04_功能模块规范/AIcove助手/交互组件方案.md)。

## 背景

助手的界面只有 Markdown 正文和输入框上方的临时卡片，讲配置步骤、带用户排障只能靠一问一答。用户 2026-10-18 要求参考 ChatGPT Intelligent UI、自己给 DSH 做的插件和 DEEIX-Chat，给 AIcove 做一版交互组件，「先试试」，界面统一性后面再看。

## 决定

1. **格式**：模型在回复正文里写语言名为 `aicove-ui` 的围栏代码块，内容是 JSON（`component`、`id` 与属性）。它是输出格式，不是工具。围栏已是 ADR0047 的保护区，两种聊天样式都不切开；原文留在历史里，模型下一轮知道自己给过什么；解析失败退回可展开的原文。用户自己的消息里的同样代码块按代码显示。
2. **两层组件**（照 DEEIX-Chat）：目录组件只填属性（checklist、steps、decision-tree、quiz、form、stat-grid、data-table）；需要联动计算时用 `panel`（state／computed／原语）。表达式是白名单小语言（`{公式}` 模板，无赋值、无循环、无宿主访问，步数与长度有上限），纯 Dart 实现，不用 QuickJS、不进 WebView。
3. **用户操作回传给模型**：每块只存「与初始值不同的键」，按会话存本机偏好 `aicove_ui_state_v1:<会话 id>`（每会话 64 块，不同步、不进消息表，raw message 不变）。助手会话发请求时，助手插件的请求前提醒（ADR0063，order 900）把仍在本次历史里的块写成一段 `<ui_state>`，最近优先、最多 8 块 4KB，标明是用户数据不是指令，`<` 转义防止闭合标签。
4. **追问只填草稿**：`button.ask` 走对话选项的投递通道填进输入框，不替用户发送（ADR0045 同口径）。
5. **范围**：提示词只注入助手会话（每轮约 4K 字）；渲染器对所有会话的助手消息生效（只有展示和本地交互，没有副作用）。会改设置的「动作组件」留给 U3，届时只在助手会话渲染。

## 代价

- 每轮提示词多约 4K 字；块 JSON 留在历史里占 token，旧块暂不压缩。
- 组件状态只在本机，换设备看不到、也不回传。
- 同一条消息里 id 重复的块共用一份状态（未做重复检测）。
- 流式中只显示占位，块写完才出现（不做逐节点流式渲染）。

## 验收

离线：表达式／解析／编译／回传 19 项、组件 widget 测试 11 项（含两种样式、深浅色源码渲染预览）。真实 DeepSeek Flash：问语音通话准备给出 steps，排查不画画给出 decision-tree，回传勾选状态后正确答出「还差第 3 步」，三个回复的块都能无错误解析编译。实机未验。
