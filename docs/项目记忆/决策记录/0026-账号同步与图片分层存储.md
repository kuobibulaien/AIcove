# ADR0026：账号同步与图片分层存储

- 状态：accepted；消息传输粒度与图片用途规则由 ADR0028 细化替代，账号与完整同步范围继续有效。
- 日期：2026-09-13
- 授权：用户要求继续云同步；完整数据以手机为源，Mac/Windows 为接收端；Mac 既有少量数据经确认只是可清理测试数据。图片采用最近 30 天原图、较早缩略图占位，设置包含界面与全部插件。

## 决定

沿用 ADR0021 的版本文档和账号提交序号，接入 Flutter 主业务库与设置/预设适配器。用户名密码登录，账号拥有数字 ID 和独立唯一标识，设备 ID 独立持久化。令牌存入系统安全存储，密码不持久化。用户要求登录框显示明文，输入时直接显示，提交时仍清空输入框。

媒体长期身份 `media_ids` 与已上传文件 `blob_ids` 分离；媒体身份可以先存在而原图尚未上传。先同步完整历史和可用缩略图；仅聊天中超过 30 天的图片可推迟原图，其他用途全部传原图，详细用途合并规则见 ADR0028；语音与普通文件仍完整传输。保留原消息日期，不按导入时间刷新年龄。不清理已有原图；临时缓存中的唯一原图先保存到受保护目录。模型看图和导出必须解析原图，拿不到时明确提示。

实现与完整字段契约唯一入口：[云同步 v3](../../../cloud_backend/sync_v3/README.md)。不把运行中的生成任务或本机权限一起同步；未来云相册不属于本次交付。

用户随后指出串行小批上传过慢，追加 gzip JSON 与 ZIP 附件批量传输：最多 100 条业务文档/媒体元数据，附件每包最多 64 个，按体积限流并最多并发 3 包，断线后沿用已有 outbox 重试。完整限制与兼容规则仍以协议文档为准。随后实测缩略图全尺寸解码占用较高，改为引擎缩小解码，接收端附件资料采用最多 3 路并行；不同解码器生成的缩略图以服务器已确定版本为准。

## 代价与边界

媒体缩略图无法恢复丢失原图；历史中已经不存在的源文件保留身份/原位置/不可用状态。并发编辑保留两份并由用户选择，不能把“同一个账号”视为不会并发。当前本地数据集绑定单一账号，换账号切换不同本地数据集尚未实现，先拒绝串数据。服务端持钥匙加密并非端到端加密，附件文件本身仍是原始二进制。

## 验收与回滚

58 项后端测试及真实服务客户端契约测试通过；手机安装新版并开始上传，Mac/Windows 实机全部数据对齐尚未完成。登录明文框在 Mac 实际窗口确认，窄/宽组件测试通过。Mac 系统钥匙串适配另有真实写入探针与回归测试。

服务部署保留旧镜像、compose 与一致数据库副本；回滚只切镜像和配置，不能抹掉新写入的数据、媒体或密钥。客户端 outbox/inbox 保留重试进度，暂停同步不删源数据。完整测试与部署证据位于 `.codex-temp/cloud-client-v3/` 和 `.codex-temp/account-system/`。
