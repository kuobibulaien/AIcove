# ADR0021：云同步 v3 与公网服务边界

- 状态：accepted（后端原则仍有效；客户端接入、媒体契约与部署由 ADR0026 补充）
- 日期：2026-09-12
- 授权：用户在后端架构核查后要求“那你直接大重构吧，现在也没什么太重要的数据。”

## 背景

旧 v2 用时间戳分页，消息删除/恢复不会更新其创建时间；接口与 Flutter 旧服务参数、状态不一致。另有一套独立旧同步库。只补字段不能保证完整 raw 历史、并发修改和跨设备恢复。开发 Studio 与公网同步共用入口还会暴露开发管理能力。

## 决定

采用模块化单体，复用 FastAPI / SQLAlchemy / 账号体系，新增 `cloud_backend/sync_v3/`，以 `sync_v3.app:app` 作为公网入口；旧 Studio 保留决定已由 ADR0031 取代；`main:app` 现在仅转向 v3。

新版协议用有限实体类型、完整版本化业务文档、账号 epoch、对象 version 与提交顺序 seq。账号写锁把业务记录、变更和幂等回执放入同一事务；不按设备时间决定同步顺序。消息可编辑；冲突原对象不改，双方内容及附件引用保存为独立可解决记录。附件账号隔离、按摘要校验后发布。快照固定提交水位，从不可变历史分页重建，恢复作为新变更发布。

当前 v3 按账号同步完整文档集，不沿用旧 scope 开关；设备专属缓存、权限和运行会话不属于业务文档。客户端适配器须逐类定义 payload，完整保存 raw、话题、记忆、预设、绑定及可迁移设置，不能直接搬设备路径或仅上传 UI 气泡。

新增表与旧表隔离，保留旧数据，不双写、不自动把旧不完整记录转换成“完整备份”。公网账号由本机 CLI 创建，登录和账号管理继续复用；不开放注册与首管理员抢注接口。

## 代价与边界

- Flutter 接入和媒体契约后续见 ADR0026，不能将后端验收代称手机/Mac 已同步完成。
- 初版保留全部变更、回执和附件，空间会增长；压缩/清理须另行设计快照保全与过期游标恢复协议。
- 元数据、凭证、回执和快照清单服务端加密，附件原始二进制存储；不是端到端加密。固定密钥必须单独备份。
- AI 生成仍在客户端，跨设备生成接管不属于本次后端数据同步。
- 纯后端改动按根 README 宪法第 7 条验证，不构建或安装 Flutter。

## 验收与回滚

隔离数据库/附件测试覆盖并发、同时间消息分页、编辑/删除/恢复、重试、冲突、账号隔离、真实 HTTP/JWT、分页快照与文件备份恢复；真实本地 ASGI 进程验证登录、重启持久化和公网路由隔离。

远程部署与现行回滚方式见 ADR0026。回滚切回旧服务入口和代码，保留新增表/附件/密钥；旧服务不会自动读取 v3 新数据。上线前先备份 data 卷，首次启用仍须完成客户端适配与实际双设备验收。

唯一协议说明：[云同步 v3](../../../cloud_backend/sync_v3/README.md)。旧云同步施工手册、范围及分支文档已标注被本决定取代；离线 `.aicove` 导入导出能力保持其现有独立边界。
