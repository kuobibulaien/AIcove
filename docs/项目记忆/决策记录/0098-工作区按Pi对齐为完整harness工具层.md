## 背景

AIcove酱导入表情后说她不能打标：工作区工具把文件一律按 UTF-8 文本解码，图片读出来只有 `binary: true`。往下查，问题不止图片：

1. **工具结果只能是文字**。`AITool.handler` 返回字符串，`KernelToolResult.content` 是字符串，Claude／OpenAI／Gemini 三个适配器的 `buildToolResultMessages` 都只放文字。哪个工具都没法把图片交给模型，MCP 返回的图片也被写成「未转给模型」。
2. **没有执行能力**。Pi 的核心是 `bash`：下载、转换、批处理、跑脚本都靠它。我们的 `run_script`（ADR0087 第 4 条）一直没做，Agent 只能逐个文件读写。
3. **文件工具按「同步编辑器」设计**。读取按字符分页且返回 JSON（换行全部转义，费 token）；编辑、移动、删除必须带 `expected_revision`；一次只能替换一处；不能写二进制。

Pi 的对应做法（核对源码 `packages/coding-agent/src/core/tools/`、`packages/ai/src/api/`）：

- `read`：文本按行读，`offset`（从 1 开始）＋`limit`，单次最多 2000 行或 50 KB，截断时在末尾写明下次的 offset；jpg／png／gif／webp／bmp 按文件头识别，缩放后作为图片块返回；模型不支持图片时附一句说明、图片不发送。
- `write`：整文件写入，自动建目录，覆盖不需要先读。
- `edit`：一次可带多处 `edits[{oldText,newText}]`，都按原文件匹配，每处唯一且互不重叠；保留 BOM 与换行风格；返回 diff。
- `bash`：在当前目录执行命令，合并输出，只给模型最后 2000 行或 50 KB，截断时全文存临时文件；非零退出码标为错误；取消或超时杀掉整个进程树。
- `codemode`：在 QuickJS 沙箱里跑一段异步 JS，通过 `tools.<name>()` 调用其他工具（失败的子调用 reject），可以查询工具清单和声明，只把脚本输出交给模型。
- 工具结果里的图片：Anthropic 直接放进 `tool_result`；OpenAI 格式的 tool 消息放不了图，所有 tool 消息之后补一条 user 消息带图；Gemini 3 以前同样补一条 user 消息。

## 决定

### 1. 工具结果统一为「富输出」，可以带图片

- 工具输出从字符串扩展为 **文字＋图片＋错误标记＋可选结构化数据**。模型看到的是文字和图片，脚本拿到的是结构化数据（没有就用文字）。只返回字符串的旧工具不受影响；所有重新包装 `AITool` 的地方（杂活 Agent、脱敏、闸门）都要透传富输出，闸门或脱敏改写过的结果以改写后的完整字段为准。
- 内核 `KernelToolResult` 增加图片列表与错误标记，内核只透传。
- 三家编码照 Pi：Claude 把图片块放进 `tool_result.content`（所有 `tool_result` 排在同一条 user 消息的最前面）；OpenAI 格式先发 tool 消息（只有图时写「（图片见下一条消息）」），本批所有 tool 消息之后补一条 user 消息「以下是工具返回的图片：」＋图片；Gemini 在 `functionResponse` 之后补同样的 user 部分。
- **补发图片的 user 消息属于工具步骤**：运行期给它打上归属标记，上下文预算与压缩把「调用＋本批结果＋附图」当作一个整体，它不会被当成用户的最新输入。标记在发送前去掉。
- **模型不支持看图**（沿用现有视觉判断）：图片不发送，工具文字里写明「当前模型不支持看图，看不到这张图片。回复用户时必须说明两点：你看不了这张图；请用户换一个支持图片的模型后再试」，由模型自己向用户说明。
- **三份投影**，在统一的边界生成：
  1. 本次运行（一次 agent loop）：保留图片数据，后续轮次能看到；
  2. 聊天记录、杂活过程记录：文字＋逐张「［图片已省略：来源］」，不存 base64；下一次聊天运行重放时就是这段文字，需要再看就重新读；
  3. 日志与 trace：只记图片的类型、尺寸、字节数，不记 base64（普通、流式、失败日志都覆盖）。
- **大小预算**：单张图片长边 ≤ 1568 像素、编码后 ≤ 2 MiB；单个请求最多 20 张、图片合计 ≤ 12 MiB，超出的从最早的开始换成占位。预处理在后台 isolate 做：按文件头识别格式，缩小、降质量，bmp 转 png，处理失败只返回文字说明。
- **酒馆预设通道**：送进预设 QuickJS 的消息里，图片换成宿主管理的引用标记，预设处理完再换回图片，预设的 8 MiB 输入上限与 1 秒期限不变。
- MCP 工具返回的图片、错误标记与结构化结果走同一套富输出。
- 旧执行器（构建期回退）只取文字投影，图片写成占位，不装配第 3、4 条的执行类工具。

### 2. 文件工具对齐 Pi

工具名保留 `workspace_*` 前缀（和其他几十个工具同处一个列表，前缀更清楚），语义按 Pi：

- `workspace_read`：文本按行读（`offset` 从 1 开始、`limit` 行数），单次最多 2000 行或 50 KiB，结果是纯文本，截断时末尾写明下次的 offset，revision 写在末尾的说明行里；图片按第 1 条返回；其他二进制只返回类型和大小。第一行就超过 50 KiB 时不返回内容，只说明情况（H2 之后再提示用 `workspace_run_js` 截取）。
- `workspace_write`：整文件写入文本，自动建目录；覆盖已有文件不再要求 `expected_revision`。
- `workspace_edit`：`edits` 数组一次改多处，都按原文件匹配，每处唯一且互不重叠；保留 BOM 和换行风格；返回 unified diff（截断）和第一处改动的行号。旧的单处 `old_text`／`new_text` 继续接受。
- `workspace_list`、`workspace_glob`、`workspace_grep`、`workspace_move`、`workspace_delete` 保留；grep 每行最多 500 字符。
- **revision 改为可选，但仍是条件提交**：不带时工具层先读出当前 revision，再用 store 原有的条件提交写入；被别人抢先改了就报「文件刚被改过，请重新读取」，不自动重试、不覆盖。`WorkspaceStore` 的提交协议不变。将来的工作区同步（W5）仍按基准修订判冲突，不受影响。
- store 补一条路径规则：路径上任何一级目录是符号链接都拒绝（防止命令建出的目录链接把后续读写带出工作区）。

### 3. 代码模式 `workspace_run_js`（全平台）

对应 Pi 的 `codemode`，取代 ADR0087 第 4 条的 `run_script`：

- 复用现有的 `aicove_quickjs`，新增异步会话（新类，酒馆预设继续用原来的同步模式和 1 秒期限）：Promise 与 Job 调度、宿主调用挂起／恢复、原生中断回调（紧循环也能停）、内存上限。
- 参数二选一：`code`（异步函数体，可以顶层 `await` 和 `return`）或 `path`（运行工作区里的 `.js` 文件，配 `args`）。
- 脚本里可用：`tools.<工具名>(参数)` 调用本次运行的其他工具，失败或被拒绝时 reject；`tools.list()`／`tools.describe(名字)` 查清单和参数说明；`fetch(url, 选项)`；`ws.readBytes`／`ws.writeBytes`（base64，分段，单次最多 4 MiB）；`console.*`、`text()`、`image()`、`return`。没有定时器和 Node API。规范化后的工具名撞名时，两个都不提供并在清单里说明。
- 子调用经过和直接调用相同的闸门、脱敏与取消入口。需要用户确认的工具在脚本里直接失败，提示改为直接调用；脚本不能调 `workspace_run_js` 和 `workspace_shell`。
- **期限是真的停止**：工具可以声明自己的期限（脚本默认 30 秒、最长 120 秒），不受全局 30 秒工具超时截断。超时或取消时，先中断 JS、取消所有未完成的宿主操作并等它们收敛，再返回结果；每次宿主提交前都检查调用是否仍然有效，所以不会有晚到的写入。
- **`fetch` 只访问公网**：解析域名后检查全部地址（含 IPv4 映射的 IPv6），连接时使用检查过的地址，每次重定向重复检查。表情导入的抓取改用同一个入口。
- 写入经过同一个 store，记在本次 run 下，可以撤销；对外的网络请求撤销不了。
- 输出：模型只看到最后 2000 行或 50 KiB，截断时全文存到 `.aicove/outputs/`（最多 8 MiB，超过只留最后 8 MiB 并标注），路径写在结果里。
- 本轮不做 Pi 的 `store()`／`load()` 跨调用状态和非聊天模型调用。

### 4. 桌面端命令行 `workspace_shell`（macOS／Windows／Linux）

对应 Pi 的 `bash`：

- 在工作区目录里执行命令（macOS／Linux `/bin/sh -c`，Windows PowerShell），输出处理同第 3 条，返回退出码与耗时；非零退出码标为错误；默认期限 120 秒、最长 600 秒；取消或超时杀掉整个进程树并等它退出。
- **每条命令都要真人确认**，不能由审核模型放行（AIcove酱的风险档为 major）。没有真人确认通道的运行不装配：后台杂活 Agent、旧执行器，以及本轮的普通工具模式角色。普通角色等有了通用的确认卡片再开放。
- **命令造成的改动不能撤销**（和 Pi 一致：Pi 没有撤销）。确认卡片写明这一点。执行期间锁住这个工作区的其他写入；执行前给 `.aicove/` 做快照、执行后还原；执行后重新扫描工作区，把变化登记进索引（标为「命令改动」，按 run 撤销时跳过并说明）。执行前先落一条意图记录，崩溃后启动时据此重新扫描。
- macOS 应用开着沙盒，命令只能访问应用容器，很多命令行工具用不了。工具说明如实写明；沙盒是否放开另行决定。

### 5. 表情图片对 AIcove酱 可见

AIcove 默认空间（`aicove`）提供只读的 `stickers/<套组 id>/<表情 id>.<扩展名>` 视图，直接读表情库里的文件，不复制；另有生成的 `stickers/index.md`（套组名、表情 id、现有标签）。写入一律拒绝，字节接口也拒绝。这是 ADR0087 第 6 条「默认空间＝应用数据的文件视图」的第一块。

### 6. 与 Pi 的差异（本轮明确不对齐）

| 方面 | Pi | 我们 |
|---|---|---|
| 手机、平板上执行命令 | 有 bash（Termux） | 没有 shell，只有 `workspace_run_js` |
| 后台无人值守执行命令 | 可以 | 不可以（没有真人确认） |
| macOS 命令行工具链 | 完整 | 受应用沙盒限制 |
| 脚本跨调用状态、调用非聊天模型 | 有 | 本轮不做 |
| 文件范围 | 整台机器 | 授权的工作区内（shell 除外） |
| 撤销 | 没有 | 文件工具和脚本的写入可按 run 撤销；命令改动不可撤销 |

定时任务、默认空间完整投影、工作区同步（ADR0087 第 5～7 条），以及会话树（ADR0068）、压缩策略（ADR0062）、旧结果清理（ADR0061）、扩展（ADR0064 第三批）照原归属，不在本文范围。

## 代价

- 内核、三家适配器、上下文压缩、持久化、日志都要认识富输出和附图步骤，改动面大。
- 不带 revision 的写入仍是条件提交，两个任务抢同一个文件时后到的会失败，需要重读后再写。
- 代码模式和 shell 增加了攻击面：脚本可以访问公网，shell 可以动整台电脑（靠逐条真人确认挡住）。
- 图片只在本次运行内发送，之后要看还得重新读。
- 普通工具模式角色本轮没有 shell。

## 验收门

1. 支持视觉的模型（Claude、OpenAI 格式、Gemini 各一）读工作区里的 png／jpg 后能描述图片内容；不支持视觉的模型（DeepSeek）收到明确说明，回复里告诉用户换模型。
2. 聊天记录、过程记录、日志里都没有 base64；下一次聊天运行里旧图片是占位；同一次运行的后续轮次仍能看到图片；预设通道带大图不超限。
3. 文件工具：按行续读、截断说明、多处编辑（唯一、重叠、CRLF、BOM）、不带 revision 的覆盖、并发抢写失败、祖先符号链接被拒，都有离线测试。
4. 代码模式：`await fetch` 之后写文件成功；紧循环、等待 I/O、未 await 的写入、并发部分失败、超时、取消、异常之后都没有晚到的写入；域名解析到内网被拒；脚本写入能按 run 撤销；需要确认的工具在脚本里失败；现有酒馆预设与 QuickJS 测试全部通过；安卓与 macOS 原生构建通过。
5. shell：每条命令都弹真人确认，审核模型不能放行；拒绝后不执行；超时杀进程树；`.aicove/` 被还原；命令改动登记进索引且撤销时如实跳过；后台杂活 Agent 和普通角色拿不到这个工具。
6. AIcove酱 导入一套表情后能逐张看图并打上标签。
