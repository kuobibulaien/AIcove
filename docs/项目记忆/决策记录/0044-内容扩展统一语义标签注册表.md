# 0044：内容扩展统一语义标签注册表

## 背景

模型回复里的语义标签在请求副本、落库拆分、流式显示、后台回复四处被消费。改动前每个标签的知识散在 5～8 个文件、各写正则，口径不一（落库拆分的 `<tts>` 大小写敏感，流式不敏感；请求过滤支持属性与嵌套，其他地方不支持）。兼容酒馆预设后会新增 `thinking`、`details`、`options` 等大量标签，继续堆正则必然出现“显示层藏了、请求里漏了”，或者语音事件和语音段错位。

用户确认：插件和预设是同一种东西，都是**内容扩展**。插件由我们写，预设由第三方写，做的事一样：声明语义标签，再由后台按标签提供内容体验。

## 决定

- 新增纯 Dart 领域层 `features/content_tags/domain/`：
  - `ContentTagSpec` 声明一个标签：名称、别名、归属方、归属方生效或未生效时的请求动作（keep / strip / unwrap），以及显示种类。
  - `ContentTagProvider` 是内容扩展接口，声明标签与工具归属。
  - `ContentTagRegistry` 是一次请求或一次解析的快照，记录有哪些提供方、哪些生效。
  - `ContentTagScanner` 是**唯一**的标签扫描器。
- 扫描口径统一为：大小写不敏感；允许属性，带引号的值可以含 `>`；同名标签按深度配对嵌套；支持自闭合；未闭合的开标签一直吞到文本末尾，并标记为未闭合；孤立闭标签单独成段；没注册过的 `<xxx>` 当普通文本。
- 请求过滤递归处理：保留下来的元素，其正文仍按其它标签的策略继续过滤，防止外层标签一保留，内层已关闭插件的内容就漏出去。
- 同名标签以先注册的提供方为准。调用方按优先级顺序传入提供方。
- raw 永不改写。酒馆正则脚本（查找→替换，程序不理解其含义）仍归 `SillyTavernRegexProcessor`，不并入注册表。

## B1 已交付（2026-09-29）

- 语音、绘图插件以静态 `contentTags` 声明各自的标签和工具。汇总入口是 `plugins/plugin_content_tags.dart`。
- 四类消费方全部改走扫描器：
  - **请求过滤**：`ChatPluginContextPolicy` 删掉硬编码的两个布尔开关，改为按本轮有效插件 id 构造注册表。工具成对过滤也改由提供方声明。
  - **落库拆分**：`ChatMessageProcessor` 的多模态拆分、`stripPluginTags`、`collectTtsTexts`，以及 `TtsParser.parse`。
  - **插件自身解析**：`ImagePlugin.processResponse`。
  - **流式占位**：`chat_actions_stream_placeholder.dart`；另外还有历史重建里判断是否保留多段的逻辑、后台自动回复的图片判断。
- 语音插件、绘图插件与落库拆分共用 `TtsParser.isSpeechElement` / `ImagePlugin.isInlineImageElement` 这两个判断，保证事件和分段一一对齐。
- 唯一有意的行为差异：大写或带属性的 `<TTS …>` 现在各处都识别。改动前只有流式识别，落库拆分不识别。

## B2／B3 前置约束（来自 Codex 审查，均属真实泄漏或错位风险）

1. **最终请求兜底**：QuickJS／SPreset 的 `prepare` 在后端过滤之后才执行，可能重新插入已关闭插件的标签。需要把请求级注册表放进 `ApiConfig`，在每次 `prepare` 之后、调用 Provider 之前再过滤一次，重试和工具循环也要覆盖。这是现存缺口，涉及正在开发中的预设运行时文件，留给该批次处理。
2. **所有模型边界共用一个入口**：摘要、智能回复、运行时压缩目前直接读原文或自带正则。B2 前统一走“raw → 请求安全副本”。
3. **注册表贯通流式与历史**：流式投影在开始前拿到本轮注册表快照；预设标签的显示语义落库时写入 rawPayload（已解析的块或映射版本），避免解绑或修改预设后，旧消息被按新映射重新解释。
4. **流式隐藏过滤器**：`_VisibleAssistantStreamFilter` 按 `<think` 前缀匹配，而且没有嵌套深度，遇到 `<thinking>`、`<think_nya~>` 会一直等不到闭标签，吞掉后面的全文。B2 改成基于扫描器的增量过滤，要处理分片边界、别名和深度。
5. **图片上下文记录回显**：模型回显的 `<image source="history">` 目前原样显示。B2 在助手输出的显示层把它当内部内容隐藏，请求副本不变。
6. **顺序**：终态固定为“预设输出处理 → 酒馆显示正则 → 语义标签投影”。流式没有全文正则时，先按标签映射隐藏敏感标签。

## 后续批次

- **B2 thinking**：模型原生 reasoning 字段与正文里的 `<thinking>/<think>/<cot>`，在显示层统一成 `ThinkingBlock` 折叠块；请求层分开处理，由预设映射决定。`details/summary` 做成折叠块。
- **B3 options 与预设映射**：`<options>` 渲染成可点选项，点了只填入草稿，不自动发送。预设可附加标签映射（导入时推断，用户可改）。未知标签默认请求时保留、显示原样；2026-10-01 起唯一包住主要正文的未知外壳去壳显示为正文，其余仍原样（ADR0048）。

## 代价与回滚

B1 是纯代码重构，没有 schema 或配置迁移。回滚方式：撤回 `content_tags/`、`plugin_content_tags.dart` 以及各消费方的改动即可。全量测试在有无本批改动两种情况下失败集合完全一致（93 个，均为工作区既有失败），新增扫描器和一致性测试 9 项。未做实机验证。
