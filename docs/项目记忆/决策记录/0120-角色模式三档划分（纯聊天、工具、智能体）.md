# 0120：角色模式三档划分（纯聊天、工具、智能体）

关联：修订 [0097](0097-角色分聊天模式与工具模式.md)、[0088](0088-聊天模型委派杂活Agent.md)、[0111](0111-Agent模式的角色与AIcove酱同权.md)。

## 背景

ADR0097 将角色分为「聊天模式」与「工具模式」两档，其中默认的「聊天模式」在每次请求中无条件注入 `delegate_task` 与 `steer_task`（及已开启插件的直出工具）。实际运行中暴露出两类冲突：

1. 上游抗截断代理渠道一旦检测到请求中带有 `tools` 数组，便会自动注入英文强制指令逼迫模型在回答前调用工具，导致模型被迫乱调 `delegate_task` 或 `steer_task`；
2. 许多酒馆预设在提示词中要求模型查阅设定资料，模型看到 `delegate_task` 描述中的「读写文件」，误将角色设定与世界书当成需要派给后台助手查阅的文件。

## 决定

1. 角色工作模式（`RoleAgentMode`，存在 `conversations.agent_mode` 列）扩充为三档，角色编辑页「角色模式」分段控件对应展示 `纯聊天`／`工具`／`智能体`：
   - **纯聊天**（`chat`，默认，含未设置 `null`）：默认不带任何第一方工具（`supportsToolCalling = false`，`tools` 为 `null`），并关闭渠道内置联网搜索。长期记忆、时间感知、语音 `<tts>`、表情包 `<sticker/>` 等提示词与正文标签插件照常生效；绘图插件在纯聊天（或预设关闭函数调用）时自动走 `<image>` 行内标签快速路由，不再因缺少 `draw_image` 工具而静默失效；绑定的酒馆预设若自带脚本输出协议（`PresetScriptSnapshot.toolsAllowed`），仍按模型能力与预设 `function_calling` 开关正常运行。
   - **工具**（`tool`）：正常的单层 Agent（保持 ADR0097／0111 行为），前台模型直接使用角色开启的全部插件工具、工作区与 AIcove 管理工具，不派活。AIcove酱固定锁定此档。
   - **智能体**（`agent`）：参考 DeepSeek Super Agent 的「前台路由层＋后台子 Agent」架构，前台模型保持角色人设作为路由层，保留轻量直出插件工具，并将联网搜索、MCP、读写工作区等任务通过 `delegate_task`／`steer_task` 交给后台子 Agent（`TaskAgentService`）执行，结果以「杂活回执」送达后由前台角色转述。
2. 收紧 `delegate_task` 系统提示词与工具描述边界：明确声明角色设定、世界观与历史对话已在当前上下文中，日常聊天、角色扮演、写故事或画分镜严禁调用 `delegate_task`，仅当用户明确要求联网查现实信息、调用外部服务或读写工作区文件时才可派活。
3. 助手体检（`AssistantCheckup`）关于酒馆预设 `function_calling: false` 阻塞工具插件的告警，收敛为仅在 `agent`（智能体）模式下提示。

## 代价

- 存量未设置或设为 `chat` 的角色升级后直接进入「纯聊天」（不再默认带 `delegate_task` 和直出工具）；需要使用后台子 Agent 派活或定时提醒工具的角色，需在角色编辑页切到「智能体」或「工具」。
