# 0036：内容承载面与悬浮操作面分离

## 背景

全局材质（实色／磨砂／液态玻璃）开关只应作用于真正浮在内容之上的操作级表面，但既有实现让设置分组、编辑卡片等随列表滚动的大块内容背景经 `MoeFloatingSurface` 自动进入液态分支，导致大面积滚动背景随全局玻璃模式变化。用户确认分离方向：液态玻璃只应用于静态、非滚动的小表面，可上下滑动的大块背景不直接接入液态玻璃；落地基线提交 `cb260e17`。

## 备选

- 在 `MoeFloatingSurface` 内增加「内容模式」开关：同一组件两套语义，调用方靠参数区分，后续新增容器仍容易误接液态分支，不采用。
- 新建独立 `MoeContentSurface` 承载内容面语义：采用。
- 把 `liquid_glass_widgets` 的 `LiquidShape` 换成 Figma G2：实际解析版本中 `LiquidShape` 为 sealed，无法替换；悬浮面液态几何保持原状，不在本决策内改造。

## 决定

- 新增 `MoeContentSurface`（`shared/widgets/moe_content_surface.dart`）：默认不透明 `componentBackground` + Figma G2 连续圆角（`moeG2Shape`，cornerSmoothing 0.6），不读取液态分支，不产生自动阴影、描边、文字染色；显式 `blurSigma` 上限 `kMaxContentSurfaceBlurSigma = 8.0`。
- 分离规则：内容承载面（设置分组、编辑卡片、骨架卡、静态阅读面板等，含随列表滚动与静止两类）用 `MoeContentSurface`；悬浮操作面（浮标、按钮、菜单、控制条等真正浮在内容上且需响应全局材质的小表面）继续用 `MoeFloatingSurface`。
- 第一批迁移范围：`MoeSettingsGroup`、`ContactEditCard`、角色编辑骨架卡、设置根页资料卡与入口卡；其余页面按后续批次推进。
- 数据契约不变：无 schema、存储或同步协议改动；`MoeFloatingSurface` 与液态渲染器、shader、依赖均未修改，悬浮面 G2 几何留待后续决策。

## 代价

- 两套表面组件并存，新容器需要按规则选择；若误用悬浮面承载滚动内容会重新引入液态背景问题，由公共组件总览规则与测试约束。
- 操作级表面的 G2 几何统一尚未完成，`LiquidShape` sealed 限制下需要另行评估方案。

## 验收门

迁移后的内容面在全局实色／磨砂／液态三态下均不出现 `MoeLiquidGlass`／`AdaptiveGlass` 且默认无 `BackdropFilter`；显式模糊仅在全局开启且无高对比度／降低透明度辅助要求时生效（否则颜色强制不透明）；既有导航、搜索、对齐与无障碍行为不回退；后续批次逐页迁移。
