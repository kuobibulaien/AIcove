# 0056 · 联网搜索插件：多供应商与内置搜索接管

日期：2026-10-04。用户要求新增搜索服务插件（参照 Exa），随后要求“像管理多个渠道商一样管理搜索供应商”，并在最顶部提供“关闭模型内置搜索，改用此工具”的开关。

决定：

1. 插件 `web_search` 只走 Function Calling，提供 `web_search`／`web_fetch` 两个工具；不注入系统提示词。工具归属登记在 `firstPartyContentTagProviders`（ADR0044），插件关闭时历史调用成对移出请求副本。
2. 搜索供应商是有序列表（`WebSearchConfig.providers`），每家一个 `WebSearchAdapter` 实现，内置 Exa、Tavily、Brave、博查、智谱、Perplexity、Jina、Firecrawl、Serper、SearXNG。`WebSearchService` 按顺序调用，失败切下一家；`web_fetch` 先用带正文接口的供应商，都不行时直接下载网页粗提正文。
3. 内置搜索接管：开关存 `replaceModelBuiltinSearch`。聊天发送时若本轮插件生效、开关打开且模型支持工具调用，`ProviderChatRequestOptions.disableBuiltinWebSearch=true`；`AgentApiClient._prepareChatRequest` 在渠道额外参数合并之后调用 `stripBuiltinWebSearch` 去掉各家内置搜索字段（OpenAI `web_search*`、Claude `web_search_*`／`web_fetch_*`、xAI `x_search`／`search_parameters`、智谱 `{"type":"web_search"}`、Kimi `$web_search`、Gemini `googleSearch`／`urlContext`、`enable_search`、`web_search_options`、OpenRouter `plugins:[{id:"web"}]`），普通函数工具不动。

备选：在每个 ProviderAdapter 里分别判断——将来新增“厂商内置搜索”实现也要逐家配合，容易漏；放在请求体最终出口统一剥离，渠道额外参数里用户手填的内置搜索也能一并去掉。

代价：剥离靠字段名识别，新厂商的新字段需要补进 `builtin_web_search_suppressor.dart`；模型名自带搜索（如 `*-search-preview`、`:online`、Perplexity Sonar）无法通过请求体关闭。配置随云同步，其中含搜索供应商密钥，与模型渠道密钥同口径。

回滚：去掉 `disableBuiltinWebSearch` 字段与 `agent_api.dart` 的调用即可恢复原请求；插件整体回滚删 `features/plugins/web_search/` 及注册行，配置键 `aicove.plugins.web_search.config` 残留无害。
