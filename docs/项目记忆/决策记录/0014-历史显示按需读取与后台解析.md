# 历史显示按需读取与后台解析

日期：2026-09-10
状态：已实现，真机验收记录见需求日志

用户授权：定位再次点击造成的卡顿并修复，先完善统计后以真实日志验收。

## 证据与决定

PKX110 Release同一会话冷加载974ms，读取799ms、解析98ms、投影74ms；20条raw载荷39,284,777字符，其中音频结果、显示快照、补充操作各约13M字符。界面原先先取得全部raw，再决定使用显示快照。

增加前端专用`MessageRepository.getByConversationForDisplay`，沿用稳定游标、软删除/替换过滤及索引。SQLite对有非空`projectedMessages`数组的行只返回显示快照；其他行沿用完整raw。该结果只用于时间线，禁止用于模型上下文、备份或数据库回写。显示缓存无法反序列化时按raw id重新取完整行，由原有投影逻辑重建。数据库记录、schema和媒体来源均不变。

读取窗口的payload与blocks合计达到256Ki字符时，在原生平台通过compute解析、统计和投影，只返回显示消息及数值指标；小载荷直接解析，Web保持直接解析。指标`workerMs`包含任务往返，阶段时间不是帧耗时。

## 验收与回滚

回归覆盖音频URL与文本完整、分页同时间戳顺序、损坏显示缓存回退、原始查询与数据库记录完全不变，沿用冷加载共享、失败恢复、图片维护、索引和窄宽屏日志测试。真机重开同一会话，核对buildId、读取字符数、后台执行标记、显示项数和页面可见时间。

回滚只需恢复前端查询和同步转换代码；不做数据库降级、数据迁移或媒体文件恢复。此改动减少读取搬运与界面线程工作，并未消除磁盘中已有音频副本，也不代表所有卡顿均已解决。
