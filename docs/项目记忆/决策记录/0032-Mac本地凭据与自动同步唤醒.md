# Mac 本地凭据与自动同步唤醒

## 背景

用户明确要求去掉 Mac 登录态的钥匙串保护，并反馈手机发消息后 Mac 没有自动同步。当前开发包使用临时签名，覆盖安装后可能再次请求钥匙串授权。现场两端同步已开启；手机 19:02:24 提交回复，Mac 19:03:00 才刷新，约 36 秒。

## 决定

- macOS 的账号连接和电脑诊断令牌使用 `DeviceCredentialStorage`，保存在应用 Application Support 下的 `local_credentials/`。目录权限 0700、文件 0600，先写临时文件再原子替换；内容未加密。其他平台保留现有安全存储，不修改服务器认证。
- 不自动读取或删除旧钥匙串项，避免迁移本身再次卡在授权框。已有 Mac 安装需要恢复同一账号的登录；本次使用用户此前提供的账号重新认证，核对数据库 account_key 后写入本机文件。密码不保存，令牌不进入项目文件、日志、聊天导出或云同步范围。
- `CloudSyncScheduler` 监听已提交的业务表变更，合并 300 毫秒内的写入，确认 dirty 非空后唤醒上传。事务回滚不发布，远端落库产生的无 dirty 通知不回传。网络忙时本地修改保留一次后续请求，禁止并行跑同步。
- 每 3 秒执行轻量检查，空闲时仅请求现有 `status`；版本与游标未变化、无 dirty/outbox/inbox 时跳过记录和设置扫描。每五次空闲检查执行完整增量检查，补获文件、设置和无 Drift 通知的写入；应用恢复继续立即同步。既有消息快照、附件规则、冲突保护和窗口刷新保持原契约。

## 代价与回滚

本机文件可被同一系统用户下的程序读取，保护弱于钥匙串，此取舍由用户明确接受。macOS 诊断令牌首次切换存储会重新生成，后续重启保持稳定；电脑读取仍需要令牌认证。

可以恢复旧客户端与原存储实现；旧钥匙串、数据库和附件均保留。调度可退回旧 15 秒轮询，不需要服务端部署或数据/schema 迁移。

## 验证

账号持久化测试确认 Mac 未调用安全存储 MethodChannel，重建实例后可读取、覆盖和隔离诊断令牌。自动同步测试覆盖事务提交、运行中追加、避免回传和关闭取消；真实隔离 HTTP 服务双向自动送达约 3 秒，空闲检查只调用 status。实机安装、现场同步与限制记录在 `.codex-temp/account-local-sync-v1/验收记录.md`。
