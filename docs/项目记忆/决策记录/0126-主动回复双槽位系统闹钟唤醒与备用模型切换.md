# 0126：主动回复双槽位系统闹钟唤醒与备用模型切换

升级 [0079](0079-主动回复判断交给决策模型.md)、[0084](0084-主动回复按会话只由一台设备负责.md)。

## 背景

主动回复核心流水线（观察 → 决策模型定计划 → 提前生成草稿 → 到点投递）设计清晰，但在实际手机使用与长时间沉默场景下存在四类结构性断链：

1. **息屏与后台唤醒断链**：
   - `AnalyzerScheduler` 的 5 分钟观察期与 8 小时沉默期仅使用 Dart 内存 `Timer`，手机息屏后进程休眠即停表，且 `observingUntil` 未持久化导致冷启动丢失观察期。
   - `WorkManager` 后台任务对所有主动回复（含已预生成完毕的纯本地 `cached_message`）一律附加 `NetworkType.connected` 约束，在 Android Doze 断网窗口被系统压后数小时；且同一会话有多个 AI 触发器时，后台发完第 1 条便重置为 8 小时沉默窗口，未保留剩余待发计划。
   - 前台轮询误把 `requireExact && !allowExactAlarm` 当成跳过整个触发器的条件，导致未授系统精确闹钟权限时连应用打开期间也不投递。
2. **后台模型请求缺防休眠租约与备用模型切换**：
   - 后台判断、草稿预生成与到期即时生成均未持有原生唤醒锁，请求中途息屏会导致连接与退避计时器被系统冻结数十分钟；且未接入会话对话模型的备用链（Failover），主渠道限流或超时即整轮静默失败。
3. **关键动作衔接漏口**：
   - 5 分钟观察期从用户点发送起算而非 AI 回复落定后起算，且语音通话挂断未纳入活跃事件；全局关闭「允许 AI 设提醒」但单角色单独开启时，`PluginRuntime` 因插件 `isEnabled` 仅读全局布尔值而直接跳过工具注入；云同步拉回 `settings` 时未刷新调度器。
4. **沉默复查提示词与时段自相矛盾**：
   - `ProactiveReachOutKind` 选项说明将“上一轮话已聊完”归入 `stay_silent`，导致 8 小时沉默唤醒复查时模型永远选沉默无法自然破冰；且 `ProactivePlanner` 中 `newTopic` 未开放 `inHalfHour` 与 `inHours` 时段，选 `new_topic` 会被强推至次日早晨。

## 决定

1. **Android 原生双槽位系统闹钟唤醒（`analyzer` + `trigger`）与 WorkManager 精简**：
   - 新增 `ProactiveAlarmScheduler` 与 `ProactiveAlarmReceiver`，按 `analyzer`（最早观察到期／沉默到期）与 `trigger`（最早有效触发器到期，遵守免打扰顺延与负责设备门禁）维护两个独立系统闹钟槽位，持久化在原生配置并在开机、覆盖安装及精确闹钟权限变更时由 `BootCompletedReceiver` 自动恢复。
   - 拥有精确闹钟权限时调 `setExactAndAllowWhileIdle`，未授权时自动降级 `setAndAllowWhileIdle`（不静默丢弃）；闹钟触发时若主界面引擎存活则直通投递，若主界面已销毁则拉起无界面独立 Flutter 引擎（`proactiveAlarmEntrypoint`）带 3 分钟有界唤醒锁排空待办槽位并重算下一拍闹钟。
   - 已缓存好的 `cached_message` 后台任务不再附加 `NetworkType.connected` 约束；删除前台轮询对 `!allowExactAlarm` 的跳过拦截；后台投递完一条 AI 触发器后若同会话仍有待发 AI 触发器，保持 `planned` 状态不覆盖为 8 小时沉默期。
2. **防休眠生成租约、跨引擎互斥与静默备用模型切换**：
   - 后台上下文判断、草稿预生成与到期即时生成全程包裹 `AndroidKeepAliveManager.acquireGenerationLease()` 原生引用计数唤醒锁（单租约带安全超时上限）；`AnalyzerScheduler` 通过 `AutoReplyClaimStore`（`'analyzer:$conversationId'`）跨 Isolate 互斥，杜绝主引擎与无界面引擎并发重复分析。
   - 抽取共享的会话备用模型候选链解析器：未单独指定判断模型（「跟随对话模型」）时判断阶段与草稿生成／即时生成阶段均按主模型 → 备用模型顺序静默切换（仅对非取消错误切换，绝不触发前台确认弹窗）；显式指定独立判断模型时保持单模型隔离不回退聊天模型。
3. **观察期起算点、持久化与单角色提醒开关对齐**：
   - `ConversationProactiveState` 持久化 `observingUntil`，并在 AI 整轮回复结束（`conversationIdleEventsProvider`）及语音通话挂断落库后重新起算 5 分钟观察期；云同步应用 `settings` 后主动触发 `AnalyzerScheduler.refreshSchedule()`。
   - `TriggerPlugin.isEnabled` 在全局开启或任一会话覆盖开启时保持启用，会话内工具暴露统一按 `settings.allowAiSetRemindersFor(conversation)` 裁决，无会话旧 XML 兜底仍仅按全局开关生效。
4. **消除沉默复查提示词矛盾并补齐破冰时段**：
   - 区分“刚聊完几分钟无需硬接”与“已隔数小时且未连着打扰可自然分享新话题”，并在 `ProactivePlanner.allowedSlots[ProactiveReachOutKind.newTopic]` 中补入 `inHalfHour` 与 `inHours`。

## 代价

- Android 侧新增双槽位 `AlarmManager` 持久化调度与无界面引擎入口（复用既有 `KeepAliveWakeLocks` 与 `AutoReplyClaimStore`），换取应用划掉或手机深度休眠后仍能按时分析与投递，同时保持应用静置期 Dart 零周期轮询。
