# 0085 桌面宽屏通话放进独立小窗

- 状态：accepted（2026-10-16 用户要求：宽屏像微信那样另开一个通话小窗）
- 日期：2026-10-16
- 关联：ADR0074（语音通话路线）

## 背景

通话界面原先在聊天页里显示（10-16 改成嵌入视图），宽屏下仍占掉聊天区。用户要的是独立的系统窗口：通话在小窗里，主窗口照常聊天、打字进通话。

Flutter 官方多窗口 API（2026-08 博客发布，所有窗口共用一棵组件树）到 3.47 仍只在 main 渠道的实验开关后面，稳定版用不了。

## 决定

1. **选型**：引入 `desktop_multi_window` 0.3.1（Mac／Windows／Linux）。每个窗口是一个独立引擎，内存不互通。
2. **真相源**：通话（`ActiveVoiceCall`、话筒、合成、播放、存档）只在主窗口引擎里跑。小窗是镜像：主窗口经 `WindowMethodChannel`（每通电话一个通道名）推送状态、计时和外观，小窗回传按钮（话筒、扬声器、挂断、关窗）。协议在 `ui/features/voice_call/window/voice_call_window_protocol.dart`，主窗口一侧是 `VoiceCallWindowLink`，小窗一侧是 `RemoteVoiceCall`；两侧共用 `VoiceCallView`，它只依赖 `VoiceCallControls` 接口。
3. **小窗引擎只注册窗口插件**（`window_manager`，以及它居中要用的 `screen_retriever`）。原生入口是 Mac 的 `MainFlutterWindow.swift`、Windows 的 `flutter_window.cpp`。小窗不碰数据库和设置；`main(args)` 按 `multi_window` 参数分流到 `runVoiceCallWindow`。
4. **外观不写死**：壁纸（聊天页那张）、亮暗、主题色、根界面材质参数（`MoeGlassTheme`）都由主窗口计算（`voiceCallWindowAppearanceOf`）。应用层的 `VoiceCallWindowSync` 在任一项变化时重推。小窗背景用和宽屏根界面同一个 `MoePageSurface`；纯色档不盖这一层，直接露出壁纸。
5. **何时用小窗**：桌面（Mac／Windows）宽屏拨出或接听时决定，整通电话不变。打开失败退回聊天页里的视图。窄屏和手机仍在聊天页里，用左上角收起成悬浮窗。
6. **生命周期**：关小窗即挂断。挂断后小窗显示「通话已结束」，约 1.2 秒后关掉；没接通的留着显示原因。在小窗里的通话不随切换角色或关闭聊天页挂断。不允许并发：同一时间只有一通电话、一个小窗，再点拨号是把小窗提到前面。

## 代价

- 新增一个原生插件依赖，并改了两端原生入口。Windows 原生侧未在本机编译验证。
- 小窗冷启动一个引擎，比页面切换慢，内存多一份。
- 状态要序列化同步；等官方多窗口进稳定版，可换成共用组件树，删掉镜像这一层（通话视图已只依赖接口）。
- 不能用 `windowManager.destroy` 关小窗：它在 Mac 上会退出整个应用，只能取消拦截后 `close`。
- 带小窗时 Mac 调试会话热重启会超时，改代码后要停掉重新 start。

## 验收门

Mac：宽屏拨号弹出小窗；主窗口打字进通话；小窗按钮生效；关窗即挂断并存档；主窗口切换亮暗或材质参数时小窗跟着变。Windows 实机：同上，并确认小窗有系统关闭按钮。
