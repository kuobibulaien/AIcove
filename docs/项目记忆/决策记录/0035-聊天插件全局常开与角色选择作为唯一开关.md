# 0035：聊天插件全局常开，角色选择是唯一生效开关

## 背景

六个普通聊天插件（记忆、表情包、语音、绘图、时间感知、酒馆兼容）的三级详情页顶部曾各有一个全局启用开关。用户明确：三级页不需要顶部开关，插件默认就是开启的；实际控制在单个角色卡/会话的插件选择里。绘图与语音的持久化默认本就是 `false`，若只删 UI 而不归一存储读取，曾被关闭的插件会永久卡死在关态且再无入口打开。

## 备选

- 仅删 UI 开关、保留存储语义：旧存储 `enabled:false` 的插件永久关闭且无恢复入口，不采用。
- 删除 `enabled` 字段：请求快照与测试仍需构造禁用态（如 `TtsPlugin.forRequest`、`VoicePresetApplication` 的角色级闭包），字段保留，不采用。
- 读取层归一 `enabled:true` + 移除六个详情页开关：采用。

## 决定

- 存储读取恒为启用：`MemoryConfig`/`StickerConfig`/`TimeAwarenessConfig`/`TtsConfig` 的 `fromJson` 忽略旧 `enabled` 值；`appSettings.imageGenerationEnabled` 恒为 true；`SillyTavernPresetStore.loadPluginSettings` 恒为启用。
- 六个详情页移除顶部开关及其对内容区的 gating；页面内功能性开关（注入项、预设逐条开关、世界书条目等）保留。
- 聊天插件索引页仅主动关怀保留「已启用/已禁用」徽标。
- 角色侧：`chat_plugin_selector` 与 `character_plugins_section` 不再按全局状态禁用普通插件行；「全局未开启」提示仅对主动关怀生效（其开关耦合前台服务与通知权限，保留）。
- `TavernPluginSettings.enabled` 字段保留但读取端恒 true；`savePluginSettings` 对 `defaultPresetId` 无条件校验，防止旧存的「关 + 坏引用」读成「开 + 坏引用」后每次请求抛错。
- 角色/会话语义不变：`enabledPlugins == null` 全部允许，显式列表只放行列出的插件；酒馆无按角色开关位，由 `recipeId` 绑定表达。

## 代价

- 进程内仍可通过手工构造 `enabled:false` 的快照表达禁用（测试、请求路径），但 UI 与持久化不再有入口。
- 若未来需要重新引入全局关闭，需要同时恢复 UI 入口与存储语义。

## 验收门

六个详情页无顶部开关且内容直接可用；旧存储 `enabled:false` 读取后行为与开启一致；角色卡插件开关仍是生效门槛；主动关怀开关与其服务/权限副作用不变。
