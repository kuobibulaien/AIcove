# 0124：聊天模式三合一为统一路由层与后台执行架构

取代 [0097](0097-角色分聊天模式与工具模式.md)、[0111](0111-Agent模式的角色与AIcove酱同权.md)、[0120](0120-角色模式三档划分（纯聊天、工具、智能体）.md)；升级 [0088](0088-聊天模型委派杂活Agent.md)；由 [0127](0127-主聊天极简双工具收敛与前后台边界加固.md) 进一步收敛。

## 背景

ADR0120 将角色工作模式划为「纯聊天／工具／智能体」三档，在角色编辑页保留了冗余的模式切换：

1. 陪聊角色（`纯聊天`）与路由角色（`智能体`）本不该由用户手动切换模式，而应完全由角色是否开启后台办事能力决定；
2. 干活角色（`工具`，含 AIcove酱与内置漫画家）直接将数十个软件管理、工作区与扩展包工具塞进主对话上下文，既割裂了与「前台路由层＋后台执行助手」双层架构的统一性，也让主对话上下文被大量工具参数与结果污染。

## 决定

1. **废除三档工作模式，统一双层路由架构**：所有角色（普通陪聊角色、内置漫画家与 AIcove酱）主对话统一为轻量化人设路由层，繁重工具与外部办事任务一律由后台助手（`TaskAgentRunner`）执行。角色编辑页移除「角色模式」分段切换。
2. **按有效后台能力自动启停路由工具**：
   - 当角色未开启任何本机可用的后台办事能力（无可用联网搜索、无可用 MCP、无可用扩展包、无定时触发器、无工作区授权、无软件管理权限）时，主对话请求 `supportsToolCalling = false`、`tools = null`（生图走 `<image>` 行内标签），保持纯净零工具请求，杜绝上游抗截断反代因检测 `tools` 字段而注入强制调工具指令；
   - 仅当角色拥有至少一项本机可用的后台办事能力且模型与绑定预设允许工具调用时，主对话才挂载 `delegate_task`／`steer_task`（及稳定生图路由下的 `draw_image`）。
3. **软件管理能力插件化（`aicove_assistant`）**：
   - 原绑定在 `RoleAgentMode.tool` 上的 AIcove 管理工具集、本机全工作空间授权、bash 环境变量渠道 Key 与「修改前每次问我」审批门禁，独立拆为角色能力开关 `aicove_assistant`（界面展示为「软件管理」）。
   - AIcove酱恒定锁定开启该能力，内置漫画家默认开启，存量 `agent_mode == 'tool'` 角色在首次加载迁移时自动补入 `'aicove_assistant'`。
   - 后台 `TaskAgentRunner` 接管 `aicove_*` 与工作区工具执行并复用 `AssistantToolGate`／`AssistantApprovalPort` 审批门禁；主对话仅保留轻量 `aicove-ui` 快捷面板说明与 `uiState` 提醒，不再暴露 `aicove_*` 与工作区工具。
4. **短任务 3 秒当轮秒回，慢任务转后台**：
   - `delegate_task(start)` 默认最多等待 3 秒；3 秒内产生回执的小任务直接认领该回执并将结果（`status`/`summary`/`question`/`detail`/`artifacts`）当轮返回主对话，本轮消息成功落库后完结回执投递防重复转述（若本轮聊天失败未落库则释放认领，交回异步转告兜底）；
   - 超过 3 秒未完成的任务返回 `accepted`，展示淡色等待条并在完成后走异步回执转告。
5. **跨角色取材素材单轮展开与跨轮折叠**：
   - `TaskReceiptBlock` 新增可选 `detail` 字段（上限 16000 字符 / 48 KiB，整块上限 56 KiB），后台助手内置 `submit_reference_material` 工具提交完整摘录素材；
   - `ChatRequestMessageBuilder` 仅在该回执或内联调用之后尚未产生新的已完成 assistant 回复时展开 `detail`，后续轮次自动折叠剥离 `detail`，仅保留简短 `summary`。
6. **兼容与退场**：数据库 `conversations.agent_mode` 列与同步结构保留占位不删，不再驱动运行时分支；主对话长循环插话排队门禁与按模式分叉的摘要口径随之退役，改由主对话随时发起新对话触发 `steer_task`。

## 代价

- 角色开启任一有效后台能力后，主对话请求即带有 `delegate_task`／`steer_task` 工具定义，对极个别强制工具的抗截断中转站，需用户保持关闭不需要的后台能力。
- 超过 3 秒的复杂后台任务仍保留两段式等待与转告链路，以换取主对话上下文长期干净与低成本分层调度。
