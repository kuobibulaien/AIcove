# ADR0053：主动关怀去掉全局总开关

- 日期：2026-10-03
- 状态：accepted
- 范围：主动关怀插件的启用口径、Android 前台保活触发条件、设置页结构。

## 背景

聊天插件页是管理入口，其它插件都常开、由角色卡逐个勾选；只有主动关怀额外挂一个全局 `AutoReplySettings.enabled`，列表上显示「已启用」，角色卡里没开总开关时还会置灰并提示「全局未开启」。同一件事要在两处开，用户不理解。

## 备选

1. 保留总开关，只改页面排版：改动小，但「插件页再开一次」的割裂仍在。
2. 去掉总开关，与其它插件一样只看角色卡勾选；保活改为「至少一个联系人启用主动关怀」时常驻。

## 决定

采用方案 2（用户 2026-10-03 选定）。删除 `AutoReplySettings.enabled` / `guardModeEnabled` 及其存储归一化字段；排程、分析、派发、后台 WorkManager、提醒工具不再读全局开关，仍按会话 `allowsPlugin('trigger')` 判断。`proactiveCareInUseProvider` 由会话列表派生，变化时调用 `AndroidKeepAliveManager.syncGuard`。新建角色默认不勾选主动关怀（与音色一样需手动开启）。设置页首页只留待发送消息、AI 记提醒、打扰程度，模型／提示词／准时提醒／后台运行检查／历史记录收进「更多设置」。

## 代价与回滚

旧版本里「总开关关闭」但角色卡仍是全选（`enabledPlugins == null`）的老角色，升级后会开始主动关怀并常驻保活通知，需要用户在角色卡关掉。回滚恢复两个字段与各门禁即可；旧存储里残留的 `enabled` 键在新版本被归一化丢弃，回滚后默认为关闭。

## 验证

插件页、两层设置页、角色卡插件区、发送链路提醒工具相关自动化测试通过；Android 真机保活启停未验。
