# 0019 · Mac基准与全端共用界面架构

- 授权：用户准备重写全端，明确以 Mac 为基准、窄屏即手机、宽屏左侧悬浮完整手机界面并在右侧展开二级界面，要求尽量共用一套布局，并授权自行修改相排斥的规范。
- 实施状态：架构规范已确认；本批仅更新文档，现有壳可作为基础，不能视为各端重写已完成。
- 替代：ADR0018的当前架构要求；ADR0016仍为已否决方案。

## 背景

旧《界面布局说明》同时包含MainPage／SplitChatPage双首页、宽屏只切活跃聊天、桌面专属样式和后续追加的统一悬浮布局。根规范又有“旧链路不做大重构”要求，容易被误读为不允许前端整体重写。只在末尾继续追加无法避免后续开发沿用旧条款。

## 决定

1. 以[全端共用界面架构与布局规范](../../../apps/aicove_flutter/docs/界面布局说明.md)为页面、布局、导航和复用边界的唯一权威，不复制第二份详细规范。
2. Mac作为共享设计与首轮验收基准；窄屏就是手机布局。宽屏左侧完整手机一级界面整体悬浮，右侧显示窄屏同一份二级及更深页面，两种模式的业务页面集合相同。
3. 共用完整页面、标题、导航、表单、菜单与业务状态；布局壳改变位置与局部尺寸，平台能力适配承接原生窗口、安全区和输入差异。禁止独立手机／桌面业务页面和重复运行的聊天实例。
4. 统一导航目标、退栈及草稿保护语义；跨断点保持页面身份、搜索、滚动、详情栈与任务归属。左侧始终按自己的手机宽度排版，不读取全窗宽度后再创建宽屏布局。
5. 复用并演进MainPage、MoeAdaptiveShell、MoeWorkspace与Moe组件。900断点及既有悬浮尺寸作为当前集中管理的基线，可经共同验收调整，不把历史实现细节当作重写限制。
6. 原位修改有效文档中的冲突条款；历史ADR注明替代关系，保留当时结果。前端可整体重写并分批交付，业务端口、数据安全及已保存配置继续保留原有契约。

## 备选与代价

- 分别写手机版与Mac版，再抽部分列表组件：重复维护导航、表单及状态，无法保证功能一致，不采用。
- 只把手机界面缩成左侧图片／独立实例：交互与任务会重复，无法共享右侧详情，不采用。
- 共用页面、布局壳决定承载位置：采用。代价是必须收口平台样式分支、统一局部约束与导航语义，并验证缩放期间的状态及弹层归属；Mac窄窗仍不能代替真实手机键盘和返回验收。

## 验收门与边界

规范批次核对主文、项目宪法、Agent入口、组件说明、术语及ADR索引一致；本次不修改源码、运行应用或安装。

实施批次按主文第8节验收：页面集合与唯一实现映射、Mac宽窄窗口及899／900／901断点、左侧320／360／440局部宽度、草稿与详情栈跨断点保持、运行中不重复请求、菜单和转场、真实手机安全区／软键盘／系统返回。未验证平台单列缺口，不以历史构建或截图代替。

本决定不改变Flutter与现有业务契约，不将DSH proposed方案转为accepted，不自动增加Web发布要求，也不授权数据迁移、生产请求或部署。
