## 聊天与杂活都收集 v2 请求贡献

`resolveTaskPluginCapabilities` 不再识别 WebSearchPlugin／McpConnectorPlugin／PackagePlugin 具体类型，统一使用 `PluginRuntime.selectForRole` 和 `requestScopes`。生产入口仍先等待 `ensurePluginConfigsLoaded`，传入真实 Ref、设置、会话与角色选择；无 conversationId 也可收集办公插件和扩展包。

- 角色筛选后只接纳 `isOfficePluginId(id) || id.startsWith('pkg:')`。全局办公谓词不含 package，避免把普通聊天的包能力重定向到 delegate_task；memory、image、trigger、tts 等不进入杂活请求。
- 每个 scope 先 await prompt，再取 tools，保留 `toolOwners` 与按插件分组的 prompts；TaskAgentRunner 继续按 preset 同时缩窄两者。
- `PluginRequestInputs.packageExecutable` 缺省 true，PackageRequestScope 原样转交给包工具构建器。杂活默认可执行；普通聊天传 false、工具模式传 true，删除核心按具体 PackagePlugin 再过滤工具名的分支。false 时保留包提示词和技能读取，不暴露注册脚本／技能执行工具，读取工具说明也不引导调用被隐藏的执行工具。准备提示词仍加载包的脚本声明，与原路径一致。

## 装配生命周期与执行生命周期分开

`requestScopes` 改为惰性 Iterable：取得一个 scope 就立即登记或完成其清理，不能先展开整份列表再登记，否则后续工厂异常会遗失前面已构造的对象。

- 杂活每个 scope 在 finally 中 await dispose；runtime 安装也在 try 内，外层 finally 释放 KernelScope。
- 聊天 backend 逐个把 scope.dispose 登记为 KernelScope closer，再等待工作区与其他装配步骤；finally 释放全部 scope 和 runtime。单个 closer 抛错时，KernelScope 仍尝试其余清理。
- 缓存／主动交付的 ChatSendService 已在第三步采用 runtime try/finally，本轮核查后保留。
- `PluginRequestScope.dispose` 只释放装配资源。返回的工具、延迟提醒、工作区选择与预设运行时 opener 必须在装配结束后仍有效；实际执行资源由工具／内核运行自行开启和关闭。注册表中的插件实例是借用对象，不随请求装配销毁。

## 注册表不再冒充旧生命周期协调器

删除无生产、测试与工具调用的 PluginManager.initialize／enable／disable／destroy／initializeAll／destroyAll／updatePluginConfig／getPluginConfig，只保留注册、替换、注销、查询与 clear。插件自身仍在使用的生命周期／配置接口不在本次删除范围。
