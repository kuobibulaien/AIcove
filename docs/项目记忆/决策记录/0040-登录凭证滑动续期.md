# 0040：登录凭证滑动续期

> 2026-10-01：指定长期账号由 [ADR0049](0049-指定账号长期登录态.md) 部分取代，其余账号保留本决定。

## 背景

2026-09-23 排查“Mac 与手机同步失效”：Mac 本机账号文件在 09-21 11:38 被写成空 token，此后不再同步。根因是服务端 JWT 固定 7 天（`ACCESS_TOKEN_EXPIRE_MINUTES=10080`）且客户端从不续期；到期后应用启动刷新账号收到 401，按设计退出登录并保留本地数据。长期运行的应用在到期后同步请求直接 401，下次启动再被登出。结果是每台设备登录满 7 天必断一次。

## 备选

- 只把有效期调长（如 90 天）：改一个环境变量，但只是把断线推迟，到期照样断。
- 刷新令牌＋服务端会话表与吊销：最完整，但要新增表、迁移和吊销管理；当前没有任何吊销需求，属于过度设计。
- 滑动续期：用仍有效的 token 换新 token，设备只要在有效期内用过一次就不会掉线：采用。

## 决定

- 服务端新增 `POST /api/v1/auth/refresh`（`cloud_backend/auth.py`，由 `sync_v3/app.py` 注册）：鉴权沿用 `get_current_user`，过期、无效或已停用账号返回 401／403，成功返回与登录相同的 `TokenResponse`。无状态，不加表。
- 客户端 `AccountRepository.refresh()` 校验 `/me` 后调用 `AccountRemotePort.renew` 换新 token 并保存；续期返回的账号不是本机绑定账号时按失效处理。服务端未部署该接口（404／405）时保留原 token，兼容旧服务端。
- `AccountController` 除启动时刷新外，每 6 小时后台静默续期；网络等临时失败不提示，只有会话被拒（仓库已登出）才更新界面错误。
- 同一账号的 token 变化时，`CloudSyncController` 只调用 `CloudApi.updateToken` 换请求头并触发一次同步，不重建同步引擎；换账号或登出仍走原有重建路径。

## 代价

- 设备连续超过服务端有效期（默认 7 天）未打开应用，仍需重新登录一次。
- 无状态 JWT 无法吊销：泄露的 token 只要持续续期就一直有效；这与续期前“7 天内无法吊销”属同一类风险。以后需要吊销时再引入会话表。
- 客户端依赖服务端部署新接口才生效；部署前行为与原来一致。
