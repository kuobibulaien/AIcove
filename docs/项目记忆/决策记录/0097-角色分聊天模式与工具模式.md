# 0097：角色分聊天模式与工具模式

关联：ADR0073／0093（AIcove酱与全权限）、ADR0087／0088（工作区与杂活 Agent）。

## 背景

ADR0088 让所有角色的聊天模型都只拿到 `delegate_task`，联网搜索、MCP、工作区一律交给后台杂活助手。这对普通角色合适，但 AIcove酱是完整的管家，她却也要靠派活去办事：查资料、写工作区都绕一圈后台，结果回执还要再转述一次。角色之间也没有区分「只陪聊」和「直接干活」两种用法。

## 决定

1. 角色有两种工作模式，存在会话表 `agent_mode` 列（v25，取值 `chat`／`tool`，null 为聊天模式）：
   - **聊天模式**（默认，包括内置纳西妲）：联网搜索、MCP 交给后台杂活助手；聊天模型不直接拿这些工具，只拿 `delegate_task`。
   - **工具模式**：角色本身是完整 Agent，直接使用这个角色开启的全部插件工具（联网搜索、MCP）和工作区工具，不派活，`delegate_task` 不装配。
2. AIcove酱恒为工具模式（`Conversation.effectiveAgentMode` 按 id 强制），角色编辑页里锁定、不能切换；其余角色在角色编辑页的「角色模式」里切换。
3. 工作区与授权规则不变：工具模式的角色用和杂活助手相同的授权（角色授权 ∩ 本机存在），在它自己的会话里新建的工作区记到角色名下。
4. 聊天模式下，角色自己开启的非办事类插件（绘图、语音、时间感知等）仍然直接用，不因模式改成派活。只有办事类（联网搜索、MCP、工作区）改走后台。

## 代价

- 聊天模式下的绘图、语音等工具没有改成派活，因此「唯一的工具调用是派活」只对办事类成立。若要严格只留派活，绘图等要在后台 Agent 里重新装配，另立决定。
- 工具模式的角色不会有后台回执，联网搜索或写文件失败时由它自己在对话里说明。
- 工具模式的角色上下文更大（工具定义更多），模型能力不足时可能选错工具，角色编辑页的说明里写明了这一点。
- 同步协议的 `client_schema` 升到 21，旧版本设备收到带 `agent_mode` 的会话会拒绝接收，需要升级后再同步。

## 备注

- AIcove酱的工作模式不能由她自己改（资料库与工具都没有这一项），避免她把自己切回聊天模式。
