# 0065 诊断导出分级与按关联范围选择

- 状态：accepted（代码未实施）
- 日期：2026-10-07
- 关联：ADR0005（前端响应诊断与单轮 Trace 导出）、ADR0006（诊断证据与 Agent 自动抓取）、ADR0013（Release 受控诊断出口）；定位见项目记忆 README（本地隐私优先）

## 背景

现有两类导出各自成立，但没有作为一对供用户选择：

- 诊断日志（ADR0006）：`DiagnosticFacts` 只接受数值、布尔与枚举原因，采集器按字段允许列表过滤，不保存自由文本。
- 单轮 Trace 导出（ADR0005，`TraceExportPort`）：导出所选轮次的 events／apiLogs／payload／appLogs，payload 含完整请求正文。

导出范围方面，单轮导出按 `turnId`／`traceId` 关联；电脑端 `tool/collect_diagnostics.py` 主要按时间窗（`--since`）。没有记录关联编号的旧事件无法事后补齐（ADR0005 已注明）。

用户关心两点：日志默认不暴露对话正文但排查时能拿到完整内容；导出给他人时范围可控，而不是只能按日期。

## 备选

1. 黑名单脱敏：默认把用户原文与模型回复替换掉，其余字段保留。正文会经搜索关键词、画图提示词、TTS 文本、提醒／记忆标题、报错信息等字段漏出，新字段默认放行，不可靠。
2. 白名单分级＋按关联范围选择。

## 决定

采用 2。

### 两档导出

- **诊断版**（默认）：只含白名单字段——编号、计数、耗时、状态、错误码与枚举原因、构建与设备身份。任何未列入白名单的字段默认丢弃，新增字段须显式加入白名单。沿用 ADR0006 的 `DiagnosticFacts` 与采集器允许列表。
- **完整版**：在诊断版基础上附所选范围内的请求正文、回复正文、装配记录（`traceAssembly`）。仅由用户在本机主动选择，导出前明确提示“包含对话正文”。
- 两档共用同一范围选择与同一过滤快照（ADR0013 的出口），不另建通路。

### 范围选择

按优先级提供：

1. **按一次问题**：从气泡或日志条目选中一轮，导出该 `turnId`／`traceId` 及其父子关联闭包（沿用 ADR0006 的关联闭包）。
2. **按会话**：限定单个联系人会话；任何导出都不得混入其他会话的内容。
3. **按模块**：同步、音频、聊天发送、插件、记忆等分类，可多选。
4. **按异常锚点**：选中一条错误，取其前后可配置时间窗内同会话、同运行的记录。
5. **按应用运行**：按 `appRunId`，用于闪退与启动问题。
6. **按时间**：兜底，相对时间（如最近 2 小时）。

每次导出固定附**环境说明**：应用版本、构建编号、平台与设备型号、关键设置摘要（不含正文）。

### 源头打编号

- 任何新增记录点在产生时必须带上所属的轮次（如有）、会话（如有）、应用运行与模块编号；不得依赖事后按时间推断归属。
- 统一事件流（ADR0060 落地后）在一处为事件打编号；在此之前，新记录点各自遵守本条。

### 导出前预览

导出前展示内容清单：档位、范围、各模块条数、时间跨度、是否含正文、预估大小；用户确认后再生成文件。

## 验收项

1. 诊断版导出中只出现白名单字段，有测试：构造带正文的搜索词、画图提示、TTS 文本、报错信息，断言诊断版中均不出现。
2. 任一范围导出都不含其他会话内容，有测试。
3. 新增记录点缺少必需编号时测试失败（或静态检查拦截）。
4. 两档导出的范围与条数一致，差别只在正文字段。
5. 导出前预览的条数与实际文件一致。

## 代价

- 白名单需要随新字段维护，漏加会让排查信息缺失（安全侧失败，可接受）。
- 旧记录缺编号，只能按时间兜底，无法按关联精确选取。
- 电脑端采集脚本需要支持按关联与模块选择，不再只按时间窗。
