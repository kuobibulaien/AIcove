# 0067 请求用量与缓存观测，及请求前缀稳定

- 状态：accepted（代码未实施）
- 日期：2026-10-07
- 关联：ADR0038（记忆与上下文）、ADR0061（旧工具结果清理）、ADR0063（请求前提醒钩子）、ADR0065（诊断导出）

## 背景

- **看不到用量**：`core/models/chat_response.dart` 的 `TokenUsage` 只有 prompt／completion／total，没有缓存字段，且全项目无引用；各供应商返回的用量与缓存命中均未读取，无法知道命中率与成本，也无法验证 ADR0061 等“保护缓存”的做法是否生效。
- **前缀疑似每轮变化**：无绑定预设时，请求第一条 system 消息由人设、交接提示与所有插件 `getSystemPrompt` 结果拼成（`features/chat/services/chat_send_backend_service.dart` 约 513–515、666–672 行）。记忆插件 `MemoryPlugin.getSystemPrompt` 返回“常驻层＋按本轮输入与最近 4 条检索的档案”，画图插件请求提示随“是否有失败提醒”变化。开头一变，整段历史的前缀缓存失效。有绑定预设时的放置位置未核实。以上为读代码推断，需数据证实。
- **钩子是否生效不可见**：`PluginPromptEntry` 已有 `injected`／`reason`／`error` 字段，但是否进入诊断日志未核实。

## 决定

分三步，每步可独立验收与回滚。

1. **先观测**：按供应商读取用量与缓存字段（OpenAI 兼容的 `prompt_tokens_details.cached_tokens`、DeepSeek 的缓存命中／未命中字段、Anthropic 的缓存读写字段、Gemini 的缓存计数等，实施时以官方文档为准），流式请求开启返回用量的选项。每轮只把数字写入诊断日志（ADR0065 白名单字段）：输入、输出、缓存命中、缓存写入、模型、供应商。同时把每个插件钩子的生效／跳过／出错、原因与贡献字数写入诊断日志，不含正文。另记录每轮上下文占窗口的比例，以及自动压缩、运行时压缩、旧工具结果清理的触发次数，用于判断压缩质量是否值得投入（2026-10-07 用户判断：默认窗口冗余大，压缩应很少触发，以数据为准）。
2. **稳定前缀**：请求开头只放稳定内容（人设、规则、常驻记忆、全局标签说明）；按本轮变化的内容（检索出的记忆档案、时间提醒、画图失败提醒等）移到末尾，与现有提醒一样放在最后一条用户消息之前，经 ADR0063 的请求前钩子贡献。有绑定预设时同样遵守，放置细节实施时定。Anthropic 需显式标注缓存断点，实施前查官方文档确认。
3. **对比验证**：用默认测试模型 DeepSeek Flash 对同一段长对话，比较第 2 步前后的缓存命中率，结果写入需求日志。

## 验收项

1. 每轮诊断日志有用量与缓存命中数字，单测覆盖各供应商字段解析与缺失时的降级。
2. 钩子生效记录只含插件名、状态、原因与字数，测试断言不含正文。
3. 同一会话连续两轮请求，除末尾变化部分外前缀逐字一致（单测）。
4. 第 3 步真实对比数据。

## 代价

- 各供应商用量字段不同，需逐家适配与维护。
- 检索档案移到末尾后，模型对它的注意方式可能变化，需在第 3 步顺带观察回复质量。
