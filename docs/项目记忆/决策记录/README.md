# 决策记录索引

> 架构级决策一事一文件，编号递增。文件格式：frontmatter（status / date）+ 背景 / 决定 / 代价 / 验收门。
> ADR 记录"为什么这样定"，不是待办清单；项目整体进度以 [项目记忆 README](../README.md)「当前重点」 为准。

## 两列状态的含义

| 列 | 取值 | 含义 |
|---|---|---|
| 决定 | 生效 | 决定当前有效（frontmatter `accepted` / `implemented`） |
| | 部分取代 → N | 部分条款被 ADR N 修订，其余仍有效 |
| | 已取代 → N | 整体被 ADR N 取代，保留历史 |
| | 已撤回 / 已否决 | 不再作为实现依据，代码已回退 |
| | 待确认 | 提出待用户拍板（frontmatter `proposed`） |
| 落地 | 已完成 | 代码已实现，已有真机或真实环境验证 |
| | 待实测 | 代码与离线测试完成，真机／真实模型／多设备尚未验证 |
| | 部分 | 分批交付，只完成了前几批 |
| | 未开工 | 只有决定，代码未动 |
| | — | 已取代／撤回／否决，或纯规则类无需落地 |

新增 ADR 时在表尾加一行；落地进度变化时同步改「落地」与「剩余」两列，不另起段落。
