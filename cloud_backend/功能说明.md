# Cloud Backend 功能详解（小白版）

## 🎯 这个后端是干什么的？

**一句话总结：** 这是一个以「云端数据服务」为核心的后端，主要负责：
1. **管理账号**：用户注册、登录、鉴权
2. **管理数据**：同步（含 v2）、备份/恢复、回收站等
3. **扩展能力**：云触发器、云记忆库、Key 分发与额度

**它不做什么：**
- ❌ 不负责AI对话（这个在Flutter客户端做）
- ❌ 不调用OpenAI/Gemini（这个在Flutter客户端做）
- ❌ 不处理语音（这个在Flutter客户端做）

### 1️⃣ main.py - 服务器入口

**作用：** 启动Web服务器，把所有功能连接起来

**代码结构：**
```python
from fastapi import FastAPI

app = FastAPI()  # 创建服务器应用

# 注册各个功能模块
app.include_router(auth_router)      # 认证功能

app.include_router(sync_v2_router)   # 同步功能（v2）

app.include_router(admin_router)     # 管理功能

# 根路径（访问首页）
@app.get("/")
def root():
    return {"service": "MyGril Cloud Sync"}

# 健康检查（检查服务是否正常）
@app.get("/health")

    return {"status": "ok"}
```

**你访问后端时：**
- `http://localhost:8000/` → 显示服务信息
- `http://localhost:8000/health` → 显示"ok"（服务正常）
- `http://localhost:8000/docs` → 显示API文档（自动生成）
- `http://localhost:8000/app/#/` → Web版前端（如果已构建 Flutter Web 并被挂载）

### 2️⃣ auth.py - 认证模块

**作用：** 管理用户账号，验证身份

#### 功能列表：

##### 📝 注册新账号
```
POST /api/v1/auth/register

请求数据：
{
  "username": "张三",
  "password": "123456",
  "email": "zhangsan@example.com",
  "invite_code": "ABC123"  // 可选
}

返回数据：
{
  "access_token": "eyJhbGc...",  // 登录凭证
  "user": {
    "id": 1,
    "username": "张三",
    "email": "zhangsan@example.com"
  }
}
```

**干了什么：**
1. 检查用户名是否已存在
2. 检查邀请码是否有效（如果需要）
3. 加密密码（用Bcrypt加密，不会明文存储）
4. 保存到数据库
5. 生成登录Token（JWT）

##### 🔑 登录账号
```
POST /api/v1/auth/login

请求数据：
{
  "username": "张三",
  "password": "123456"
}

返回数据：
{
  "access_token": "eyJhbGc...",
  "user": { ... }
}
```

**干了什么：**
1. 查找用户
2. 验证密码
3. 生成Token（有效期7天）

##### 👤 获取当前用户信息
```
GET /api/v1/auth/me
Headers: Authorization: Bearer eyJhbGc...

返回数据：
{
  "id": 1,
  "username": "张三",
  "email": "zhangsan@example.com",
  "is_admin": false
}
```

**干了什么：**
1. 从Token中解析用户ID
2. 从数据库查询用户信息
3. 返回用户数据

##### 👑 创建首个管理员
```
POST /api/v1/auth/bootstrap-admin

请求数据：
{
  "username": "admin",
  "password": "admin123"
}
```

**干了什么：**
1. 检查是否已有用户（如果有就拒绝）
2. 创建管理员账号
3. 设置is_admin=true

### 3️⃣ sync_api.py - 数据同步

**作用：** 在云端和本地之间同步数据

#### 功能列表：

##### 📇 联系人同步

**获取所有联系人：**
```
GET /api/v1/sync/contacts
Headers: Authorization: Bearer xxx

返回数据：
{
  "contacts": [
    {
      "contact_id": "uuid-123",
      "name": "小美",
      "avatar_url": "https://...",
      "character_data": {
        "system_prompt": "你是一个温柔的女友...",
        "personality": "温柔"
      },
      "updated_at": "2025-01-14T10:00:00Z"
    }
  ],
  "count": 1
}
```

**批量上传联系人：**
```
POST /api/v1/sync/contacts

请求数据：
{
  "items": [
    {
      "contact_id": "uuid-123",
      "name": "小美",
      "avatar_url": "https://...",
      "character_data": { ... },
      "updated_at": "2025-01-14T10:00:00Z"
    }
  ]
}

返回数据：
{
  "synced": 1,           // 成功同步的数量
  "conflicts": [],       // 冲突列表（如果有）
  "errors": []           // 错误列表
}
```

**干了什么：**
1. 遍历每个联系人
2. 检查是否已存在（用contact_id判断）
3. 如果存在：
   - 比较updated_at时间戳
   - 如果服务器版本更新，报告冲突
   - 否则更新数据
4. 如果不存在：创建新记录

##### 💬 消息同步

**获取消息：**
```
GET /api/v1/sync/messages?contact_id=uuid-123&since=2025-01-14T10:00:00Z

返回数据：
{
  "messages": [
    {
      "message_id": "msg-456",
      "contact_id": "uuid-123",
      "role": "user",          // 用户消息
      "content": "你好",
      "created_at": "2025-01-14T10:05:00Z"
    },
    {
      "message_id": "msg-457",
      "contact_id": "uuid-123",
      "role": "assistant",     // AI回复
      "content": "你好呀~",
      "created_at": "2025-01-14T10:05:10Z"
    }
  ],
  "count": 2,
  "has_more": false
}
```

**批量上传消息：**
```
POST /api/v1/sync/messages

请求数据：
{
  "items": [
    {
      "message_id": "msg-456",
      "contact_id": "uuid-123",
      "role": "user",
      "content": "你好",
      "created_at": "2025-01-14T10:05:00Z"
    }
  ]
}

返回数据：
{
  "synced": 1,      // 成功上传的数量
  "skipped": 0,     // 已存在的（跳过）
  "errors": []
}
```

**干了什么：**
1. 检查每条消息是否已存在（用message_id）
2. 已存在的跳过（避免重复）
3. 新消息插入数据库

### 6️⃣ database.py - 数据库连接

**作用：** 连接SQLite数据库，创建表

**代码逻辑：**
```python
# 1. 连接数据库
DATABASE_URL = "sqlite:///./data/sync.db"
engine = create_engine(DATABASE_URL)

# 2. 创建会话工厂
SessionLocal = sessionmaker(bind=engine)

# 3. 初始化数据库表
def init_db():
    # 导入所有模型
    from models import User, Contact, Message, ...
    
    # 创建所有表
    Base.metadata.create_all(bind=engine)

# 4. 获取数据库会话（给API用）
def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

**数据存储位置：**
- 数据库文件：`cloud_backend/data/sync.db`
- SQLite格式，可以用工具查看

### 场景2：冲突处理

**情况：** 用户在两个设备上同时修改了同一个联系人

**设备1：**
```
修改"小美"的名字为"小美美"
updated_at: 2025-01-14 10:00:00
```

**设备2：**
```
修改"小美"的头像
updated_at: 2025-01-14 10:01:00  （晚1分钟）
```

**同步时：**
```
设备1 → POST /api/v1/sync/contacts
        {name: "小美美", updated_at: "10:00:00"}

后端：保存成功 ✅

设备2 → POST /api/v1/sync/contacts
        {avatar: "new.jpg", updated_at: "10:01:00"}

后端：检测到冲突！
      服务器版本(10:00:00) < 客户端版本(10:01:00)
      
后端 → 设备2
       {conflicts: [{
         reason: "服务器版本更新",
         server_version: {name: "小美美", ...},
         client_version: {avatar: "new.jpg", ...}
       }]}
```

**当前策略：** 服务器版本优先（Server-Wins）

## 🔐 安全机制

### 1. 密码加密
```python
from passlib.context import CryptContext

pwd_context = CryptContext(schemes=["bcrypt"])

# 注册时：
hashed = pwd_context.hash("123456")
# 存储：$2b$12$xxx...（不是明文）

# 登录时：
pwd_context.verify("123456", hashed)  # True
```

### 2. JWT Token
```python
from jose import jwt

# 生成Token
payload = {"sub": user_id, "exp": 过期时间}
token = jwt.encode(payload, SECRET_KEY, "HS256")

# 验证Token
payload = jwt.decode(token, SECRET_KEY, "HS256")
user_id = payload["sub"]
```

**Token内容示例：**
```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.
eyJzdWIiOjEsImV4cCI6MTcwNTIwMDAwMH0.
xxx...

解码后：
{
  "sub": 1,              // 用户ID
  "exp": 1705200000      // 过期时间
}
```

### 3. API认证
```python
# 每个需要认证的API都会：
1. 从请求头读取Token
2. 解码Token获取user_id
3. 验证用户是否存在
4. 执行操作
```

## 🛠️ 如何修改功能

### 示例：添加"收藏消息"功能

**第1步：修改数据模型（models.py）**
```python
class Message(Base):
    # ... 现有字段 ...
    is_favorited = Column(Boolean, default=False)  # 新增
```

**第2步：添加API（sync_api.py）**
```python
@router.patch("/messages/{message_id}/favorite")
async def favorite_message(
    message_id: str,
    is_favorited: bool,
    user_id: int = Depends(get_current_user),
    db: Session = Depends(get_db)
):
    message = db.query(Message).filter(
        Message.message_id == message_id,
        Message.user_id == user_id
    ).first()
    
    if not message:
        raise HTTPException(404, "消息不存在")
    
    message.is_favorited = is_favorited
    db.commit()
    
    return {"status": "ok"}
```

**第3步：重启服务**
```bash
# 数据库会自动添加新字段
python main.py
```

**第4步：在Flutter中调用**
```dart
await apiClient.dio.patch(
  '/api/v1/sync/messages/$messageId/favorite',
  data: {'is_favorited': true},
);
```

## ❓ 常见疑问解答

### Q1: 为什么不把AI逻辑放后端？
**A:** 
- 后端要处理所有用户的请求，压力大
- 用户API Key在客户端，更安全
- 客户端直接调用AI，速度快

### Q2: 数据存在哪里？
**A:**

## 🎖️ 会员分级系统和云服务

### 概述

现在后端支持**会员分级系统**，不同等级的用户可以使用不同的云服务功能。

#### 会员等级：
- **Level 0（免费）**：基础同步功能
- **Level 1（基础）**：+ 数据备份
- **Level 2（标准）**：+ Key分发和额度管理
- **Level 3（高级）**：+ 云触发器
- **Level 4（专业）**：+ 云记忆库
- **Level 99（管理员）**：所有功能 + 管理后台

### 7️⃣ Key分发系统（Level 2+）

**作用：** 管理员统一管理API Key，用户申请使用，自动扣除额度

#### 核心概念：
```
管理员 → 添加OpenAI Key到池子（总额度10万tokens）
       → 分配给用户A（月额度5000 tokens）

用户A → 请求使用OpenAI Key
      → 消耗100 tokens
      → 剩余额度4900 tokens
```

#### API端点：

**用户端：**

```
# 获取可用的Provider列表
GET /api/v1/keys/providers
返回: ["openai", "gemini", "claude"]

# 申请使用Key
POST /api/v1/keys/request
{
  "provider": "openai",
  "estimated_tokens": 100
}
返回: {
  "api_key": "sk-xxx...",  // 解密后的Key
  "quota_remaining": 4900
}

# 查看我的额度
GET /api/v1/keys/quota
返回: {
  "openai": {
    "quota_total": 5000,
    "quota_used": 100,
    "quota_remaining": 4900,
    "reset_at": "2025-02-01T00:00:00Z"
  }
}
```

**管理员端：**

```
# 添加Key到池子
POST /api/v1/keys/admin/pool
{
  "provider": "openai",
  "api_key": "sk-xxx...",
  "quota_total": 100000
}

# 分配额度给用户
POST /api/v1/keys/admin/assign
{
  "unique_id": "USER-00001",
  "provider": "openai",
  "quota_total": 5000,
  "monthly_reset": true  // 每月自动重置
}

# 查看使用统计
GET /api/v1/keys/admin/overview
```

### 9️⃣ 云触发器（Level 3+）

**作用：** 自动化任务，支持定时触发、事件触发、条件触发

#### 触发器类型：

1. **定时触发（schedule）**
```json
{
  "trigger_type": "schedule",
  "trigger_config": {
    "cron": "0 9 * * *",  // 每天9点
    "timezone": "Asia/Shanghai"
  },
  "action_config": {
    "action_type": "backup"  // 自动备份
  }
}
```

2. **事件触发（event）**
```json
{
  "trigger_type": "event",
  "trigger_config": {
    "event_type": "new_message"  // 新消息到达时
  },
  "action_config": {
    "action_type": "notification"
  }
}
```

3. **条件触发（condition）**
```json
{
  "trigger_type": "condition",
  "trigger_config": {
    "condition_type": "quota_low",
    "threshold": 100  // 额度低于100时
  },
  "action_config": {
    "action_type": "notification",
    "params": {
      "message": "额度即将用完"
    }
  }
}
```

#### API端点：

```
# 创建触发器
POST /api/v1/triggers/create
{
  "trigger_name": "每日自动备份",
  "trigger_type": "schedule",
  "trigger_config": {...},
  "action_config": {...}
}

# 获取触发器列表
GET /api/v1/triggers/list

# 启用/禁用触发器
POST /api/v1/triggers/1/toggle

# 查看执行日志
GET /api/v1/triggers/1/logs

# 触发器统计
GET /api/v1/triggers/stats/my
```

```bash
curl -X POST http://localhost:8000/api/v1/keys/admin/assign \

  -d '{"unique_id": "USER-00001", "provider": "openai", "quota_total": 5000}'
```

```bash
curl -X POST http://localhost:8000/api/v1/keys/request \
```

```dart
// Flutter客户端
```
