## 0. 结论：先做 Web 管理端，App 端暂缓迁移

本阶段不在 Flutter App 里先做完整 Agent 上下文管理 UI。正确路线改为：

```text
cloud_backend Web 管理端先成熟
        ↓
沉淀 AgentDefinition / ContextProfile / ContextRecipe / Asset Library / Preview / Trace
        ↓
稳定后再把联系人级 ChatAgent 配置迁移到 App 端
```

原因：

1. Agent 上下文系统还在抽象期，Web 管理端迭代快、调试成本低。
2. SillyTavern 预设、世界书、regex、prompt_order、trace 预览都适合先在大屏管理。
3. App 端只适合承载成熟后的轻量编辑，不适合先承载复杂导入、结构调试和迁移工具。
4. `cloud_backend` 已经有 Prompt Studio / Agent Builder 基础：`prompt_defaults_admin_api.py` + `prompt_defaults_admin_panel.html`，可以复用思路扩展。

## 1. 正确架构口径

AIcove 要做的是 **Agent 上下文管理系统**，不是提示词管理系统。

```text
AgentDefinition
  = ModelRef
  + ContextProfile
  + ContextRecipe
  + ContextAssemblyPermissions
  + ToolPolicy
  + OutputContract
  + PostProcessors / DeliveryChannel
```

所有 Agent 都有同一套定义面；区别是权限和职责边界：

| Agent | 权限口径 | 说明 |
|---|---|---|
| ChatAgent | `full_chat` | 联系人级前台聊天，拥有完整上下文装配权限 |
| ProactiveAgent | `proactive_specialized` | 主动关怀，读取联系人上下文但输出受审核 / 投递策略限制 |
| AnalyzerAgent | `analyzer_specialized` | 后台分析，偏窗口、记忆、运行时事实、JSON 决策 |
| MemoryAgent | `memory_specialized` | 记忆总结 / 写入，不做聊天风格渲染 |
| RendererAgent | `renderer_specialized` | 消费输出事件和工具策略，不重新组装角色卡 / 世界书 |

联系人级 ChatAgent 第一阶段仍按：

```text
contactId == conversation.id
agentId = chat_agent:<contactId>
contextRecipeId = standard_chat_recipe:<contactId>
```

## 3. Web 管理端目标

新增一个 **Agent Context Studio**，定位是管理和验证 Agent 上下文节点，不是普通 App 设置页。二改后的前端主口径是 **Node Studio + Agent Build 流程图**：Node Studio 管所有组成上下文的元素，Agent Build 像流程图一样拼装节点库子节点；触发策略和 Agent Flow 字段折叠进画布右侧属性面板，不再做重复页。具体前端改造交接文档见：

```text
C:\ide\aicove\cloud_backend\Agent节点界面前端改造说明_20260430.md
```

核心能力：

```text
Agent Context Studio
  ├─ Agent Profiles：所有 Agent 的定义面
  ├─ Contact ChatAgents：联系人级 ChatAgent 列表与绑定
  ├─ Node Studio：角色卡 / 预设 / prompt / prompt_order / 世界书 / 记忆 / 运行时事实 / tool / 输出契约
  ├─ Agent Build：流程图画布，拖拽节点库子节点、连线、保存 graph
  ├─ SillyTavern Importer：导入 ST preset 并做结构摘要
  ├─ Assembly Preview：上下文组装预览、token budget、provider messages
  └─ Migration Export：导出给 Flutter App 迁移使用的稳定配置
```

## 6. API 设计

新增路由统一挂在：

```text
/api/v1/agent-context-admin
```

### 6.1 面板

```text
GET /panel
```

兼容旧入口，重定向到 `/api/v1/prompt-defaults-admin/panel`。

### 6.2 文档读写

```text
GET /document
PUT /document
POST /document/validate
POST /document/export
```

说明：

- `GET /document`：读取 `data/agent_context_admin.json`，不存在则返回默认文档。
- `PUT /document`：保存完整文档。第一阶段可不接真实 DB。
- `POST /document/validate`：校验 id 唯一性、绑定引用、权限合法性。
- `POST /document/export`：导出给 App 迁移使用的稳定 JSON。

### 6.3 Agent Profiles

```text
GET /agents
POST /agents
GET /agents/{agent_id}
PUT /agents/{agent_id}
DELETE /agents/{agent_id}
POST /agents/{agent_id}/duplicate
POST /agents/{agent_id}/preview
```

### 6.4 Contact ChatAgents

```text
GET /contacts
GET /contacts/{contact_id}/chat-agent
POST /contacts/{contact_id}/chat-agent/ensure
PUT /contacts/{contact_id}/chat-agent
```

实现说明：

- `GET /contacts` 第一阶段可以从 `models.Conversation` 读取已同步联系人。
- 如果没有同步数据，也允许 Web 面板创建“本地草稿 Contact”。
- `ensure` 用于按 `conversation.id` 自动生成：

```text
agentId = chat_agent:<contactId>
contextRecipeId = standard_chat_recipe:<contactId>
contextProfile.scope = full_chat
```

### 6.5 Asset Library

```text
GET /assets
POST /assets
GET /assets/{asset_id}
PUT /assets/{asset_id}
DELETE /assets/{asset_id}
```

查询参数：

```text

?type=lorebook
?type=regex_set
?type=extension_prompt
?type=tool_policy
?type=output_contract
```

### 6.6 SillyTavern Import

