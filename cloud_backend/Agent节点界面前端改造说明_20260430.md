# Agent Build 流程图前端改造说明（交给 Claude）

> 目标读者：负责 `cloud_backend` Web 管理端的 Claude。  
> 当前后端：`C:\ide\aicove\cloud_backend\agent_context_admin_api.py`  
> 管理入口：`http://127.0.0.1:8000/api/v1/prompt-defaults-admin/panel`  
> 本文覆盖用户最新纠正：**Agent Build 不是 Agent 列表，也不是重复的 Agent 管理页；Agent Build 应该像流程图一样拼装节点库的子节点。**

## 0. 必须先改掉的误区

当前截图里的问题：

```text
Agent Build 顶部进入后，主体仍然是 Agent 卡片列表；
下面又拆出“蓝图 Agent / Agent Flow / 联系人 / ST 导入 / 预览 / 导出”等子页；
这会把 Agent Build 做成另一个管理后台，和节点库、联系人、预览大量重复。
```

正确口径：

```text
Node Studio = 节点库，负责创建/维护可复用子节点。
Agent Build = 流程图画布，负责把节点库里的子节点拖到画布上并连线。
```

所以：

- `Agent Build` 的主体必须是流程图 canvas。
- Agent 列表只能是左侧选择器，不是主内容。
- `Agent Flow` 不应该再作为重复 tab；它应该折叠进 Agent Build 右侧属性面板。
- `联系人 / ST 导入 / 预览 / 导出` 可以保留为独立顶层或工具入口，但不要塞在 Agent Build 里重复管理。

## 1. 顶层信息架构

建议顶层只保留这组：

```text
Node Studio | Agent Build | 联系人 | ST 导入 | 预览 | 导出
```

其中：

| 顶层 | 作用 |
|---|---|
| Node Studio | 节点库：创建/编辑节点原型，如 prompt、preset、tool、输出契约 |
| Agent Build | 流程图画布：选择一个 Agent，把节点库子节点拖到画布并连线 |
| 联系人 | 联系人和 `chat_agent:<contactId>` 保障 |
| ST 导入 | 导入 ST preset，并生成节点库里的 preset/prompt_order 节点 |
| 预览 | 对当前 Agent 图做安全组装预览 |
| 导出 | 导出文档快照/迁移配置 |

不要再在 Agent Build 内部做“蓝图 Agent / Agent Flow / 联系人 / 导入 / 预览 / 导出”的二级导航。

## 2. Agent Build 页面布局

Agent Build 应该是三栏流程图编辑器：

```text
┌────────────────────────────────────────────────────────────┐
│ 顶栏：Agent Build / 保存 / 预览 / 同步状态                  │
├───────────────┬──────────────────────────────┬─────────────┤
│ 左侧 Agent/节点 │ 中间流程图画布                │ 右侧属性面板 │
│               │                              │             │
│ Agent 选择器   │  [角色卡] → [预设] → [记忆]    │ 当前节点属性 │
│ 节点库筛选     │       ↘ [tool policy] → [输出] │ 当前边属性   │
│ 可拖拽子节点   │                              │ 触发策略     │
└───────────────┴──────────────────────────────┴─────────────┘
```

### 2.1 左侧栏

左侧分两块：

1. Agent 选择器：
   - 搜索 Agent。
   - 新建 Agent。
   - 当前 Agent 基础信息只显示一行，不做卡片瀑布流。

2. 节点库抽屉：
   - 从 `GET /nodes` 读取。
   - 按 `nodeTypeGroups` 分组。
   - 节点卡片可拖到画布。
   - 卡片只显示 `name / nodeType / safeSummary`。

### 2.2 中间画布

中间必须是流程图画布，最小能力：

- 放置节点。
- 拖动节点位置。
- 节点之间连线。
- 删除节点/边。
- 保存/加载布局。
- 节点开关 enabled。
- 支持入口节点和输出节点标记。

不要求一开始接入复杂图库；可以先用原生 DOM + SVG 线，后续再换 React Flow / Vue Flow。当前面板是单文件 HTML，推荐先用：

```text
absolute positioned div node + svg path edge + pointer events
```

### 2.3 右侧属性面板

右侧根据选择对象切换：

- 选中 graph node：显示 `label / nodeId / nodeType / slot / enabled / config JSON`。
- 选中 edge：显示 `source / target / sourcePort / targetPort / condition / enabled`。
- 未选中：显示当前 Agent 的 `triggerPolicy / deliveryChannel / contextProfile`。

`Agent Flow` 原本要表达的内容全部放这里，不再另开重复页。

## 3. 后端 API

Base：

```text
/api/v1/agent-context-admin
```

### 3.1 Schema

```http
GET /schema
```

使用：

```text
nodeTypes
nodeTypeGroups
triggerKinds
agentBuildGraph.edgePorts
```

不要硬编码 nodeTypes。

### 3.2 节点库 Node Studio

```http
GET /nodes
GET /nodes?type=prompt
POST /nodes
GET /nodes/{nodeId}?includeRaw=true
PUT /nodes/{nodeId}
DELETE /nodes/{nodeId}
```

节点库负责“子节点原型”，不是 Agent 的流程图实例。拖到画布后，会变成 graph node instance。

### 3.3 Agent 选择

```http
GET /agents
POST /agents
GET /agents/{agentId}
PUT /agents/{agentId}
```

Agent 列表只做选择器。不要把 Agent 卡片列表作为 Agent Build 主界面。

### 3.4 Agent Build 流程图

读取当前 Agent 的流程图：

```http
GET /agents/{agentId}/graph
```

保存流程图：

```http
PUT /agents/{agentId}/graph
Content-Type: application/json

{
  "graph": {
    "nodes": [
      {
        "id": "g_role_card_1",
        "nodeId": "role_card_xxx",
        "nodeType": "role_card",
        "label": "角色卡",
        "enabled": true,
        "position": {"x": 120, "y": 180},
        "slot": "identity",
        "config": {}
      },
      {
        "id": "g_preset_1",
        "nodeId": "st_preset_xxx",
        "nodeType": "silly_tavern_preset",
        "label": "ST 预设",
        "enabled": true,
        "position": {"x": 380, "y": 180},
        "slot": "preset",
        "config": {}
      }
    ],
    "edges": [
      {
        "id": "e_role_to_preset",
        "source": "g_role_card_1",
        "target": "g_preset_1",
        "sourcePort": "out",
        "targetPort": "in",
        "enabled": true
      }
    ],
    "entryNodeIds": ["g_role_card_1"],
    "outputNodeIds": ["g_preset_1"],
    "viewport": {"x": 0, "y": 0, "zoom": 1}
  }
}
```

关键约束：

- `graph.nodes[].id` 是画布实例 ID。
- `graph.nodes[].nodeId` 必须引用节点库真实节点。
- 同一个节点库 `nodeId` 可以被拖多次，每次是不同 graph node instance。
- 保存 graph 时，后端会同步生成兼容旧预览和统计的 bindings。

### 3.5 触发策略/Agent 属性

```http
GET /agents/{agentId}/flow
PUT /agents/{agentId}/flow
```

这不是独立页面；在 Agent Build 右侧属性面板里编辑：

```json
{
  "triggerPolicy": {
    "triggerKind": "user_message",
    "source": "foreground_conversation",
    "enabled": true
  }
}
```

### 3.6 旧线性绑定接口

```http
GET /agents/{agentId}/nodes
PUT /agents/{agentId}/nodes
```

这是兼容接口，不要作为新版 Agent Build 的主要 UI。新版主 UI 使用 `/graph`。

## 4. 画布交互细节

### 从节点库拖到画布

拖拽时读取节点库卡片：

```js
{
  nodeId: node.id,
  nodeType: node.nodeType,
  label: node.name
}
```

落到画布后创建：

```js
{
  id: crypto.randomUUID(),
  nodeId,
  nodeType,
  label,
  enabled: true,
  position: { x, y },
  slot: inferSlot(nodeType),
  config: {}
}
```

### slot 默认推断

```text
role_card -> identity
silly_tavern_preset -> preset
prompt -> prompt
prompt_order -> prompt_order
lorebook -> world_info
memory -> memory
conversation_window -> conversation
runtime_facts -> runtime
regex_set / regex_transform -> transform
tool / tool_policy -> tool
output_contract -> output
provider_renderer -> renderer
post_processor -> post_process
```

### 连线语义

第一阶段连线只表达“执行/装配顺序”，不要过度解释成真实代码执行流。后续 runtime 接入后再细分：

```text
in / out / success / failure / tool / fallback
```

## 5. UI 文案要求

必须使用：

- 节点库
- 子节点
- 流程图
- 画布
- 连线
- 触发策略
- 输出契约

避免使用：

- 提示词管理系统
- 资产管理页
- Agent 卡片列表作为 Build 主体
- Agent Flow 独立重复 tab

## 6. 验收清单

- 打开 Agent Build 后，主区域是流程图画布，不是 Agent 卡片列表。
- 左侧可以选择 Agent，也可以从节点库拖子节点到画布。
- 画布节点可以移动、删除、连线。
- 右侧属性面板能编辑当前节点/边/Agent 触发策略。
- 保存调用 `PUT /agents/{agentId}/graph`。
- 刷新后调用 `GET /agents/{agentId}/graph` 能恢复节点位置和连线。
- `Agent Flow` 不再作为重复主 tab；相关字段进入右侧属性面板。
- Node Studio 仍负责节点库 CRUD，不承担流程图编排。
