# Dart Type Safety

## 基本规则

- 尽量使用明确类型，避免无约束的 `dynamic`。
- 外部 API / JSON 数据进入业务层前要转换为明确模型。
- 可空字段必须表达真实语义，不能用空字符串代替缺失值。

## 数据模型

- Drift / API DTO / UI view model 的职责要区分。
- UI 展示模型不能反向作为数据库或模型上下文真相源。
- 多模态消息、工具调用结果、Agent 输出要保留结构化字段，避免只存拼接文本。

## 禁止模式

- 为了省事把复杂响应一路传 `Map<String, dynamic>` 到 UI。
- 未处理 null 就强制 `!`。
- 将供应商私有响应格式泄漏到上层业务逻辑。
