# Error Handling

## FastAPI 错误

- API 层优先使用 FastAPI / HTTPException 表达明确状态码。
- 认证、权限、参数错误要返回可诊断信息，但不能泄露密钥、token、真实用户隐私。
- 管理 API 与普通用户 API 要保持权限边界。

## 诊断

- 命令报错、测试不过、逻辑漏洞要报告：遇到什么、原计划是什么、建议怎么办。
- 报告后可以继续修复，但不能吞掉失败。

## 禁止模式

- `except Exception: pass`。
- 把异常详情原样返回给前端，尤其是生产环境路径、密钥、SQL。
- 为了让接口成功而静默跳过关键数据写入。
