> v4 按终审（`方案终审_chat-first-paint_20260719.md`）照单采纳 N1-N4：base64 精确门统一为规范化

## 背景

用户反馈：每次进入聊天页面，聊天记录都要等一会儿才显示；重复进入同一会话也慢。

已由主会话（Claude）与 codex 双线独立诊断交叉验证，结论一致，报告见
`scratch/diagnostics/聊天首屏加载慢_codex诊断_20260716.md`。根因摘要：

1. **头号根因**：`ConversationTimelineCache` 的图片尺寸升级机制——快照内任一 `ImageBlock` 缺宽高即判定「需要升级」，升级用纯 Dart `image` 包在主 isolate 整图解码；远程 `http(s)` 图、丢失/损坏文件永远补不上尺寸，导致每次读快照都重新调度升级；升级结束后无条件广播变更通知，触发订阅端重新 resolve → 再次调度，构成自激循环。成功补出的宽高不写回数据库，应用重启后全部重算。
2. **放大器**：升级任务（解码＋逐 raw message 的投影映射写库事务）与 `watchWindow` 首个窗口读取共用 `_runConversationTask` 按会话串行队列，热快照读取被慢任务卡在队头。
3. **暴露条件**：消息窗口 Provider 为 autoDispose，重进页面首帧必为 AsyncLoading；本有内存快照兜底，但被 1、2 卡住后兜底也画不出来。

## 目标（MVP，三刀）

1. **止血自激循环（收敛性）**：图片尺寸升级必须收敛——升级无实际变化时不替换快照、不写投影映射、不发通知；解析失败的图片来源（以稳定来源身份标识，非投影 UUID）本次应用生命周期内不再重试；`http(s)` 远程图不做隐式下载取尺寸。
2. **切断首屏阻塞（读旁路＋无丢通知）**：内存快照命中时，窗口首值为无副作用的纯读，不排入会话串行队列；`watchWindow` 在首值读取前建立变更订阅（缓冲），保证「首值与监听建立之间」完成的任何变更不丢失；`peekWindow` 改为严格纯读。图片尺寸升级移出内容写入调用栈（`upsert`/`replace` 等不再内联解码、不 await 解码）。
3. **去掉主线程整图解码（成本）**：原生平台在后台 isolate 做「元数据探测」（不解码像素帧；仍需读取完整编码字节），失败回退整图解码；**Web 平台本次禁用遗留尺寸回填**（探测桩恒返回失败，静默收敛，不在主线程解码）。成功解析且存在稳定 `message_blocks` 真相源行的，宽高以 CAS 语义写回该行，使重启后不再重算。

## 非目标（本次不做）

- 不改消息窗口 Provider 的 autoDispose 语义。
- 不做「图片写入时即持久化宽高」的写入侧改造。
- 不为「真相源在 `messages.raw_payload` / supplement 投影、没有 `message_blocks` 行」的图片做持久化写回（这类来源本生命周期内以稳定来源身份收敛，不重复解码；跨重启仍会重算一次，**另立后续任务**处理 raw payload 写回）。
- 不实现完全独立的 maintenance lane（本次以「读旁路＋有界批次」控制占用；见 design 风险节，完整 lane 另立后续任务）。
- 不加数据库索引、不动冷启动 DB 查询（需真机 EXPLAIN/分段计时后另立任务）。
- 不改滚动/分页/流式对齐等视口语义，不动未提交的滑动优化改动。
- `replaceMessagesTransient`（流式瞬态内容）不参与尺寸升级调度；瞬态内容最终经持久路径（`appendAssistantMessages` 等 → `upsertMessages`/`replaceMessages`）落库时由该路径的调度点接管。

## 验收标准

收敛性：
- [ ] 快照含不可解析图片（仅 `https` URL／本地文件丢失／损坏图）时：`https` 类根本不产生探测；丢失/损坏类恰好探测一次即记入 attempted，其后 `peekWindow`/`watchWindow`/内容写入不再触发新探测；全败的维护轮不替换快照、不写任何 DB、不发通知（无自激）。
- [ ] attempted 身份基于「raw 消息 id＋复合来源指纹」，重新投影（块 UUID 变化）不会绕过 attempted。
- [ ] 探测成功但无 DB 行（或写回失败）的来源：同生命周期内重投影/reload 后的新块**直接带宽高且不再探测**（状态表回放），不会出现「不再探测且宽高丢失」；同一 payload 换包装（data URL／裸 base64／空白差异）重投影同样回放成功；状态表超容量逐出时 attempted 与尺寸同进同出，被逐出来源允许重新探测，不出现永久失忆。
- [ ] 候选超过单轮上限（4）时经尾处理接力最终全部处理；接力期间排入的内容任务先于下一维护批次执行。
- [ ] 探测在途时 `clearConversation`/删除会话/`dispose`：任务失效后不写 DB、不安装快照、不通知、不重排队。

首屏与订阅：
- [ ] `peekWindow` 严格纯读：调用前后维护调度计数不变。
- [ ] 内存快照命中时，`watchWindow` 首值不排入会话串行队列：队列被人为阻塞时首值仍及时产出；阻塞释放后订阅端能收到后续最新窗口（覆盖「变更发生在首值与监听建立之间」的窗口，含 visibility 变更）。

调度覆盖：
- [ ] 经 `upsertMessages`、`replaceMessages`、`loadOlderMessages`、`reloadConversationFromRawStore` 引入的缺尺寸本地图，无需再调用 load/peek/watch 即被调度探测；且这些内容 API 自身不 await 探测（探测被人为挂起时内容调用照常完成）。

持久化与并发安全：
- [ ] 有稳定 `message_blocks` 行的本地图成功解析后，宽高合并写回该行 `data` JSON：仅覆盖正整数 `width/height`，其余字段原样保留；新建缓存实例（模拟重启）装载后不再探测。
- [ ] 导入场景（DB 行 id ≠ data.id）能按来源指纹命中真相源行并写回。
- [ ] 投影合成块（无 DB 行）：跳过写回，仅内存生效＋attempted 收敛，不报错。
- [ ] 写回为 CAS 语义：探测期间来源被外部写路径替换（同 id 换图）时，旧尺寸不得写入新图、不得覆盖新快照；软删除行不写回；单块写回失败不影响其余块、不产生未处理异常。

平台：
- [ ] 原生平台探测在后台 isolate 执行，主 isolate 无整图解码调用；字节上限（32MB）在**大块分配前**预检（文件用 `File.length()`，base64 用解码尺寸估算）。
- [ ] Web（双硬门）：`flutter build web` 编译通过；chrome 平台运行态测试证明桩恒返回失败、无 `Isolate.run` 路径、缓存一次 attempted 后静默收敛。两门必须**实际执行且通过**；环境缺失 ⇒ 任务停在 blocked/未完成并如实上报，**不得进入收尾**。

语义保持：
- [ ] 内容写入路径的投影映射同步语义不变；几何维护路径不触碰投影映射。
- [ ] 既有测试全绿：`conversation_short_window_store_test.dart`、`conversation_timeline_paging_test.dart`、`short_window_frontend_boundary_test.dart`、`chat_page_lifecycle_test.dart`。
- [ ] `flutter analyze` 无新增错误/警告。

## 自主决策（AI 设计，供扫读否决）

- **失败重试策略与状态表**：内存级**统一来源状态表**（attempted＋成功尺寸单表单 LRU，每会话上限 512、同进同出、clear/delete/dispose 清理），key＝raw 消息 id＋复合来源指纹；成功路径已写回 DB 持久收敛，失败路径每次冷启动最多重付一次，被逐出来源最多多付一次探测，换取实现简单与可自愈。
- **指纹与正确性分层**：指纹（含 base64 的 FNV-1a 64 采样哈希）只作索引，碰撞后果限于多一次/漏一次探测；一切「写哪个行/补哪个块」的决策以**规范化来源值**（路径规范化全等／base64 规范化 payload 全等）精确相等为门，结构上排除写错尺寸，且包装差异不影响结论。
- **状态表尺寸写入时机**：仅在维护轮 CAS 分类完成后写入（≥1 行成功／仅异常无成功行的内存降级／无 backing row）；全部 stale、在途失效、探测失败一律不写。
- **在途失效**：以会话 epoch＋dispose 标志使在途探测结果失效，不强杀 isolate、只丢弃结果。
- **Q1 决策（持久化范围）**：本次只对有真实 `message_blocks` 行的图片持久化；raw payload / supplement 来源仅内存收敛，跨重启会重算一次，后续任务补真相源写回。验收已按此收窄。
- **Q2 决策（同步/备份传播）**：写回的 `width/height` 定义为「可再生、向后兼容的图片元数据」，允许进入导出/备份/同步；消费侧使用以来源指纹匹配为前提，来源不同不复用尺寸。
- **Web 策略**：本次直接禁用 Web 的遗留尺寸回填（桩恒失败＋attempted 收敛），不引入 Web Worker；Web 首屏收益来自读旁路与去自激，与原生一致。
- **队列占用**：维护批次有界（单轮探测块数上限），剩余候选重新排队，让内容任务有插队机会；完整 maintenance lane 另立任务。
