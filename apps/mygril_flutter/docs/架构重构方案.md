# MyGril 架构重构方案（参考 Kelivo）

> 编写日期：2025-12-28
> 参考项目：kelivo-master
> 核心思想：**前端（UI）和后端（逻辑/数据）完全分开**

---

## 📊 Kelivo 的分层模式

Kelivo 采用了清晰的三层架构：

```
lib/
├── core/                    # 🔧 后端层（业务逻辑 + 数据）
│   ├── models/              # 数据模型定义
│   ├── providers/           # 状态管理（Riverpod/Provider）
│   └── services/            # 业务服务（API调用、数据处理）
│       ├── api/             # API 服务
│       ├── chat/            # 聊天业务逻辑
│       ├── storage/         # 存储服务
│       └── ...
│
├── shared/                  # 🧩 公共组件（跨功能复用）
│   ├── widgets/             # 公共 UI 组件
│   ├── animations/          # 动画工具
│   └── responsive/          # 响应式布局
│
├── theme/                   # 🎨 主题系统
│
├── features/                # 📱 前端层（纯 UI）
│   ├── chat/
│   │   ├── pages/           # 页面
│   │   ├── widgets/         # 页面专用组件
│   │   └── models/          # 视图模型（仅UI相关）
│   │
│   ├── settings/
│   │   ├── pages/
│   │   └── widgets/
│   │
│   └── ...
│
└── utils/                   # 工具函数
```

**核心特点：**
1. **`core/`** = 后端（models + providers + services）
2. **`features/`** = 前端（pages + widgets）
3. **`shared/`** = 公共 UI 组件
4. **业务逻辑全在 `core/services/`，UI 只负责展示和调用 Provider**

## 📋 各层职责明细

### 1. `core/models/` - 数据模型

**只放数据结构定义**，不含业务逻辑。

```dart
// ✅ 正确：纯数据结构
class Conversation {
  final String id;
  final String displayName;
  final List<Message> messages;
  // ... 只有字段和 copyWith
}

// ❌ 错误：不要在模型里放业务逻辑
class Conversation {
  Future<void> sendMessage() { ... }  // 这个该放到 service
}
```

**包含：**
- `conversation.dart` - 对话实体
- `message.dart` - 消息实体
- `message_block.dart` - 多模态块
- `provider_auth.dart` - Provider 认证信息
- `app_settings.dart` - 设置数据结构
- `auto_reply_trigger.dart` - 触发器
- `tts_config.dart` / `memory_config.dart` - 插件配置

---

### 2. `core/providers/` - 状态管理

**Riverpod Provider**，连接 UI 和 Service。

```dart
// 状态 Provider
final conversationsProvider = AsyncNotifierProvider<...>(...);
final activeConversationProvider = Provider<...>(...);

// 配置 Provider
final appSettingsProvider = StateNotifierProvider<...>(...);
final ttsConfigProvider = StateNotifierProvider<...>(...);
```

**职责：**
- 管理应用状态
- 调用 Service 执行业务逻辑
- 向 UI 提供数据

---

### 3. `core/services/` - 业务服务

**核心业务逻辑**，每个子目录是一个业务领域。

#### `services/chat/` - 聊天服务
```dart
class ChatService {
  Future<Message> sendMessage(String convId, String text);
  Future<Message> sendWithImage(String convId, String imagePath);
  Future<void> retry(String messageId);
}
```

#### `services/api/` - API 层
```dart
class AgentApi {
  Future<ChatResponse> chat(ChatRequest request);
  Stream<String> streamChat(ChatRequest request);
}
```

#### `services/auto_reply/` - 主动消息
```dart
class TriggerService {
  Future<void> analyzeTrigger(String convId);
  Future<void> executeTrigger(AutoReplyTrigger trigger);
}
```

#### `services/storage/` - 数据库
```dart
// database.dart - Drift 数据库定义
// repositories/ - 数据仓库
class ConversationRepository {
  Future<List<ConversationData>> getAll();
  Future<void> upsert(ConversationData data);
}
```


---

### 6. `features/` - 前端层（纯 UI）

**只放页面和页面专用组件**，不含业务逻辑。

```dart
// ✅ 正确：只负责 UI 和调用 Provider
class ChatPage extends ConsumerWidget {
  Widget build(context, ref) {
    final messages = ref.watch(messagesProvider);
    return ListView(...);
  }
  
  void _onSend(String text) {
    ref.read(chatServiceProvider).sendMessage(convId, text);
  }
}

// ❌ 错误：不要在 UI 里写业务逻辑
class ChatPage {
  Future<void> _onSend(String text) async {
    final api = AgentApi();
    final response = await api.chat(...);  // 这该放到 service
    // ...
  }
}
```

**按功能分子目录：**
- `chat/` - 聊天页面
- `character/` - 角色页面
- `settings/` - 设置页面
- `auto_reply/` - 主动消息页面
- `plugins/` - 插件设置页面
- `home/` - 主页框架

## ✅ 分层规则总结

| 层 | 目录 | 放什么 | 不放什么 |
|------|------|--------|----------|
| **模型层** | `core/models/` | 数据结构、实体类 | 业务逻辑 |
| **状态层** | `core/providers/` | Riverpod Provider | UI 组件 |
| **服务层** | `core/services/` | 业务逻辑、API调用、数据库操作 | UI 相关代码 |
| **公共UI** | `shared/` | 可复用的 UI 组件 | 业务逻辑 |
| **主题** | `theme/` | 颜色、样式 | 组件 |
| **页面层** | `features/` | 页面、页面专用组件 | 业务逻辑 |
