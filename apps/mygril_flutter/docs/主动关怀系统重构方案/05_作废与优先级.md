# 05 作废与优先级

> 本文档描述触发器的作废条件与优先级处理规则

---

## 为什么需要作废机制？

### 问题场景

```
晚上 10:30 - 用户说"我去睡了"
晚上 10:31 - AI 管家创建"早安"触发器，预计早上 8:00 触发
晚上 11:00 - 用户睡不着，又回来聊天
早上 8:00 - 触发器触发，发送"早安呀~昨晚睡得好吗？"

问题：用户昨晚都聊了很久了，这个"早安"显得很奇怪
```

### 作废的意义

- 避免发送不合时宜的消息
- 让 AI 的主动关怀更加智能
- 区分"必须发送"和"可以跳过"的场景

---

## 优先级定义

| 优先级 | 枚举值 | 典型场景 | 来源 |
|--------|-------|---------|------|
| **高** | `high` | 用户明确设置的提醒/闹钟 | 用户主动要求 |
| **中** | `medium` | AI 自动创建的普通关怀 | AI 管家分析 |
| **低** | `low` | 情感性、可有可无的消息 | AI 管家分析 |

---

## 作废规则

### 高优先级（high）

**场景**：用户说"明天 8 点叫我起床"

**规则**：**不作废**，无论如何都会触发

**原因**：用户明确要求的提醒，不能擅自取消

```dart
case AutoReplyTriggerPriority.high:
  return false;  // 永不作废
```

### 中优先级（medium）

**场景**：AI 分析用户去睡觉了，创建早安触发器

**规则**：用户发送新消息后作废

**原因**：如果用户已经开始新的对话，说明预生成的内容可能已经过时

```dart
case AutoReplyTriggerPriority.medium:
  // 口径确认：用“最后一条用户消息 id/时间”判断是否有新消息（不要用总消息数量）
  return hasNewUserMessage;
```

### 低优先级（low）

**场景**：AI 想发一条"想你了"

**规则**：
1. 用户发送新消息 → 作废
2. 用户正在聊天界面 → 作废

**原因**：这类消息是锦上添花，用户在聊天时不应该打扰

```dart
case AutoReplyTriggerPriority.low:
  // 条件 1：用户发了新消息
  if (hasNewUserMessage) return true;
  // 条件 2：用户正在聊天界面
  if (isChatActive) {
    return true;
  }
  return false;
```

> 口径确认：作废判断统一使用 `contextLastUserMessageId` / `contextLastUserMessageAt`。  
> 类比：以前用“房间里总人数”判断“用户有没有来过”，会把 AI 自己进出也算进去；现在改成“只看最后一个用户的脚印”，才不会误伤。

## 作废检查时机

### 时机 1：触发时检查

在触发时间到达时，发送消息之前检查：

```dart
Future<void> _fireTrigger(AutoReplyTrigger trigger) async {
  // 获取当前状态
  final convList = _ref.read(conversationsProvider).valueOrNull ?? const [];
  Conversation? conv;
  for (final c in convList) {
    if (c.id == trigger.conversationId) {
      conv = c;
      break;
    }
  }
  // 只看 user role 的最后一条消息（id/时间），忽略 assistant/system/tool
  String? currentLastUserMessageId;
  DateTime? currentLastUserMessageAt;
  final messages = conv?.messages ?? const [];
  for (final m in messages.reversed) {
    if (m.role == 'user') {
      currentLastUserMessageId = m.id;
      currentLastUserMessageAt = m.createdAt;
      break;
    }
  }
  final isChatActive = _ref.read(activeConversationIdProvider) == trigger.conversationId;

  // 检查是否应该作废
  final shouldExpire = trigger.shouldExpire(
    currentLastUserMessageId: currentLastUserMessageId,
    currentLastUserMessageAt: currentLastUserMessageAt,
    isChatActive: isChatActive,
  );

  if (shouldExpire) {
    final reason = _getExpireReason(
      trigger,
      currentLastUserMessageId,
      currentLastUserMessageAt,
      isChatActive,
    );
    await _expireTrigger(trigger, reason: reason);
    return;
  }

  // 继续发送...
}

String _getExpireReason(
  AutoReplyTrigger trigger,
  String? currentLastUserMessageId,
  DateTime? currentLastUserMessageAt,
  bool isChatActive,
) {
  final hasNewUserMessage = () {
    // 1) 创建时没有用户消息，但现在有了
    final hadNoUserMessageAtCreate =
        trigger.contextLastUserMessageId == null && trigger.contextLastUserMessageAt == null;
    final hasUserMessageNow = currentLastUserMessageId != null || currentLastUserMessageAt != null;
    if (hadNoUserMessageAtCreate && hasUserMessageNow) return true;

    // 2) 优先用 ID 判断
    if (trigger.contextLastUserMessageId != null && currentLastUserMessageId != null) {
      return currentLastUserMessageId != trigger.contextLastUserMessageId;
    }

    // 3) 退化用时间判断
    if (trigger.contextLastUserMessageAt != null && currentLastUserMessageAt != null) {
      return currentLastUserMessageAt.isAfter(trigger.contextLastUserMessageAt!);
    }

    return false;
  }();

  if (hasNewUserMessage) return '用户在触发前发了新消息';
  if (isChatActive) {
    return '用户正在聊天界面';
  }
  return '未知原因';
}
```

### 时机 2：用户发消息时即时作废（可选优化）

为了更及时地清理，可以在用户发消息时主动检查：

```dart
// 在 ChatActions.send() 中
Future<void> send(String text) async {
  // 先检查并作废低优先级触发器
  await _expireLowPriorityTriggers();

  // 然后正常发送消息
  // ...
}

Future<void> _expireLowPriorityTriggers() async {
  final triggers = _ref.read(autoReplyTriggersProvider).valueOrNull ?? [];
  final activeConvId = _ref.read(activeConversationIdProvider);

  for (final trigger in triggers) {
    // 只处理当前会话的活跃触发器
    if (!trigger.isActive) continue;
    if (trigger.conversationId != activeConvId) continue;

    // 低优先级：立即作废
    if (trigger.priority == AutoReplyTriggerPriority.low) {
      await _expireTrigger(trigger, reason: '用户发送了新消息');
      continue;
    }

    // 中优先级：不需要立即作废（触发时再比较“最后一条用户消息”）
    // 原因：用户可能只是补充一句，然后又沉默；是否作废由“触发时刻”的规则统一判断
  }
}
```

## 作废后的处理

### 1. 更新状态

```dart
Future<void> _expireTrigger(AutoReplyTrigger trigger, {required String reason}) async {
  await _updateTrigger(
    trigger.id,
    status: AutoReplyTriggerStatus.expired,
    expireReason: reason,
  );
}
```

### 2. 取消后台任务

如果注册了 WorkManager 任务，需要取消：

```dart
Future<void> _expireTrigger(AutoReplyTrigger trigger, {required String reason}) async {
  // 更新状态
  await _updateTrigger(...);

  // 取消后台任务
  await BackgroundService.cancelTask('trigger_${trigger.id}');
}
```

### 3. 日志记录

```dart
AppLogger.info('TriggerController', '触发器已作废', metadata: {
  'id': trigger.id,
  'title': trigger.title,
  'priority': trigger.priority.name,
  'reason': reason,
  'createdAt': trigger.createdAt.toIso8601String(),
  'wasScheduledFor': trigger.nextFireAt.toIso8601String(),
});
```

### 4. 通知 UI（可选）

```dart
// 发送事件通知 UI
_lifecycleController.add(TriggerExpired(trigger, reason));

// UI 可以选择显示一个轻量提示
// "早安触发器已取消（您发送了新消息）"
```

## 优先级分配策略

### 对话 AI 创建的触发器

用户明确要求时，分配 **高优先级**：

```dart
// TriggerPlugin.handleCreateReminder()
Future<String?> _handleCreateReminder(Map<String, dynamic> args) async {
  await _ref.read(autoReplyTriggersProvider.notifier).createTrigger(
    title: args['title'],
    time: parseTime(args['time']),
    prompt: args['prompt'],
    priority: AutoReplyTriggerPriority.high,  // 用户要求 = 高优先级
    source: TriggerSource.userRequest,
  );
  return '好的，我会在 ${args["time"]} 提醒你';
}
```

### AI 管家创建的触发器

AI 管家在工具调用时指定优先级：

```dart
// AI 管家的工具调用
schedule_proactive({
  "title": "早安问候",
  "delay_minutes": 480,
  "priority": "medium",  // AI 自己判断
  "prompt": "..."
})
```

### 优先级判断指南（给 AI 管家的提示词）

```
优先级分配指南：

high（高）- 用于用户明确要求的提醒
  - "明天叫我起床" → high
  - "下午 3 点提醒我开会" → high
  - "2 小时后叫我" → high

medium（中）- 用于基于对话上下文的关怀
  - 用户说去睡觉 → 早安问候 → medium
  - 用户说去开会 → 会后问候 → medium
  - 用户说去吃饭 → 饭后问候 → medium

low（低）- 用于纯情感性、可有可无的消息
  - 长时间没聊天 → "想你了" → low
  - 随机关心 → "在干嘛呢？" → low
  - 节日祝福 → low
```

## 边界情况处理

### 情况 1：用户发消息后很快又不活跃了

```
10:30 - 创建触发器（记录 lastUserMessageAt = 10:30）
10:35 - 用户发了一条消息（lastUserMessageAt 变为 10:35）
10:36 - 用户又不活跃了
08:00 - 触发时间到

问题：用户只是发了一条，然后又没动静了，应该作废吗？
```

**当前策略**：作废（中/低优先级）

**替代策略**（更复杂）：
- 记录用户最后活跃时间
- 如果用户发消息后又沉寂了一段时间，可以不作废

```dart
// 更复杂的判断逻辑（可选实现）
bool shouldExpireWithGracePeriod({
  required DateTime? contextLastUserMessageAt,
  required DateTime? currentLastUserMessageAt,
  required int gracePeriodMinutes,
}) {
  if (contextLastUserMessageAt == null || currentLastUserMessageAt == null) return false;
  if (!currentLastUserMessageAt.isAfter(contextLastUserMessageAt)) return false;

  // 用户发了新消息，但如果之后又沉寂了一段时间，可以不作废
  final silenceDuration = DateTime.now().difference(currentLastUserMessageAt);
  if (silenceDuration.inMinutes > gracePeriodMinutes) {
    return false;  // 用户又沉寂了，不作废
  }

  return true;  // 作废
}
```

### 情况 2：触发器跨天

```
周五 22:00 - 创建"周一早安"触发器
周六 - 用户聊了很多
周日 - 用户聊了很多
周一 08:00 - 触发

问题：跨了两天，用户中间又聊过很多，怎么判断要不要作废？
```

**当前策略（本次重构口径）**：中/低优先级只要检测到“最后一条用户消息 id/时间”与创建时不同，就作废  
（也就是：用户在这段时间里只要发过任何新消息，就认为预生成内容可能过时）

**替代策略**：
- 高优先级的长期触发器不受影响
- 中/低优先级的长期触发器可能需要特殊处理

```dart
// 对于长期触发器，放宽作废条件
bool shouldExpire(...) {
  final duration = nextFireAt.difference(createdAt);

  // 超过 24 小时的触发器，只有用户"最近"发了消息才作废
  if (duration.inHours > 24) {
    // （可选）检查最近 1 小时内是否有“用户消息”（lastUserMessageAt）
    // 而不是“从创建以来只要用户聊过就作废”
    // ...
  }

  // 原有逻辑
}
```

### 情况 3：多个触发器同时到期

```
08:00 - 触发器 A（早安）
08:00 - 触发器 B（起床提醒）

问题：两个同时触发怎么办？
```

**策略**：按优先级排序，依次触发

```dart
Future<void> _pollDueTriggers() async {
  final triggers = state.valueOrNull;
  if (triggers == null) return;

  final now = DateTime.now();

  // 筛选到期的触发器
  final dueTriggers = triggers
      .where((t) => t.isActive && t.shouldFire(now))
      .toList();

  // 按优先级排序（高 → 中 → 低）
  dueTriggers.sort((a, b) => a.priority.index.compareTo(b.priority.index));

  // 依次处理
  for (final trigger in dueTriggers) {
    await _fireTrigger(trigger);
    // 每个触发器之间稍微间隔，避免消息堆叠
    await Future.delayed(const Duration(seconds: 2));
  }
}
```
