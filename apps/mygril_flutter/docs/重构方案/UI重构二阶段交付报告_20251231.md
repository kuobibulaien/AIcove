本次重构完成了 **UI与业务逻辑的物理分离**。通过将所有页面文件从 `features/*/presentation/pages/` 迁移到 `lib/src/ui/features/`，我们构建了更清晰的前端架构。现在，`features/` 目录专注于纯业务逻辑（数据、领域模型、Providers），而 `ui/` 目录专注于界面展示。

```
        ├── home/pages/
        ├── plugins/pages/
        └── settings/pages/
```

## 4. 后续开发指南

### 4.1 新增页面
*   所有新的页面（Page）应当直接创建在 `lib/src/ui/features/<模块名>/pages/` 下。
*   业务组件（Widget）如果只被该模块使用，可以放在 `ui/features/<模块名>/widgets/`（如需创建）或者保留在 `features/<模块名>/presentation/widgets/`。
*   通用的组件（如按钮、特殊卡片）应当放在 `ui/shared/widgets/`。

### 4.2 Import 规范
在 UI 页面中引用业务逻辑时，请使用相对路径指向 `features/` 目录：
*   ✅ `import '../../../../features/chat/providers2.dart';`
*   ✅ `import '../../../../ui/shared/widgets/moe_toast.dart';`

（注：虽然相对路径较长，但能明确层级关系。也可以考虑使用 `package:mygril_flutter/...` 的绝对路径）

### 4.3 遗留问题
*   目前仍有约 310 个 info 级别的 linter warnings（主要是代码风格相关）。建议在后续迭代中逐步清理。
*   `features/chat/presentation/pages/` 目录下可能还留有空的文件夹，可以安全删除。
