# 1. 背景与目标

---

## 📌 背景

### 当前插件系统现状

目前项目的插件系统位于 `lib/src/features/plugins/`，包含：

```
plugins/
├── domain/
│   └── plugin.dart          # 插件抽象基类
├── plugin_manager.dart      # 插件管理器
└── implementations/         # 具体插件实现（如 TTS）
```

**Plugin 基类现状**：

```dart
abstract class Plugin {
  String get id;              // 唯一标识
  String get name;            // 显示名称
  String get description;     // 描述
  IconData get icon;          // 图标
  bool get enabled;           // 是否启用
  
  Future<String?> getSystemPrompt({String? userMessage});
  Future<PluginProcessResult> processResponse(String text);
  void updateConfig(Map<String, dynamic> config);
  Map<String, dynamic> getConfig();
}
```

**PluginManager 现状**：

```dart
class PluginManager {
  void register(Plugin plugin);
  void unregister(String pluginId);
  List<Plugin> getAllPlugins();
  List<Plugin> getEnabledPlugins();
  Future<String> getSystemPrompts();
  Future<PluginProcessResult> processResponse(String text);
}
```

### 存在的问题

| 问题 | 说明 | 影响 |
|-----|------|------|
| **缺少元数据** | 没有版本号、作者、配置模板等信息 | 无法做版本检查、无法自动生成配置 UI |
| **缺少生命周期** | 插件没有初始化/销毁的时机 | 资源无法正确管理，可能内存泄漏 |
| **缺少注册机制** | 插件无法声明"我能做什么" | 每个插件都要自己写解析逻辑，无法统一管理 |
| **无法支持 Function Calling** | 没有 AI Tool 的概念 | 后续接入 LLM 的工具调用会很困难 |

---

## 🎯 目标

### 核心目标

建立一套**完整、规范、可扩展**的插件架构，为后续功能扩展打好基础。

### 具体目标

#### 目标 1：元数据系统

使每个插件具有完整的"身份信息"：

```dart
PluginMetadata(
  id: 'com.mygril.tts',
  name: 'TTS 语音合成',
  version: '1.0.0',
  author: 'MyGril Team',
  description: '将 AI 回复转换为语音',
  icon: Icons.record_voice_over,
  configSchema: {
    'apiKey': ConfigField(type: 'string', label: 'API 密钥'),
    'voice': ConfigField(type: 'select', label: '声音', options: [...]),
  },
)
```

**好处**：
- 可以在 UI 展示完整的插件信息
- 可以**根据 configSchema 自动生成配置界面**
- 可以做版本兼容性检查

#### 目标 2：生命周期管理

让插件在正确的时机执行正确的操作：

```
App 启动 → onInitialize() → 加载配置、初始化资源
用户启用 → onEnable() → 开始工作
用户禁用 → onDisable() → 暂停工作
App 退出 → onDestroy() → 释放资源
```

**好处**：
- 写插件时清晰知道在哪里做什么
- 系统自动管理生命周期，避免资源泄漏
- 可以做启用/禁用的状态切换

#### 目标 3：功能注册机制

让插件能声明自己提供的功能：

```dart
class MyPlugin extends Plugin {
  @override
  List<CommandHandler> getCommands() => [
    CommandHandler(command: '/help', handler: showHelp),
  ];
  
  @override
  List<AITool> getTools() => [
    AITool(name: 'search', description: '搜索', handler: doSearch),
  ];
}
```

**好处**：
- 插件只管声明功能，系统负责调度
- 可以统一收集所有插件的 AI Tool，用于 Function Calling
- 新增功能类型很方便

## 📊 预期成果

### 1. 新建文件

```
plugins/domain/
├── plugin_metadata.dart      # 元数据定义
├── plugin_state.dart         # 状态枚举
├── config/
│   └── config_field.dart     # 配置字段定义
└── handlers/
    ├── command_handler.dart  # 命令处理器
    ├── ai_tool.dart          # AI 工具
    └── llm_hook.dart         # LLM 钩子
```

### 2. 改造文件

```
plugins/
├── domain/plugin.dart        # 添加生命周期 + 注册接口
└── plugin_manager.dart       # 支持生命周期管理
```

### 3. 新增能力

| 能力 | 说明 |
|-----|------|
| 自动生成配置 UI | 根据 configSchema 渲染表单 |
| 生命周期管理 | 正确的初始化和清理 |
| 命令系统 | 用户输入 /xxx 触发插件功能 |
| AI 工具注册 | 为 Function Calling 做准备 |
| LLM 钩子 | 在请求/响应前后介入处理 |

---

## ⚠️ 约束条件

1. **向后兼容**：现有插件的核心逻辑不变，只需适配新接口
2. **渐进式迁移**：新框架搭好后，现有插件可以逐个迁移
3. **最小改动原则**：只添加必要的接口，不过度设计
