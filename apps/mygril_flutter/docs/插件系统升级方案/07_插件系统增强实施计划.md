# 🔌 插件系统增强实施计划 (Context & Multimedia)

## 1. 目标与范围

本计划旨在增强 MyGril 插件系统的交互能力和多媒体支持，使其更接近 AstrBot 的灵活度，同时保持 Dart 的类型安全。

**核心目标：**
1. **Context Injection (P0)**: 让插件能感知上下文（对话ID、用户）并拥有主动行动能力（发送消息）。
2. **Multimedia Support (P1)**: 让插件能直接返回图片、音频、UI 组件，而不仅是文本。

**明确不包含：**
- ❌ 元编程/注解支持（留待后续阶段）。

---

## 2. P0: 增强上下文访问能力 (Context Injection)

### 2.1 核心类定义 (`plugin_context.dart`)

将在 `lib/src/features/plugins/domain/` 下新建 `plugin_context.dart`。

```dart
/// 插件上下文
/// 提供给插件 Handler 使用，包含当前环境信息和操作能力
class PluginContext {
  // ========== 环境信息 ==========
  
  /// 当前对话 ID
  final String conversationId;
  
  /// 发送者信息 (可选，若无法获取则为空)
  final String? userId; // 或 User 对象
  final String? userName;

  // ========== 主动能力 (Actions) ==========
  
  /// 发送文本消息
  final Future<void> Function(String text) sendText;
  
  /// 发送图片消息
  final Future<void> Function(String imagePath) sendImage;
  
  /// 发送错误提示 (Toast)
  final Future<void> Function(String message) showToast;

  PluginContext({
    required this.conversationId,
    this.userId,
    this.userName,
    required this.sendText,
    required this.sendImage,
    required this.showToast,
  });
}
```

### 2.2 接口改造

**1. 修改 `CommandHandler` (`command_handler.dart`)**

```dart
// 现在的签名：
// final Future<String> Function(List<String> args) handler;

// 改造后的签名：
final Future<String> Function(PluginContext context, List<String> args) handler;
```

**2. 修改 `PluginManager` (`plugin_manager.dart`)**

- `handleCommand` 方法需要构造 `PluginContext` 并传入 Handler。
- 需要在 `PluginManager` 中注入能够发送消息的回调函数（这可能需要从 UI 层或 Service 层传入 `PluginManager`）。

### 2.3 实施步骤

1.  **创建 `PluginContext` 类**。
2.  **更新 `CommandHandler` 定义**：这会破坏现有插件的编译，需要同步修复。
3.  **重构 `PluginManager`**：
    - 增加 `setContextDelegate` 或类似机制，允许外部注入 `sendMessage` 等实现。
    - 在 `handleCommand` 中透传 Context。
4.  **修复现有插件**：更新 StickerPlugin、SearchPlugin 等的 handler 签名。

## 3. P1: 增强多媒体支持 (Multimedia Support)

### 3.1 核心类定义 (`plugin_content.dart`)

将在 `lib/src/features/plugins/domain/` 下新建 `plugin_content.dart`。

```dart
import 'package:flutter/widgets.dart';

/// 插件返回的内容基类
sealed class PluginContent {
  const PluginContent();
}

/// 纯文本内容
class PluginTextContent extends PluginContent {
  final String text;
  const PluginTextContent(this.text);
}

/// 图片内容
class PluginImageContent extends PluginContent {
  final String localPath;
  final String? caption;
  const PluginImageContent(this.localPath, {this.caption});
}

/// 音频内容
class PluginAudioContent extends PluginContent {
  final String localPath;
  final Duration? duration;
  const PluginAudioContent(this.localPath, {this.duration});
}

/// 自定义 UI 内容 (高级特性)
class PluginWidgetContent extends PluginContent {
  final Widget widget;
  const PluginWidgetContent(this.widget);
}
```

### 3.2 接口改造

**修改 `PluginProcessResult` (`plugin.dart`)**

```dart
class PluginProcessResult {
  // 旧字段保留但标记为过时，或者作为 computed property
  // final String processedText; 
  
  /// 新增：结构化内容列表
  final List<PluginContent> contents;
  
  /// 事件列表（保持不变）
  final List<PluginEvent> events;

  // 辅助 getter：兼容旧代码，获取所有文本内容的拼接
  String get textBody => contents.whereType<PluginTextContent>().map((e) => e.text).join('\n');
}
```

### 3.3 实施步骤

1.  **创建 `PluginContent` 类族**。
2.  **更新 `PluginProcessResult`**：引入 content 列表。
3.  **更新 `BasePlugin` 和现有插件**：
    - 修改 `processResponse` 的返回值构建方式。
    - 例如 StickerPlugin 不再只是返回文本，而是可以返回 `PluginImageContent`（如果有本地图的话）或者继续用 Text + Event。
4.  **UI 适配**：
    - Chat 页面在渲染 AI 回复时，如果遇到 `PluginProcessResult`，不仅要显示文本，还要遍历 `contents` 渲染图片或音频组件。
