## 📦 核心概念

### 概念 1：元数据 (Metadata)

**定义**：描述插件"是什么"的信息，就像 App 的应用信息。

**包含内容**：
- 基本信息：id、name、description、version、author
- 展示信息：icon、displayName
- 配置模板：configSchema（定义插件有哪些配置项）
- 兼容信息：minAppVersion、dependencies

**作用**：
1. 在 UI 展示插件信息
2. 自动生成配置界面
3. 版本兼容性检查
4. 依赖关系检查

---

### 概念 2：生命周期 (Lifecycle)

**定义**：插件从创建到销毁经历的各个阶段。

**状态流转图**：

```
         ┌──────────────┐
         │ Uninitialized│  (刚创建，未初始化)
         └──────┬───────┘
                │ initialize()
                ▼
         ┌──────────────┐
         │    Ready     │  (初始化完成，待启用)
         └──────┬───────┘
                │ enable()
                ▼
         ┌──────────────┐
    ┌───▶│   Enabled    │◀──┐  (已启用，正常工作)
    │    └──────┬───────┘   │
    │           │ disable() │ enable()
    │           ▼           │
    │    ┌──────────────┐   │
    │    │   Disabled   │───┘  (已禁用，暂停工作)
    │    └──────┬───────┘
    │           │ destroy()
    │           ▼
    │    ┌──────────────┐
    └────│  Destroyed   │      (已销毁，资源已释放)
         └──────────────┘
```

**生命周期钩子**：

| 钩子 | 调用时机 | 典型用途 |
|-----|---------|---------|
| `onInitialize()` | App 启动 / 插件安装 | 加载配置、初始化客户端 |
| `onEnable()` | 用户启用插件 | 开始监听、注册功能 |
| `onDisable()` | 用户禁用插件 | 停止监听、暂停服务 |
| `onDestroy()` | App 退出 / 插件卸载 | 释放资源、关闭连接 |
| `onConfigChanged()` | 配置变更 | 应用新配置 |

### 概念 3：功能注册 (Handler Registration)

**定义**：插件声明自己能提供的功能，由系统统一管理和调度。

**三种功能类型**：

#### 1. 命令处理器 (CommandHandler)

用户输入特定命令时触发。

```dart
// 用户输入：/tts 你好
// 系统找到 TTS 插件的 /tts 命令，调用它
CommandHandler(
  command: '/tts',
  alias: {'/语音', '/speak'},
  description: '将文字转为语音',
  handler: (args) => convertToSpeech(args.join(' ')),
)
```

#### 2. AI 工具 (AITool)

给 AI 用的工具，实现 Function Calling。

```dart
// AI 判断需要查天气，调用 search_weather 工具
AITool(
  name: 'search_weather',
  description: '搜索指定城市的实时天气',
  parameters: {
    'city': ToolParameter(type: 'string', description: '城市名'),
  },
  handler: (args) => weatherApi.get(args['city']),
)
```

#### 3. LLM 钩子 (LLMHook)

在 LLM 请求/响应的关键节点介入。

```dart
// 在发送请求前，注入当前时间
LLMHook(
  type: LLMHookType.beforeRequest,
  handler: (request) {
    request.systemPrompt += '\n当前时间：${DateTime.now()}';
  },
)

// 在收到响应后，记录日志
LLMHook(
  type: LLMHookType.afterResponse,
  handler: (response) {
    logger.info('AI 回复：${response.text}');
  },
)
```

## 🔄 数据流设计

### 插件初始化流程

```
App 启动
    │
    ▼
PluginManager.initializeAll()
    │
    ├─▶ 遍历所有注册的插件
    │       │
    │       ▼
    │   plugin.onInitialize()
    │       │
    │       ▼
    │   检查 plugin.enabled
    │       │
    │       ├─ true ──▶ plugin.onEnable()
    │       │
    │       └─ false ─▶ (保持 Ready 状态)
    │
    ▼
初始化完成
```

### 用户消息处理流程

```
用户发送消息
    │
    ▼
检查是否是命令 (以 / 开头)
    │
    ├─ 是 ──▶ 匹配 CommandHandler ──▶ 执行 ──▶ 返回结果
    │
    └─ 否 ──▶ 正常发送给 AI
                  │
                  ▼
            触发 beforeRequest 钩子
                  │
                  ▼
            收集所有 AITool ──▶ 加入请求
                  │
                  ▼
            发送 LLM 请求
                  │
                  ▼
            收到响应 ──▶ 触发 afterResponse 钩子
                  │
                  ▼
            processResponse() (现有逻辑)
                  │
                  ▼
            展示给用户
```

## 🔒 设计原则

1. **向后兼容**
   - 现有的 `getSystemPrompt()` 和 `processResponse()` 保留
   - 新增的钩子方法提供默认空实现

2. **渐进增强**
   - 新功能（命令、工具、钩子）都是可选的
   - 插件可以只实现需要的部分

3. **单一职责**
   - 每个类只做一件事
   - `PluginMetadata` 只描述信息
   - `Plugin` 只定义行为
   - `PluginManager` 只管理生命周期和调度

4. **配置驱动**
   - 通过 `configSchema` 声明配置项
   - 系统可根据 schema 自动生成 UI
