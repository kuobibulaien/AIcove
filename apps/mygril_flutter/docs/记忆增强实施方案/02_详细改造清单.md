- 旧数据保留 `conversation_id=NULL`，只读兼容

### 1.2 L1 画像存储（P0-MUST）

目标：为 L1 画像提供持久化存储。

方案选择：在 memories 表中用 `layer='L1'` 标记，不另建表。

理由：
- L1 条目也需要 conversation_id 隔离（不同角色的画像不同）
- 复用已有的 CRUD 和同步机制
- 数量极少（5~15 条），不影响检索性能

额外约束：
- L1 记忆不参与淘汰（不进入 `_evictIfNeeded`）
- L1 记忆不参与混合检索（检索时 `WHERE layer != 'L1'`）
- L1 读取走独立方法 `getProfileMemories(conversationId)`

### 1.3 消息总结标记（P0-MUST）

目标：记录每条消息是否已被总结，支持失败重试。

现状确认：消息已持久化在 `Messages` 表中（`database.dart` line 61），直接在消息表上加字段。

```sql
ALTER TABLE messages ADD COLUMN summarized INTEGER NOT NULL DEFAULT 0;
ALTER TABLE messages ADD COLUMN summarized_at INTEGER;
```

同时保留 `summarization_records` 表作为轮次级幂等记录（防止分轮总结时部分成功后重试导致重复入库）：

```sql
CREATE TABLE IF NOT EXISTS summarization_records (
  id TEXT PRIMARY KEY,
  conversation_id TEXT NOT NULL,
  date_key TEXT NOT NULL,                -- '2026-02-11' 归属日期
  round_key TEXT NOT NULL,               -- 稳定轮次键（幂等主键语义）
  round_index INTEGER NOT NULL DEFAULT 0, -- 轮次序号（仅用于日志/展示，不参与幂等）
  first_msg_time INTEGER NOT NULL,       -- 该轮第一条消息时间戳
  last_msg_time INTEGER NOT NULL,        -- 该轮最后一条消息时间戳
  message_count INTEGER NOT NULL,
  summarized INTEGER NOT NULL DEFAULT 0,
  summarized_at INTEGER,
  error_message TEXT,
  created_at INTEGER NOT NULL,
  UNIQUE(conversation_id, date_key, round_key) -- 幂等性细化到轮次级别（稳定键）
);
```

幂等机制说明：
- 不拆分时：`round_key = 'day:{date_key}'`，插入一条记录
- 拆分时：每个轮次生成稳定键，例如 `round_key = sha1('{date_key}|{first_msg_time}|{last_msg_time}')`
- `round_index` 仅用于日志展示，不作为幂等判据
- 总结成功后同时更新 `summarization_records.summarized=1` 和相应消息的 `messages.summarized=1`
- 失败重试时，按 `round_key` 查 `summarization_records.summarized=0`，只重做未完成轮次
- 为避免重试时轮次重排：轮次划分必须基于“该日全量消息（含已总结）”，不能只基于未总结子集

### 1.4 FTS5 关键词检索表（P0-MUST）

目标：支持 BM25 关键词检索通道。

实现路线（沿用 v1 定案）：

```sql
CREATE VIRTUAL TABLE IF NOT EXISTS memory_fts
USING fts5(memory_id, conversation_id, tokenized_content);
```

分词规则：

1. 连续中文（Han）片段：2-gram 切分。
   示例：`用户喜欢吃火锅` → `用户 户喜 喜欢 欢吃 吃火 火锅`
2. 连续 ASCII 字母/数字：整词保留并转小写。
   示例：`iPhone16手机` → `iphone16 手机`
3. 标点与空白作为分隔符，不进入 token。
4. 查询侧复用同一分词函数。
5. 默认 AND 精确召回；零命中回退 OR。
6. 单汉字查询走 `instr(content, ?)` 子串兜底。

Dart 伪代码（沿用 v1）：

```dart
String tokenizeForFts(String text) {
  final tokens = <String>[];
  final runs = splitByScriptRuns(text); // Han / ASCII / Other

  for (final run in runs) {
    if (run.isHan) {
      if (run.value.length < 2) {
        tokens.add(run.value);
      } else {
        for (var i = 0; i < run.value.length - 1; i++) {
          tokens.add(run.value.substring(i, i + 2));
        }
      }
      continue;
    }
    if (run.isAsciiWordOrNumber) {
      tokens.add(run.value.toLowerCase());
    }
  }

  return tokens.join(' ');
}
```

Drift 落地方式：
- 建表/删表：`customStatement()`
- 检索：`customSelect()` 或 raw SQL
- `memories ↔ memory_fts` 同步由 Repository 手动维护

### 2.1 混合检索（P0-MUST）

新增方法：`searchTopKHybrid(queryVector, queryText, {required String conversationId, int k = 5})`

实现：

```
1. 向量通道：
   - getCandidates(conversationId, limit=300)
   - WHERE layer != 'L1' AND deleted_at IS NULL
   - 计算余弦相似度，取 top20

2. BM25 通道：
   - tokenizeForFts(queryText) → FTS5 MATCH
   - WHERE conversation_id = ? (从 memory_fts 表)
   - 取 top20

3. 合并去重（按 memory_id）：
   - 两通道都命中的记忆：两个分数都有
   - 单通道命中的：另一个分数为 0

4. 混合打分：
   - vector_norm = min-max 归一化到 [0,1]
   - bm25_norm = min-max 归一化到 [0,1]
   - hybrid_score = 0.7 * vector_norm + 0.3 * bm25_norm

5. 按 hybrid_score 排序，取 topK

6. 命中记忆更新 use_count += 1, last_active_at = now

7. 如果命中记忆 needs_enrichment == 1，标记待重新丰富
```

注意：`importance`/`recency` **不参与检索排序**。检索只看相关性。

### 3.1 结构化总结输出（P0-MUST）

目标：从 PEIJ 浮点数升级为分类 + 分层。

AI 总结 Prompt 模板：

```text
你是一位经验老道的心理分析师和关系策略师。
请分析以下一天的聊天记录，提取值得记忆的事实。

对每条事实，你需要判断：
```

### 3.2 入库流程重排（P0-MUST）

```
AI 输出 JSON
    │
    ▼
字段级容错解析
    │
    ▼
对每条 item：
    │
    ├─ 系统根据 category + 对话质量 裁定最终 target_layer
    │  （AI 的建议可能被系统覆盖）
    │
    ├─ 计算 content_hash = sha256(fact)
    │
    ├─ 去重检查：findByContentHash() → 已存在则跳过
    │
    ├─ 如果 target_layer == L2：
    │   ├─ 关联检查：实体匹配 + 向量相似度 > 0.65
    │   │   ├─ 有关联 → 调用合并服务
    │   │   └─ 无关联 → 用 L2 全维度格式写入 content
    │   ├─ 生成 embedding
    │   └─ 入库 memories + memory_fts
    │
    ├─ 如果 target_layer == L3：
    │   ├─ 用 L3 简要格式写入 content
    │   ├─ 生成 embedding
    │   └─ 入库 memories + memory_fts
    │
    ├─ 如果 target_layer == L4：
    │   ├─ 用 L4 标题格式写入 content
    │   ├─ 生成 embedding
    │   └─ 入库 memories + memory_fts
    │
    └─ 如果 target_layer == None → 不入库

    │
    ▼
处理 profile_suggestion：
    ├─ 查看该特征是否已在 L1 中
    ├─ 查看 L2 中同类特征出现次数
    ├─ 累计 ≥ 3 次 → 晋升 L1
    └─ < 3 次 → 暂不晋升，等下次积累

    │
    ▼
标记消息 summarized=true
```

### 3.3 L2 格式化入库（P0-MUST）

```dart
String formatL2Content({
  required String fact,
```

### 3.4 次日总结触发逻辑（P0-MUST）

新增方法：

```dart
/// 检查并触发对历史未总结消息的总结
/// 在用户发送新消息时调用
Future<void> checkAndTriggerDailySummarization({
  required String conversationId,
}) async {
  // ❗ 总结任务必须直接查库取消息，不依赖 UI 内存列表
  // （因为 UI 可能有分页截断，无法保证全量）
  //
  // 1. 先查询“待处理日期”：
  //    在 messages 中找出 conversation_id=? 且 summarized=0 且 date<today 的 date_key 列表
  //
  // 2. 对每个待处理 date_key，查询该日全量消息（含 summarized=0/1）：
  //    WHERE conversation_id = ? AND date(createdAt)=date_key
  //    ORDER BY createdAt ASC
  //
  // 3. 对该日全量消息判断是否拆分：
  //    a. 用户消息数 <= roundSplitThreshold → 整天一起总结
  //    b. > roundSplitThreshold → 按 1h 间隔拆分轮次
  //
  // 4. 为每个总结单元（整天 / 单轮）生成稳定 round_key：
  //    - 整天：day:{date_key}
  //    - 分轮：sha1({date_key}|{first_msg_time}|{last_msg_time})
  //
  // 5. 按 round_key 检查 summarization_records：
  //    已存在且 summarized=1 → 跳过
  //    已存在且 summarized=0 → 重试
  //    不存在 → 新建记录并执行
  //
  // 6. 总结成功 → 更新 summarization_records.summarized=1
  //    + 批量更新对应消息 messages.summarized=1
  // 7. 总结失败 → 记录 error_message，下次触发时重试
}
```

### 5.3 检索查询构造（P0-MUST）

旧逻辑：用用户最新一条消息做查询

新逻辑：用最近 2~3 条消息拼接做查询

```dart
String buildSearchQuery(List<Message> recentMessages) {
  // 取最后 2~3 条消息（包含 AI 的回复）
  // 拼接为一段文本
  // 如果拼接后太长（>200字），截取最后 200 字
  final toUse = recentMessages.length > 3
      ? recentMessages.sublist(recentMessages.length - 3)
      : recentMessages;
  return toUse.map((m) => m.content).join('\n');
}
```

优化：如果用户消息是纯语气词（"嗯""好的""哈哈"，长度 < 5 且无实体词），跳过检索，沿用上一轮结果。
