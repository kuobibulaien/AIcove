# 记忆增强实施方案 v2（四层架构）

更新时间：2026-02-12
适用仓库：`apps/mygril_flutter`

## 1. 方案背景

本方案是对原 v1 方案的全面重构。v1 基于 PEIJ 浮点数评分 + 两阶段排序，在讨论中发现以下根本性问题：

1. **AI 打分不可靠**：让 LLM 输出 0~1 的浮点数，换模型/换温度结果会变，不可控。
2. **重要性与召回脱节**：不管记忆重要性多高，一旦被注入 prompt 效果都一样。真正要解决的是**召回率**。
3. **层级太扁**：原方案只有 memories + diaries 两层，缺乏用户画像和记忆的分级管理。
4. **触发时机有缺陷**：每 N 条消息触发会截断话题、重复总结。

本 v2 方案吸收了以下学术/工程成果：

| 来源 | 吸收点 |
|------|--------|
| Stanford 生成式智能体 (2023) | 检索以相关性为主，重要性不参与检索排序 |
| MemoryBank / 艾宾浩斯遗忘曲线 (2024, AAAI) | 记忆的生死靠长期使用行为筛选，不靠一次性打分 |
| LUFY 心理学记忆模型 (2025, 京都大学) | 情绪唤醒度是最强信号；保留 <10% 对话就够 |
| OpenClaw 两层架构 | 日常层 + 核心层分离；静默晋升机制 |
| 确定性记忆系统 | AI 只做分类，系统做规则，同样输入永远同样结果 |

## 2. 核心设计原则

> **AI 只做它擅长的事（理解语义、分类），系统做它擅长的事（规则、计算）。**
> **不让 AI 干不稳定的事（打浮点数分数）。**

1. **召回率优先**：重要记忆通过"内容丰富度"天然获得更高召回率，不在检索公式里加权重要性。
2. **四层分级**：L1 画像（永驻）、L2 重要事件（丰富）、L3 日常流水（简要）、L4 碎片（标题级）。
3. **容量驱动淘汰**：不按时间删记忆，只在容量满时压缩/删除最不值钱的。
4. **层级动态流动**：记忆被召回→重新丰富（向上），容量满了→压缩（向下）。
5. **AI 分类 + 系统规则**：取消浮点数评分，AI 只做 6 选 1 分类，系统规则决定分层和淘汰。
6. **关联记忆合并**：同一主题的多条记忆合并为一条带时间线的记忆，避免召回过时信息。
7. **次日总结**：以 24 小时窗口整天对话为单位总结，第二天首条消息触发，避免拆碎话题。

## 4. 施工边界

本期范围：

1. 四层记忆架构（L1/L2/L3/L4）及层间流动机制。
2. 混合检索（向量 + BM25）。
3. AI 分类入库（替代 PEIJ 浮点数评分）。
4. 关联记忆合并与更新。
5. 次日总结触发 + Pre-Flush 应急存档。
6. 消息总结标记（防重复、支持失败重试）。
7. 数据库结构与迁移（含 FTS5）。
8. conversation_id 隔离。
9. 容量驱动的压缩/淘汰机制。

本期不做：

1. 云端同步协议大改（仅做本地兼容预留）。
2. 大规模 UI 重设计（仅做最小管理入口）。
3. 群聊/多用户权限体系。
4. 本地情感分析模型部署（用关键词表近似替代）。
