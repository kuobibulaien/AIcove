# 角色卡在 AIcove 里的结构（2026-10）

## 字段

| 字段 | 说明 |
|---|---|
| 名字（displayName） | 列表和聊天页显示的名字 |
| 简介（description） | 列表里显示的一句话简介；设计上用了酒馆预设时作为场景（scenario，`{{scenario}}`）发给模型。**已知问题：简介目前不会存进数据库**，改了会很快丢失、重启后为空，所以 `{{scenario}}` 实际常是空的；你也不能改它 |
| 人设提示词（persona_prompt） | 发给模型的核心设定；没绑定酒馆预设时作为系统提示词的第一段 |
| 自定义绘图提示 | 只有开启绘图插件时才拼到系统提示词末尾 |
| 自称／称呼用户 | 可选 |
| 音色 | 语音插件用的音色预设 |
| 插件选择 | 「全部插件」（存为空值）和「只开列出的」两种；在角色编辑页把普通插件全部勾上就是「全部插件」。MCP 连接器和空间不算在「全部」里，必须显式勾选。**新建角色默认一个插件都不开** |
| 酒馆预设 | 可绑定一个；绑定后由预设负责组装系统提示词（人设通过预设里的角色描述位置进入） |
| 思考档位 | 可按模型覆盖，默认「最低」档 |
| 开场白 | 导入角色卡时可选一条，写成会话里的第一条角色消息，不是字段 |

## 写人设提示词的建议格式

AIcove 内置角色都用 Markdown 分节，清楚好改：

```markdown
# 名字
## 身份
## 性格
## 说话方式（口癖、称呼用户、自称）
## 边界（不做什么）
```

- 写具体行为而不是形容词（「被夸会先嘴硬再偷偷开心」好过「傲娇」）。
- 不要把插件说明（语音、绘图、表情包标签的用法）写进人设：这些由插件在请求时统一注入，写进人设会和全局说明打架。
- 篇幅一般 300～1500 字；太长会挤占上下文，可以用 aicove_inspect_context 看实际 token。

## 导入

- 角色编辑页「从图片导入」：SillyTavern PNG 角色卡或角色卡 JSON；「从链接导入」：角色卡直链或 chub.ai 角色页。
- 角色卡里带的世界书、正则会随卡导入为一个绑定的新预设。
