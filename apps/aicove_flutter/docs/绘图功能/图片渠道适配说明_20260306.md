# 图片渠道适配说明

> 更新日期：2026-03-12

这次把图片请求从聊天协议里拆开了。现在图片生成单独走图片协议判断，不再复用 `Claude/Gemini` 的聊天端点。

## 当前支持

### 1. NovelAI

- `requestFormat = novelai`
- 走 `POST /ai/generate-image`
- 保留现有模型兜底和 ZIP 解包逻辑
- `nai-diffusion-4*` 走最小 V4.5 请求体：
  - 保留 `params_version / width / height / n_samples / steps / scale / sampler`
  - 保留 `v4_prompt / v4_negative_prompt`
  - 不再给 V4.5 硬塞 `qualityToggle / legacy / sm / cfg_rescale / autoSmea` 这类旧字段
- `nai-diffusion-3` 继续保留旧版兼容字段
- `customConfig.image_parameters` 只允许补充额外参数，不再覆盖核心字段，避免旧配置把 V4.5 请求体冲坏

### 2. OpenAI 兼容图片接口

- `requestFormat = openai`
- 默认走 `POST /v1/images/generations`
- 返回同时兼容：
  - `data[].b64_json`
  - `data[].url`
- 如果返回的是 URL，客户端会自动下载图片再落本地

## 关键文件

- `lib/src/core/api/image_providers/image_provider_adapter.dart`
  - 图片协议请求/响应抽象
- `lib/src/core/api/image_providers/image_provider_adapter_factory.dart`
  - 图片协议选择器
- `lib/src/core/api/image_providers/openai_compatible_image_adapter.dart`
  - OpenAI 兼容图片适配器
- `lib/src/core/api/agent_api.dart`
  - 图片生成入口，先判协议再分发

## 设置页调整

- 新增渠道时：
  - 对话渠道可选 `OpenAI / Claude / Gemini`
  - 图片渠道可选 `OpenAI / NovelAI`
- 渠道详情页的 `API 格式` 也按渠道用途动态显示

## 新增约定

OpenAI 兼容图片渠道可额外使用这些 `customConfig`：

- `imageEndpoint`
  - 自定义图片生成路径
- `imageResponseFormat`
  - 可选 `b64_json` 或 `url`
- `image_parameters`
  - 追加到请求体里的渠道特有参数
