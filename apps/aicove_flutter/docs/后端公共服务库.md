### MemoryService.ingestMessages

位置：`features/memory/services/memory_service.dart`

```dart
Future<void> ingestMessages({
  required String conversationId,
  Iterable<String>? candidateMessageIds,
  int? beforeTimestampExclusive,
  required MemoryIngestTrigger trigger,
})
```

职责：
- 统一处理“消息分轮 -> LLM 总结 -> 写入 memories -> 记录 summarization_records -> 标记 messages.summarized”
- 对同一 `conversationId` 做串行化，避免 daily / pre-flush 并发重复入库
- 对已成功的 round 保持幂等，再次调用会直接跳过或只修复脏标记

触发器枚举：

| Trigger | 用途 | 说明 |
|---------|------|------|
| `MemoryIngestTrigger.daily` | 次日总结 | 允许在低消息量日期聚合成 `day:$dateKey` |
| `MemoryIngestTrigger.preFlush` | 上下文截断前入库 | 仅处理候选消息，始终使用严格 round key |
| `MemoryIngestTrigger.manual` | 预留手动触发 | 供后续“立即总结/后台任务”复用 |

新增触发器的方式：
1. 在 `MemoryIngestTrigger` 中增加新枚举值
2. 在调用侧只负责传入 `conversationId` 和范围参数
3. 不要复制分轮、记账、标记逻辑，统一调用 `ingestMessages()`

## 设计原则

### 1. 门面模式
```
外部调用 → ChatActions (门面 + 模型 failover)
              ↓
  ChatSendService（编排）
      ↓         ↓               ↓
  ChatRequestConfigBuilder  ChatRequestMessageBuilder  ChatPluginContextBuilder
      ↓
  ChatSendApiRunner（API + 工具循环）
              ↓
  ChatMessageProcessor ← ChatTtsHandler
              ↓
  AgentApiClient ← ProviderAdapterFactory → OpenAI/Claude/Gemini Adapter
```

### 2. 职责分离
- **服务层**：纯业务逻辑，不依赖 UI
- **数据层**：数据持久化和访问
- **领域层**：数据模型定义
- **表现层**：UI 组件和页面

### 3. 依赖注入
- 使用 Riverpod Provider 管理依赖
- 服务之间通过 Provider 互相访问
- 避免直接实例化，方便测试
