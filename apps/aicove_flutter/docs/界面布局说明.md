# 全端共用界面架构与布局规范

> 生效日期：2026-09-11。状态：已确认的重写目标；规范生效不代表所有端已实现或验收。
> 2026-09-12 更新：明确三个一级页面的标题与纯图标底部导航；本批验证结果见项目需求日志。
> 本文是全端页面结构、响应式布局、导航及复用边界的唯一权威规范。决策背景见 [ADR0019](../../../docs/项目记忆/决策记录/0019-Mac基准与全端共用界面架构.md)，组件清单见 [公共组件总览](公共组件总览.md)。

## 1. 核心决定

以 macOS 为设计、开发和首轮验收基准，实现类 Telegram 的布局。所有客户端共用一套页面、组件、导航语义和业务状态；布局只有窄屏与宽屏两种模式。

- **窄屏模式就是手机模式**：一级界面占满可用内容区；打开二级及更深页面时，在同一内容区逐层进入、返回。
- **宽屏模式 = 左侧悬浮的完整手机一级界面 + 右侧展开的二级及更深页面**：左侧包含标题、搜索、内容和底部导航，作为整块表面悬浮；右侧承载窄屏原本全页打开的同一个详情页面。
- **宽屏包含窄屏的全部页面与入口**：两种模式的业务页面集合相同，改变的是页面放置位置与可用尺寸。每个页面只有一份实现，不能只共享列表内容却复制标题、表单、菜单、导航和提交逻辑。
- **Mac 基准不等于 Mac 专用页面**：在 Mac 同时验证宽窗口和窄窗口，手机直接使用同一套窄屏布局。既有窗口壳、安全区与输入适配通过平台能力接入。

这里的“全端”规定所有客户端的共同 UI 架构；本次不重新选择 Flutter 之外的框架，也不自动变更发布平台清单（Web 已于 2026-09-13 按 ADR0030 移除）。未来纳入的客户端同样遵守本规范。

## 2. 页面组成与承载关系

```text
共享的页面与状态
├─ 一级界面：聊天 / 角色 / 设置 + 共用底部导航
└─ 详情导航栈：聊天 / 资料 / 设置子页 / 编辑页 / 更深页面

窄屏                               宽屏
┌─────────────────────┐           整窗连续工作区背景
│ 一级界面或详情栈顶页 │           ╭────────────────╮  ┌────────────────────┐
│                     │           │ 同一个一级界面  │  │ 同一个详情栈顶页   │
│ 一级页带底部导航    │           │ 标题/搜索/内容  │  │ 聊天、设置、编辑等 │
└─────────────────────┘           │ 共用底部导航    │  │ 未选择时为空态     │
                                  ╰────────────────╯  └────────────────────┘
                                   四周留白、圆角、阴影
```

1. 一级页面由 `MainPage` 统一组织，仅有聊天、角色、设置三个主界面。三个页面的顶部标题分别固定为「聊天」「角色」「设置」；聊天首页不再以「联系人」作为标题，具体会话详情继续显示联系人名称。三个主界面中只有角色页放搜索框（2026-10-01 用户裁决），聊天页与设置页不放。聊天列表保持单列，提供新建，不增加“全部／未读”筛选。设置根页包含「设置」标题、头像与名字个人卡片，以及「账号／模型／通用／插件／局域网同步／调试」入口。点击个人卡片进入共用个人资料编辑页，保存后同步头像与名字；六个入口收进一个与资料卡同宽、同底色表达式的圆角 20 容器，不显示行间分隔线与副标题。个人资料仍可从「通用」进入，提示词节点与数据管理仍可从「调试」进入。
2. 聊天、角色资料、角色编辑、个人资料、模型／插件／记忆等设置子页，均属于共享详情页面。三级及更深页面继续进入同一个详情栈，不增加第三栏。
3. 左侧“完整手机界面”指完整一级导航与页面能力；在宽屏点击详情入口后，详情显示在右侧，不在左侧再打开一份。不创建手机模拟器、远控实例或另一份应用。
4. 宽屏没有选中详情时保留完整左侧手机界面，右侧显示轻量空态；不得隐式选择联系人、发起请求或把右侧变成一套独立首页。
5. 窄屏详情覆盖一级界面，默认不显示一级底部导航；回到一级界面后恢复原标签与列表位置。宽屏打开详情期间，左侧底部导航保持可用。
6. 共用底部导航依次为聊天、角色、设置，常态只显示图标，不显示选中或未选中项的文字说明；用图标形态与主题色区分选中态。保留完整按钮点击区域、系统底部安全区，以及「聊天／角色／设置」读屏标签和选中状态。窄屏手机与宽屏左侧使用同一个 `CustomBottomNav`。
7. 角色首页参照 Telegram 联系人页：居中「角色」标题、右上角唯一新建按钮、公共搜索框 `MoeSearchField` 和不分组的单列角色。搜索词同时按名称过滤角色，并跨全部会话按关键词匹配聊天记录（只含用户与助手消息，排除已删除和被替换的版本，最新在前，最多 100 条）；结果分「角色」「聊天记录」两段，记录行显示会话头像、名称、时间和围绕关键词截取并高亮的片段，点击进入该会话（暂不定位到具体消息）。移除「收藏的角色」「创建新角色」重复入口及「我的角色／收藏／推荐角色」分组；已有角色与内置角色按 ID 合并，每个角色仅一行，本地资料优先。行内只显示圆形头像、名称和有内容的简介，分割线从文字区起始；不显示「查看角色资料」占位说明，不模拟在线状态。空搜索提示居中，输入时恢复左对齐；点击角色仍通过同一详情栈进入资料页，收藏数据与角色数据保留。

## 3. 分层与复用边界

| 层次 | 职责 | 允许的变化 |
|---|---|---|
| 平台窗口与能力适配 | 原生窗口按钮、菜单栏、安全区、软键盘、返回手势、鼠标与触控 | 按实际系统能力适配，不定义另一套业务页面 |
| 自适应布局壳 | 计算模式、左右尺寸、面板悬浮、背景及页面承载区域 | 随窗口约束变化，统一管理 |
| 导航与页面状态 | 一级选择、详情栈、页面身份、草稿及滚动恢复 | 由用户操作变化，不能由跨断点重置 |
| 共享业务页面 | 页面标题、搜索、列表／表单、菜单、输入与操作 | 依据所在面板的局部尺寸调整排布 |
| 应用与数据层 | UseCase、Port、Provider、Service、Repository | 延续现有业务契约；不依赖窄宽屏模式 |

优先演进现有 `MoeAdaptiveShell`、`MoeWorkspace`、`MainPage` 和 Moe 公共组件。现有实现不足时修改其共同职责，不另建 `MacHomePage`、`MobileSettingsPage`、`DesktopSettingsPage` 等平行页面体系，也不为本次重写先创建通用 UI 框架。

同一页面身份只挂载一个有效实例。共用实现不意味着同时在隐藏手机树和右侧树各启动一个 `ChatPage`；布局重排不能重复订阅数据、请求历史、发送消息或启动媒体任务。允许首次访问时惰性创建页面，不能因模式切换丢失已访问页面的状态。

平台判断集中在窗口／能力适配和必要的公共组件内部。业务页面不得以 `Platform.isMacOS`、`isDesktop` 等条件选择不同整页布局、不同功能入口或不同提交链路。文字大小、面板尺寸和输入能力足以决定的差异，不按操作系统分叉。

## 4. 尺寸与窗口约束

模式根据应用实际可用内容宽度计算，使用 Flutter 逻辑像素；不使用物理分辨率或设备名称判断“手机／桌面”。当前基线沿用统一 900 断点，数值可在后续共同布局验收后集中调整。

| 项目 | 当前设计基线 |
|---|---|
| 窄屏 | 内容宽度 < 900，单页占满可用内容区 |
| 宽屏 | 内容宽度 ≥ 900，左侧悬浮手机面板 + 右侧详情 |
| 左侧内容宽度 | 默认 360，可拖动范围 320–440 |
| 左侧悬浮外观 | 外围留白 12，整块圆角 28，轻阴影；窄屏取消这些外框装饰 |
| 右侧宽度 | 至少 460，左侧实际最大宽度同时受右侧余量约束 |
| 调整宽度 | 面板间隙提供 8 宽拖动热区，无实体分割线；双击恢复默认值 |
| 详情起点 | 左侧内容宽度 + 两侧留白，默认 360 + 12 × 2 = 384 |

断点、留白、宽度与圆角统一来自 `ui/theme/tokens.dart`；布局壳统一计算可用空间，业务页不能各写一套断点。宽屏判断同时确保留白和左右最小宽度可容纳；以后调整常量也不得使两侧重叠。

**页面必须读取所在面板的局部约束。** 例如 1250 宽窗口里的左侧 360 宽面板，仍按 360 宽手机布局渲染，不能读到全窗宽度后再分双栏；右侧详情同样按右侧剩余宽度布局。壳负责传递正确的尺寸、安全区和键盘遮挡，页面避免重复扣减。

固定数值是默认尺寸，不是强制锁定文字行高。长标题、大字号、短窗口和软键盘场景仍须可滚动、可返回、可保存；不能用整体缩小手机截图的方式适配。

## 5. 统一导航与状态契约

### 5.1 同一入口、同一目的页面

一级入口统一调用 `MoeWorkspace.open`；声明式路径通过 `MoeWorkspace.openLocation`。详情中的进一步跳转使用其所属 Navigator。具体路由表及页面工厂只定义一次，窄宽屏、深链接与快捷入口解析到相同页面和目标 ID。

宽屏从左侧一级界面选择二级页时，替换右侧现有详情及其下级栈，不把不同二级页积累为返回历史。宽屏二级页直接显示，同级切换不播放进入或退出动画；进入三级及更深页面、逐级返回和窄屏导航仍保留原有动画。右侧二级根页不显示左上返回按钮；从右侧进入三级及更深页面才保留返回。缩回窄屏时，同一二级页恢复返回入口。未保存编辑阻止离开时，保留当前页面并提示先完成或退出编辑，不能用继续压栈绕过保护。聊天、设置、角色资料和新建角色入口共用此规则。

旧的“窄屏 push 路由，宽屏只改 activeConversationId、不维护详情导航”的做法失效。宽屏的选中态可由当前导航状态派生，不能反过来成为第二套路由真相源。

| 操作 | 窄屏结果 | 宽屏结果 | 共同要求 |
|---|---|---|---|
| 点击联系人／设置子项 | 详情覆盖内容区 | 替换右侧二级页，不累积同级历史 | 页面类型、目标 ID、操作和数据契约一致 |
| 详情中进入编辑／下级页 | 同栈继续进入 | 右侧同栈继续进入 | 返回恢复上级页面，不新增平台专用路径 |
| 返回一层 | 回到上级详情，栈空则露出一级界面 | 回到上级详情，栈空则右侧为空态 | 先处理当前弹层与未保存内容保护，再退栈 |
| 切换一级标签 | 在一级界面切换标签 | 只切换左侧一级内容 | 不隐式清空已有详情、未保存编辑或正在执行的任务 |
| 切换联系人／关闭详情 | 通过统一导航策略执行 | 同样经过统一策略 | 不静默丢弃草稿；已有编辑保护需保留或明确确认处理 |

只有壳的呈现方式可以随模式变化；页面是否替换、压栈、保留及提交的业务语义不能各端自行决定。“宽屏关闭详情”仍遵守普通返回的草稿保护规则，不能强制清空栈。

### 5.2 跨断点保持同一现场

从宽屏缩成窄屏时，已打开的详情栈顶页成为当前全页；没有详情时显示当前一级页。从窄屏放大时，一级页恢复到左侧，原详情栈完整放到右侧。

切换必须保留：一级标签、搜索词、选中联系人、列表滚动位置、详情栈顺序、表单草稿与校验状态、输入文字与附件、编辑目标、消息生成与媒体播放归属。软键盘和焦点可根据系统能力调整，但不得清空输入或自动提交。

导航容器与页面元素身份必须稳定；改变布局时不替换整棵有状态页面树、不生成新的 Navigator key、不清空 Provider 或重建另一份会话。退场完成前保留页面挂载与背景，使用视觉完成信号（如 `TransitionRoute.completed`），不能把 `pop` 的逻辑返回当作动画完成。

### 5.3 弹层与操作范围

菜单、表单弹窗、选择器与确认操作归属触发它的页面和局部 Navigator；宽屏详情弹层默认约束在右侧，一级弹层归左侧。只有已定义为应用级的操作才覆盖整窗。局部弹层打开时由统一壳处理焦点与输入屏障，不能让背后的页面误接收点击或键盘操作。

右键、长按、更多按钮可进入同一操作集合；按钮和触控入口必须完整，不把功能只藏在鼠标悬停或键盘快捷键里。菜单和底部选择器的表现差异在共用组件内按可用空间与输入方式处理。

### 5.4 编辑自动保存（2026-09-12）

已有角色、模型、插件预设、提示词与设置的编辑默认自动保存，不再要求点击“保存／确定”或在正常返回时确认。输入停顿后合并保存，返回及关闭弹窗时立即补存最后一次修改；开关和选择变化也进入同一保存流程。打开页面或只移动光标不写数据，中文输入法组合尚未确认的文字不提前提交。

保存沿用现有应用层与存储契约，写入串行执行，旧结果不得覆盖较新的编辑。校验或持久化失败时保留可编辑草稿并显示重试；只有持久化成功才视为已保存。并发内容冲突不得静默覆盖，放弃冲突草稿并重新加载属于显式恢复操作。

创建独立对象、发送消息、付费生成、导入导出和删除仍是用户明确触发的动作；删除和放弃冲突修改保留必要确认。此规则不把未实现的占位功能变成已实现功能。公共接入方式见[公共组件总览](公共组件总览.md)的 `MoeAutoSaveController`。

### 页面转场（2026-09-14）

- 窄屏进入二级及更深页面、宽屏详情继续进入下级时，统一采用 Flutter 官方 `CupertinoPageRoute` / `CupertinoPage` / `CupertinoRouteTransitionMixin`；方向、时长、曲线、底层视差、阴影、返回手势、动画中断和减少动画均交给 SDK；使用官方实现不等于手机动画或性能已经验收。
- 不维护自写横向位移 Tween、相邻路由动画跟踪、提前返回 Simulation 或可调转场曲线；快速进退仍须验证实际页面；出现问题先区分导航集成、页面绘制与 SDK 行为，不以“官方就是这样”为由判定通过，也不重新添加自写轨迹补丁。旧设置抽屉入口同样使用官方 Cupertino 页面路由。
- 宽屏从一级页打开或切换同级详情仍直接切换，保留左侧一级页。透明工作区的遮罩策略和页面状态保护属于承载适配，不重写动画。
- 窄屏根页位于详情 Navigator 外，维持原地承载；二级页从右侧滑入。详情栈内部底层页的视差由官方实现。
- 组件库可提供独立的候选转场对照实验（2026-09-14：Motor、官方 SpringSimulation、flutter_physics），由用户手动体验；不修改业务页面路由，也不将演示通过视为全栈导航或实机性能通过。实验接入说明见[调研文档](03_前端开发规范/动画组件详解/连续打断转场方案调研.md)。
- 图片预览、裁剪、卡片展开和组件内微动不属于页面横向转场，本规则不改变这些交互。

## 6. 共同外观与平台边界

- 全局不使用多余图标：名称、说明或操作文字已能表达含义时，不再搭配重复装饰图标。适用于所有页面的标题、列表、设置行、预设、文字按钮和弹出菜单，包括消息页右上角菜单及插件内部页面。保留返回、展开、更多等独立图标控件，以及必要的选择或结果状态标记；删除等危险操作通过文字颜色和确认流程表达。移除图标时同时移除占位间距，不留空图标列。
- 标题、列表、表单、聊天气泡、输入区、菜单和主题统一通过现有 Moe 组件及 Token 实现。Mac 上确立的设计同步用于窄屏手机；禁止“桌面先换一套，手机永远保留旧版”的架构分支。
- 悬浮标题、操作胶囊和输入区由共用组件根据空间排布；紧凑模式可重排、折叠次要动作，但不能减少功能或另写手机页面。当前代码里的桌面样式开关属于后续实施收口项，不视为已满足本条。
- 宽屏左侧的标题、内容与底栏必须作为一个整体悬浮。工作区纯背景统一绘制一次，贯穿整个窗口并延伸到左侧面板四周；消息与业务控件不注册为背景。聊天保留会话壁纸或自定义背景，普通二级及更深页面通过 `MoePageScaffold` 将自身底色交给同一背景承载，右侧页面表面透明；没有显式底色时沿用主题的页面底色。所有标题栏（一级、详情、聊天）静止时透明，页面内容延伸到栏后，滚动内容进入栏下方时才出现苹果式滚动边缘（模糊＋向下淡出，纯色或降低透明度时退为不透明栏与分隔线），规则与组件见 ADR0039。下级跳转同样不能在右侧叠加整页暗色遮罩；返回动画完成后恢复上级背景，不能残留上一聊天的壁纸。
- 默认头像继续为空白；默认工作区与聊天背景使用主题纯色空白，不绘制 Telegram 图案或渐变壁纸，预设背景图片后续另行提供；已有自定义头像、主题色、聊天背景优先。重写不得通过换布局覆盖用户设置。
- Mac 宽屏原生红黄绿位于左侧悬浮面板左上角；Mac 窄窗口沿用独立顶部窗口栏，页面控件使用下方完整行。系统菜单栏仍由 macOS 管理，不把它复制进手机页面。手机使用系统安全区，不显示桌面窗口栏。
- 原生窗口适配须覆盖缩放、全屏进退、最小化恢复和切屏；桌面窄窗口验证可以检验共用布局，不能代替手机安全区、软键盘和系统返回验收。

### 设置根页的尺寸参考（2026-09-13）

以用户提供的 Telegram 设置截图为本轮视觉参考，独立设置字号、触控目标与留白，不再整体乘 4/3：个人卡片与入口容器外距 12、卡片内距 16、头像 56、头像与文字间距 12，个人卡片常规高度 88；名字 17、说明 14、入口文字 16，入口图标 30 圆角方形色块、行内距横向 16 纵向 11，常规行高 52。系统大字号允许自然增高，名字过长单行省略。个人卡片与入口容器外沿对齐，头像与行图标、卡片与行箭头保持对齐。

按 2026-09-16 用户要求，设置根页「账号／模型／通用／插件／调试」五个分类图标改用类 iOS 配色与 Material 圆角图形：账号 person_rounded #007AFF、模型 layers_rounded #5856D6、界面 tune_rounded #32ADE6、插件 extension_rounded #AF52DE、调试 terminal_rounded #FF9500；白色图形 19 置于圆角 7 的 30 方形纯色色块上，无渐变、描边或阴影。该要求仅适用于设置根目录，子页继续遵守去除多余装饰图标的规则。

设置页底色与聊天、角色根页一致：共用面板内保持透明，独立承载时使用主题表面色，不额外叠加底色。2026-09-16 起个人卡片与入口容器统一为 `MoeContentSurface` 内容承载面：不透明 `componentBackground` 底色、G2 连续圆角 20（`moeG2Shape`），不再使用半透明表面色透出背景材质；箭头使用弱化文字色 55% 不透明度。入口行内不显示分隔线与副标题，入口图标色块为圆角 7 的 G2 方形（`MoeG2Decoration`）。

同一批内容面已覆盖 `MoeSettingsGroup`、`ContactEditCard` 与角色编辑骨架卡；其余独立页面内容卡片及操作级控件（按钮、浮标、菜单等）的 G2／悬浮几何改造尚未完成，仍按后续批次推进，不得以本批结果宣称全项目已统一。

## 7. 实施边界与现状

本次用户已确认全端重写的架构方向，并授权直接修订冲突规范。原“不做一次性大重构／旧 UI 只顺手收口”不再限制前端页面与导航重写。实施按可验收的功能批次推进，最终收敛到同一套界面。

现有 Flutter、Riverpod、应用层 Port 与数据契约继续作为接入边界。制定 UI 规范不等于确认 DSH 等 proposed 方案，也不授权数据／schema 迁移、删除用户数据、供应商请求、部署或改变账户状态。涉及这些内容时按对应任务单独处理。

当前源码已有统一壳、左侧悬浮面板和详情栈，可作为重写基础；旧桌面样式分支、全量路由语义一致性及全端功能覆盖仍需实施验收。不得引用 ADR0018 的历史测试或安装记录，宣称本规范已在所有端实现。

推荐实施顺序：

1. 盘点每个一级、二级及更深页面，记录共享实现位置、入口、导航目标、局部尺寸及待收口的平台分支。
2. 统一壳、页面身份、导航状态及尺寸传递，在 Mac 宽窄切换中通过状态保持验收。
3. 按聊天、角色、设置及子功能接入同一套页面与公共视觉组件；每批同时验宽窄布局。
4. 验证实际移动端的安全区、软键盘、触控与返回，以及其它目标桌面端窗口能力，最后处理已确认退役的旧入口。

回滚以每批改动前的文件快照和范围差异为准，保留已有工作树修改；不能通过整体 reset 恢复旧版。规范最初于 2026-09-11 仅修订文档；后续代码、安装与验证结果按批次记入项目需求日志。

## 8. 验收标准

下表是完整矩阵，只在改动布局壳、导航栈、断点或跨页面共享排布机制的批次执行。不改变界面行为的修改无需界面验收；只改单个页面时，检查该页面在窄／宽两种承载下的实际表现；改动公共组件或主题时，按其实际影响从下表挑选对应项（例如只改按钮颜色，检查该组件在浅／深主题下的显示即可）。说明未执行的项目，不因为无关改动重跑整张表。

| 检查 | 必须满足 |
|---|---|
| 页面覆盖 | 为本批每个页面列出唯一实现位置及窄／宽入口；宽屏右侧可打开窄屏全部二级及更深页面，窄屏可完成相同业务操作 |
| Mac 窄／宽布局 | 至少检查 360／420 和 1000／1280 逻辑宽度；窄屏单页完整，宽屏左侧整机悬浮且右侧可用 |
| 断点与拖动 | 899／900／901 边界，以及连续缩放与拖宽；无溢出、双重导航、页面重建或状态丢失 |
| 局部约束 | 宽屏左侧 320／360／440 内容宽度仍使用手机排布；右侧在最小宽度下可读可操作 |
| 导航与草稿 | 聊天→资料→编辑时跨断点，再返回／取消／保存；栈序、草稿、校验及目标归属正确 |
| 运行中状态 | 流式输出、加载历史、附件选择或媒体播放期间缩放，不重复请求、不停止任务、不串会话 |
| 弹层与动画 | 长菜单、快速连续进退、手势取消及关闭详情，范围、焦点、退出位置连续且保护草稿 |
| 可访问性 | 浅／深主题、长标题、1.0／1.8 倍字号、短窗口和键盘遮挡下，可返回且可完成核心操作 |
| 平台验证 | Mac 原生按钮与全屏恢复；实际手机触控、系统返回、安全区和软键盘；未验证平台单列缺口 |

### 手机端与Mac窄屏一致（2026-09-11，当前补充）
手机共用Mac窄屏的联系人列表、底部导航、悬浮聊天头部、输入区和纵向操作菜单；没有Mac的40px应用标题行。顶部只避让手机状态栏，下方从左排列圆形返回、资料胶囊与操作胶囊。角色目录的头像与列表项直接进入对应聊天，不再提供角色展示页；聊天内头像仅显示当前角色，菜单“详情”直接进入角色编辑。聊天菜单依次为详情、壁纸、绘图预设、清空历史记录、删除该角色（红色），不再保留独立聊天设置页。绘图预设仅在该角色启用绘图插件时显示，点击唤出与角色卡共用的绘图配置包选择列表，选中即写回角色绑定；多选改由消息长按菜单进入消息选择模式，底部仅保留左侧删除、右侧分享两个48px圆形图标悬浮按钮，不显示文字，共用悬浮材质并保留读屏标签；分享先从底部弹出随联系人实际行数收缩的面板，最高占屏幕85%，超出只滚动联系人；上方头像多选，底部紧贴并排「导出为图片」「直接分享」；选好联系人再点「直接分享」，在独立留言悬浮窗中选择「发送」或「取消」，留言可留空；发送给联系人后以可打开的聊天记录集合气泡保存，通过各接收方会话触发AI回复，空留言同样触发；删除沿用前端隐藏并保留确认。选择数量和取消入口位于顶部，空选时禁用底部按钮；选择按钮按实际可见气泡生成，替换左侧联系人头像的42px区域；联系人头像隐藏时保留原尺寸，用户消息沿用左侧预留空白，消息位置、宽度与换行不变，内部空块不生成选择按钮；隐藏记录仅在本机保存，不修改原始历史与模型上下文。聊天／角色／设置直接用底部切换，不再保留重复侧栏。手机键盘和系统返回继续使用平台能力，键盘占位不参与输入浮层的背景与圆角绘制。宽屏仍保留左侧悬浮手机面板及右侧详情。
