## 🤔 什么是公共组件？

想象你在搭乐高：
- **公共组件** = 预制好的乐高积木块
- 不用每次都从零开始做，直接拿来用就行
- 改一处，所有用到它的地方都会变

## 全局交互外观（2026-09-12）

[`moe_interaction_theme.dart`](../lib/src/ui/theme/moe_interaction_theme.dart) 统一关闭鼠标悬停底色与额外阴影；组件常态阴影、按压反馈、键盘焦点、读屏标签及业务长按操作保留。`app.dart` 在 Navigator 外用 `TooltipVisibility(visible: false)` 关闭所有悬停／长按文字提示，覆盖页面、菜单和弹窗。

局部按钮调用 `styleFrom` 时用 `withoutHoverFeedback(...)` 包装，避免局部前景色重新生成悬停效果；ElevatedButton 保留显式常态 elevation。Slider 显式传入 `overlayColor: moeInteractionOverlay`，避免 activeColor／局部 SliderTheme 绕过全局主题。MoeIconButton 不再维护悬停颜色状态。

## 高级材质系统（2026-09-14 统一命名）

**高级材质**统称随全局材质设置切换的**纯色、毛玻璃、液态玻璃**。它描述组件接入统一材质系统的能力，不是第四种模式，也不只指液态玻璃。旧文档中的“玻璃材质系统”“统一三态表面”在指这套能力时统一称为“高级材质”；具体渲染效果仍用各自名称。

“跟随全局”包含从低到高的「纯色／模糊／玻璃」三个材质等级。纯色保持不透明；模糊与玻璃各有「模糊度」「底色填充」两条独立滑条（2026-10-03；底色填充两种等级均为 0%–100%，模糊度在模糊等级为 10%–100%、玻璃为 0%–100%），一条只管背景模糊、一条只管底色不透明度，互不带动。两条滑条的 50% 为「推荐」档（2026-10-04），即最接近 iOS 的参数，拖到 48%–52% 自动吸附并在数值旁标注“推荐”。新安装默认为「模糊」推荐档（模糊度 50%、底色填充 50%，2026-10-05），只写入新建的设置存储；已有存储缺少这些字段时仍按旧规则回退玻璃。代码类名与原存储字段保持兼容。

### 模糊配方（2026-09-14，2026-10-01 改薄）

统一实现：`ui/theme/moe_frosted_material.dart`。沿用 Flutter 官方 Cupertino 的饱和度颜色矩阵（先提饱和度再高斯模糊，让背后颜色透出），但不再照搬弹窗（Alert）厚材质：2026-10-01 用户反馈原配方（固定 80% 底色、sigma 最高 30）太重、没有苹果通透感，改为向系统栏的薄材质靠拢。模糊 sigma 按全局强度经 `blurSigmaForSetting` 由 10%–100% 映射到 2–20，推荐档 50% 为 10（与 Flutter `CupertinoNavigationBar` 系统栏模糊一致）。底色填充同时控制底色与饱和度矩阵（2026-10-04）：0% 无底色、无调色，只剩纯模糊；0%–50% 底色线性升到 55%、矩阵线性加到完整强度；50%–100% 矩阵保持完整，底色升到 72%。浅色底色 `#F8F8F8`；深色底色按不透明度反推，使其叠在纯黑页面上始终等于容器色 `#1C1C1C`。背景、文字、悬浮表面使用同一配方，不响应局部覆盖或液态分层加厚。存储低于 10% 的旧值（含 0）只在显示与渲染时保底到 10%，不回写存储。内容不进入滤镜，圆角、布局与交互仍由原组件提供。系统要求不透明时回退纯色。

来源：[Apple UIBlurEffect](https://developer.apple.com/documentation/uikit/uiblureffect)、[Apple systemMaterial](https://developer.apple.com/documentation/uikit/uiblureffect/style/systemmaterial)、[Flutter 3.29.3 dialog.dart](https://github.com/flutter/flutter/blob/3.29.3/packages/flutter/lib/src/cupertino/dialog.dart)（饱和度矩阵出处，保留 Flutter BSD 许可）。Apple 未公开系统材质滤镜参数，模糊范围与底色不透明度为本项目调校值，不能称为 UIKit 原生调用或与 iOS 像素一致。

验证：`moe_frosted_material_test.dart` 覆盖强度映射、底色随强度单调变薄且低于弹窗 80%，并按存储强度 0／3.2／16／32 将 MoeFloatingSurface 与 MoeLiquidGlass 两条消费路径、三种材质层级与同一配方逐像素比较；`dark_surface_layering_test.dart` 校验三档深色底色叠纯黑均等于容器色。

### Mac 完整液态渲染前提（2026-09-14）

当前项目 Flutter 3.44.6 的 Mac 引擎默认未启用 Impeller；`macos/Runner/Info.plist` 必须保留 `FLTEnableImpeller = true`，同时覆盖 Debug／Release。更改后需要重新构建并启动，热重载无效。着色器初始化成功不代表完整液态路径生效；验收应看到启动日志 `Using the Impeller rendering backend (Metal)`，且运行树进入 `LiquidGlassLayer`／`_RawLiquidGlass`，而非 `LightweightLiquidGlass`。仅看到设置选择液态或 `MoeLiquidGlass` 外层不足以确认。系统要求降低透明度时仍按无障碍规则降级。

### 高级材质三态规范（2026-09-12 规则，2026-09-14 命名）

- 全局基础配色（2026-09-14，2026-09-29 修订暗色）：亮色主背景、次级背景和卡片／容器共用 `#FFFFFF`；暗色主背景与次级背景为纯黑 `#000000`，卡片／容器（`panel`／`componentBackground`、Material `surfaceContainer*`）为 `#1C1C1C`，必须比页面底色浅一档。纯色模式及移动表面回退的实色一律取 `componentBackground`，不取 `surface`；需要与页面同色的整页承载面（如主页外壳）显式传 `solidColor: colors.surface`。模糊材质暗色底色按各档不透明度反推，叠在纯黑上与容器同为 `#1C1C1C`；窄屏全屏主页外壳不接材质。应用主题不再读取旧亮色背景预设；保留其存储值，不迁移数据。此约定只统一配色，不改变高级材质的模式、透明度、模糊、折射、描边、阴影或文字底色叠加，也不覆盖独立聊天壁纸。

参与统一材质切换的组件，其背景只有三种状态；纯色是正式模式，不仅是关闭效果后的降级结果。

| 状态 | 背景表现 | 现有设置对应关系 |
|---|---|---|
| 纯色 | 不透明主题底色，不模糊、不折射 | `glassEffectEnabled == false`，忽略 `useLiquidGlass` |
| 模糊 | Cupertino 背景高斯模糊（按全局强度 10%–100% 映射 sigma 3–30）、饱和度处理和固定浅深色底色 | `glassEffectEnabled == true && useLiquidGlass == false` |
| 玻璃 | 使用统一液态玻璃材质，提供折射与玻璃边缘效果，按可读性规则加权响应全局参数 | `glassEffectEnabled == true && useLiquidGlass == true` |

- 三种状态互斥；界面设置的「材质等级」按由低到高的顺序以三选一表达。`AppSettings.surfaceMaterial` 与 `MoeGlassTheme.material` 由原有两个布尔字段派生，`setSurfaceMaterial` 串行保存两个字段，不新增或迁移持久化字段。
- **材质分两类（2026-10-03 用户裁决，取代原悬浮／背景／文字三层）**：①**组件材质**（`MoeMaterialBaseline.component`）用于悬浮操作栏、浮标、按钮等不移动的悬浮组件，直接跟随全局高级材质，无任何保底；②**背景材质**（`MoeMaterialBaseline.background`）用于承载文字的背景——页面／弹层／对话框背景、搜索框、输入框、菜单与文字卡片、滚动边缘——只有**模糊度保底**（玻璃模式 25%），**没有底色保底**。两类底色都只取全局「底色填充」，因此组件材质与背景材质始终同一底色，不会出现两种颜色。模糊模式整体使用 Cupertino 配方，不区分两类的保底；具体公式见下文材质参数说明。
- 切换改变背景材质及配套底色、描边、阴影，不改变组件布局、内容、交互和业务状态。统一主题色来源，不要求所有组件使用完全相同的不透明度；选中态、危险操作色等语义色保留。
- 接入组件应通过公共材质容器响应全局模式，同时遵守下文「液态玻璃使用范围」，不能将全局玻璃选择等同于所有表面必须启用液态分支。背景整块绘制一次；搜索框、输入框及文字卡片保留自己的背景材质表面，不给每个 Text 单独铺底；按钮按下文按钮组件规范绘制独立悬浮材质。内部文字输入装饰保持透明，避免重复铺底。
- ~~文字类组件的浅层透明底色（2026-09-14）~~：已于 2026-10-03 取消（被上条“材质分两类”取代）。原 6% `textMaterialTint` 与文字层 25% 底色保底会让文字组件与悬浮组件底色不一致，现背景材质只保留模糊保底，底色统一跟随「底色填充」。
- 无障碍要求不透明时应回退纯色；液态能力不可用时可回退毛玻璃。实际渲染降级不覆盖用户选择；纯色模式不得残留背景模糊或折射。
- 根页面背景不绘制玻璃边缘线或透镜高光。`MainPage` 明确设置 `useLiquid: false`、无边框及阴影，在液态模式下保留统一模糊和透色；独立悬浮组件与按钮继续响应液态效果。此例外同时适用于手机根页和宽屏左侧的根页背景。
- 本规范定义组件背景材质，不自动修改聊天壁纸、图片内容或静态图片模糊缓存；具体组件接入按批次推进。

### 液态玻璃使用范围（2026-09-16 用户确认）

- **Premium 液态玻璃仅用于静态、非滚动表面。** 这是组件选材的使用约束，不因当前滚动错位问题而放宽。
- **会随内容上下滚动的大块背景不得直接接入液态玻璃**，包括随 `ListView`／`CustomScrollView` 移动的设置分组、卡片及内容面板背景；不能因为全局选择了玻璃模式，就把所有公共容器无差别接入液态分支。此类大面积内容背景统一使用 [`MoeContentSurface`](#6-moecontentsurface---内容承载面不透明卡片)；内容面同样适用于不随滚动移动的静态阅读面板，2026-09-16 起 `MoeSettingsGroup`、`ContactEditCard`、角色编辑骨架卡与设置根页卡片已迁移。
- 判断对象是承载材质的表面本身：固定表面后方或内部的内容滚动，不等于该表面随滚动移动；但固定不代表自动获得液态资格，仍须遵守根页面背景等已有豁免和实际渲染验收要求。
- 几乎不滚动的豁免（2026-10-03）：滚动只作为大字号溢出兜底的固定内容（如聊天更多面板九宫格）用 `MoeRarelyScrolledRegion` 包住滚动容器的内容，其下表面忽略最近一层 `Scrollable`、继续跟随全局材质；外层拖动弹层、滑钮跟随层和排序代理仍强制实色。列表或预期会滚动的内容不得使用。
- 接入公共材质容器不等于必须启用液态分支；后续组件调整须先核对本节使用范围，再决定材质。2026-09-22 起 `MoeFloatingSurface` 与直接入口 `MoeLiquidGlass` 共用 `moe_surface_motion.dart` 守卫：表面位于 `Scrollable` 内、可拖动底部弹层内、`DraggableScrollableSheet` 内、跟随位移的 `CompositedTransformFollower` 内或排序拖动项内时，保持实色背景，不创建液态着色器或背景滤镜；显式开启玻璃也不能绕过。排序项移入 Overlay 后由拖动监听器祖先继续约束。仅在表面内部滚动的内容不会禁用固定外框材质。
- 上述守卫覆盖搜索、输入、分段选择、旧卡片、滚动操作区及滑钮等公共入口；新内容卡片仍直接使用 `MoeContentSurface`，不以运行时降级替代正确选材。自定义自由位移动画须遵守同一规则，不能把导航／菜单的有限过渡与任意拖动混同。验证见 `moe_moving_surface_test.dart` 的真实拖动、排序代理、窄宽／浅深色、首帧像素与草稿焦点检查；运行中应用及手机验收结果单独记录。

### 高级材质接入排查

先区分两个维度：**材质模式**是纯色／毛玻璃／液态玻璃；**材质类别**是组件材质／背景材质（见上文“材质分两类”）。一个组件接入高级材质后，再按用途选择层级，参数与公式统一见下文「玻璃材质设计令牌」。

| 排查状态 | 判定标准 |
|---|---|
| 已接入 | 独立表面通过公共容器跟随全局三态，响应全局「模糊度」「底色填充」两条滑条，并使用合适的材质类别；或明确共用已接入的父级表面；液态分支须符合上文使用范围，不能仅凭调用公共容器判定合规 |
| 部分接入 | 使用了公共容器，但调用方固定模式／厚度，或另铺不透明底色遮盖效果，导致全局设置不能完整生效 |
| 未接入 | 应有独立材质的表面仍自行绘制固定底色、模糊或液态效果，未消费统一主题 |
| 无需独立接入 | 纯文字、图片／壁纸内容、色值预览及系统原生窗口控件；菜单／列表行可共用父级表面，独立应用按钮统一接入下文按钮材质 |

### 1. ⭐ MoeFloatingSurface - 标准悬浮毛玻璃表面（推荐公共组件）

📄 `lib/src/ui/shared/widgets/moe_floating_surface.dart`（由 `widgets/index.dart` 统一导出）

**是什么**：专为悬浮操作栏、浮标、控制胶囊打造的标准化高级材质容器，支持纯色、毛玻璃、液态玻璃。它封装了完整的外部阴影、圆角裁剪、背景模糊、主题底色和透明 Material 语义层。

**液态分支绘制约束**：`MoeLiquidGlass` 用 `Stack` 将铺满组件的玻璃底层与清晰内容分开；内容按同一形状裁剪，不能作为液态着色器的子内容再次包裹内层材质，否则搜索框等嵌套背景会偏移。搜索框轮廓统一由外层材质绘制，`TextField` 不再重复描边。完整液态回归使用 `--enable-impeller` 检查渲染像素，普通组件测试中的降级路径不能替代。 同一表面的底色、阴影、边框与内容裁剪必须采用同一形状；LiquidOval 1.4.4 的边框绘制会忽略 side，外观轮廓使用 Flutter OvalBorder 对应实现。

**毛玻璃承载液态控件（2026-09-14 修正）**：根背景 `useLiquid: false` 后会进入 `MoeFloatingSurface` 的毛玻璃分支；这个分支也必须将 `BackdropFilter` 作为仅铺底的 `Positioned.fill`，与内容并列，不能继续把整棵业务子树作为滤镜的 child。否则内层液态 shader 的屏幕坐标与外层滤镜采样纹理原点不一致，可表现为轮廓偏移、截断或液态效果消失。仅验证液态嵌套液态不足以覆盖实际根页面，须同时运行 `moe_liquid_backdrop_alignment_test.dart` 的毛玻璃父层、浅深色和缩放像素回归。

**已知未解决问题（2026-09-16 复核）**：当前锁定的 `liquid_glass_widgets 1.5.0` 在祖先 Transform 平移和真实 ListView 首次滚动时均可出现玻璃着色未随位置同步；公共 `MoeLiquidGlass` 默认 premium，设置分组也经此路径，而依赖 README 明确不保证 premium 在 ListView／CustomScrollView 内正确渲染。静态嵌套修复不等于动态验收。显式复现：`tool/flutterw test --enable-impeller test/ui/shared/widgets/moe_liquid_motion_known_issue_test.dart --dart-define=RUN_KNOWN_LIQUID_MOTION=true`，当前祖先平移和滚动原路径两项仍失败，默认跳过，不能计入通过项。新增测试侧对照在 jumpTo 后、单帧绘制前将玻璃子树标为重绘，同一滚动样例通过；这只定位动态更新链路，不是已交付补丁，也不证明连续滚动／合成动画均已修复。09-14 普通重绘补偿试验无效已撤回，不能与此次时序对照混同。三组相关像素测试的资源初始化已适配 1.5.0 着色器文件名；证据见根目录 `scratch/liquid-motion-20260916/`。本轮未更改生产材质或依赖、未更新应用、未做 Mac 实际窗口与手机验收。后续组件选材以本文件「液态玻璃使用范围」为准，不以放宽 Premium 的静态、非滚动限制来处理误用。 2026-09-22 应用公共入口已对滚动／拖动表面回退实色，原依赖问题不等于修复；上述复现中的滚动样例改为直接调用依赖 `AdaptiveGlass(premium)`，避免被应用守卫降级后误判渲染器已正常。

**毛玻璃／纯色分支结构**（液态分支委托 `MoeLiquidGlass`，业务子树保持同一身份）：
```text
DecoratedBox（外部柔和阴影 colors.glassShadow，不被圆角裁剪截断）
└─ ClipRRect（边界裁剪，支持自定义圆角 radius）
   └─ Stack（背景与内容并列，保持同一业务子树身份）
      ├─ Positioned.fill → IgnorePointer → BackdropFilter → SizedBox.expand（仅铺底，按模式与厚度启用）
      └─ Material（glassTintForFill 底色 / 纯色底色 + 边框）
         └─ child（清晰内容，可含液态控件）
```

**参数列表**：

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `child` | `Widget` | **必填** | 悬浮层内容（如输入条、操作按钮、图标、表单等） |
| `radius` | `double` | `28.0` | 圆角半径（常见取值：普通悬浮卡片 `28`、按钮 `16~22`、胶囊/圆形浮标 `999`） |
| `blurSigma` | `double?` | `null` | 局部覆盖模糊强度。为 `null` 时自动读取全局 `MoeGlassTheme.blurSigma`（默认 16.0） |
| `blurEnabled` | `bool?` | `null` | 局部覆盖是否启用模糊。为 `null` 时自动读取全局 `MoeGlassTheme.enabled` 并结合系统高对比度状态 |
| `useLiquid` | `bool?` | `null` | 默认跟随全局材质；关闭效果或要求不透明时仍回退纯色 |
| `solidColor` | `Color?` | `null` | 纯色模式底色，默认 `colors.surface`；玻璃模式共用 `colors.glassSurface` |
| `borderRadius` | `BorderRadius?` | `null` | 局部圆角覆盖，例如底部弹层仅顶部圆角 |

### 3. 🎨 玻璃材质设计令牌 (Tokens)

📄 `lib/src/ui/theme/tokens.dart`

`MoeColors` 中包含 3 个专用颜色令牌，全部支持 `copyWith` 与 `lerp` 平滑动画插值：

| Token 属性 | 用途 | 浅色模式默认值 | 深色模式默认值 |
|---|---|---|---|
| `colors.glassSurface` | 历史玻璃色令牌（内容面板统一使用 surface） | 中性白色 36% 不透明度 | 中性 `#202020` 30% 不透明度 |
| `colors.glassBorder` | 悬浮面板细边框 | 白色 55% 透明度（高光微边） | 白色 7% 透明度（暗光细边） |
| `colors.glassShadow` | 悬浮面板阴影色 | 黑色 6% 不透明度（轻浮空感） | 黑色 16% 不透明度（深沉浮空感） |

以下参数仅用于玻璃等级及其无着色器降级路径，内容表面以 `colors.surface` 统一色相。`MoeMaterialBaseline.component` 用于组件材质（无保底），`background` 用于背景材质（MainPage、弹层、对话框、搜索框、公共输入框、菜单、历史文字卡片及滚动边缘，模糊保底25%）。应用按钮使用组件材质，主操作以半透明强调色染色。历史 FrostedGlassCard 优先使用全局设置，无主题时才用自身默认值。

模糊：令 `t = clamp(sigma / 32)`，`s = blurFactor + (1 - blurFactor) × t`，渲染 sigma 为 `20 × s²`（`MoeMaterialBaseline.blurSigma`），推荐档 50% 为 5，取 liquid_glass_widgets 1.5 按 iOS 26 校准的默认模糊（2026-10-04，原上限 12、中档 3）。底色（2026-10-03 起与模糊独立）：玻璃为 `glassSurface.a × fill`（`MoeColors.glassTintForFill`），模糊为 `MoeFrostedMaterial.surfaceTint(fill:)`，0%–50%–100% 分段线性映射 0%–55%–72%（深色在极低填充时底色封顶为白，叠黑底略暗于容器色）；两类材质共用同一结果，不分层加厚。纯色与系统不透明辅助功能仍使用实心表面；液态共用模糊与底色计算，折射参数独立，边框、阴影沿用各自规则。

**命名常量**：
- `kDefaultGlassBlurSigma = 16.0`：悬浮栏默认模糊强度
- `kMinGlassBlurSigma = 0.0`：模糊强度调节下限
- `kMaxGlassBlurSigma = 32.0`：模糊强度调节上限

### 4. ⚙️ 用户设置联动与持久化

1. **设置字段**（`AppSettings`）：
   - `glassEffectEnabled`（`bool`，默认 `true`）：控制是否启用玻璃毛玻璃效果。
   - `useLiquidGlass`（`bool`）：玻璃效果开启时选择液态玻璃；关闭时选择毛玻璃。三态映射见本节开头规范。
   - `glassBlurSigma`（`double`，默认 `16.0`，限制在 `0.0 ~ 32.0`）：沿用原存储契约，只驱动模糊。
   - `glassTintFill`（`double`，存储键 `glass_tint_fill`，0–1，2026-10-03 新增）：只驱动底色。未存储时按 `glassBlurSigma / 32` 推导，保持旧外观；首次调整任一滑条即写入当前值，此后两者独立。仅本机设置（`localGeneralSettings`），无数据迁移。
2. **设置界面入口**：
   位于「界面设置」(`UiSettingsPage`) 的「材质等级」分组，按由低到高提供「纯色／模糊／玻璃」三选一。
   - 模糊与玻璃均显示「模糊度」「底色填充」两条百分比连续滑条（键 `material-blur-slider`／`material-tint-slider`）；模糊度在模糊等级下限 10%、玻璃下限 0%；底色填充两种等级下限均为 0%。模糊度按 `value / 100 * 32` 存入 `glassBlurSigma`，底色填充按 `value / 100` 存入 `glassTintFill`。显示保底不回写存储。
   - 切换模式保留两条当前值；纯色隐藏滑块。
   - 保存失败显示重试提示，未持久化成功的选择不发布到全局主题。

### 6. MoeContentSurface - 内容承载面（不透明卡片）

`lib/src/ui/shared/widgets/moe_content_surface.dart`（由 `widgets/index.dart` 统一导出）

**是什么**：设置分组、编辑卡片、骨架卡、静态阅读面板等内容区域的标准容器。默认不透明 `componentBackground` 实色 + Figma G2 连续圆角（`moeG2Shape`，cornerSmoothing 0.6），不跟随全局玻璃／液态模式，不自动产生液态材质、透镜、文字染色、阴影或描边。

**与 `MoeFloatingSurface` 的分工**：悬浮控制条、浮标、按钮、菜单等**浮动小表面**继续用 `MoeFloatingSurface`（响应全局三态材质）；页面内容卡片、分组容器用 `MoeContentSurface`。新需求默认选内容面，只有真正浮在内容上、需要响应全局材质的控件才用悬浮面。

**结构与状态**：`ShapeDecoration`（阴影）→ `ClipPath`（`ShapeBorderClipper`）→ `Material(shape)`（底色、描边、水波纹），三层共用同一条 G2 路径；`KeyedSubtree` + 稳定 `GlobalKey` 保证切换模糊或全局材质模式时子树草稿、焦点、滚动状态不重建。

**可选小模糊**：`blurSigma` 是唯一显式模糊入口（默认 0，上限 `kMaxContentSurfaceBlurSigma = 8`），仅在全局玻璃开启且系统未要求高对比／降低透明度时生效；被禁用时回退不透明实色且无滤镜。模糊层只作 `Positioned.fill` 铺底，子内容不进入滤镜合成。

**参数列表**：

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `child` | `Widget` | **必填** | 内容 |
| `radius` | `double` | `MoeSettingsLayout.cardRadius`（20） | 统一圆角半径，可为 0 |

📄 `lib/src/features/chat/presentation/widgets/incremental_message_text.dart`

`MessageBubble` 对至少 512 字符且含硬换行的正文使用此组件：复用已完成段落的 `Text` 子树，追加时只重新排版变化的段落，不冻结文字。短正文和无硬换行正文仍使用原生 `Text`。样式变化会刷新全部段落；空行、CRLF、字号缩放及整条消息读屏语义均有测试。

离线真机复测：`flutter run --profile --no-resident -d <device> -t tool/chat_scroll_probe.dart`，必须前台且解锁，`valid: true` 才能使用采样结果；脚本使用合成流，不发模型请求。2026-09-05 同机 120Hz 对照，加入段落复用前后拖动帧 UI P95 为 11.138ms → 3.798ms，超 8.33ms 预算帧为 124/836 → 0/949。该对照仅覆盖单个长气泡，基线已含本轮滚动控制修复，并非整个旧版本；不能代表开启消息分段后的表现，也不代表真实模型解析、网络和图片解码的全部耗时。

**多气泡补测（2026-09-05）**：探针现默认启用分段，使用 `tool/chat_segmented_fixture.dart` 的内存 SQLite（开启外键）、内存偏好与假模型输入，运行真实 ChatActions 分段/占位/收尾链路；旧单气泡对照追加 `--dart-define=SEGMENTED=false`。采样还须检查 `behaviorPassed: true`、拖动期间新增气泡数、实际气泡坐标误差与回底距离；几何在 `endOfFrame` 后读取，不能拿固定 16ms 延时当布局完成。多气泡的结构事件允许重建列表，不能拿单气泡的“零列表重建”作验收。

本轮修复：跟随时跳过入场动画的消息不再保留待播放资格，避免下一段出现时旧气泡补播动画；明确跟随时停止布局对齐后残留的回弹，用户拖动/惯性仍不干预；有等待展示的完整分段时保持 flush 有效，即使模型暂无新增量也按延迟显示。守卫：`test/ui/features/chat/widgets/chat_message_list_segmented_delivery_test.dart`，实际 360/1000px、0/0.3 秒分段延迟，以及新增 12 个气泡的惯性轨迹对照。

### 按钮组件

独立应用按钮统一经 `MoeButtonSurface` 接入 `MoeFloatingSurface` 的悬浮层，跟随纯色／毛玻璃／液态玻璃与全局厚度，并继承不透明辅助功能降级。强调色和显式语义色只作染色：不透明度上限为浅色22%、深色28%，原本更淡的透明度保留；文字使用主题文字色或显式语义色。沿用按钮布局与回调，紧贴文字的旧入口补少量内边距以避免圆角裁切文字。

已有 `MoeFloatingSurface` 包裹的内部按钮共用外层背景与轮廓，`MoeButtonSurface` 不再创建第二层玻璃、默认描边或阴影；右上角操作胶囊、输入胶囊及弹出菜单的内部操作遵守此规则；下方展开面板中的模型、思考、相册等独立大按钮通过 `shareParentSurface: false` 保留各自材质和轮廓。内部仍保留语义染色、按压与显式键盘焦点提示。

`withMoeInteractionTheme` 通过 `ButtonStyle.backgroundBuilder` 覆盖 Text／Filled／Outlined／Elevated／Icon／SegmentedButton；`withoutHoverFeedback` 将显式按钮背景转为材质染色，保留按压和键盘焦点反馈。四类 Moe 按钮、聊天更多／附件操作、分段／筛选／能力选择、编辑入口与页面自绘操作复用同一容器；Chip 共用透明主题并由按钮表面承载。菜单和列表行继续共用整块父级表面，色值预览保留真实颜色。语音气泡内部的播放、暂停与失败重试图标属于气泡内容，不接独立按钮材质／底色／描边／阴影，直接使用气泡前景色，保留点击与状态反馈。

#### MoeSettingsGroup - 设置分组容器 (Settings Group Container)

iOS 风格的设置分组卡片，自动处理最后一行的分割线。

**⚠️ 宽度规范（重要）**：
> `MoeSettingsGroup` 默认外边距为 `EdgeInsets.zero`，自身不再承担水平内缩；默认圆角 20（`MoeSettingsLayout.cardRadius`），背景与连续圆角统一委托 `MoeContentSurface`。
> 设置分组随列表滚动，按上文「液态玻璃使用范围」使用 `MoeContentSurface` 不透明内容面（默认 `componentBackground`、`blurSigma` 为 0），不进入液态分支。
> 二级及更深设置页统一用 `MoeSettingsContent` 包裹内容（一般在 `ListView` 外层）：按所在面板宽度计算单侧内缩 `inset = (宽度 × 0.04).clamp(12, 32)`，内容列宽 `min(760, 宽度 − 2 × inset)` 并居中；水平约束无界时按 760 渲染，不读全窗 MediaQuery。组内卡片横向铺满内容列，组间距用 `MoeSettingsLayout.sectionGap`，列表只用 `MoeSettingsLayout.verticalListPadding`。
>
> ```dart
> // ✅ 正确用法
> MoeSettingsContent(
>   child: ListView(
>     padding: MoeSettingsLayout.verticalListPadding,
>     children: [
>       MoeSettingsGroup(
>         title: '分组',
>         children: [...],
>       ),
>       const SizedBox(height: MoeSettingsLayout.sectionGap),
>       MoeSettingsGroup(children: [...]),
>     ],
>   ),
> )
>
> // ❌ 错误用法（页面内自定义 maxWidth 或给 group 补水平边距）
> Center(
>   child: ConstrainedBox(
>     constraints: const BoxConstraints(maxWidth: 820),
>     child: ListView(children: [MoeSettingsGroup(...)]),
>   ),
> )
> ```
>
> 不在 `MoeSettingsContent` 范围内、且仍依赖旧版默认外边距的调用点，须显式传 `margin: EdgeInsets.symmetric(horizontal: 16)` 保留原间距。

| `children` | `List<Widget>` | 子组件列表（通常是 MoeSettingsRow） |

| `backgroundColor` | `Color?` | 卡片背景色 |
| `borderRadius` | `BorderRadius?` | 卡片圆角（默认 20） |

**使用示例**：

## ⌨️ 键盘弹出规范 (新增 2026-01-25)

### 问题背景

在底部弹窗（BottomSheet）中有输入框时，键盘弹出会导致界面抖动。

**错误做法**：在 `SingleChildScrollView` 或 builder 内部使用动态 `viewInsets.bottom` 作为 padding：
```dart
// ❌ 错误：内容区域每次键盘高度变化都会重新布局，导致抖动
SingleChildScrollView(
  padding: EdgeInsets.fromLTRB(20, 16, 20, 24 + viewInsets.bottom),
  ...
)
```

**正确做法（新规范）**：**不推高整个 sheet 外框**，只在内部内容区用 `AnimatedPadding` 给键盘让位，让观感更像“输入框抬起”，而不是“整块弹窗飞起来”：
```dart
// ✅ 正确：外框不动，内部内容区给键盘让位（推荐）
final viewInsets = MediaQuery.viewInsetsOf(context);
return Container(
  ...
  child: AnimatedPadding(
    duration: kAnimFast,
    padding: EdgeInsets.only(bottom: viewInsets.bottom), // 内部让位
    child: SingleChildScrollView(
      padding: const EdgeInsets.all(16), // ✅ 固定 padding
      ...
    ),
  ),
);
```

### 已封装的组件

| 组件 | 键盘处理 | 说明 |
|------|---------|------|
| `MoeBottomSheet` | ✅ 已内置 | builder 内部只需使用**固定 padding** |
| `AddProviderSheet` | ✅ 已修复 | 自定义 sheet，内部 AnimatedPadding 处理 |
| `showCreateAutoReplyTriggerSheet` | ✅ 已修复 | 自定义 sheet，内部 AnimatedPadding + 可滚动处理 |
| `MeoTalkDialog` | ✅ 已修复 | 含输入框的底部对话框会跟随键盘上移 |

### 公共内容弹窗布局（2026-09-13）

参考 [Apple Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets)，Flutter共用实现，不新增平台页面。顶部28圆角、36×5拖动条；导航栏基础高度52、标题17半粗体，左右操作区等宽以保证长短标题始终居中，超长标题省略。关闭按钮为44触控区内32圆形按钮，不用“取消”误导自动保存表单。

- `MoeBottomSheet` 统一管理导航栏、内容、可选 `footer` 与安全区。底部操作区外距左右20、上下12，内容页面不重复补底部安全区。短列表按内容收缩；长内容由调用方提供可滚动组件。宽屏最大宽度640，仍归属调用方Navigator。
- 浅色模式的底部弹窗不压暗背景，由全局 `BottomSheetThemeData.modalBarrierColor` 统一设为透明，内容弹窗、操作菜单与直接调用的底部选择器共用；点击空白处关闭及阻挡背景点击的行为不变，深色模式沿用默认遮罩。
- `footer` 放确认等明确动作与必要说明；普通编辑仍自动保存。模型导入选择器的全选放在导航栏右侧，数量说明居中置于整行确认按钮上方；搜索与列表共享滚动区，让短窗口、大字号与键盘组合下内容仍可访问。
- 材质继续遵循前文可读性加权，整块只绘制一层，内部经 `MoeSurfaceGroup` 共用，不增加导航分隔白线或实心列表白板。
- 源码渲染与布局测试不等于实机运行端已更新；本批验证与缺口见项目需求日志。

### 使用 MoeBottomSheet 的正确姿势

```dart
showMoeBottomSheet(
  context: context,
  title: '编辑',
  builder: (context) => Padding(
    padding: const EdgeInsets.all(16),  // ✅ 固定 padding
    child: Column(
      children: [
        TextField(...),
        MoePrimaryButton(...),
      ],
    ),
  ),
);
```

### 自定义 BottomSheet 的正确姿势

如果不使用 `MoeBottomSheet`，需要自己处理键盘（同样遵循“外框不动、内部让位”）：

```dart

  context: context,
  isScrollControlled: true,
  backgroundColor: Colors.transparent,
  builder: (context) {
    final viewInsets = MediaQuery.viewInsetsOf(context);
    return Container(
      ...

        duration: kAnimFast,
        padding: EdgeInsets.only(bottom: viewInsets.bottom), // ✅ 内部
        child: SingleChildScrollView(
          padding: const EdgeInsets.all(16), // ✅ 固定
          ...
        ),
      ),
    );
  },

```

### 一级手机面板悬浮（2026-09-11，追加纠正）

用户明确要求左侧完整手机界面悬浮在整个窗口上。`MoeAdaptiveShell`宽屏给一级面板12px外围留白、28px整体圆角和轻阴影，标题／内容／底栏统一裁剪；原有竖直分割线改为间隙中的8px拖动热区。360宽是面板内容宽度，默认详情起点为384；900断点与320–440可调范围保留，右侧最少460，窗口不足时限制最大左栏宽度。窄屏取消面板留白和圆角；两侧元素用稳定key调整绘制顺序，保留搜索、草稿和详情栈。

`MoeWorkspaceBackground`：聊天／空白详情和通过`MoePageScaffold`接入的普通二级及更深页面，把纯背景注册给当前详情路由，宽屏只在工作区底层绘制一次，背景贯穿整个窗口；窄屏在页面本地绘制。不得把消息内容、交互控件或业务页面作为背景注册。`MoeDetailStackObserver`仅根据最上层PageRoute选择背景，弹出菜单不改背景，退出页到Route.completed后才释放；普通资料／设置使用自身底色贯通全窗，未指定时使用主题页面底色；不能只让右侧透明而漏掉背景注册。

`ParallaxSlidePage`与`ParallaxSlidePageRoute`新增`dimPreviousPage`，默认true保持原行为。桌面透明聊天与宽屏工作区内全部详情跳转（含局部Navigator继续进入下级）关闭旧Cupertino全页暗色遮罩，避免贯通背景在详情边界出现暗色接缝；动画和手势统一遵循官方 Cupertino，见上述页面转场规范。Mac原生按钮使用相同外围留白，在宽窄缩放后重新对齐标题行。


本批背景回归：`test/ui/shared/widgets/immersive_detail_pages_test.dart` 验证普通详情及下级背景注册、整窗实际像素、浅深色、360／420／899／900／901／1000／1280宽度、320／440左栏与草稿身份保持；原生实测范围见2026-09-12项目需求日志。

### 消息多选与长图导出（2026-09-12）

- 聊天中的文字、图片、语音菜单共用「多选」入口；Mac 同时支持长按和右键。发送中的消息暂不参与选择。
- `ChatMessageSelection` 由共享 `ChatPage` 持有，按显示气泡 ID 与时间线顺序选择；旧文本分段逐气泡勾选，导出不包含未选段落。多选状态不写数据库或聊天上下文。
- `ChatSelectionRegion`／`ChatSelectableMessage` 复用 `MoeCheckbox`。点击可切换，沿左侧勾选区上下拖动可连续选择／取消；消息区长按后也可拖动连选，普通滑动仍翻阅历史。靠近上下边缘自动滚动，反向缩短范围恢复拖动前的选择。
- 多选期间保留 Composer 草稿并隐藏输入区，顶部显示数量，底部以 `MoeFloatingSurface` 承载左删除、右分享的圆形图标按钮；返回先退出多选。宽窄布局使用同一状态与页面，底部避让按工具栏实际高度测量。
- `ChatImageExportPage` 预览后保存；`renderChatImage` 在独立渲染树中复用 `MessageBubble`，按所选内容生成完整 PNG，不依赖当前可视区。保留气泡颜色、文字、头像和图片，背景沿用当前会话的背景图、底色、遮罩与模糊参数，按图像宽高比逐张向下接续并裁切末张；不包含勾选框、输入框或工具栏。预览页顶部导航与底部保存控件位于长图头尾，与图片共同滚动。
- `ChatShareSheet` 共用底部弹窗，按联系人实际行数收缩，高度最多占可用屏幕的85%，达到上限只滚动联系人区；上方选择联系人，底部紧贴并排「导出为图片」「直接分享」。点击「直接分享」后才打开独立留言悬浮窗，提供「取消」「发送」；取消不发送且保留联系人选择，留言输入文字及提示文字居中。留言可留空，显式发送通过 `ChatActions.forwardMessages` 绑定接收会话，落库后触发该会话AI回复；不会切换当前活跃聊天。批量中已受理的接收方不会因后续接收方失败而重复发送。
- `ChatRecordBlock` 是带结构化记录的文本块：集合卡片可进入 `ChatRecordPage` 查看来源消息；请求文本明确标记「用户与谁的聊天记录」，留言作为同一用户消息的独立文本块。使用原有JSON存储，不迁移数据库；旧客户端可读文本回退。详见 [ADR0025](../../../docs/项目记忆/决策记录/0025-聊天记录集合分享.md)。
- 长图默认逻辑宽 420、最高 2 倍像素；限制最大边长和像素总量，过长会提示分批导出。图片先解码并完成独立 LayoutBuilder 的构建；加载失败或超时明确提示。桌面选择 PNG 保存位置，Android 沿用相册保存与权限流程，iOS 沿用文件保存。
- 回归入口：`chat_message_selection_test.dart`、`chat_selection_page_test.dart`、`chat_image_export_test.dart`、`chat_image_save_test.dart`；原生宽窄验收及平台缺口见项目需求日志。
