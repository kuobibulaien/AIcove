# 提示词默认值系统

更新时间：2026-05-28

## 目标

把项目里分散的硬编码提示词统一收口到一个源码级真相源里，方便：

- 统一维护默认提示词
- 支持 `{variable_name}` 风格的动态模板
- 通过 Web 管理面板直接修改打包进 APK 的默认值
- 为后台 Agent Builder 保存可预览、可复用的 Agent 蓝图

## 真相源

- JSON 源文件：`C:\ide\aicove\apps\aicove_flutter\assets\prompt_defaults.json`
- Dart 生成文件：`C:\ide\aicove\apps\aicove_flutter\lib\src\core\prompts\prompt_builtin_defaults.g.dart`
- 模板渲染器：`C:\ide\aicove\apps\aicove_flutter\lib\src\core\prompts\prompt_template_renderer.dart`
- 代码生成脚本：`C:\ide\aicove\cloud_backend\prompt_defaults_codegen.py`

## 工作流

1. 在 JSON 里维护 `variables`、`prompts` 和可选的 `agents`
2. 保存后执行代码生成，把 `prompts` 同步成 Dart 常量；`agents` 作为管理后台蓝图元数据保留在 JSON 中
3. Flutter 代码统一通过 `PromptBuiltinDefaults.xxx` 读取默认提示词
4. 运行时如需插值，统一走 `PromptTemplateRenderer`

## 内置默认积木边界

`prompt_defaults.json` 里的 `prompts` / `variables` 是软件随包发布的内置默认积木，只能通过 Web 管理面板维护。保存后会重新生成 Dart 常量，App 更新时这些内置节点按新包内容直接覆盖。

移动端后续允许用户自由新建自己的上下文积木并组装 Agent，但不应把这些内置默认积木做成手机端可编辑对象。也就是说，项目只规定几块不可自定义的默认积木，不限制用户创建新积木、引用默认积木或自由组装 Agent。

## Web 管理面板

后端启动后可直接打开：

- 面板入口：`http://127.0.0.1:8000/prompt-admin`
- API：`http://127.0.0.1:8000/api/v1/prompt-defaults-admin/document`

面板能力：

- 浏览 / 搜索所有默认提示词
- 编辑标题、分类、ID、`dartName`、模板正文、变量列表
- 维护变量目录（名称 / 描述 / sampleValue）
- 用 sampleValue 预览模板渲染结果
- 对当前提示词模拟后台 Agent 运行时组装：`objectivePrompt + extraInstruction`，实时查看最终 system prompt
- 后端已提供 Agent 蓝图 CRUD 与预览接口，前端可基于这些接口实现可视化 Agent Builder
- 保存后自动重生成 Dart 默认值文件

## 手机端管理入口

手机端提供运行时管理页：

```text
设置 → 提示词节点
```

该页读取本地打包的 `prompt_defaults.json` 与 `agent_context_defaults.json`，用于核对内置提示词、Flutter 运行用途和 Agent Build 图节点的对应关系。内置默认节点在手机端只读，不允许本机覆盖模板；默认节点的变更仍由 Web 管理面板维护，保存后生成新的 Dart 默认值。

手机端可以新增自定义节点。自定义节点保存在 SharedPreferences，ID 不能与内置默认节点重复；当 Web 默认配置新增或更新同名默认节点时，默认节点作为权威配置使用，自定义节点不能覆盖它。

## Agent 蓝图后端

`prompt_defaults.json` 允许新增顶层 `agents` 数组，用于保存后台 Agent Builder 的源码级蓝图。蓝图不会生成 Dart 常量；它是管理后台和后续运行时适配器可读取的结构化元数据。

### 接口

基础前缀：

```text
http://127.0.0.1:8000/api/v1/prompt-defaults-admin
```

Agent 相关接口：

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/agent-schema` | 返回前端构建 Agent Builder 所需的轻量 schema |
| `GET` | `/agents` | 列出所有 Agent 蓝图 |
| `POST` | `/agents` | 新增 Agent 蓝图，请求体可为 `{ "agent": {...} }` 或直接为 agent 对象 |
| `GET` | `/agents/{agent_id}` | 读取单个 Agent，并附带预览结果 |
| `PUT` | `/agents/{agent_id}` | 替换保存单个 Agent |
| `DELETE` | `/agents/{agent_id}` | 删除单个 Agent |
| `POST` | `/agents/preview` | 预览临时或已保存的 Agent 装配结果 |

预览接口示例：

```json
{
  "agentId": "auto_reply.default",
  "variables": {
    "assistant_name": "小海",
    "system_reminder": "距离上一轮对话已经过去 10 分钟，适合轻量顺接。"
  }
}
```

也可以直接提交未保存的临时蓝图：

```json
{
  "agent": {
    "id": "custom.agent",
    "name": "自定义 Agent",
    "promptBlocks": [],
    "contextBlocks": [],
    "allowedToolNames": [],
    "maxRounds": 3
  }
}
```

预览响应核心字段：

- `objectivePrompt`：由 `promptBlocks[target=objective]` 渲染后拼接
- `extraInstruction`：由 `promptBlocks[target=extraInstruction]` 与 `contextBlocks[injectAs=extraInstruction]` 渲染后拼接
- `systemPrompt`：`objectivePrompt + "\n\n" + extraInstruction`
- `contextEntries`：上下文块预览；`recent_messages` 会映射成 `contextSpec`
- `allowedToolNames`：工具白名单
- `backgroundAgentDefinition`：可给 Flutter 运行时适配成 `BackgroundAgentDefinition` 的 JSON
- `runArguments.extraInstruction`：运行时传给 `BackgroundAgentService.run(...)` 的额外指令
- `warnings`：缺失 prompt、空 objective 等非致命问题

### Agent 蓝图结构

最小结构：

```json
{
  "id": "auto_reply.default",
  "name": "主动回复 Agent",
  "description": "基于最近聊天窗口生成主动消息。",
  "enabled": true,
  "variables": {
    "assistant_name": "当前角色"
  },
  "promptBlocks": [
    {
      "id": "objective",
      "label": "人设 / 任务",
      "enabled": true,
      "kind": "prompt_ref",
      "target": "objective",
      "promptId": "auto_reply.agent.objective",
      "variables": {
        "assistant_name": "{assistant_name}"
      }
    }
  ],
  "contextBlocks": [
    {
      "id": "recent_messages",
      "label": "最近 10 条聊天",
      "enabled": true,
      "type": "recent_messages",
      "injectAs": "contextMessages",
      "lastMessages": 10,
      "includeUser": true,
      "includeAssistant": true,
      "includeSystem": false,
      "includeTimestamps": false
    }
  ],
  "allowedToolNames": [],
  "modelRef": null,
  "temperature": 0.7,
  "maxRounds": 1,
  "contextSpec": {
    "lastMessages": 10,
    "includeUser": true,
    "includeAssistant": true,
    "includeSystem": false,
    "includeTimestamps": false
  }
}
```

### 字段规则

- `promptBlocks[].kind`
  - `prompt_ref`：从 `prompts[].id` 引用模板
  - `inline`：使用块内 `template`
- `promptBlocks[].target`
  - `objective`：进入 `BackgroundAgentDefinition.objectivePrompt`
  - `extraInstruction`：进入本次运行的 `extraInstruction`
- `contextBlocks[].type`
  - `recent_messages`：映射 `BackgroundContextSpec`
  - `memory`：指定记忆或记忆样本文本
  - `runtime`：运行态 JSON/状态说明
  - `custom_text`：任意自定义上下文
  - `prompt_ref`：引用已有提示词作为上下文块
- `contextBlocks[].injectAs`
  - `contextMessages`：表示运行时应作为上下文消息注入
  - `extraInstruction`：预览时拼入 `extraInstruction`
  - `metadata`：仅作为结构化元数据给前端展示或运行时消费

后端会校验：

- agent id 唯一且非空
- prompt/context block id 在单个 agent 内唯一
- `prompt_ref` 必须引用存在的 `prompts[].id`
- `maxRounds`、`lastMessages` 必须为正整数
- `allowedToolNames` 必须是字符串数组

## 默认提示词拆分原则

`prompts[]` 只放需要独立维护、独立预览或运行时必须独立消费的提示词大块。不要把装配过程里的小标题、行模板、兜底格式、字段说明等纯格式片段拆成独立 prompt 卡片；这些片段应放在对应 Dart 组装代码里，或合并进更大的提示词模板。

判断方式：

- **应该进 `prompts[]`**：模型任务 prompt、system 级说明、工具 schema 的独立字段描述、可由后台/用户单独编辑的模板。
- **不应该进 `prompts[]`**：`### 标题`、`- {field}` 行模板、固定 fallback 行、只解释另一个模板变量含义的字段说明。

例如时间感知默认值只保留两条：一条 `time_awareness.system.default` 用于 system 侧说明 `<system-reminder>` 和时间字段含义；一条 `time_awareness.reminder.default` 用于渲染插在最后一条真实用户消息前的时间提醒。

推荐顺序：

1. 在 `prompt_defaults.json` 增加一条 `prompts[]`
2. 填好：
   - `id`
   - `dartName`
   - `title`
   - `category`
   - `description`
   - `variables`
   - `template`
3. 执行：

```powershell
python C:\ide\aicove\cloud_backend\prompt_defaults_codegen.py
```

4. 在 Flutter 代码里引用：

```dart
PromptBuiltinDefaults.somePromptName
```

5. 如果模板里有变量，再用：

```dart
PromptTemplateRenderer.renderTrimmed(
  PromptBuiltinDefaults.somePromptName,
  <String, Object?>{
    'foo': fooValue,
  },
);
```

## 注意事项

- 管理面板修改的是**源码默认值**，手机端默认节点不提供本机覆盖
- Web 端保存并同步到项目后的默认值会直接作为 App 默认节点；当前打包资源路径需要重新构建 App 才会进入已安装包
- 手机端自定义节点不能使用内置默认节点 ID，避免覆盖 Web 默认配置
- `PromptTemplateRenderer` 默认会保留未知变量占位符，避免把图片提示词里的示例 `{tag}` 误替换掉
