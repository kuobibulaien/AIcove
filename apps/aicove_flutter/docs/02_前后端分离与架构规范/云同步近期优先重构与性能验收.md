# 云同步近期优先重构与性能验收

日期：2026-09-13。下方性能表为首批本地隔离 HTTP/SQLite 测试。后续用户授权重接真实数据，服务与客户端已更新；线上接入状态单独记在文末，不混用模拟速度。

## 已实施的结构变化

- 业务库保留完整 raw、消息块和投影关系；服务端用轻量索引选择每个会话最近 50 条，设置与近期消息优先入库，历史按页补齐。
- 读取当前实体版本，过滤已经包含在父快照里的旧子实体；旧日志仍用于一致快照/备份，不参与无用重放。
- 文件身份和实际文件传输解耦，稳定本地目标路径允许设置先恢复。持久队列保留失败工作，图片到达时自动刷新。
- 版本基线不再保存第二份完整消息正文；业务入库和冻结 outbox 改为有界事务，缓存表结构查询。
- 上传先检查缺失摘要；只消费连续已确认的序号，避免重复传文件和把刚上传的正文下载回来。

实现沿用现有 FastAPI/SQLAlchemy 与 Drift，参考了[成熟项目的源码结构](云同步开源数据结构调研.md)，未接入 PowerSync/Matrix/TDLib SDK。取舍、迁移与回滚见 [ADR0029](../../../../docs/项目记忆/决策记录/0029-近期优先读取与独立媒体队列.md)。

## 方法与可复现范围

Python 隔离 FastAPI 服务，真实 JWT/HTTP 与 gzip；Flutter 使用实际 CloudSyncEngine、CloudLocalStore、MediaStore 和磁盘 SQLite。每个同步 HTTP 请求人为增加 100 ms 延迟，计时不含登录、生成数据和测试编译；第一批可用指事务已提交且设置已读到，不是 UI 已绘制。

固定数据集包含 5 个会话、完整设置项、1,000 或 10,000 条原消息，每条含 raw/工具字段、一个消息块和两个投影映射，服务端额外保留三倍数量的旧独立子记录。10 个近期原件各 64 KiB、独立缩略文件各 1 KiB；二进制是可校验摘要的模拟内容，不用于评估真实图片解码。消息内容逐条不同，避免整库重复字符串导致异常高压缩率。

源端上传测试把同一批模拟业务记录放进一个全新本地库和空测试账号，10 个原件重新注册；源端不预置缩略图，数据准备不计时。基线代码固定在 `.codex-temp/sync-read-v2/baseline/`，当前版与基线使用相同数据/SDK/数据库/延迟。每次全量恢复验证消息、块、映射数量和规范化正文 SHA256；10 个所需原件已落盘，媒体队列完成。

仅为该 Mac 上单次模拟网络对照，未测真实服务器带宽、手机文件扫描与图片解码、2 GB 原图迁移、系统调度、三端 UI 帧耗时或 Windows。不能据此保证真实设备相同秒数。

源端正文提交在 4.301 s 完成，剩余媒体独立完成。两版原文校验摘要一致：`178adde090fe5dfaeedde9b4ee9d09e9d59d546d46b71710b9e19cb61426a3f6`。数据库体积是主文件，并非包含保护副本/旧媒体索引/所有附件的设备总占用。

接收端压缩正文流量没有夸大成数量级下降：基线 bootstrap 约 680 KB，新 read 约 600 KB，完整消息内部仍保留原始内容。明显提速主要来自近期优先、移除旧实体/逐条提交和文件等待；上传后的回读流量则被消除。
