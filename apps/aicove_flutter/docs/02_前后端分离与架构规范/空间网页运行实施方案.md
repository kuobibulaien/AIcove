## 3. 服务 `webapp_server.dart`

### 3.1 监听

- 候选端口 47823～47842。先试应用数据目录下 `webapp/port` 记录的端口，再按顺序试其余。
- 每个端口：先绑 `InternetAddress.loopbackIPv4`；再绑 `loopbackIPv6`（`v6Only: true`）。IPv6 失败时看错误：地址被占用（errno `EADDRINUSE`，Windows `WSAEADDRINUSE` 10048）→ 关掉 IPv4、换下一个端口；其他错误（不支持 IPv6）→ 只用 IPv4。
- 成功后写回 `webapp/port`；与上次不同时 `start()` 返回 `portChanged: true`，供界面提示一次。
- 单例；构造参数：`WorkspaceStore store`、`Directory dataDir`、候选端口列表（测试传 `[0]`）、`clock`。

### 3.2 空间登记

- `allow(String wsId)` 登记，进程内有效。Host 按 `<wsId 小写>.localhost:<port>` 匹配。
- 未登记、不存在的空间：404。

### 3.3 每个请求的检查（按顺序）

1. `Host` 必须是 `<已登记 wsId>.localhost:<port>`，否则 403。
2. 请求带 `Service-Worker: script` 头 → 403。
3. 方法：`GET`、`HEAD`；`/__aicove/` 下另允许 `POST`。其他 405。
4. `POST` 的 `Origin` 必须等于 `http://<wsId>.localhost:<port>`，否则 403。
5. 路径（`/__aicove/` 之外）：
   1. 取 `uri.pathSegments`（Dart 已逐段解码一次，不再解码）。原始 `uri.path` 为空、`/` 或以 `/` 结尾时，视为目录请求：去掉末尾的空段，记下「目录」标记。
   2. 剩余每段：空段、`.`、`..`、含 `/`、`\`、NUL 的，一律 404。
   3. 用 `/` 连接后过 `WorkspacePathRules.normalize`（目录请求且段为空时跳过，表示根目录）；任一段折叠大小写后是 `.aicove` → 404。
   4. 目录请求：在该目录下依次找 `index.html`、`index.htm`。

   不区分原因、统一 404。

### 3.4 响应头（所有响应，包括错误和宿主接口）

```
Cache-Control: no-store
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
Cross-Origin-Resource-Policy: same-origin
Content-Security-Policy: default-src 'self' data: blob:; script-src 'self' 'unsafe-inline' 'unsafe-eval' data: blob:; style-src 'self' 'unsafe-inline' data: blob:; img-src 'self' data: blob:; media-src 'self' data: blob:; font-src 'self' data: blob:; connect-src 'self' data: blob:; worker-src 'self' data: blob:; frame-src 'self' data: blob:; form-action 'self'; base-uri 'self'; frame-ancestors 'self'
```

不返回任何 `Access-Control-*` 头，`OPTIONS` 走 405。

### 3.5 静态文件

- `store.stat` 拿大小；≤ 4 MiB 用 `read`，更大的用 `readRange` 每段 1 MiB 流式写出。
- 非 HTML 支持单段 `Range: bytes=a-b`／`a-`／`-n`，206＋`Content-Range`；不合法 416。HTML 忽略 `Range`，总是 200 完整返回注入后的页面。
- `Content-Type`：`lookupMimeType(path, headerBytes)`，`text/*`、`application/javascript`、`application/json`、`image/svg+xml` 加 `; charset=utf-8`（HTML 除外，见 3.6）；取不到用 `application/octet-stream`。

### 3.6 HTML 注入

- 按**字节**处理，不解码。从头扫描前缀：跳过 UTF-8 BOM、空白（空格、`\t`、`\n`、`\f`、`\r`）和完整的注释 `<!-- … -->`，可重复。扫描停下的位置若是不区分大小写的 `<!doctype`，在它之后第一个 `>` 后面插入；否则插在 BOM 之后的位置 0（没有 doctype 的页面本来就是 quirks 模式，插在前面不改变模式）。注释没有闭合时按「没有 doctype」处理。插入内容：
  ```html
  <script src="/__aicove/shim.js?page=<URL 编码的页面路径>"></script>
  ```
  这是 ASCII，在 UTF-8 和各种 ASCII 兼容编码下都成立；解析器会把它放进隐式 `<head>`，先于页面任何脚本同步执行；doctype 之前只有注释和空白，不触发 quirks 模式。
- 文件开头是 UTF-16 BOM 时不注入、照样返回；启动器在打开前就拒绝这类文件并说明编码要求（第 5 节），所以正常流程不会走到这里。
- `Content-Type: text/html`，不加 charset（尊重页面自己的 `<meta charset>`）。

### 3.7 宿主接口（前缀 `/__aicove/`；空间里同名路径被遮住，可接受）

`page` 参数必须是该空间里存在的 `.html`／`.htm` 路径，否则 404。存档路径 `savePath` = 页面路径去掉扩展名 + `.save.json`。

**原则：GET 接口没有任何副作用**（外站用 `<script>`／`<img>` 发起的 GET，CORP 只能挡住它读响应，挡不住服务端已经做的事）。创建、关闭 run 和写入都只走 `POST`，并要求 `Origin` 同源（3.3 第 4 条）且 `Sec-Fetch-Site: same-origin`（Chrome、Edge、Firefox 都会发；缺失也拒绝）。

| 接口 | 行为 |
|---|---|
| `GET shim.js?page=` | 读 `A/webapp/shim.js`（启动时从 `rootBundle` 载入一次；测试可注入），前面拼一行 `var __AICOVE_BOOT__ = <JSON>;`。JSON：`{page, savePath, revision, text, quota}`，`text` 是存档文件原文（不存在为 `null`），`revision` 对应原文。只读。 |
| `GET state?page=&known=` | `{"revision": ..., "text": <原文或 null>}`，只有 revision 与 `known` 不同时才带 `text`。记一次活动（3.9）。只读。 |
| `POST run?page=` | 新建 `webapp-<uuid>` 并登记，同一页面的旧 run 关闭；返回 `{runId}`。撤销进行中返回 503 `busy`。 |
| `POST save?page=` | **请求体就是存档文件原文**（`Content-Type: application/json`），元数据放请求头：`X-AIcove-Base`（revision，新建时为空串）、`X-AIcove-Run`（runId）。自定义请求头让跨站请求必须先预检，而服务不放行任何预检，多一层保护。体积上限 16 MiB，与存档文件上限相同。检查：`runId` 已登记、属于本空间本页面、未关闭；原文能 `jsonDecode` 成 Map 且 `format == "aicove.webapp.save.v1"`、`localStorage` 是 Map（只校验，不重新序列化）。然后 `store.write(原文字节, expectedRevision: base, runId)`。 |

`POST save` 的响应：

| 情况 | 状态与体 |
|---|---|
| 成功 | 200 `{"revision"}` |
| 当前文件内容与请求体完全相同（含响应丢失后重试） | 200 `{"revision"}`，不写 |
| revision 不符 | 409 `{"error":"conflict","revision","text"}` |
| store 报 `busy`，或撤销进行中 | 503 `{"error":"busy"}`，客户端稍后重试 |
| 体超限 | 413 `{"error":"too_large"}` |
| 原文不合格式 | 400 `{"error":"bad_save"}` |
| `runId` 未登记／已关闭 | 409 `{"error":"run_closed"}` |

### 3.8 run 登记与撤销屏障

- 服务端记 `runId → {wsId, page, closed}`，每个空间一个「在途写入」计数和一个「撤销中」标记。
- `undoRun(wsId, runId)`：服务层包装 `store.undoRun`，整个过程是一道屏障：
  1. 置「撤销中」：此后该空间的 `POST run`、`POST save` 一律 503 `busy`；
  2. 关闭该空间全部 run；
  3. 等在途写入归零；
  4. 调 `store.undoRun`；
  5. 清「撤销中」。

  页面随后重试，拿到 `run_closed` 或 `conflict`，按外部修改处理（另开 run）。空间页的撤销按钮（主会话接线）对所有 run 都改走这个包装：非网页 run 只多了一道无害的屏障。

### 3.9 活动与安卓保活

- 记录最后一次请求时间。`WebAppLauncher.open` 时调用 `AndroidKeepAliveManager.setWebAppActive(true)`；服务每 30 秒检查一次，连续 2 分钟没有请求就 `setWebAppActive(false)`；之后再有请求就再尝试置 true（App 在后台时可能失败，记日志）。
- 保活退出后 App 若被冻结，页面的请求会连续失败；替身据此提示用户回到 AIcove（4.3）。

## 4. 替身脚本 `A/webapp/shim.js`

同步执行，只用 ES2017，不依赖任何库。读取 `__AICOVE_BOOT__` 后立刻删除这个全局变量。

### 4.1 编解码

- `decodeSave(text) → Map`：`JSON.parse`；`format` 必须是 `aicove.webapp.save.v1`、`localStorage` 是普通对象，否则视为损坏。每个值：字符串原样；对象／数组 `JSON.stringify`；数字、布尔、`null` 用 `JSON.stringify` 转成字符串。
- `encodeSave(map) → text`：每个值 `v`：`try { p = JSON.parse(v) }`，`p` 是对象或数组且 `JSON.stringify(p) === v` 时存 `p`，否则存 `v`。整体 `JSON.stringify(save, null, 2)`；UTF-8 字节超过 16 MiB 时改为 `JSON.stringify(save)`。
- 键顺序：`Map` 的插入顺序；`decodeSave` 按文件里对象键的顺序插入（JS 对整数样式的键会提前，这与浏览器原生 localStorage 的 `key(i)` 顺序本来就不保证一致，可接受）。

### 4.2 Storage 替身

- 数据放在闭包里的 `Map`。`Proxy` 包一个以 `Storage.prototype` 为原型的普通对象，方法 `getItem`、`setItem`、`removeItem`、`clear`、`key` 和 getter `length` 全部自己实现并定义在目标对象上（不调用原生 `Storage.prototype` 的方法）。
- 语义按 HTML 规范：值 `String(v)`；`getItem` 不存在返回 `null`；`key(n)` 先转无符号整数，越界 `null`；缺少必需参数抛 `TypeError`。
- Proxy 陷阱按 Web IDL 旧式平台对象（有命名属性 getter／setter／deleter、没有 `[LegacyOverrideBuiltIns]`）的规则：
  - **读**（`get`／`has`／`getOwnPropertyDescriptor`）：字符串键在 Map 里、且原型链上没有同名属性时，是可见的命名属性，返回 Map 的值；否则按普通对象处理（所以 `setItem('getItem', 'x')` 后 `storage.getItem` 仍是方法）。
  - **写**（`set`）：字符串键一律调用 `setItem`，包括 `storage.getItem = 'x'`（存进 Map，方法不变）；`defineProperty` 对字符串键同样转成 `setItem(String(desc.value))`。
  - **删**（`deleteProperty`）：字符串键是可见的命名属性时 `removeItem`；否则按普通对象。
  - `ownKeys`：Map 的键在前，再接目标对象自身的键；Symbol 键落在目标对象上。
  - 验收时用真实浏览器的原生 `localStorage` 跑同一组用例作对照，避免测试桩复制同样的错误。
- 容量：维护 `used = Σ utf8Len(JSON.stringify(k)) + utf8Len(JSON.stringify(v))`；`setItem` 后超过 `quota`（5 MiB）则抛 `new DOMException(msg, 'QuotaExceededError')`、数据不变。`utf8Len` 手写按码点计数，不分配 `TextEncoder` 缓冲。
- 安装：先保存原生 `window.localStorage` 的引用（读取可能抛异常，捕获后记为不可用）；`Object.defineProperty(window, 'localStorage', {value, configurable: true, enumerable: true, writable: false})`；随后检查 `window.localStorage === 替身`，不成立就进入「未接管」状态，只显示提示，不写盘。

### 4.3 写盘状态机

把「流程阶段」「有没有没写盘的改动」「在途请求」分开记：

- `phase`：`normal`、`conflict`、`broken`、`unmanaged`（没接管成功，只提示不写盘）。
- `seq`：每次改动加 1；`savedSeq`：最近一次成功写盘对应的 `seq`。`dirty = seq !== savedSeq`。
- `inflight`：最多一个在途请求（写入或轮询二选一）。
- `epoch`：本地 revision 每变一次加 1。每个请求发出时记下当时的 `epoch`，响应回来时 `epoch` 已变就整个丢弃（防止晚到的轮询把自己的写入当成外部修改）。

| 事件 | 处理 |
|---|---|
| 改动 | `seq++`，更新待写快照（4.4）。只有 `phase == normal` 时才安排写盘：重置 2 秒计时，首次 dirty 起 10 秒内必写。`conflict`／`broken` 期间照常记录改动，但不写、不退出当前阶段 |
| 计时到／页面 hidden | `phase == normal`、`dirty`、没有在途请求时发写入：记下本次 `seq` 与 `epoch`，`text = encodeSave(map)`；体积 ≤ 60 KiB 且页面 hidden 时加 `keepalive: true`。所有请求 15 秒超时（`AbortController`）。还没有 runId 时先 `POST run` |
| 写入 200 | `revision = 新值`、`epoch++`、`savedSeq = 发出时的 seq`；仍 dirty 就继续计时 |
| 写入 503／网络失败／超时 | 3 秒后重试。连续失败 3 次且页面可见时，显示一行提示「连不上 AIcove，请回到 AIcove 再点一次运行」，请求成功后自动消失 |
| 写入 409 `conflict` | `phase = conflict`，保存服务端返回的 `revision`、`text` |
| 写入 409 `run_closed` | 丢掉 runId，按「检查到外部修改」处理 |
| 写入 400／413 | `phase = broken`（本页数据写不进去），提示，不重试 |
| 轮询（页面可见、没有在途请求时每 2 秒 `GET state?known=`） | revision 等于本地 → 无事；不同 → 检查到外部修改 |
| 检查到外部修改 | 服务端文本无法解码 → `phase = broken`，提示「存档文件格式有误，本页进度暂不保存」，继续轮询；能解码时：不 dirty → 停所有计时、删本页快照、`location.reload()`；dirty → `phase = conflict` |
| `broken` 期间轮询到可解码的新文本 | 回到上一行「能解码时」的处理 |
| `conflict` | 弹浮层（Shadow DOM、最高层级）两个按钮：「放弃本页进度，载入新存档」→ 删本页快照、reload；「保留本页进度并覆盖」→ 丢掉 runId（下次写入前重新 `POST run`），以服务端最新 revision 为 base，`phase = normal` 并立即写入 |
| `pagehide` | 同「页面 hidden」 |

### 4.4 待写快照与启动补写

- **同一页面只有一个标签页负责写盘**：替身启动时用 Web Locks `navigator.locks.request('aicove:' + 页面路径, {ifAvailable: true}, …)` 申请锁并一直持有到标签页关闭（`*.localhost` 是安全上下文，Chrome、Edge、Firefox 都支持）。拿到锁之前改动只记在内存里；拿不到锁的标签页 `phase = unmanaged`，提示「这个游戏已在另一个标签页打开，本页进度不会保存」，不写盘、不碰快照。浏览器没有 Web Locks 时按拿到锁处理。
- 快照存在原生 localStorage（接管前保存的引用），键 `__aicove_pending__:` + 规范化页面路径，不同页面互不干扰，同一页面只有持锁的标签页读写。内容 `{base, seq, text}`，`text` 用紧凑 JSON（`JSON.stringify(save)`）。
- 每次改动后覆盖写入快照。写入成功时：若快照的 `seq` 等于这次写出的 `seq`，删除快照；更大（写出期间又有改动）就只把快照的 `base` 改成新 revision。
- 原生 localStorage 不可用或写快照时超额：页面显示一次「关闭页面后未保存的进度无法找回」，之后不再尝试写快照，其余功能照常。
- 启动时：
  - 没有本页快照 → 用 `__AICOVE_BOOT__.text` 初始化。
  - 快照 `text` 与 boot 的内容相同（解码后逐键相等）→ 删除快照，用 boot 初始化。
  - 快照 `base === boot.revision` → 用快照初始化，标 dirty，立即写。
  - 其余情况 → **用快照初始化**（游戏运行的就是要保留的这份），标 dirty，`phase = conflict`：「保留本页进度并覆盖」按 4.3 正常写入；「放弃本页进度，载入新存档」删快照并 reload，从磁盘版本重新开始。
- 读快照是同步的，启动时就按上面的规则选好初始数据，游戏脚本读到的就是它；写盘、删快照、弹浮层都等拿到锁之后才做。拿不到锁时这些都不做（内存里即使是另一个标签页的快照也不会写回）。

## 5. 启动器 `webapp_launcher.dart`

- `Future<WebAppOpenResult> open(String wsId, String path)`：
  1. 校验扩展名、文件存在、开头不是 UTF-16 BOM（否则报「只支持 UTF-8 编码的网页」）；算出 `savePath` 并用 `WorkspacePathRules` 检查合法（路径过长等直接报错）。
  2. `server.start()`（幂等）、`allow(wsId)`。
  3. `AndroidKeepAliveManager.setWebAppActive(true)`（此时 App 在前台）。
  4. 拼地址（路径各段 `Uri.encodeComponent`），`launchUrl(externalApplication)`；返回 false 时抛带说明的异常。
  5. 返回 `{uri, portChanged}`。
- Provider：`webAppLauncherProvider`，依赖 `workspaceStoreProvider`。

## 6. 安卓原生改动

- `PersistentGuardService`：新增 `webAppActive` 静态状态。前台服务保持条件里加上它；通知标题优先级：`generationActive` →「正在回复…」，否则 `webAppActive` →「网页游戏运行中」（占位，主会话定稿），否则原有文字。网页状态不设超时、不持有唤醒锁、不影响生成状态的计数与超时。
- `MainActivity` 的 keep_alive 通道加方法 `setWebAppActive({active})`，模式照抄 `setGenerationActive`。
- `AndroidKeepAliveManager.setWebAppActive(bool)`：非安卓直接返回。

## 7. 工作区工具说明

`_open` 返回里加一段固定说明（模型可见）：

- `.html`／`.htm` 可由用户在空间页点「运行」，在默认浏览器里打开；页面只能加载本空间里的文件，依赖 CDN 的要先下载到空间里；只支持 UTF-8 等 ASCII 兼容编码。
- 存档在同目录 `<文件名去扩展名>.save.json`，格式 `{"format":"aicove.webapp.save.v1","localStorage":{...}}`：值是对象／数组时可以直接改字段，其余是原样字符串。改完后游戏页面几秒内自动重载。
- 网页代码用了 `indexedDB` 的，那部分进度存在浏览器里，你看不到也改不了，要提醒用户。RPG Maker MV 等引擎的存档是压缩过的字符串，要先解码再改，改完按原方式编码回去。
