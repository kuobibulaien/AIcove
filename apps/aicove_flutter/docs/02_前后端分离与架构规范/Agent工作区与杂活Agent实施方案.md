## 2. 目标与不做

**目标**：实现 ADR0087、ADR0088 的全部决定，分批交付，每批都能独立验收。

**不做**：L1～L4 设备插件；挂载用户文件夹；git；IDE 与命令行；远程操作他机工作区；工作区上云；三方合并。

## 3. 数值与计量口径

| 项 | 上限 | 计量与超限行为 |
|---|---|---|
| 单段文件名 | 100 个 UTF-16 码元，且 ≤ 200 UTF-8 字节 | NFC 后计算，两种口径都要满足；超出时拒绝。给冲突后缀留出余量 |
| 整条相对路径 | 150 个 UTF-16 码元 | 四端共同预算：Windows 传统路径上限 260，减去应用数据根目录加工作区 UUID（约 110）。超出时拒绝。本机根目录过长、预算不够时，阻止新建和导入，并说明原因；实际根目录长度在 W1 的四端测试中实测 |
| 冲突副本名 | 遵守以上两项 | 算法：`<截短的原名> (冲突 <合法化设备名≤16> <yyMMddHHmm> <哈希4>).<扩展名>`。原名按剩余的两种预算（UTF-16、UTF-8）截短，设备名先过一遍文件名规则 |
| 单次写入／编辑的文本 | 1 MiB | 按写入后的 UTF-8 字节计算；超出时拒绝 |
| 单个文件 | 32 MiB | 包括经脚本写出的文件；超出时拒绝 |
| 单次 `read` 返回 | 64 KiB | 超出部分用续读游标分页 |
| `grep`／`glob`／`list` 结果 | 200 条、64 KiB | 截断时标注已截断并给出续查游标 |
| 工作区总配额 | 512 MiB | 计入工作区内全部文件、冲突副本和入站暂存；不计入 `.history/` |
| 修改历史 | 30 天、1 GiB | 先到哪个先清哪个；进行中的撤销所引用的内容不清理；正在运行的 run 触到上限时，后续写入失败，并提示先清理 |
| `run_script` 整次期限 | 30 秒 | 包括等待宿主的时间；超时后取消所有宿主操作，不允许晚到的写入 |
| `run_script` JS 堆 | 64 MiB | 仅指 QuickJS 堆；宿主读写另外受上面的单文件上限约束 |
| `run_script` 日志输出 | 64 KiB | 截断时标注 |
| HTTP | 单次 30 秒、响应 2 MiB、最多 5 次重定向 | 超出时失败或截断，并标注 |
| 同时运行的杂活任务 | 每台设备 3 个 | 超出时排队（`queued`） |
| 回执 `summary`／`question` | 600／300 字符，且各 ≤ 2 KiB | 按 grapheme 截断，同时满足字节上限，标注已截断 |
| 回执 `artifacts` | 20 项 | 超出时只保留前 20 项，并标注 |
| 整条回执（序列化后的块） | 8 KiB | 超出时依次压缩 artifacts、question、summary |
| `run_script` 返回值 | 64 KiB（序列化后） | 超出时截断，并标注 |
| 杂活 Agent 最大轮数 | 20 | 预设可改 |

所有上限都要有「上限前、等于上限、超过上限」三种测试。

## 4. 分批

### W1 工作区核心与界面

**范围**
1. `features/workspace/`：
   - `WorkspacePathRules`：ADR0087 第 2 条的全部路径规则，纯 Dart。
   - `WorkspaceIndex`：本机索引库 `workspaces/.index.sqlite`，独立于 `aicove.db`，不动主库版本。存文件索引（路径、revision、大小）、修改历史、撤销进度、配额，以及 W3 的定时运行记录和 W5 的待落地状态。
   - `WorkspaceCommitter`：条件提交协调器。按 ADR0087 第 2 条的意图记录三步走：
     1. 在 `BEGIN IMMEDIATE` 事务里校验 revision 和操作代次、检查并占用涉及的路径（move 同时占用源和目标）、预留配额、写意图记录、保存修改前的内容；
     2. 写临时文件并改名；
     3. 在第二个事务里更新索引（内容哈希＋最后修改操作 ID），标记意图完成、释放路径占用，并标记为待同步。

     测试要包括：第一步提交后暂停，另一个 isolate 写同一路径，必须被拒绝。

     启动时，以及恢复完成之前，先处理未完成的意图，期间拒绝写入。
   - `WorkspaceRegistry`：本机登记表，存在索引库里，不随设置同步。
2. 元数据 `.aicove/workspace.json`（ID、名称、描述、创建时间），由宿主写入，对文件工具只读。
3. 工作区插件（v2）：`workspace_open`、`workspace_create`、`read`／`write`／`edit`／`list`／`glob`／`grep`／`move`／`delete`。
4. 撤销：按 run 逆序进行，逐项检查「最后修改操作 ID」：等于这一项本身，或者等于本次撤销中刚撤掉后一项时产生的撤销操作，才允许撤销（撤销操作记录 `undoes`）。补测：同一轮里多次改写同一个文件后整轮撤销；撤销中断后续跑。某个路径一旦遇到后续修改，这个路径在本轮更早的记录全部跳过，并报告出来。进度持久化。清理历史时按引用是否可达，同步固定的内容、进行中撤销引用的内容都不清。
5. 授权：工作区插件的角色绑定存「可访问工作区 ID 列表」。在 `selectForRole` 旁边新增有效授权解析（角色 ∩ 预设 ∩ 全局 ∩ 本机）。编辑角色时保留本机没有的 ID。
6. **W1 不把工作区工具挂给聊天模型**，只在测试宿主和调试版的「杂活预演」入口里注册，避免在聊天历史里产生办事类调用。
7. 界面：
   - 底部「角色」改为「工作区」：列表（带成员设备前缀）、新建、只读文件浏览、按 run 撤销；
   - `RoleCardContent` 的搜索（角色＋聊天记录）迁到 `ContactsPage` 顶部；
   - 术语表注明 `MoeWorkspace` 是布局外壳，不是 Agent 工作区。

**验收**：ADR0087 验收门 1～4；聊天页的搜索结果与原来的角色页一致（测试）；界面附源码渲染预览（宽屏、窄屏）。

**回滚**：去掉插件注册和标签页改动；`workspaces/` 目录与索引库保留，不删除。

**实施记录（2026-10-16）**

### W2 杂活 Agent 与派活

**开工前需用户确认**：主数据库 v23→v24，新增 `agent_tasks` 表（schema 迁移）。

**范围**
1. 杂活 Agent 预设（插件 `task_agent`）与装配配方 `ContextProfile.taskAgent`：不自动装配聊天记录。
2. `delegate_task`（`start`／`reply`／`cancel`）：
   - 先写入 `agent_tasks`，再返回 accepted；
   - 请求键是宿主持久化的复合键（设备＋会话＋聊天 run＋轮次＋工具调用 ID），命中时还要核对角色和会话；
   - 办事类工具从聊天模型的工具清单中移除；聊天 run 一律对最终的供应商请求体执行 `builtin_web_search_suppressor`，不再看联网搜索插件在不在；
   - 请求副本按「聊天请求允许回放的工具」成对剔除办事类历史；
   - 用带迁移前历史的会话做**最终请求断言**，而不是只检查工具清单。
3. 状态机与事务：所有会产生回执的状态变化（终态、`needs_input`），都与回执消息、待转告记录（按 `notify` 字段决定是否创建）放在同一个事务里；过程记录 `agent_tasks/<id>.jsonl` 先写到检查点，再推进状态；`reply` 新开 run，从检查点恢复上下文。
4. `TaskReceiptBlock`：
   - 字段按 ADR0088 第 4 条（含 `notify` 与各项上限）；
   - 正文标签在 ADR0044 注册表中声明；
   - 任务卡片与请求副本都从这个块派生；
   - 记忆整理跳过回执，导出时转成一行文字。
5. 转告：本机「待转告」记录以 `receipt_id` 为键；负责设备认领后，复用主动回复的发送链路。每条转告候选的物理消息 ID 为 `receipt_id`＋设备 ID，都正常同步、各自保留；显示与请求副本按 `receipt_id` 去重：最早创建者胜出，同一时间按设备 ID 排序。不用修改同步引擎的合并逻辑。
6. 控制请求：`TaskControlBlock` 在处理函数返回前落库；执行设备消费时，「标记已消费」与状态变化在同一事务里，按 `control_id` 幂等；导入和编辑历史时不生成可执行的控制事件；问题回执 ID 不匹配的一律忽略。执行设备离线时，卡片上显示出来。
7. 取消：
   - 工具 handler 增加取消令牌参数，文件提交与 HTTP 在提交前检查；
   - 取消后等在途操作收敛，再进入终态；
   - 外部请求已经发出时，标记 `side_effect_uncertain`。
8. 启动恢复：`queued` 重新排队；`running` 改为 `interrupted`；有回执但未转告的继续转告；已转告的不重复。
9. 总开关：持久保存，带代次号，行为按 ADR0088 第 8 条。

**验收**：
- ADR0088 验收门 1～6；
- 每个事务边界的杀进程测试；
- 用真实模型（DeepSeek flash）跑一遍「查一件事 → 回执 → 人设转告」。

**回滚**：先用总开关停掉所有在途工作（ADR0088 第 8 条），再用编译期开关关闭 `delegate_task`，恢复原来的工具清单和回放规则；`agent_tasks` 表与已有的回执消息保留。旧代码按正文把回执显示成普通文字。

  - 工作区插件尚无全局开关，按角色授权∩本机存在解析。
  - 转告去重：转告消息原始载荷带 `taskRelayReceiptId`，生成前后各查一次已有转告即放弃；两台设备在同步间隔内同时转告时，两条都留在原始历史，显示与请求副本按 receipt_id 只留最早创建的一条（同时间按原始消息 ID，不是方案写的设备 ID：转告消息 ID 仍是普通随机 ID）（10-17 补）。显示侧只在已载入的消息之间比较：最早那条若在未翻到的更早一页，翻到之前会先显示较晚那条。
  - 回执正文标签：ADR0044 注册表新增「系统事件标签」声明（`ContentEventLabelSpec`，方括号 `[名称：详情]`，按正文开头匹配，不走尖括号扫描器），`杂活回执` 由 `delegate_task` 提供方声明并有一致性测试；备份导出时回执块去掉结构化字段、正文转成一行文字，导入后是普通文字消息（10-17 补）。控制事件消息在备份导出里仍原样保留。
  - 「执行设备离线」：本机没有任务行时，详情页读聊天历史里该任务最新的回执，仍是「需要你回答」就显示「执行设备离线或未同步」（10-17 补）；聊天里的回执卡片本身不显示这一状态。
  - 进行中的 HTTP 请求不会被中途掐断，只在工具开始前和工作区提交前检查取消。
  - 正在生成时到达的回执先不转告，最迟 60 秒后由扫描重试。

### W3b 脚本运行与定时任务

**范围**
1. 宿主桥：`ws.read/write/list`（经 `WorkspaceCommitter`）、`http.fetch`、`notify`、`log`。
2. `run_script(workspace, path, args)`。
3. 定时任务：
   - 每个任务的定义单独存成 `.aicove/schedules/<id>.json`，只能通过 `schedule_*` 工具修改，字段按 ADR0087 第 5 条；同一任务出现并发修改时暂停这个任务，等用户选定；第一版不提供更换执行设备；
   - 运行记录存在索引库，以「任务 ID＋版本＋计划触发时刻」为键原子认领；
   - 执行前重读启用状态、成员、执行设备；
   - 按创建者时区计算触发时刻，夏令时按墙上时间处理；
   - 用补跑游标保证最多补跑一次；中途崩溃的记为「结果不确定」。
4. 调度：安卓由现有 WorkManager 与前台服务共同调度，两者经同一个原子认领互斥；桌面端在进程内计时；iOS 只在前台和系统给的后台时机执行。
5. 界面：工作区页的定时任务列表与开关。

**验收**：
- ADR0087 验收门 5；
- 前台与后台抢同一次触发，只执行一次；
- 修改或关闭任务后，旧认领失效；
- 重启后最多补跑一次；
- 跨夏令时触发时刻正确；
- 双设备时只有执行设备执行。

**回滚**：先用总开关停掉调度器并取消已登记的系统后台任务，再移除工具与调度器注册；定义文件与运行记录保留；重新启用时不补跑关闭期间错过的触发。

### W5 工作区同步

**范围**
1. 成员实体：每台设备一个实体（`wsm:<工作区 UUID>:<设备 ID>`），只有这台设备自己能写，内容为加入或退出，加自己的递增版本号。退出者的成员实体是鉴权的唯一例外入口，其他成员会继续转发。
2. 能力协商：在每次同步会话的 `status` 请求与响应里交换 `workspace_files_v1`，缺少就当作不支持；只对声明了的设备采集、发送工作区实体。
3. 工作区文件实体：
   - 实体 ID 为 `ws:<工作区 UUID>:<路径 SHA-256 前 32 位十六进制>`，原路径放在载荷里；
   - `lan_contract.dart` 的 kind 白名单与校验做相应扩展；
   - 工作区实体不进入云端上传或代传。
4. 鉴权：摘要、游标、修订、附件、分块、入站写入，全部检查对方是否为成员；`manifest` 增加接收设备参数。
5. 落地：
   - 发布修订前，先把内容固定为 `.history/blobs` 中的不可变快照，并登记为同步固定引用（当前修订、冲突副本、正在传输的内容都不会被历史清理删掉）；
   - 入站内容先下载到暂存区并校验哈希，再经 `WorkspaceCommitter` 落地（路径规则、配额、条件写入）；
   - 待落地状态存在索引库，重启后继续；
   - 本机修改在提交的同一个事务里标记为待同步。
6. 冲突：并发修改时，另一份按第 3 节的冲突副本名算法命名。删除留墓碑。
7. 导入：列出在线已配对设备上的工作区（只列名称和描述）。源设备给请求方一次性导入授权，覆盖首次复制和提交加入记录，可以幂等重复；中断后凭同一个授权续传。
8. 退出：本机写入退出记录；本地副本保留。

**验收**：
- ADR0087 验收门 6；
- 三台设备成员变化；
- 导入中断后续传；
- 退出时第三台设备离线；
- 设备获知退出之后，拒绝退出者的请求；
- 直接用已知附件哈希索取被拒绝；
- 新旧客户端混用；
- 路径达到最长上限；
- 启用后再关闭，整轮同步正常。

**回滚**：关闭能力声明后，采集、摘要、修订、附件、应用全部不再处理工作区实体；本地文件不动。
