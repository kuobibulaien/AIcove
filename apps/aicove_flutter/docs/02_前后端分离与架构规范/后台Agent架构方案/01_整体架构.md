# 01 整体架构

> 本文档描述后台 Agent 运行时的职责边界与整体数据流

---

## 一句话定义

后台 Agent 运行时 = “从主聊天读取一小段上下文，套一份任务预设，挂一组允许的工具，然后在独立 session 中执行”的公共服务。

---

## 为什么不是“隐藏聊天窗口”

“新开上下文窗口”是表现形式，不是架构抽象。

如果把后台能力直接理解成“偷偷多开几个聊天窗口”，容易带来 4 个问题：

1. 运行逻辑与 UI 语义混淆。
2. 每个后台能力都自己维护 prompt 和上下文拼接。
3. 主聊天与后台链路边界不清。
4. 后续很难复用到记忆、触发器、反思等不同任务。

因此，这里把抽象上升为：

- `BackgroundAgentDefinition`：描述“这个 Agent 是谁”
- `BackgroundContextSpec`：描述“它能看什么”
- `BackgroundAgentService`：描述“它怎么跑”

---

## 分层

```
主聊天消息
   │
   ▼
ChatHistoryStore
   │
   ▼
BackgroundContextSpec
   │
   ▼
BackgroundAgentDefinition
   │
   ▼
BackgroundAgentService
   │
   ├─ 过滤工具白名单（AITool）
   ├─ 组装 system prompt
   ├─ 分配独立 sessionId
   └─ 调用共享工具循环 runner
   │
   ▼
BackgroundAgentRunResult
   │
   ├─ 写入记忆系统
   ├─ 写入触发器系统
   ├─ 写入反思记录
   └─ 写入风险信号
```

## 角色划分

### 1. 主聊天

负责：

- 实时对话
- UI 交互
- 多模态消息交付

不负责：

- 记忆总结执行
- 后台触发器规划
- 日志/报告类异步分析

### 2. 唤醒方

负责：

- 决定什么时候调用后台 Agent
- 传入 conversationId 与额外运行参数

可以是：

- `AnalyzerScheduler`
- Memory 的次日总结入口
- App 生命周期事件
- 手动按钮
- 后台任务框架

不负责：

- 具体上下文拼接
- 工具白名单解析
- 模型调用链

### 3. 后台 Agent 运行时

负责：

- 读取主聊天窗口消息
- 生成独立运行上下文
- 控制工具能力边界
- 统一执行模型调用与工具循环
- 返回结构化结果

不负责：

- 唤醒时机
- 结果持久化策略
- UI 呈现

---

## 设计原则

### 1. 只做运行，不做调度

调度和运行拆开后，后台 Agent 才能真正复用。

### 2. 上下文单一来源

后台 Agent 看到的对话内容必须直接来自主聊天 `ChatHistoryStore`，而不是另起一套存储。

### 3. 工具显式授权

后台 Agent 不能默认拿到所有工具，必须通过白名单选择。

### 4. 独立 session

每次后台执行都要有独立 `sessionId`，避免把后台 prompt、工具调用轨迹污染主聊天会话。

### 5. 结果结构化

后台 Agent 的输出应该以结构化结果为主，便于上层系统决定如何消费。

---

## 第一批接入方

本方案优先支持 3 类接入方：

1. 记忆机制
2. 主动关怀/触发器规划
3. 对话反思/日报类任务

其中，记忆机制是第一优先级接入方，因为它最需要：

- 复用主聊天上下文
- 控制上下文窗口大小
- 控制工具权限
- 与主聊天彻底隔离

---

## 与现有架构的关系

### 复用

- 复用 `ChatHistoryStore` 作为上下文读取入口
- 复用 `AITool` 作为工具定义协议
- 复用 `PluginManager.getAllTools()` 作为工具提供入口
- 复用 `ChatSendApiRunner` 内的工具循环能力

### 收敛

后续希望把“后台分析怎么跑”这件事从各业务里抽掉，统一改成：

`业务模块 -> BackgroundAgentDefinition -> BackgroundAgentService.run(...)`

而不是：

`业务模块 -> 自己读上下文 -> 自己拼 prompt -> 自己配工具 -> 自己跑模型`
