# 02 定义与运行时

> 本文档描述后台 Agent 公共类定义，以及一次运行的标准链路
> ⚠️ 本组方案已被 [Agent上下文管理总架构](../Agent上下文管理总架构.md) 吸收，现行口径以总架构为准（详见本组 [README](README.md)）

---

## 公共类命名

### 1. `BackgroundAgentService`

通用后台 Agent 运行服务。

职责：

- 按定义读取主聊天上下文
- 组装运行消息
- 过滤可用工具
- 分配独立 session
- 执行模型调用与工具循环
- 返回运行结果

### 2. `BackgroundAgentDefinition`

后台 Agent 的定义对象。

建议字段：

- `id`
- `name`
- `objectivePrompt`
- `contextSpec`
- `allowedToolNames`
- `modelRef`
- `temperature`
- `maxRounds`

### 3. `BackgroundContextSpec`

上下文范围配置。

建议字段：

- `lastMessages`
- `includeUser`
- `includeAssistant`
- `includeSystem`
- `includeTimestamps`

后续可扩展：

- `anchorMessageId`
- `summaryBeforeWindow`

### 4. `BackgroundAgentRunResult`

后台 Agent 运行结果。

建议字段：

- `text`
- `toolCalls`
- `toolResults`
- `rawResponse`
- `usedMessages`

---

## 推荐入口

建议公开的核心入口保持极简：

```dart
Future<BackgroundAgentRunResult> run({
  required BackgroundAgentDefinition definition,
  required String conversationId,
  String? extraInstruction,
})
```

如果需要强调“上下文来自主聊天”，也可以在后续增加语义更强的包装入口：

```dart
Future<BackgroundAgentRunResult> runFromConversation(...)
```

但真相源建议只有一套，避免双入口长期漂移。

## 一次运行的执行链路

### 1. 读取主聊天上下文

`BackgroundAgentService` 通过 `ChatHistoryStore` 读取消息：

- 指定 `conversationId`
- 应用 `BackgroundContextSpec`
- 只取本次需要的消息窗口

### 2. 过滤消息角色

根据 `BackgroundContextSpec` 决定是否保留：

- user
- assistant
- system

必要时可在这里附加时间戳文本。

### 3. 组装 system prompt

推荐规则：

```text
system prompt = objectivePrompt + extraInstruction
```

其中：

- `objectivePrompt` 来自 `BackgroundAgentDefinition`
- `extraInstruction` 来自本次调用

这样能保证：

- Agent 的固定身份稳定
- 单次任务差异通过额外说明注入

### 4. 解析工具白名单

工具来源不重新定义，直接复用现有 `AITool`：

- 先从 `PluginManager.getAllTools()` 获取当前可用工具
- 再按 `allowedToolNames` 做白名单过滤

好处：

- 不新增第二套工具协议
- 业务方只关心“允许哪些工具”
- 现有 Trigger / Memory / Image 等工具都可以直接复用

### 5. 分配独立 session

每次后台运行都应生成独立 session，例如：

```text
bg_agent_{definition.id}_{timestamp}
```

目的：

- 与主聊天上下文隔离
- 不让后台提示词污染会话历史
- 便于日志和可观测性区分

### 6. 执行模型调用与工具循环

优先复用现有 `ChatSendApiRunner` 的主循环能力。

原因：

- 现有聊天链路已经支持 Tool Calling
- 现有链路已经兼容不同 provider
- 现有链路已经处理了工具执行与回写

若直接复用时发现耦合过强，再把其中公共部分下沉成共享 runner，让聊天与后台 Agent 共用。

### 7. 返回统一结果

执行完成后，不在 `BackgroundAgentService` 内直接做持久化，而是返回 `BackgroundAgentRunResult` 给上层决定：

- 写入记忆
- 创建触发器
- 生成报告
- 记录风险信号

## 为什么不用 `background_service.dart`

`background_service.dart` 当前更偏：

- WorkManager 执行器
- 通知发送链路
- 历史兼容逻辑

它的问题在于：

1. 运行入口与后台框架强绑定
2. 历史上绕过过统一适配层
3. 不适合作为“通用后台 Agent 运行时”

因此，本方案将其视为“调度/执行环境适配层”，而不是公共运行类的落点。

## 代码落点建议

建议独立成一个新的文档/模块分组，而不是挂在某个单业务目录下：

- `lib/src/features/background_agent/domain/background_agent_definition.dart`
- `lib/src/features/background_agent/domain/background_context_spec.dart`
- `lib/src/features/background_agent/background_agent_service.dart`

如需后续补充结果对象：

- `lib/src/features/background_agent/domain/background_agent_run_result.dart`

这样既方便被记忆系统调用，也方便被触发器、反思系统复用。
