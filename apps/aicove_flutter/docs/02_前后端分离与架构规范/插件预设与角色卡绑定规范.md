# 插件预设与角色卡绑定规范

> 日期：2026-09-06
> 状态：架构方向已确认；绘图、音色正在改造，其余插件逐步接入。本文是目标规范，不代表代码已全部实现。
> 决策依据：[ADR 0008](../../../../docs/项目记忆/决策记录/0008-插件配置统一预设化与角色绑定.md)。

## 术语澄清（2026-09-06，用户补充）

**本文的“插件预设”本质是插件配置包：一小包已经打包好的、供某项插件能力使用的专属设置，不是酒馆预设。** 后续跨模块文档、需求与界面说明优先写“插件配置包”“音色配置包”“绘图配置包”“默认配置包”。既有“音色预设／绘图预设”可作为带插件限定的别名；本文后续的“预设”均仅指上述配置包。

| 术语 | 含义与边界 |
|---|---|
| 插件配置包（Plugin Configuration Package） | 渠道、模型、参数、资源引用等一组专属设置的逻辑组合；“包”不强制表示 ZIP 文件或新的存储格式 |
| 酒馆预设（SillyTavern Preset） | 项目兼容的酒馆预设资源，涉及提示词条目、顺序及相关生成配置；不是插件配置包的同义词 |
| 酒馆兼容插件的配置包 | 若该插件采用配置包，可引用酒馆预设、正则、世界书等资源；外层配置包与内部兼容资源是不同对象，不能混用身份、格式或绑定含义 |

不得在两类对象同时出现的页面、接口说明、导入导出说明中只写“预设”让读者猜；须明确“插件配置包”或“酒馆预设”。此澄清不改变酒馆预设兼容需求，不要求本次重命名代码字段、迁移数据或改文件路径。统一口径见[术语表](../../../../docs/项目记忆/术语表.md)。

## 1. 核心决定与适用范围

**插件专属设置统一打包成插件配置包，由配置包集中管理；角色卡按插件绑定对应配置包；“默认设置”改为“默认配置包”（此前称“默认预设”）。**

这不是只给绘图和音色增加一个选择框，而是所有插件的统一配置方向。尤其是涉及多渠道、多供应商、多模型及繁杂参数的插件，不再让角色或调用方到各处分开拼配置。简单插件按实际需要接入，不强造渠道、模型等不存在的字段。

统一的是管理与绑定规则，不要求不同插件共用一份参数结构，也不等于把全部插件塞进一个总预设。角色可分别绑定一个音色预设、一个绘图预设等；同类插件一次选择一个预设，预设可被多个角色复用。

## 2. 配置归属

| 对象 | 职责 |
|---|---|
| 插件预设 | 管理该插件一次使用所需的完整子配置，包括渠道引用、模型与能力参数等 |
| 角色卡 | 保存按插件区分的预设绑定引用，不另存一份可独立漂移的渠道、模型与参数组合 |
| 插件默认预设 | 为未单独绑定该插件预设的角色提供默认选择，不再维护另一套独立默认参数 |
| 渠道配置 | 管理供应商连接与凭据；预设引用具体渠道配置，不把 API 密钥复制进可分享预设 |
| 插件运行时 | 解析预设、验证配置并通过既有 Port / Adapter 执行，不绕过项目分层 |

预设 ID 与供应商音色 ID 是两个概念。渠道也须指向具体供应商配置，不能仅凭“同一供应商类型／适配器”认定两个渠道的资源通用。此处规定语义，不固定数据库表名或序列化字段名。

## 3. 代表性预设

### 音色预设

角色卡绑定的是一套可用于语音合成的配置，不只是声音名称或音频路径。

| 子配置 | 内容 |
|---|---|
| 渠道 | 具体供应商配置引用 |
| 模型 | 该渠道使用的 TTS 模型 |
| TTS 基本参数 | 语速等合成参数，按供应商能力定义 |
| 音色资源 | 供应商音色 ID、参考音频文件／资源引用等，按音色来源选择 |
| 附属配置 | 参考文本、情感参数等该模型实际需要的内容 |

声音目录、编辑、试听与正式合成都必须遵守预设的渠道和模型归属，不能把不同供应商资源混用。无须某项参数的供应商不强制填写该参数。

### 绘图预设

包含渠道、模型、画师串（风格）、基础绘图参数及生图辅助提示词。辅助提示词通常使用内置内容，编辑入口收进高级设置。

基础绘图参数是参考值，不是全部锁死。模型可在工具契约和供应商允许范围内传入合理参数；本次请求的覆盖值不反写预设，也不能借参数覆盖擅自更换渠道或角色绑定。

## 4. 默认选择与运行边界

1. 角色有明确绑定时使用该预设；未绑定时使用该插件的默认预设。修改默认预设不改写已有明确绑定。
2. 明确绑定的预设丢失、渠道不可用或模型／资源不兼容时，提示具体问题，不静默切到其他供应商或音色；没有默认预设时提示选择或创建。
3. 按发起请求的角色解析有效预设，固定该次请求使用的配置快照；执行中切换页面、角色或修改默认项，不改变已发起请求的归属。
4. 预设管理承接复杂参数编辑；角色侧以绑定选择为主。统一管理不强制现在就建设一个新的全局管理框架或页面。
5. 插件启停、授权、运行状态不因预设化被取消；预设绑定不等于自动启用插件或获得调用权限。

## 5. 分批实施与数据边界

插件业务与配置迁移按功能批次落实，沿用本规范的预设、绑定及请求快照契约。2026-09-11 已确认全端前端重写：插件管理、设置与编辑页同样遵守[全端共用界面架构与布局规范](../界面布局说明.md)，旧“插件不全量重写”限制不适用于这些共享页面；业务及数据迁移仍按下表另行验证。

| 事项 | 后续实施要求 |
|---|---|
| 旧配置 | 先确认归属，再转换为等效预设与绑定；无法确定归属的记录保留并标记待处理，不猜供应商 |
| 迁移与回滚 | 每批另列迁移、验证和回滚方案，获确认后执行；本次文档确认不授权数据迁移 |
| 共享编辑与删除 | 编辑前说明影响绑定角色；删除前检查引用并明确处理方式，不制造无提示的悬空绑定 |
| 导入导出 | 明确预设定义、角色绑定、音色文件等依赖的携带与映射策略；只有 ID 不等于跨设备恢复可用 |
| 凭据与缺失依赖 | 不随角色分享泄露密钥；渠道或资源缺失时明确提示重新绑定，不宣称恢复成功 |

## 6. 实施验收门（尚未在本次执行）

1. 两个角色分别绑定不同预设，使用各自渠道、模型及资源；同类适配器的不同渠道不会串用音色。
2. 未绑定角色使用默认预设；修改默认选择不会覆盖明确绑定；无效绑定有可定位提示。
3. 编辑预设按共享引用生效，但已发起请求不被中途切角色或改配置影响。
4. 绘图允许合法请求参数覆盖且不污染预设；语音试听和正式合成采用一致的配置解析规则。
5. 各实施批次验证旧配置迁移、引用删除及导入导出依赖，并按项目要求完成测试、静态检查和窄／宽屏运行验收。

## 7. 与旧文档的关系

语音、绘图模块文档保留旧实现资料用于排查；其中全局渠道、全局选中音色、分散默认参数等描述，不再作为新增／重构的目标设计。发生配置归属冲突时，以本文为准；供应商协议与具体实现细节仍查模块文档。

本规范中的“插件预设”不是 SillyTavern 提示词预设，也不替代 Agent 上下文配方、工具权限或输出契约。
