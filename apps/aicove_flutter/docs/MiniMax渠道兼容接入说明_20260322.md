# MiniMax 渠道兼容接入说明（2026-03-22）

## 目标

让设置页导入的 MiniMax 聊天渠道同时兼容：

- 国内 OpenAI 兼容：`https://api.minimaxi.com/v1`
- 国际 OpenAI 兼容：`https://api.minimax.io/v1`
- 国内 Anthropic 兼容：`https://api.minimaxi.com/anthropic`
- 国际 Anthropic 兼容：`https://api.minimax.io/anthropic`
- 国内原生文本接口：`https://api.minimaxi.com/v1/text/chatcompletion_v2`
- 国际原生文本接口：`https://api.minimax.io/v1/text/chatcompletion_v2`

## 设计结论

1. MiniMax 官方文档公开了 OpenAI 兼容、Anthropic 兼容和原生 `chatcompletion_v2` 三种文本接法。
2. 项目原先只有 `openai / claude / gemini` 适配器，没有 MiniMax 原生文本适配器。
3. MiniMax 官方文档没有给出一个稳定承诺的文本模型列表 API；导入阶段不应强依赖 `/models`。

## 实现策略

### 1. 协议识别

- 如果地址命中 `/v1/text/chatcompletion_v2`，走 `MiniMaxAdapter`
- 如果地址命中 `/anthropic`，继续走 `ClaudeAdapter`
- 其他 MiniMax host 默认按 OpenAI 兼容地址处理

### 2. 地址规范化

`MiniMaxAdapter` 允许三种输入：

- 裸 host：自动补到 `/v1/text/chatcompletion_v2`
- `/v1` base：自动补到 `/v1/text/chatcompletion_v2`
- 完整 raw endpoint：直接原样使用，不再二次拼接

### 3. 模型探测

MiniMax 导入阶段不再把 `/models` 当成唯一前置条件，而是按地址类型分流：

- `/v1` OpenAI 兼容地址：优先尝试同地址下的 `/models`
- `/anthropic` 兼容地址：优先尝试同 host 的 `/v1/models`
- `/v1/text/chatcompletion_v2` 原生地址：不做模型列表探测，直接回退文档兜底模型
- 如果远端探测失败或返回空列表，再回退到文档中公开的聊天模型清单，保证导入后立即可用

当前兜底模型：

- `MiniMax-M2.7`
- `MiniMax-M2.7-highspeed`
- `MiniMax-M2.5`
- `MiniMax-M2.5-highspeed`
- `MiniMax-M2.1`
- `MiniMax-M2.1-highspeed`
- `MiniMax-M2`

## 验证点

1. 填 `https://api.minimax.io/v1/text/chatcompletion_v2` 时，请求地址不再被补成 `/v1/chat/completions`
2. 填 `https://api.minimaxi.com/v1` 时，能按 OpenAI 兼容协议发起聊天
3. 填 `https://api.minimax.io/anthropic` 时，能按 Anthropic 兼容协议发起聊天
4. 填 `https://api.minimax.io/v1` 时，导入优先尝试 `https://api.minimax.io/v1/models`
5. 填 `https://api.minimax.io/anthropic` 时，导入优先尝试 `https://api.minimax.io/v1/models`
6. 导入 MiniMax 时，即使 `/models` 探测失败，也能得到可用模型列表
