# 纯多模态流式收尾修复（2026-03-24）

## 1. 现象

- 模型流式回复只有 `<tts>...</tts>` 时，前端会直接提示生成失败。
- 模型流式回复只有 `<tts>...</tts><image>...</image>` 这类纯多模态内容时，也会被整轮判失败。
- 用户侧看到的是“没有普通文本，所以整轮失败”，而不是正常收到语音/图片消息。

## 2. 根因

这次问题由两个点叠加触发：

1. `chat_actions.dart` 的流式收尾逻辑默认要求至少有一条“文本锚点”才能提交正式时间线。
2. 当 `buildResult.messages` 里没有文本消息时，收尾阶段会直接抛出“流式收尾缺少可提交的文本锚点消息”。

对于纯多模态回复：

- `<tts>` 在流式阶段只会先产生语音占位，不一定有最终文本消息。
- `<image>` 在快速链路里通常走后补图片，不会天然生成文本锚点。
- 因此这类回复虽然合法，但会被旧逻辑误判成“空回复失败”。

此外，`chat_send_api_runner.dart` 在隐藏工具状态文案时，旧逻辑会把 `rawReplyText` 一起清空，导致像 `<image></image>` 这样的原始占位符无法继续传给后续消息投影链路。

## 3. 修复

### 3.1 流式收尾改成“有锚点就提交，没锚点就回退到纯多模态补发链路”

文件：

- `lib/src/features/chat/chat_actions.dart`

策略：

- 若流式正文能形成文本锚点，仍按原来的正式时间线提交。
- 若流式正文无法形成文本锚点，但本轮回复包含多模态标签，则不再抛错。
- 改为清掉临时流式占位，并走现有 `ChatTtsHandler.deliverSegmentedMessages()` 的纯多模态补发链路。

这样：

- 纯 `<tts>` 会正常生成语音占位并补齐音频。
- 纯 `<tts> + <image>` 会正常补齐语音和图片。
- 不再因为“没有普通文本”就把整轮判成失败。

### 3.2 隐藏工具状态文案时保留 `rawReplyText`

文件：

- `lib/src/features/chat/services/chat_send_api_runner.dart`

策略：

- 继续隐藏用户不需要看到的状态文案，例如 `Image generated and sent.`。
- 但不再清空 `rawReplyText`。
- 让原始回复里的 `<image></image>` 等占位符继续保留下来，供后续消息投影和多模态解析使用。

## 4. 回归测试

新增覆盖：

- `chat_actions_test.dart`
  - 仅有 `<tts>` 的流式回复，不应因缺少文本锚点而失败。
  - 仅有 `<tts> + <image>` 的流式回复，不应因缺少文本锚点而失败。
- `chat_send_api_runner_fast_async_image_test.dart`
  - 隐藏工具状态文案时，`rawReplyText` 仍应保留原始 `<image></image>` 占位。

## 5. 结论

这次修复后的原则是：

- “没有普通文本”不等于“生成失败”。
- 只要这轮回复里存在合法的多模态内容，就应该按多模态链路继续交付，而不是直接整轮报错。

## 6. 同日追加修复：列表上弹/图片抽搐/TTS 强插（2026-03-24）

### 6.1 用户反馈现象

- 发送消息后，历史列表仍有上弹感，重生成链路也会被带着抖动。
- 图片出现前，占位气泡会先消失再插图，导致列表先回拉再下压。
- 消息不是“生成中 -> 一条条出现”的节奏，语音条会被直接强插进时间线。

### 6.2 本次落地改动

1. `chat_actions_stream_placeholder.dart`

- 流式阶段不再把 `<tts>` 片段直接转成 pending 音频消息。
- `segmentDelay` 改为真实生效：按节奏逐段放出文本，未到时机只保留“生成中...”占位。
- 收尾前增加节奏追平：若还有未放出的文本段，会先按 `segmentDelay` 依次放出，再做最终收尾。

2. `chat_tts_handler.dart`

- 流式后补阶段由“整段后台任务”改为“先同步插入占位，再异步补齐内容”。
- 图片占位先稳定挂到时间线，再异步升级成最终图片，减少“先消失再出现”的空窗。

3. `chat_actions_test.dart` / `chat_message_list_auto_scroll_guard_test.dart`

- 回归用例改为唯一会话 ID，避免短列表磁盘快照污染导致误判。
- 补强并调整断言：流式阶段不应提前出现 pending 语音条；语音 pending 不再额外注入三点文字。

### 6.3 已验证用例（节选）

- `send 遇到 TTS 标签时，流式阶段不应先插入 pending 语音条`
- `send 遇到前置 TTS 标签时，不应让语音占位抢在正文前单独出现`
- `后补图片接管占位时，不应先清空临时层再等待稳定时间线补位`
- `send 遇到 <tts>...<image>...文本 混排时，应先落完后续文本，再用尾部生成中气泡等待慢图`
- `用户发送后应立即回到底部查看最新消息`
