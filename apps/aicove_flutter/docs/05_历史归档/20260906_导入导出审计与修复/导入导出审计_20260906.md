# 数据导入导出审计（2026-09-06）

## 结论与边界

**当前 `.aicove` 不能作为四项数据的完整备份，也不适合直接把“只勾角色卡”的文件分享给别人。** 角色记忆没有接入，选择范围不约束真实读写，多项设置和聊天附带数据丢失；异常文件与 ID 冲突还会危及本地数据。

本次按用户确认只排查、补复现测试，不修业务代码、不迁移数据库、不调用生产接口、不读取手机聊天或真实导出包。全部文件攻击、覆盖、失败恢复测试限定在每个测试独立的临时目录，源/目标为两个独立内存 SQLite 数据库。非外部模型/多代理审计。

- 最终共 **61 场景：23 通过，38 未通过**。新测试 42 场景（9 过、33 未通过）；已有 UI 审计 19 场景（14 过、5 未通过）。失败数不是独立 bug 数。
- 测试按期望安全行为断言，确认的问题保留红色，供修复后复验；不是把错误行为写成“应当通过”。
- 新增两份测试静态检查无问题。连同业务模块检查仅 9 条既有 info，无 error/warning。
- `flutter pub get`、正常主入口 `flutter build apk --debug` 成功。没有安装到手机。
- 已尝试 `flutter run --no-resident -d macos -t /tmp/aicove_transfer_smoke.dart`：因本机无 `xcodebuild` 失败。隔离入口只展示合成预览，不初始化正常 App 或真实 DB；没有修改全局 Xcode 配置。**原生运行验收未完成**，APK 编译不等价于真机导入成功。

### 依赖核对（静态确认，未额外算实测 bug）

`voice_file` 目前在角色编辑器中是音色预设 ID（不是一概代表可复制的文件路径）。它会原样导出，但 `ttsPluginConfigProvider.voicePresets` 的预设定义、供应商/模型依赖不在包中。不能据此声称跨设备“声音可用”。`recipe_id` 本身已漏导；即使补上，它依赖 Documents 下 `aicove/sillytavern_presets` 的 JSON，也不能只复制一个 ID 就宣称预设恢复。预设脚本/正则授权不能随分享包自动获得本地执行授权。

## 已通过能力与证据缺口

**确实能用的部分**：T17 本地独立图片/音频 block 的实际字节与目标路径；T18 同时间戳消息顺序；T19 重复 merge 去重；T20 createNew 重映射角色/消息/block 及 data.messageId；T21 未来版本服务拒绝且 DB 不变；T23 基础卡与旧设置；T29 排除图片/音频字节；T30 角色选择隔离与 skip；T31 损坏 ZIP 不写 DB。已有 UI 14 个通过场景详见证据 JSON。

**没有验证、不宣称完成**：

1. 真机文件选择器、Downloads 权限/存储提供商、系统分享取消与成功、离线重装后恢复；本轮没有覆盖手机现场。
2. 万条以上记录、巨型 raw payload、ZIP 炸弹、磁盘满、杀进程、并发导入/导出与同时生成消息。静态可见全量内存 ZIP/JSON、无大小数量限制、无一致性快照、毫秒临时目录重名风险，未给性能数值。
3. 历史真实 `.aicove` 样本兼容性；本轮只测试当前 v1、坏包及未来版本。设计稿写 singular `conversation.json`，现实现 plural `conversations.json`，没有证据证明旧发布版实际生成过前者。
4. 云端备份/同步、记忆回收站、日记/墓碑与 MD 跨模式迁移；不将本地审计结果推成云端结论。
5. 同名模板、分支谱系、音色/供应商/预设依赖的最终产品策略；外部 URL 头像仅检验原字符串保留，没有网络下载。
