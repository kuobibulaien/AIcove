# 聊天块导入校验修复（2026-09-06）

承接用户“继续查严重问题”。范围：图片、语音、文本、思考块导入成功后却无法被聊天读取，以及块内部消息归属残留。仅修改 `lib/src/features/backup/data/conversation_importer.dart`，新增 `test/features/backup/import_block_integrity_test.dart`；不改插件预设、角色设置、备份版本或数据库 schema。

## 根因与修复

| 问题 | 原因 | 修复 |
|---|---|---|
| DB中有块，但聊天读取时丢掉 | importer只保证JSON能存成字符串；MessageBlockConverter.fromDb会吞掉领域解码异常并返回null。缺图片来源、缺文字、错误字段类型等都能导入成功 | 对image/audio/mainText/thinking在提交前使用实际领域解码器校验，失败抛ImportException，交由已有事务回滚 |
| 图片没有内容仍通过 | ImageBlock的“至少一个来源”原本只是构造断言，不能依赖release保留assert | 显式检查非空localPath/url/base64；成功状态的音频显式检查非空url，再验证字段结构 |
| 旧v1包合法但内层身份不全 | 标准id/type/messageId仅在外层，读取器却从data读取 | 根据实际目标行补齐data.id/messageId/type/status；支持text→mainText别名，不替用户猜正文 |
| data.messageId仍指向外部消息 | 旧代码仅在该值恰好位于copy映射中时替换；恶意或损坏的其他值会残留 | data.messageId始终使用实际目标msgId，data.id始终使用目标blockId。工具参数中的普通数据不改 |
| 类型与数字表达不一致 | 外层image、内层mainText可被当另一个类型读；合法durationSeconds=2在领域模型中要求double | 内外类型不一致则拒绝；有限且非负的音频时长转double，避免合法整数表达被悄悄丢块 |

校验发生在同一导入事务中，文件已经复制后才遇到坏字段也能回滚消息并清理本次附件目录。没有覆盖原记录来“修复”坏包，也没有修改读取器使它忽略损坏内容。

## 边界

1. 这是数据结构与归属校验，不是图片解码、音频播放或远端资源可用性验证；base64内容和文件编码是否可播放仍未实测。
2. 文件、工具、代码、表情及扩展块的业务字段未在本批增加同等级领域校验；只同步其标准身份与检查内外类型一致性，不能宣称所有块类型已完整支持。
3. 有效pending等非成功状态的空音频URL仍可按原领域语义保留；成功音频缺失URL不能假报恢复完成。
4. 不修复用户已损坏的数据库，不执行生产请求或真实备份覆盖；数据均为临时文件和独立内存SQLite。
5. 回滚仅撤本轮importer增量，无schema回退；会重新暴露静默丢块问题，不建议日常回退。
