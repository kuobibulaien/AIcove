## 本轮最小修复

仅改业务文件 `lib/src/features/backup/data/conversation_exporter.dart`；不改 importer、聊天发送/还原链路、角色设置、插件预设、备份版本或 DB schema。

| 问题 | 复现 | 修复 |
|---|---|---|
| 选中的本地图片、语音、普通文件缺失仍导出成功 | H01 三场景：先生成有效旧备份，再让一个被选中附件不存在；旧实现又生成一份成功但不完整的新包 | 停止导出并明确报错，保留原记录和旧备份，清理本次临时目录 |
| 损坏的附件 JSON 被转换成空 map | H03 三场景：非空非法 JSON、JSON 数组、JSON null | 拒绝导出；错误提示不包含原始 JSON。空字符串旧数据仍按原有空对象逻辑兼容 |
| 本地头像/立绘不存在仍悄悄丢图 | H05 两场景 | 与本地附件一样拒绝不完整导出；不改变图片文件的实际内容 |
| 内置资源及远端头像/立绘在往返后变 null | H06 两场景，双向真实服务与两个独立 SQLite 库 | 导出保留 assets/http/https 原引用；导入已支持这些引用，无需改 importer。不是下载远端图片，也不保证远端地址永久可用 |

有意排除的图片/音频不要求本地文件存在，文字仍可恢复（H02）；只选角色卡不读取或解析未选中的损坏聊天（H04）。上述控制组通过，避免把“用户不想备份媒体”和“用户要求备份但实际缺失”混为一谈。

## 仍未修复的高优先级聊天问题

H07 的两个场景分别验证图片与语音：

1. 用真实 `ChatMessageProjectionCodec.copyWithSupplementInsertOps` 保存聊天补充操作到 `messages.raw_payload`；附件为真实临时文件。
2. 用真实 `ChatFrontendMessageProjectionService.projectMessage` 还原导出前的记录，确认实际存在 1 个图片/语音内容块，不是测试自行猜测显示结果。
3. 调用真实 exporter → importer → DB converter → 相同的聊天还原服务。
4. 导入成功，但还原后的媒体数量为 0。原正文仍在；没有把“所有聊天正文丢失”作为结论。

**这是真实聊天内容丢失，不是预设或角色设置变化。** 当前 exporter 只读取 message_blocks，不输出 raw_payload，也不收集其中的补图/语音文件；现有 projector 却依靠这些材料还原聊天。因此仅修文件缺失检查不能覆盖该路径，现版本仍不能当作完整聊天媒体备份。

本轮保留 H07 红测，只确认事实；没有盲目把整个 raw_payload 原样打进备份。后续最小方案必须界定聊天所需数据与敏感/无关材料、附件路径映射和 createNew 的 ID 映射，不能借此扩展到插件预设或角色配置迁移。
