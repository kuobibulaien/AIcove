# 文件与表情包导入导出修复（2026-09-06）

承接用户确认继续检查文件和表情包。仅改两个备份服务及既有 `transfer_stoploss_test.dart`，不改插件预设、角色设置、DB schema 或 `.aicove` v1 版本，不搬运整个表情库。

## 修复内容

| 问题 | 根因 | 最小修复 |
|---|---|---|
| 表情包文件不在备份中 | 导出只复制image/audio/file，没有读取emoji.path；之后本地路径又被移除 | 收集消息实际引用的表情文件，复用安全文件复制与导入路径重映射 |
| 缓存表示中的文件/表情被漏掉 | DB raw_payload已保存的projectedMessages可含FileBlock/EmojiBlock，导出提取只认识图片和语音 | 白名单转成v1已有标准块，保留名称、MIME、大小或emojiId/标签/原文；不导出整份payload或供应商配置 |
| 已隐藏附件或旧元信息再次出现 | 高优先级表示仅约束图片/语音；即使引用相同，旧DB块的名称/表情文字也被保留 | 四类文件型块均按有效表示与出现次数匹配；保持块身份，但用当前白名单元信息替换旧元信息 |
| 排除选项不一致 | 关闭图片未排除表情；同时关闭图片/语音又过早跳过普通文件缓存 | 表情随图片开关排除；普通文件不受图片/语音开关影响。保持此前损坏payload且明确排除媒体时只保留可读正文/标准块的降级边界，不声称恢复损坏材料中的未知文件 |
| 导入成功但文件/表情块无法读取 | 缺少领域必填字段或文件大小非法，读取器会吞掉解码错误 | file/emoji加入已有领域读取校验；成功状态的路径不得为空，文件大小必须为非负整数；坏包整批回滚 |

仅对真实保存为标准块的文件/表情启用提取；不会把assistant专用补充数组中的未知kind强行当文件执行。缓存中仅剩文字时，也不会重新带回旧DB附件。
