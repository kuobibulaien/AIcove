# 聊天补图/语音兼容修复（2026-09-06）

用户已确认兼容方案：不改备份版本，将遗漏媒体补成原消息的标准附件；保留正文和归属，但不保证原始长回复中的精确插入位置。只处理聊天严重 bug，不涉及插件预设或角色设置迁移。决策见 [ADR 0011](../../../../../docs/项目记忆/决策记录/0011-聊天媒体备份复用标准附件块.md)。

## 实现

| 位置（相对客户端根目录） | 改动 |
|---|---|
| `lib/src/features/backup/data/conversation_exporter.dart` | 读取 DB raw_payload 中的媒体材料，白名单转换为 v1 原有 image/audio blocks；补必要的原始正文 TextBlock，保留消息 id/content/role/conversation_id/created_at。源 DB 不修改 |
| 同上 | 媒体来源优先级与正常聊天还原一致：非空 projectedMessages → 非空 supplementInsertOps → pluginContents/toolAudioResults。不会把低优先级的过期附件再导出，也不复制整份 raw_payload、调用参数或供应商配置 |
| 同上 | 与已存在的 DB 媒体块按引用和出现次数匹配，避免同一材料重复表示；有意重复的两次图片仍保留两次，同一个源文件只复制一次。补充块 ID 稳定，内嵌图片和普通块均服从排除选项 |
| `lib/src/features/backup/data/conversation_importer.dart` | 新建副本时同步重映射外层 block.id 与 data.id；data.messageId 仍经原有映射绑定新消息。继续使用上一批的路径校验、事务和附件目录回滚 |
| `lib/src/features/chat/services/chat_frontend_message_projection_service.dart` | 单行归属修正：passthrough 气泡的 sourceMessageId 必须是当前 raw.id。DB sourceMessageId 是导入来源，不可拿它作为新副本气泡的操作目标；不改变分段或数据库中的来源记录 |

不新增导出格式字段，不升级 `format_version`，不改 DB schema。标准块中的媒体文字、时长、尺寸、提示词按已知字段保留；不重新解释插件配置。

## 复现与修复顺序

原 H07 两个场景已经确认媒体丢失。本轮先将测试加载路径补全为与 ChatHistoryStore 相同的“消息行+消息块”读取，再调用真实 converter/projector。**这不是降低断言**：仍要求导出前实际存在媒体，导入后媒体可还原，额外检查目标文件字节、原正文、时间、消息/角色归属及源 DB 未修改。

- 扩展到四种来源后的初始28场景：16过、12败。
- 媒体修复后28场景全过；再追加新建副本语音展示引用测试，复现引用旧角色消息，先红后修。
- 再追加内嵌图片重新导出时排除测试，复现“没复制文件但 base64 仍出包”，先红后修；排除对应媒体块，同时保留原 message.content。
- 复核时发现纯文本导出不应解析未使用的损坏媒体 payload，补 H17 红测后加短路保护。
- 最终检查追加 H18–H20，先复现3败：高优先级缓存已隐藏/替换的旧 DB 图片被重新导出，以及用户消息错误读取 assistant 专用补充材料。修正角色边界和有效媒体出现次数筛选，不再简单合并旧 DB 附件与新材料。

## 验收边界与剩余风险

- 保证本次覆盖的图片/语音作为原消息附件保留，不保证原来的气泡数量、文本精细分段或字符级插入位置；附件通常归到正文之后。
- 保留原始 `message.content`，不搬运缓存中的另一份文本，不承诺还原全部隐藏思考、工具语义、插件文本输出或话题交接。原“整份 raw_payload 相等”审计仍红是明确未实现范围，不应把它改成无条件通过。
- 关闭图片/语音时会排除对应标准块（含其媒体附带文字）；原始 message.content 不改。语音附带文字、远端地址只是保留数据，不等于本轮已经试听或联网下载验证。
- 文件测试验证实际字节与路径，不做图片解码/音频播放质量验收；未在用户手机上执行真实备份/恢复，也未测试所有旧版发布程序。v1结构兼容不等于旧版所有缺陷已修。
- 大包内存、断电恢复、所有未知 payload 形态、完整角色记忆等仍不在本批。坏材料明确报错，不在不确定时默默丢数据。
