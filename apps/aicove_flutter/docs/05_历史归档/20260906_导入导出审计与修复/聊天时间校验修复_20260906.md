# 聊天时间校验修复（2026-09-06）

## 结果与范围

本轮只修改 `lib/src/features/backup/data/conversation_importer.dart` 和既有 `test/features/backup/transfer_stoploss_test.dart`。不改排序算法、备份v1、schema、插件预设或角色设置。

- 复现：±8640000000000001毫秒可以写入SQLite并返回ImportResult，但超过Dart DateTime可表示范围，预览转换会报错。replace路径还可能用不可显示的新记录替换原聊天。
- 修复：共用索引验证中检查角色created_at/updated_at、消息created_at。明确存在的值必须为整数且在±8640000000000000毫秒内；否则ImportException，在事务写入和附件复制之前拒绝。错误不带聊天正文。
- 字符串和小数此前已经报TypeError，并非假成功；现在转为一致、可读的导入错误。
- 缺省/null沿用旧逻辑：预览未知、导入回退当前时间。它不保证原历史时间可恢复；本轮未增加时间推断或重写旧包。
- 时间属于基础索引检查：有选聊天时覆盖包内全部消息，即使问题记录的角色未选中也拒绝；只导角色卡仍忽略聊天。未选角色坏内容块仍可以不解析，时间与具体块校验不同。

## 顺序核验与未覆盖范围

S03通过真实导出器 → 副本导入 → 原始消息稳定查询验证同毫秒三条记录：即使消息ID字典序与插入顺序相反、导入生成新ID，也仍保留原插入次序和毫秒值。S04验证零/负时间按时间顺序读取，不能把1970年前日期误判为非法。

这不是全场景顺序保证：合并到已有聊天时的同毫秒插入、分页边界、消息块相同sort_order、缺失时间的旧包仍需独立验收。本轮不改稳定排序仓储、不擅自给消息时间加毫秒，不把UI投影当作原始消息真相源。
