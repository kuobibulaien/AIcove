# 并行分工与窗口作业单

## 使用原则

本作业单是给多窗口并行施工准备的。

核心规则只有三条：

1. 同一时间不要让两个窗口改同一组核心文件。
2. 依赖上游结果的任务不要提前下放。
3. 先做“收口”和“兼容壳”，再做“删除旧代码”。

---

## 推荐窗口划分

### 窗口 A：聊天主链

负责：

- `features/chat/application/`
- `features/chat/services/` 中与主执行骨架直接相关的文件

目标：

- 建立 `ChatTurnCommand`
- 建立新主入口
- 收聊天执行骨架

禁止同时动：

- `core/api/`
- `ui/features/chat/` 主页面

---

### 窗口 B：API 运行时

负责：

- `core/api/`
- transport / runtime / facade / orchestrator

目标：

- 收 `agent_api`
- 收 direct / stream / image 执行边界

禁止同时动：

- 聊天页面层
- TTS / image 插件本体

---

### 窗口 C：provider 与 adapter 统一

负责：

- `core/api/providers/`
- `core/api/image_providers/`
- TTS provider 抽象设计稿对应实现

目标：

- 建立统一 metadata / capabilities / registry 口径

依赖：

- 需要窗口 B 先给出 API runtime 边界

---

### 窗口 D：TTS 专项

负责：

- `features/plugins/tts/`

目标：

- 收 resolver
- 收 runtime
- 收 synthesis / voice catalog adapter

依赖：

- 需要窗口 C 的 provider 口径稳定

禁止同时动：

- `core/api/` 核心 facade

---

### 窗口 E：生图专项

负责：

- `features/plugins/image/`
- 与 image 强耦合的图像 adapter 实现

目标：

- 建立统一图像生成命令
- 让工具链和快速链走同一执行主链

依赖：

- 需要窗口 B、C 基础边界稳定

---

### 窗口 F：聊天 UI 与交付回归

负责：

- `ui/features/chat/`
- 聊天相关 UI 测试

目标：

- 页面层瘦身
- 视图只走新命令入口
- 验证流式交付与滚动不退化

依赖：

- 需要窗口 A 的主链接口基本稳定

---

### 窗口 G：其他插件标准化

负责：

- `features/plugins/memory/`
- `features/plugins/sticker/`
- `features/plugins/time_awareness/`
- `features/plugins/trigger/`

目标：

- 统一模板
- 统一配置协议
- 统一事件输出

---

### 窗口 H：测试与清理

负责：

- `test/`
- dead code 清理
- 命名治理
- 文档与施工记录维护

依赖：

- 必须在主链切换后介入

---

- 窗口 B

### 批次 2

- 窗口 C
- 窗口 D
- 窗口 E

### 批次 3

- 窗口 F
- 窗口 G
- 窗口 H

---

## 每批交付要求

1. 写清本批变更的真相源文件。
2. 写清兼容壳是否还保留。
3. 写清测试覆盖了什么。
4. 写清是否允许下一批继续并行。

---

## 什么时候不能并行

下面这些时刻应暂停并行，先串行确认：

1. 聊天主链入口还没冻结时
2. API facade 和 runtime 边界还没冻结时
3. provider metadata / capability 口径还没冻结时
4. TTS resolver 语义还没冻结时
5. NovelAI 是否正式接入 adapter 体系还没定案时

---

## 完成标准

1. 每个窗口有独立写入范围。
2. 上下游依赖关系明确。
3. 不会出现多个窗口同时改同一核心文件的冲突施工。
