# 迁移路径与分阶段实施

## 总原则

这轮不能一次性大爆炸，必须按主轴拆阶段。

每个阶段最多只动一个主轴：

- 聊天主链
- API 执行边界
- 供应商适配器
- TTS 插件
- 生图插件
- 周边插件标准化

禁止同一阶段同时重做：

- 数据结构
- 路由
- UI
- 服务层

---

## Phase 0：冻结契约与基线

### 目标

- 冻结现有主链行为
- 建立测试与诊断基线
- 明确新旧兼容壳

### 交付物

- 关键链路的契约测试清单
- provider 解析与 fallback 基线
- TTS / image 现状矩阵

---

## Phase 1：收聊天主链

### 目标

- 建立统一 `ChatTurnCommand`
- 建立唯一 `ChatTurnUseCase`
- 开始把旧入口转发到新主链

### 依赖

- 不依赖 adapter 统一先完成
- 但需要先冻结 API 层外部调用口

### 不做

- 不在这个阶段大改 UI
- 不在这个阶段删旧链

---

## Phase 2：收 API 执行边界

### 目标

- 建立 facade / orchestrator / transport / runtime 分层
- direct / stream / image 统一 transport

### 依赖

- 需要 Phase 0 的契约测试

### 输出

- 新 transport
- 新 runtime
- 旧 support 进入兼容壳阶段

---

## Phase 3：收 provider 与 adapter 统一口径

### 目标

- 建立统一 metadata / capabilities / registry
- 收紧 fallback
- 为 TTS 和 image 做统一接入模型准备

### 依赖

- API runtime 需要基本稳定

### 输出

- registry 设计落地
- 新增厂商接入模板

---

## Phase 4：收 TTS

### 目标

- 统一厂商解析入口
- 建立 synthesis adapter
- 拆 voice catalog adapter
- 收配置与 UI 语义

### 依赖

- 需要统一 provider 口径

### 输出

- TTS runtime 成型
- `TtsPlugin` 变薄
- `TtsService` 不再承担全部厂商分支

---

## Phase 5：收生图

### 目标

- 建立统一 image generation use case
- 让工具链和快速链共用执行主链
- NovelAI 正式进入 adapter 体系

### 依赖

- API runtime 稳定
- provider / adapter 口径稳定

---

## Phase 6：收周边插件与死代码

### 目标

- 标准化小插件模板
- 清理确认无调用的旧文件、旧注释、旧 helper
- 收命名与目录

### 依赖

- 主链与插件主轴完成切换

---

## 阶段回滚原则

每个阶段都必须有明确回滚点：

1. 保留旧接口一段时间
2. 旧入口只做兼容壳
3. 新链路通过 feature flag 或显式切换开关验证
4. 新旧链路切换前先补日志比对
5. 删除旧代码前必须完成 smoke test

---

## 推荐节奏

### 第一批

- Phase 0
- Phase 1
- Phase 2

这是基础设施批次，不建议和插件改造并行抢相同文件。

### 第二批

- Phase 3
- Phase 4
- Phase 5

这是供应商模型和重型插件批次。

### 第三批

- Phase 6
- 全量回归

---

## 完成标准

1. 每阶段都有清晰开始条件和完成条件。
2. 任一阶段失败时，可以退回上一阶段稳定点。
3. 不会再出现多个窗口同时改同一核心文件的无序施工。
