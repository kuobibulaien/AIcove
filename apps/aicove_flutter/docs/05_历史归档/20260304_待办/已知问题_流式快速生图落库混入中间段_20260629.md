# 已知问题：流式快速生图场景最终落库混入中间段未合并

> 创建日期：2026-06-29
> 级别：P2（功能可用，仅测试断言失败，非阻断项）

## 背景

在「占位气泡钉底」改造（禁用 `_promoteGeneratingPlaceholder`）期间跑回归测试时发现。**经金标准验证：此问题与占位钉底改造无关，是既有问题**——把改造完全撤销（promote 还原）后该测试仍以完全相同的方式失败。

## 失败测试

`apps/aicove_flutter/test/features/chat/chat_actions_test.dart:5906`
`send 遇到快速生图标签时，不应把 <image> 提示词流式展示或落库给用户`

- 复现 send service：`_StreamingInlineImageSendService`（同文件 L1444）
- 流式 delta：`第一句。<image>1girl, cat ears, masterpiece</image>第二句。`
- `processedText`：`第一句。第二句。`
- `buildAssistantMessages` 返回的最终消息列表只有 1 条 `['第一句。第二句。']`（L1521-1529）

## 失败现象

断言（L5978）：`expect(storedTexts, <String>['第一句。第二句。'])`

实际：`['第一句。', '第一句。第二句。', '第二句。']`（3 条独立消息）

## 根因方向（待进一步定位）

最终落库时混入了流式期间的中间分段消息（`第一句。`、`第二句。`），未被最终 `buildResult` 的单条合并消息替换/清理。推测在最终落库清理逻辑（`_deliverPostStreamSupplements` / `deliverAssistantMessages` / chat_history_store 合并路径）中，流式中间段没被正确清除。

与 `promote` 机制无关——promote 只影响流式期间占位/段 id 复用，不影响最终 finalize/commit 的落库清理。

## 验证证据

把 `chat_actions_stream_placeholder.dart` `git checkout` 到改造前版本（promote 还在），单独跑该测试：

```
Expected: ['第一句。第二句。']
  Actual: ['第一句。', '第一句。第二句。', '第二句。']
```

与改造后失败结果完全一致 → 确认改造未引入此问题。

## 处置

本轮「占位钉底」改造不处理此问题（超出范围）。后续单独定位最终落库清理逻辑修复。
