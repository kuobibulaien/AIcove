# 正式版上线前阻断项：存储体积治理

> 创建日期：2026-03-04  
> 级别：P0（未完成不可发版）

## 背景

在安卓端实测中，应用仅使用约两天，应用数据体积达到约 `1.8GB`。  
当日定位结果显示，主要占用来自日志与生图文件，而不是聊天数据库本体。

关键体积分布（实测）：

- `app_flutter/logs`：约 `1.2GB`
- `app_flutter/generated_images`：约 `503MB`
- `app_flutter/aicove.db + wal + shm`：约 `24MB`

## 上线前必须完成（阻断清单）

1. Release 默认关闭“完整原始内容落盘”

- 不再默认写入 `rawContext`、`rawRequestBody`、`rawResponseBody`、`streamEvents` 等重字段。
- 仅保留排障必要元信息：接口、状态码、耗时、traceId、错误码、token 统计等。

2. 流式日志改为“聚合结果日志”

- 不记录每个 chunk 的完整事件数组。
- 仅记录最终聚合文本长度、工具调用数量、失败原因等摘要。

3. 引入日志滚动与总量上限

- 单文件上限（建议 `8MB`）。
- 日志目录总量上限（建议 `50MB`）。
- 超限时自动删除最旧文件（按时间）。

4. 诊断模式开关化

- 完整日志仅在“手动开启诊断模式”时写入。
- 诊断模式自动过期（建议 `24小时`）。
- Release 默认关闭，且需明显 UI 提示当前状态。

5. Trace Payload 在 Release 默认关闭

- 常规成功请求不写 trace payload 文件。
- 仅失败请求可按采样写入，且同样受目录总量限制。

6. 生图目录增加自动清理策略

- `generated_images` 设置总量上限（建议 `200MB`）与时间上限（建议 `30天`）。
- 超限按“最旧优先”清理。

7. 日志中心“清空”行为修正

- 当前清空内存列表不等于删除磁盘文件。
- 需要提供“删除磁盘日志”能力，并明确提示影响范围。

## 验收标准（建议）

- 连续高频使用 48 小时后，应用数据不应超过 `300MB`（无大量生图场景）。  
- 开启诊断模式后，关闭并过期后应自动回落到上限范围。  
- 手动“清空日志”后，`logs` 目录体积应显著下降并可被验证。
