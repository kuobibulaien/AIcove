# 前端架构整改建议（审计中，未批准实施）

这份建议解释已复现问题背后的共性，以及分批修复的边界。它不是新架构决策，也不代表全项目审计完成。逐项证据见[系统审计](前端系统审计_20260906.md)，剩余检查见[覆盖表](前端审计覆盖表_20260906.md)。目前没有修改业务代码。

## 判断

项目已经具备Riverpod状态层、设计Token、公共组件、聊天应用服务和专项测试；不能把现状概括成“完全没有架构”。问题主要是这些边界没有成为所有页面共同遵守的规则。布局、保存、退出与异步返回在不同页面各自实现，相同错误因此重复出现。

| 共性 | 当前证据 | 建议落点与约束 |
|---|---|---|
| 列表没有统一的可用空间/滚动契约 | F01模型测试、F08操作菜单、F12导入页、F15预设、F22提示框、F25备份；有滚动的页面仍可能被固定头尾挤压 | 沿用现有MoeBottomSheet/列表体系；头尾受屏幕与键盘约束，长内容占剩余空间并可滚动。长集合使用单一滚动容器；禁止拿shrinkWrap+NeverScrollable当默认解决方案 |
| 公共控件只统一外观，交互契约不完整 | F09禁用长按、F10空开关值、F19切换条、F21标签高度、F25主按钮 | 先修现有组件的禁用、缺省值、文字尺寸与键盘焦点约定，再核验实际调用页；不再创建第二套按钮/弹窗 |
| 异步结果直接捕获页面或旧快照 | F04测试/批量卸载、F05检测覆盖新key状态、F07日记、F24导出进度 | 页面负责展示状态，操作层按稳定ID写入最新数据；mounted只保护界面存活，不能代替请求顺序/编辑版本校验。进度不依赖已销毁WidgetRef |
| 保存成功缺少统一定义 | F06供应商防抖取消、F17画师退出丢编辑、F18存储失败仍成功、F20输入草稿、F23设置开关不更新 | 区分编辑值、已提交值、已持久化值；保留原有显式保存/自动保存体验，但明确各自退出与失败规则。失败保留草稿且能重试；成功提示必须来自实际保存结果 |
| 相同资源存在多套解析方式 | F16收藏远程立绘；导出/预览非assets头像当FileImage源码候选 | 沿用AvatarHelper及现有媒体解析工具，统一asset/file/data/http来源分派；媒体下载、缓存、展示、保存职责分开，避免页面自己猜路径 |
| 大小屏与主题有多个状态入口 | app.dart实际断点768、文字默认1.2/上限1.8；文档旧断点900；根UI缩放MediaQuery一致性候选；SkinScope与Theme扩展各有职责 | 以现有app.dart/Token为单一尺寸口径；界面组件按父约束布局，主题颜色从Theme扩展读取；切断点时保留导航状态。先动态证明候选，再决定是否改根布局 |

## 已核实的依赖边界问题

- `ui/shared/widgets/index.dart`导出`settings_drawer_panel.dart`，后者直接引用`ui/features/settings/pages/settings_page.dart`。共享组件入口因此把业务页面带回来。建议将设置抽屉的业务组装归回设置功能目录，公共抽屉只接收内容与关闭回调；暂不移动文件。
- UI同时位于`ui/features`和`features/*/presentation`，并保留转发文件，例如聊天目录的auto_reply_trigger_form只export实际自动回复表单。先记录兼容入口与真实实现，迁移时逐步收口；不按目录名批量重写、不删除未确认调用边界。
- `SkinScope`提供形状/装饰接口，`context.moeColors`读取Theme扩展，`accentColorProvider`读取AppSettings，另有历史常量颜色。它们不是天然错误，但新代码应明确哪层拥有颜色与形状；同ID皮肤配置更新的通知、非法颜色输入仍是候选，当前仅一个静态皮肤，未算在线bug。
- 本轮静态搜索在UI/presentation发现原生showDialog、showModalBottomSheet及两类包装入口并存。出现次数包含定义/示例，不能等同真实入口数；整改依据是已复现的不一致行为，而不是API数量本身。

## 建议分批实施与验收

1. **先处理可见布局**：用户指出的多key和模型列表、公共长内容弹窗/按钮。保留现有配置结构；验收默认1.2和上限1.8、320/360/1000px、100项、末项可操作及排序手势；加横屏/键盘实机检查。修F01/F02时不要把F03全量构建问题隐藏起来。
2. **再处理数据可靠性**：旧快照回写、保存失败与退出草稿、设置页状态同步。每条路径先已有失败测试，再修最小调用链；明确取消操作和仅离开页面的区别，避免为mounted补丁偷偷取消用户请求。
3. **收口共同实现**：在前两批行为稳定后，再合并资源解析、表单退出策略、共享/业务依赖和必要的长列表实现。只抽取重复且已证明需要的部分，不增加全局通用基类或再套一层状态框架。
4. **最后补真实场景验收**：窄宽屏、主题、真实中文字体、键盘、滚动/拖拽、导航返回和媒体。Widget测试通过不能替代帧性能或设备体验；不使用生产请求来代替本地可控测试。

每批独立检查diff、相关静态分析/测试、编译运行及设备窄宽屏验收。保存范围内补丁/备份作为回滚，保留既有工作树变更，不执行整仓重置。若触及数据迁移、核心API或生产操作，单独列出影响与回滚再确认。

## 现阶段不能承诺的结论

173个纳入文件已有局部检查记录；仍有未验证的完整页面交互、媒体与系统交互，以及未动态复现的竞态候选。现有审计失败测试是缺陷基线，测试总数不是独立bug数，也不是覆盖率。整改优先级以数据损失、无法操作、常用入口受影响为依据；完整审计完成后再形成最终执行范围。
