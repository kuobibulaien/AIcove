# 聊天删除仅前端可见实施说明

> 更新日期：2026-04-23  
> 适用范围：`apps/aicove_flutter/` 聊天时间线删除动作

---

## 1. 背景

项目宪法已经明确：

- 数据库 raw message 是聊天请求上下文的唯一真相源
- 用户点击“编辑”会改变 canonical context
- 用户点击“删除”默认只是前端动作，不改变 canonical context

但在本次修复前，聊天页的 `deleteMessage` 仍然会直接走 `softDeleteMessages(...)`，进而：

- 软删除 `messages`
- 软删除 `message_blocks`
- 删除 projection mapping
- 在某些情况下清空 `contextStartMessageId`

这与“删除仅前端可见”的基石规则冲突。

---

## 2. 本次落地后的规则

### 2.1 用户手动删除消息

用户在聊天页点击“删除”后：

- 只隐藏前端时间线中的对应消息
- 不修改 raw DB
- 不修改 canonical request context
- 不修改 `contextStartMessageId`

如果删除的是 assistant 的某个 projected 气泡：

- 只隐藏该 projected bubble
- 同源 raw assistant 仍然完整保留
- 同源其他 projected bubble 仍可见

如果删除的是未分段的整条消息：

- 前端按 raw message 维度隐藏整条消息
- raw 语义仍保留在数据库中

### 2.2 失败消息撤回（recall failed）

失败消息撤回不是普通“前端删除”。

它的语义仍然是：

- 把失败消息内容回填到输入框
- 从会话里真正移除该失败消息

因此 `recallFailedMessage(...)` 继续走 `softDeleteMessages(...)`，不复用普通删除的前端隐藏逻辑。

---

## 3. 实现边界

本次采用**最小改动**，不改表结构：

- 不新增数据库表
- 不给 raw message 增加“前端删除态”字段
- 不让前端删除动作污染真相源

实现方式：

1. 在 `ConversationTimelineCache` 内维护前端隐藏集合
   - `hiddenRawMessageIds`
   - `hiddenProjectedMessageIds`
2. UI 时间线窗口在输出时按隐藏集合过滤
3. canonical context 仍完全从 raw DB 读取

因此本次实现的“删除可见性”是**前端态 / 会话内态**，而不是数据库语义。

## 5. 验证点

本次至少验证以下两类行为：

1. 用户删除后，前端时间线不再显示该消息
2. 用户删除后，canonical context 仍包含原始 raw message

额外验证：

- 重新从 raw store reload 时间线后，当前会话内的前端隐藏态仍然生效
- `recallFailedMessage(...)` 仍保持原有“真正删除失败消息”的语义

---

## 6. 当前仍未覆盖的点

本次没有处理“前端删除态跨 App 重启持久化”。

这不是遗漏，而是刻意保持边界：

- 先把“删除不会污染数据库真相源”这件事做对
- 若未来确实需要“删除可见性持久化”，应单独设计前端态持久化方案
- 该方案不得回退为修改 raw message 语义
