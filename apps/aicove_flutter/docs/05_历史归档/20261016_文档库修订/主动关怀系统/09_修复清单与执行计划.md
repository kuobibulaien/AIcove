## 1. 执行原则

1. 先修高风险：优先处理误删、误发、重发、状态错乱。
2. 再做收敛：统一触发与发送链路，减少并行实现。
3. 最后增强：补齐预生成、可观测性、测试与文档一致性。

## 4. 分批修复计划

### Batch A（止血）

1. 修复跨会话/跨来源误删。
2. 修复触发器操作时序（全 await）。
3. 接入 `analyzerPrompt` 运行时配置。
4. 主动发送前增加总开关门禁。

### Batch B（链路收敛）

1. 明确前台/后台单链路主实现，另一条降级为可控兜底。
2. 统一 trigger 状态机与发送结果回写（fired/failed/expired）。
3. 用 `triggerId` 贯穿任务注册、取消、追踪。

### Batch C（配置落地）

1. 落地 `dailyLimit/minInterval/quietHours/allowExactAlarm`。
2. 统一 Trigger 插件开关与主动回复总开关语义。
3. 收敛 XML fallback（灰度开关后下线）。

### Batch D（质量与可观测性）

1. 增加主动回复专项单测/集成测试。
2. 增强 trigger log 可视化与失败诊断。
3. 同步重构文档，消除设计与实现偏差。
