## 现状核对（避免重复造轮子）

在开始改代码前，先确认当前工程的真实情况（以 `apps/aicove_flutter/lib/src` 为准）：

- **TriggerPlugin**：`lib/src/features/plugins/trigger/trigger_plugin.dart` 仍在 `processResponse()` 里用 XML 标签兜底（`<create_trigger>` / `<delete_trigger>`）。
- **AI 管家**：`lib/src/features/chat/data/context_analyzer.dart` 目前是“强约束 JSON”解析，不是 tool_calls。
- **触发器存储**：`lib/src/features/chat/data/auto_reply_trigger_storage.dart`（SharedPreferences），不是数据库默认落地。
- **Tool Calling 基础设施已存在**：`AgentApiClient.sendMessageRich(... tools: ...)` + provider adapters + `AITool`/`ToolParameter` + `ChatSendService` 自动注入 tools 并执行 tool_calls。

因此本次改造的重点是“把触发器系统接入现有 Tool Calling 链路”，而不是新增一套 sendMessageWithTools / tool_calls 解析。

### 4.3 完善“两回合（可递归）工具调用”底座（必须）

**目标**：让工具调用的结果能回填给模型，用于生成“人话确认/下一步工具调用”。  
典型链路：`search_reminders` → 模型看结果 → 继续 `delete_reminder(query)` → 再用人话确认删除了哪条。

**涉及文件**：
- `lib/src/features/chat/services/chat_send_service.dart`（两回合执行与递归控制）
- `lib/src/core/api/agent_api.dart`（`sendMessageRich` 必须支持透传 `tool_calls/tool_call_id/role=tool`）
- `lib/src/core/api/providers/openai_adapter.dart`（OpenAI：基本可直接透传 messages）
- `lib/src/core/api/providers/claude_adapter.dart`（Claude：需要支持 tool_use ↔ tool_result 的二次请求转换）
- `lib/src/core/api/providers/gemini_adapter.dart`（Gemini：需要支持 functionCall ↔ functionResponse 的二次请求转换）

**关键点（不满足会“看起来像 tool 执行了但 AI 不会说人话”）**：
- `AgentApiClient.sendMessageRich()` 当前会把 role 强制成 system/assistant/user，并丢弃 `tool_calls/tool_call_id`，必须改为“原样透传 messages 结构”。  
- 第二回合请求必须携带同一份 `tools` 定义（否则模型拿到结果也无法继续调用下一步工具）。

参考：`lib/src/features/ai_tools/function_calling_example.dart`（已有示例，不建议另起炉灶）。

// 旧数据迁移
AutoReplyTrigger migrateOldTrigger(Map<String, dynamic> oldJson) {
  return AutoReplyTrigger(
    // ... 现有字段 ...

    // 新字段默认值
    contextSnapshot: null,
    contextLastUserMessageId: null,
    contextLastUserMessageAt: null,

  );
}
