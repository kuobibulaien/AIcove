# 06 原生工具调用改造

> 本文档描述如何将现有的 XML 标签解析改造为原生工具调用（Function Calling）

> ⚠️ 实现更新（2026-06-13）：文中的 `ContextAnalyzer.analyzeAndSchedule()` 已拆分——`ContextAnalyzer.analyze(...)` 只返回决策，调度与触发器写入由 `AnalyzerScheduler`（`lib/src/features/auto_reply/data/analyzer_scheduler.dart`）负责。与本文冲突处以 `.trellis/spec/agent-context/index.md` 为准。

---

## 改造目标

| 方面 | 现状（XML 标签） | 目标（原生工具调用） |
|------|----------------|-------------------|
| **解析方式** | 正则表达式匹配 | API 结构化返回 |
| **可靠性** | 依赖 AI 正确输出格式 | 模型原生支持，更可靠 |
| **跨模型** | 需要每个模型学习格式 | OpenAI/Claude/Gemini 都支持 |
| **调试** | 难以追踪解析失败 | 结构化日志，易于调试 |

---

## 和当前工程的关系（先对齐现实）

本项目里“原生工具调用（Tool Calling）”的基础设施**其实已经具备**，不需要从零搭：

- **工具抽象**：`lib/src/features/plugins/domain/handlers/ai_tool.dart`（`AITool`）+ `lib/src/features/plugins/domain/handlers/tool_parameter.dart`（`ToolParameter`）
- **收集工具**：`lib/src/features/plugins/plugin_manager.dart`（`getAllTools()` / `findToolByName()`）
- **把 tools 发给模型**：`lib/src/features/chat/services/chat_send_service.dart`（`prepareApiConfig()` 会在 provider capabilities 包含 `tools` 时注入工具）
- **跨厂商适配**：`lib/src/core/api/providers/*_adapter.dart`（OpenAI/Claude/Gemini 的 tools 格式转换 + tool_calls 解析）
- **拿到 tool_calls**：`lib/src/core/api/agent_api.dart`（`AgentApiClient.sendMessageRich()` 返回 `SendMessageRichResult.toolCalls`）

前置条件（不满足就只能走兜底方案）：
- **模型侧必须支持 tools**：provider 的 `capabilities` 里包含 `tools`（`ChatSendService.prepareApiConfig()` 会据此决定是否注入 tools）
- **必须有直连 API Key**：`sendMessageRich()` 会直接走 OpenAI/Claude/Gemini 的官方接口；如果 `providerApiKey` 为空会直接报错
- 因此：对话 AI 侧的 tools（走 ChatSendService）在没配直连 key 时会自动退化为“无 tools”；AI 管家侧（ContextAnalyzer）改为 tools 后也必须考虑“无 key 时继续走旧的 JSON 解析路径”

所以本次“触发器/主动关怀”改造的关键，不是“再造一个工具系统”，而是：
1) 给 TriggerPlugin/ContextAnalyzer 提供正确的 `AITool` 定义；2) 把 tool_calls 的执行结果正确落地（创建/删除触发器、调度主动关怀）。

### 改造后代码结构

```dart
class TriggerPlugin extends BasePlugin {
  // ... 现有字段 ...

  // ========== 新增：工具注册 ==========

  @override
  List<AITool> getTools() {
    if (!enabled) return [];

    return [
      AITool(
        name: 'create_reminder',
        description: _createReminderDescription,
        parameters: _createReminderParams,
        handler: _handleCreateReminder,
      ),
      AITool(
        name: 'delete_reminder',
        description: _deleteReminderDescription,
        parameters: _deleteReminderParams,
        handler: _handleDeleteReminder,
      ),
    ];
  }

  // ========== 工具处理函数 ==========

  Future<String?> _handleCreateReminder(Map<String, dynamic> args) async {
    final title = args['title'] as String;
    final timeStr = args['time'] as String;
    final prompt = args['prompt'] as String?;

    // 解析时间
    final scheduledTime = _parseTime(timeStr);
    if (scheduledTime == null) {
      return '抱歉，我没能理解这个时间格式';
    }

    // 获取当前会话信息
    final conv = _ref.read(activeConversationProvider);
    if (conv == null) {
      return '当前没有活跃的会话';
    }

    // 记录创建时“最后一条用户消息”（用于作废判断）
    Message? lastUser;
    for (final m in conv.messages.reversed) {
      if (m.role == 'user') {
        lastUser = m;
        break;
      }
    }

    // 创建触发器
    await _ref.read(autoReplyTriggersProvider.notifier).createTrigger(
      title: title,
      type: AutoReplyTriggerType.fixed,
      nextFireAt: scheduledTime,
      allowNight: true,
      requireExact: false,
      delayMinutes: 0,
      prompt: prompt,
      priority: AutoReplyTriggerPriority.high,  // 用户要求 = 高优先级
      source: TriggerSource.userRequest,
      conversationId: conv.id,
      contextLastUserMessageId: lastUser?.id,
      contextLastUserMessageAt: lastUser?.createdAt,
    );

    AppLogger.info('TriggerPlugin', '通过工具调用创建触发器', metadata: {
      'title': title,
      'time': scheduledTime.toIso8601String(),
    });

    // 返回确认消息（会展示给用户）
    return '好的，我会在 ${_formatTime(scheduledTime)} 提醒你～';
  }

  Future<String?> _handleDeleteReminder(Map<String, dynamic> args) async {
    final id = (args['id'] as String?)?.trim();
    final query = (args['query'] as String?)?.trim();

    // 1) 优先按 id 删除（最准确）
    if (id != null && id.isNotEmpty) {
      await _ref.read(autoReplyTriggersProvider.notifier).deleteTrigger(id);
      AppLogger.info('TriggerPlugin', '通过工具调用删除触发器', metadata: {'id': id});
      return '好的，已经取消了这个提醒';
    }

    // 2) 否则按 query 删除：先在当前会话里搜索匹配的提醒
    if (query == null || query.isEmpty) {
      return '请告诉我要取消哪个提醒（例如“起床闹钟”）';
    }

    final conv = _ref.read(activeConversationProvider);
    if (conv == null) return '当前没有活跃的会话';

    final triggers = _ref.read(autoReplyTriggersProvider).valueOrNull ?? const [];
    final candidates = triggers
        .where((t) => t.conversationId == conv.id)
        .where((t) => t.title.contains(query) || (t.prompt ?? '').contains(query))
        .toList();

    if (candidates.isEmpty) {
      return '我没找到匹配“$query”的提醒';
    }
    if (candidates.length > 1) {
      final preview = candidates.take(3).map((t) => '「${t.title}」').join('、');
      return '我找到了多条匹配的提醒：$preview… 你想取消哪一个？';
    }

    final target = candidates.first;
    await _ref.read(autoReplyTriggersProvider.notifier).deleteTrigger(target.id);
    AppLogger.info('TriggerPlugin', '通过工具调用删除触发器(query)', metadata: {
      'query': query,
      'id': target.id,
    });
    return '好的，已取消：${target.title}';
  }

  // ========== 保留兼容：XML 标签解析（标记废弃） ==========

  @override
  @Deprecated('请使用原生工具调用，此方法仅作为兜底兼容')
  Future<PluginProcessResult> processResponse(String text) async {
    // 保留现有逻辑，但添加日志警告
    if (text.contains('<create_trigger') || text.contains('<delete_trigger')) {
      AppLogger.warning('TriggerPlugin', 'AI 使用了废弃的 XML 标签格式，应使用原生工具调用');
    }

    // ... 现有解析逻辑 ...
  }

  // ========== 辅助方法 ==========

  DateTime? _parseTime(String timeStr) {
    // 尝试 ISO 8601 格式
    try {
      return DateTime.parse(timeStr);
    } catch (_) {}

    // 尝试 HH:mm 格式
    try {
      final parts = timeStr.split(':');
      if (parts.length >= 2) {
        final h = int.parse(parts[0]);
        final m = int.parse(parts[1]);
        final now = DateTime.now();
        var d = DateTime(now.year, now.month, now.day, h, m);
        if (d.isBefore(now)) {
          d = d.add(const Duration(days: 1));
        }
        return d;
      }
    } catch (_) {}

    return null;
  }

  String _formatTime(DateTime time) {
    final now = DateTime.now();
    final isToday = time.day == now.day && time.month == now.month && time.year == now.year;
    final isTomorrow = time.day == now.day + 1 && time.month == now.month && time.year == now.year;

    final timeStr = '${time.hour.toString().padLeft(2, '0')}:${time.minute.toString().padLeft(2, '0')}';

    if (isToday) return '今天 $timeStr';
    if (isTomorrow) return '明天 $timeStr';
    return '${time.month}月${time.day}日 $timeStr';
  }
}
```

```dart
class ContextAnalyzer {
  Future<void> analyzeAndSchedule(Conversation conversation) async {
    if (!_shouldAnalyze(conversation)) return;

    final settings = await _ref.read(appSettingsProvider.future);
    final pluginManager = _ref.read(pluginManagerProvider);

    // 1. 准备历史消息
    final messages = _prepareMessages(conversation);

    // 2. 构建系统提示词
    final systemPrompt = _buildSchedulerPrompt(conversation);

    // 3. 获取模型配置
    final (model, provider, apiKey, apiBase) = _getModelConfig(settings);

    // 4. 定义工具
    final tools = [
      _scheduleProactiveTool,
    ];

    // 5. 调用 AI（使用独立 session + 原生 tools）
    final sessionId = 'scheduler_${DateTime.now().millisecondsSinceEpoch}';

    // 说明：
    // - 工程里已经有 AgentApiClient.sendMessageRich(tools: ...) + ToolCall 解析
    // - schedule_proactive 这类“只需要执行一次就结束”的工具，不要求二次回合把结果回传给模型
    final rich = await _agent.sendMessageRich(
      agentId: 'scheduler',
      sessionId: sessionId,
      modelFullId: '$provider:$model',
      messages: [
        {'role': 'system', 'content': systemPrompt},
        ...messages,
      ],
      userText: '',
      temperature: 0.3,
      token: settings.backendApiKey,
      providerApiBase: apiBase,
      providerApiKey: apiKey,
      tools: tools.map((t) => t.toOpenAISchema()).toList(),
    );

    // 6. 处理 tool_calls
    await _processToolCalls(rich.toolCalls, conversation);
  }

  AITool get _scheduleProactiveTool => AITool(
    name: 'schedule_proactive',
    description: '''

如果不需要安排任何消息，不要调用此工具。
''',
    parameters: {

        type: 'string',
        description: '触发原因描述',
        required: true,
      ),
      'delay_minutes': ToolParameter(
        type: 'integer',
        description: '延迟分钟数',
        required: true,
      ),
      'priority': ToolParameter(
        type: 'string',
        description: '优先级',

      'prompt': ToolParameter(

  Future<String?> _handleScheduleProactive(Map<String, dynamic> args) async {
    final title = args['title'] as String;
    final delayMinutes = args['delay_minutes'] as int;
    final priorityStr = args['priority'] as String;
    final prompt = args['prompt'] as String;
    final allowNight = args['allow_night'] as bool? ?? false;

    final priority = _parsePriority(priorityStr);
    final nextFireAt = DateTime.now().add(Duration(minutes: delayMinutes));

    // 获取当前会话
    final conv = _currentConversation;
    if (conv == null) return null;

    // 创建上下文快照
    final contextSnapshot = _createContextSnapshot(conv);

    // 记录创建时“最后一条用户消息”（用于作废判断）
    Message? lastUser;
    for (final m in conv.messages.reversed) {
      if (m.role == 'user') {
        lastUser = m;
        break;
      }
    }

    // 创建触发器
    await _ref.read(autoReplyTriggersProvider.notifier).createTrigger(
      title: title,
      type: AutoReplyTriggerType.delay,
      nextFireAt: nextFireAt,

      requireExact: false,

      contextSnapshot: contextSnapshot,

      'title': title,
      'delayMinutes': delayMinutes,
      'priority': priorityStr,
    });

    return null;  // 不需要返回给 AI

  String _buildSchedulerPrompt(Conversation conversation) {
    final pendingTriggers = _getPendingTriggers(conversation.id);

    return '''
你是 ${conversation.title} 的主动关怀调度员。你的任务是分析对话，决定是否需要在未来某个时间主动联系用户。

当前时间：${DateTime.now().toIso8601String()}
角色名称：${conversation.title}
用户称呼：${conversation.addressUser ?? '用户'}

${pendingTriggers.isNotEmpty ? '''
已有的待发送触发器：
${pendingTriggers.map((t) => '- ${t.title}（${t.nextFireAt.toIso8601String()}）').join('\n')}
''' : '当前没有待发送的触发器。'}

分析指南：
1. 如果用户提到要去做某事（睡觉、开会、工作、出门等），考虑在事后发送关心
2. 如果对话自然结束，根据时间段考虑是否问候
3. 不要创建与已有触发器重复或冲突的新触发器
4. 如果不需要创建触发器，就不要调用工具

优先级选择：
- medium：普通的关心问候（用户发新消息后取消）
- low：纯情感性消息如"想你了"（用户在聊天界面时取消）
- 注意：high 只用于用户明确要求的提醒，这里不应该使用
''';
  }

  Future<void> _processToolCalls(List<ToolCall> toolCalls, Conversation conversation) async {
    if (toolCalls.isEmpty) {
      AppLogger.info('ContextAnalyzer', 'AI 管家决定不创建触发器');
      return;
    }

    _currentConversation = conversation;

    for (final toolCall in toolCalls) {
      if (toolCall.name == 'schedule_proactive') {
        await _handleScheduleProactive(toolCall.arguments);
      }
    }

    _currentConversation = null;
  }
}
```

## 工具注入时机

### 对话 AI：由 ChatSendService 自动注入（无需改 ChatRequestBuilder）

当前工程里，tools 的注入发生在 `lib/src/features/chat/services/chat_send_service.dart` 的 `prepareApiConfig()`：

- 只有当 provider capabilities 包含 `tools` 时才会注入
- 注入的工具来自 `PluginManager.getAllTools()`（已启用插件的 tools 全量注入）

这意味着“按需注入（只在疑似提醒时才带 create_reminder）”如果要做到**严格按需**，需要改插件接口或改发送链路，属于额外工程量。
更符合 KISS 的落地方式是：**保持全量注入 tools**，但在 `TriggerPlugin.getSystemPrompt(userMessage: ...)` 里只在“用户明确要设提醒”时给出工具使用指导，从而降低误触发。

### AI 管家：始终注入 schedule_proactive

Scheduler 这条链路不经过 ChatSendService，可在 `ContextAnalyzer.analyzeAndSchedule()` 内部固定传入 tools：`[schedule_proactive]`。

## 重要：工具调用结果怎么“回到对话里”？

目前 `ChatSendService.executeApiCall()` 会：
1) 把 tools 发给模型；2) 拿到 `tool_calls` 后执行 handler；3) **直接把模型首轮返回的 text 当作回复**。

口径确认：我们**确定采用“两回合（可递归多回合）工具调用”**（方案 A）。

原因（用大白话类比）：
- 现在的实现像“AI 说：我去打电话，然后你真去打了电话，但你没把电话结果告诉 AI”，所以 AI 没法把最终结论说给用户听。
- 两回合就是“AI 先提需求→系统执行→把执行结果回传→AI 再把结果说人话”。

### 目标行为（必须满足）

只要出现 tool_calls，最终展示给用户的回复以“最后一回合的 assistant 文本”为准，而不是第一回合的半成品。

适用工具：
- `create_reminder` / `delete_reminder`
- `list_reminders` / `search_reminders`
- 以及现有的 `speak`（TTS）等工具（副作用工具也允许走两回合，让模型更自然地继续说话）

### 两回合（可递归）流程（实现要点）

参考：`lib/src/features/ai_tools/function_calling_example.dart`

建议在 `lib/src/features/chat/services/chat_send_service.dart` 内实现一个循环（最多 3-5 轮，防止死循环）：

1. **第一回合**：`sendMessageRich(... tools: ...)` 得到：
   - `assistantText`
   - `toolCalls[]`
   - 以及“可被复用到下一轮的 assistant 消息结构”（见下节）
2. **执行工具**：对每个 `toolCall`：
   - `PluginManager.findToolByName(toolCall.name)` 找到 `AITool.handler`
   - 执行 `handler(args)` 得到 `toolResultText`
   - 组装一条“工具结果消息”，追加到 messages
3. **第二回合**：把“第一回合的 assistant 工具调用消息”+“工具结果消息们”追加到 messages，再次调用 `sendMessageRich`
   - 注意：第二回合仍需要携带同一份 `tools` 定义（让模型可以继续调用下一步工具，例如先 `search_reminders` 再 `delete_reminder`）
4. 若第二回合仍返回 tool_calls，重复 2-3，直到 tool_calls 为空或达到轮次上限

### 关键：必须能把 tool_calls 写回 messages

要实现上面的流程，工程需要支持两类消息进入下一轮请求：

1) **assistant 工具调用消息**
- OpenAI 内部格式（建议作为工程内统一格式）：
  - `role: 'assistant'`
  - `content: ''`（允许空）
  - `tool_calls: [...]`（原样保留，含 id/name/arguments）

2) **tool 工具结果消息**
- OpenAI 格式：
  - `role: 'tool'`
  - `tool_call_id: 'call_xxx'`
  - `content: '...'`

因此需要改动：
- `lib/src/core/api/agent_api.dart`：`sendMessageRich()` 目前会把除 `system/assistant` 外的 role 都压成 `user`，并且会丢弃 `tool_calls/tool_call_id`，需要支持 `role: tool` 和这些字段透传。
- `lib/src/core/api/providers/claude_adapter.dart` / `lib/src/core/api/providers/gemini_adapter.dart`：目前只支持“发 tools + 解析 tool_calls”，还不支持把 tool 结果消息转换成各自的二次请求格式。

### 各 Provider 的二次请求格式（落地口径）

我们以“OpenAI tool 消息格式”作为工程内统一表示，然后在 adapter 层做转换：

- **OpenAI**（`chat/completions`）
  - 直接发送 messages（包含 `assistant.tool_calls` + `tool` role 消息）
  - tool 结果消息示例：
    - `{ "role": "tool", "tool_call_id": "call_abc", "content": "{\"ok\":true,\"result\":...}" }`

- **Claude (Anthropic)**（`/v1/messages`）
  - assistant 的 tool_calls → 转成 content block：`{type:"tool_use", id, name, input}`
  - tool 结果消息 → 转成 user content block：`{type:"tool_result", tool_use_id: <id>, content: <string>, is_error?: true}`
  - 参考：Anthropic 官方流程（tool_use → tool_result → 再次 messages.create）

- **Gemini**（`generateContent` REST）
  - assistant 的 tool_calls → 转成 `parts: [{ functionCall: { name, args } }]`
  - tool 结果消息 → 转成 `parts: [{ functionResponse: { name, response } }]`
  - 参考：Google Gemini function calling 文档（functionCall → FunctionResponse → 再次 generate）

### 工具返回值的统一约定（强烈建议）

为了让 Claude 的 `is_error`、以及 Gemini 的 `functionResponse.response` 能稳定表达成功/失败，建议所有工具 handler 返回 JSON 字符串：

- 成功：`{"ok": true, "result": <any>}`
- 失败：`{"ok": false, "error": "<message>"}`

`ChatSendService` 在组装 tool 消息时不要“拼自然语言”，直接把这段 JSON 作为 tool content 传回模型，让模型自己组织给用户看的话术。
