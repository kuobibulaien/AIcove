## 一、背景与目标

### 问题现状
主动回复功能由 GPT 实现的半成品代码组成，存在以下核心问题：
1. 前台轮询与后台 WorkManager 双链路并行，无互斥协议，存在重复发送风险
2. 后台生成不含人设与输出约束，文案口吻与前台不一致
3. quietHours / dailyLimit / minInterval 门禁未生效
4. preparing 状态未真正落地，预生成逻辑半残
5. WorkManager inputData 含明文密钥，安全风险
6. XML 兜底仍可修改触发器，行为面过大
7. 测试覆盖不足，缺少集成测试

### 实施目标
按照"先止血、再收敛、最后增强"的原则，将主动回复从半成品演进为可生产就绪状态。

---

## 二、实施方案

### 阶段 0：止血

#### 0-1：后台生成接入人设与输出约束
**问题：** 后台生成文案口吻与前台不一致，缺少角色人设  
**方案：** 
- 后台生成调用 `buildBackgroundProactiveMessages`，使用 `PromptBuiltinDefaults.autoReplyBackgroundObjective` 注入人设
- 添加纯文本输出约束（禁止工具调用、多模态标签）
- 注入当前时间感知与上下文信息

**实现位置：** `background_service.dart` L829-L867

#### 0-2：补全三重门禁
**问题：** quietHours / dailyLimit / minInterval 配置存在但未被消费  
**方案：**
- 实现 `evaluateBackgroundSendGates` 在后台任务执行前检查三重门禁
- allowNight 触发器豁免静默时段限制
- 门禁触发时返回建议重试延迟

**实现位置：** `background_service.dart` L198-L251  
**测试覆盖：** `background_service_test.dart` L20-L118

#### 0-3：事件顺序消费
**问题：** 单值 StateProvider 在同一帧内被覆盖导致事件丢失  
**方案：**
- 新增 `AutoReplyTriggerEventBus` 使用 StreamController 顺序消费事件
- `autoReplyTriggerEventProvider` 保留给 UI 做轻量刷新

**实现位置：** `auto_reply_trigger_controller.dart` L23-L44

---

### 阶段 1：收敛

#### 1-1：缓存策略优化
**问题：** preparing 状态未真正落地，预生成逻辑半残  
**方案：**
- 60 分钟内的 cachedContent 视为新鲜，直接使用
- 超过 60 分钟视为过期，优先即时生成，失败时回退缓存兜底
- 删除 `preparing` 状态，状态机只保留 created/pending/prepared/fired/expired/cancelled

**实现位置：** `background_service.dart` L668-L723

#### 1-2：前后台原子认领互斥
**问题：** 两条链路无互斥协议，存在重复发送风险  
**方案：**
- 新增数据库表 `auto_reply_trigger_claims`（Schema v14）
- 前台轮询与后台 WorkManager 通过数据库文件锁原子认领执行权
- 认领失败的一方跳过执行，由认领成功方发送消息
- 24 小时自动清理过期认领记录

**实现位置：**
- `database.dart` Schema v14
- `auto_reply_claim_store.dart`（新增）
- `auto_reply_trigger_controller.dart` L563-L574（前台认领）
- `background_service.dart` L515-L535（后台认领）

**测试覆盖：**
- `auto_reply_claim_store_test.dart`（单元测试）
- `auto_reply_integration_test.dart` L147-L178（集成测试）

#### 1-3：WorkManager inputData 瘦身
**问题：** inputData 含明文 apiKey/model，安全风险且换 key 不生效  
**方案：**
- 新增 `auto_reply_request_config.dart` 工具类
- `app_settings.dart` 暴露 `mapUiModelsToAppSettings` 公开映射入口
- 后台执行时通过 SharedPreferences 现读最新配置（含直连模式兜底）
- WorkManager inputData 只保留 triggerId / convId / prompt / characterName

**实现位置：**
- `auto_reply_request_config.dart`（新增）
- `app_settings.dart` L211-L215
- `background_service.dart` L282-L298
- `auto_reply_trigger_controller.dart` L794-L819（删除配置快照逻辑）

**测试覆盖：** `auto_reply_trigger_controller_background_schedule_test.dart` L156-L158

---

### 阶段 2：遗留清理

#### 2-1：XML 兜底默认关闭
**问题：** XML 标签解析仍可修改触发器，行为面过大  
**方案：** `TriggerConfig.xmlFallbackEnabled` 默认值改为 `false`，XML 标签只清理展示不执行

**实现位置：** `trigger_config.dart` L18

#### 2-2：多模态补渲染
**问题：** 后台纯文本消息打开 App 后无法补渲染  
**方案：** 后台消息存储 `rawPayload` 字段，前台读取时通过 `ChatMessageProjectionCodec` 自动补渲染

**实现位置：** `background_service.dart` L1034

#### 2-3：SessionManager 死代码清理
**问题：** SessionManager 完全未被引用，是残留死代码  
**方案：** 删除 `session_manager.dart`

**实现位置：** 删除文件 `lib/src/features/chat/data/session_manager.dart`

#### 2-4：补充集成测试
**问题：** 缺少端到端集成测试  
**方案：** 新增 4 个集成测试覆盖：
1. 触发器完整生命周期（created → pending → fired）
2. 前后台认领互斥
3. 静默时段门禁
4. 24 小时过期清理

**实现位置：** `auto_reply_integration_test.dart`（新增）

### 阶段 3：记忆联动契约

**方案：** 在 `.trellis/spec/agent-context/index.md` 补充"Proactive Memory Linkage"场景，定义接口契约：

- 注入点：analyzer 与 agent 的 context 参数

**实现位置：** `.trellis/spec/agent-context/index.md` L179-L229
