## 核心组件职责

### 1. ChatActions（聊天动作中心）

**文件**：`lib/src/features/chat/chat_actions.dart`

**职责**：
- 处理用户发送消息
- 调用对话 AI（具体发送链路下沉到 ChatSendService）
- 发送主动关怀消息
- 在用户发消息时检查是否需要作废触发器

**关键方法**：
```dart
class ChatActions {
  /// 发送用户消息
  /// 新增：检查是否需要作废 pending 触发器
  Future<void> send(String text) async {
    // 1. 检查并作废低优先级触发器
    await _checkAndExpireTriggers();

    // 2. 调用 ChatSendService 执行发送：
    //    - 组装 messages + system prompt
    //    -（如模型支持）注入 tools
    //    - 执行 tool_calls
    //    - 运行插件兜底解析（XML 标签等）
  }

  /// 发送主动关怀消息
  /// 改造：使用 proactive system prompt，不把触发器当 userText
  Future<void> sendProactiveTrigger(AutoReplyTrigger trigger) async {
    // 使用预生成的内容，或实时生成
  }

  /// 检查并作废触发器
  Future<void> _checkAndExpireTriggers() async {
    // 根据优先级决定是否作废
  }
}
```

### 2. ChatSendService（发送链路核心）

**文件**：`lib/src/features/chat/services/chat_send_service.dart`

**职责**：
- 准备 API 配置（provider/model/apiKey/toolPrefs/system prompt/messages）
- 当模型支持 `tools` 能力时：收集 `PluginManager.getAllTools()` 并注入到请求
- 调用 `AgentApiClient.sendMessageRich()` 获取 text + tool_calls
- 执行 `tool_calls`（通过 `PluginManager.findToolByName()` 找到对应 `AITool.handler`）
- 运行 `PluginManager.processResponse()`（兜底解析 XML 标签等）

> 注意：当前实现是“单回合”：执行完工具不会把工具结果回传给模型生成二次回复。  
> 口径确认：本次重构会把这里升级为“两回合（可递归）工具调用”（见 `06_原生工具调用改造.md`）。

### 3. AnalyzerScheduler（触发时机统一入口）

**文件**：`lib/src/features/auto_reply/data/analyzer_scheduler.dart`

**职责**：
- 统一“什么时候触发 AI 管家分析”的规则：
  - 5 分钟无新消息
  - App 切后台（延迟约 10 秒防抖）
  - 频繁切后台的冷却期
- 触发时调用 `ContextAnalyzer.analyze(conversation, proactiveState: ...)` 获取决策
- 负责把 `ContextAnalysisDecision` 落到 `ConversationProactiveState` 与 `AutoReplyTrigger`

**接入点（施工时别漏）**：
- `lib/src/features/chat/chat_actions.dart`：用户发送完成后，调用 `analyzerSchedulerProvider.scheduleAnalysis()`（5 分钟无消息触发）
- `lib/src/app.dart`：App 生命周期切后台时，调用 `analyzerSchedulerProvider.onAppBackground()`（10 秒防抖 + 冷却期）

**重构要求（口径确认）**：
- 不再分散触发：`ChatActions` 里现有的 `_scheduleContextAnalysis()`（2 秒延迟直触发）应收敛到 `AnalyzerScheduler`
- `SessionManager` 里的触发器 TODO 不再继续扩展（避免两套调度器并存）

### 4. ContextAnalyzer（AI 管家）

**文件**：`lib/src/features/auto_reply/data/context_analyzer.dart`（`features/chat/data/context_analyzer.dart` 仅保留 re-export 兼容入口）

**职责**：
- 对话结束后分析是否需要创建触发器
- 使用**独立的 session**，不污染聊天上下文
- 通过后台 Agent 与调度工具生成 `ContextAnalysisDecision`
- 不直接调度或落库触发器；这些副作用由 `AnalyzerScheduler` 统一执行

**关键方法**：
```dart
class ContextAnalyzer {
  /// 分析对话并返回主动关怀决策
  Future<ContextAnalysisDecision?> analyze(
    Conversation conversation, {
    required ConversationProactiveState proactiveState,
  }) async {
    // 1. 从 ChatHistoryStore 读取 DB raw message 上下文
    // 2. 构建独立后台 Agent 请求
    // 3. 调用 AI，带上主动关怀调度工具
    // 4. 返回 session_patch / trigger_plan 决策给 AnalyzerScheduler
  }
}
```

### 5. TriggerPlugin（触发器插件）

**文件**：`lib/src/features/plugins/trigger/trigger_plugin.dart`

**职责**：
- 定义触发器相关的 AI 工具
- 执行工具调用
- XML 标签解析仅作为兜底（重构后应标记废弃并加警告日志）

**关键方法**：
```dart
class TriggerPlugin extends BasePlugin {
  @override

    return [
      AITool(
        name: 'create_reminder',
        description: '创建一个定时提醒...',
        parameters: {...},
        handler: _handleCreateReminder,
      ),
      AITool(
        name: 'delete_reminder',
        description: '删除一个提醒...',
        parameters: {...},
        handler: _handleDeleteReminder,
      ),
    ];
  }
}
```

### 6. AutoReplyTriggerController（触发器控制器）

**文件**：`lib/src/features/chat/data/auto_reply_trigger_controller.dart`

**职责**：
- 管理触发器的 CRUD
- 轮询检查到期的触发器
- 处理预生成内容
- 处理作废逻辑
  - 现状补充：目前触发后只会发出事件（`autoReplyTriggerEventProvider`），真正“发消息”在 AutoReplyService 中完成

**关键方法**：
```dart
class AutoReplyTriggerController {
  /// 创建触发器
  Future<void> createTrigger({...}) async {
    // 1. 创建触发器，状态 = created
    // 2. 记录“创建时最后一条用户消息”的 id/时间（用于作废判断）
    // 3. 触发预生成
  }

  /// 预生成内容
  Future<void> prepareContent(String triggerId) async {
    // 1. 获取上下文快照
    // 2. 用独立 session 调用 AI
    // 3. 保存预生成内容
    // 4. 状态 → prepared
  }

  /// 触发检查
  Future<void> checkAndFire(String triggerId) async {
    // 1. 检查是否应该作废
    // 2. 如果不作废，发送消息
    // 3. 状态 → fired 或 expired
  }
}
```

### 7. AutoReplyService（触发器→发消息桥接）

**文件**：`lib/src/features/chat/data/auto_reply_service.dart`

**职责**：
- 监听 `autoReplyTriggerEventProvider` 的 fired 事件
- 找到对应的触发器数据，然后调用 `ChatActions.sendProactiveTrigger()`

> 现状问题：当前实现会“临时拼一个假的 AutoReplyTrigger”，导致 prompt/cachedContent 等关键信息丢失；重构后应改为用真实 trigger 数据。

## 数据流

### 场景 A：用户主动要求创建提醒

```
用户: "明天早上8点叫我起床"
          │
          ▼
┌─────────────────────────────────────────────────────────────────┐
│                         ChatActions.send()                       │
│  1. 将消息发送给对话 AI                                           │
│  2. 对话 AI 识别到用户意图，调用 create_reminder 工具             │
│  3. ChatSendService 执行 tool_calls（通过 PluginManager 找到工具） │
│  4. TriggerPlugin 的 AITool.handler 创建触发器                    │
│  5. AI 回复确认话术（见下方“单回合/两回合”说明）                  │
└─────────────────────────────────────────────────────────────────┘
          │
          ▼
触发器创建完成（priority = high，用户明确要求）
```

> 单回合/两回合说明：当前工程的 `ChatSendService.executeApiCall()` 是“单回合”实现：  
> - 会执行工具，但**不会**把工具返回结果再回传给模型生成第二段回复。  
> - 口径确认：本次重构会把 `ChatSendService` 升级为“两回合（可递归）工具调用”（执行工具→追加 tool 结果→再请求一次），让模型用“人话”确认结果，并支持后续链式工具（例如先 `search_reminders` 再 `delete_reminder`）。

## 上下文隔离策略

为了避免污染聊天上下文，系统使用三种不同的 session：

| Session 类型 | 用途 | 命名规则 |
|-------------|------|---------|
| **聊天 session** | 用户与 AI 角色的对话 | `conv_{conversationId}` |
| **管家 session** | AI 管家分析对话 | `scheduler_{timestamp}` |
| **预生成 session** | 生成主动消息内容 | `proactive_{triggerId}` |

```dart
// 聊天 session - 保持上下文连续性
final chatSessionId = 'conv_${conversation.id}';

// 管家 session - 每次分析用新的，不累积
final schedulerSessionId = 'scheduler_${DateTime.now().millisecondsSinceEpoch}';

// 预生成 session - 每个触发器独立
final proactiveSessionId = 'proactive_${trigger.id}';
```
