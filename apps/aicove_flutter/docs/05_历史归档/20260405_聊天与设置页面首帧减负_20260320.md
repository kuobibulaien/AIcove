# 聊天与设置页面首帧减负

更新时间：2026-04-01

## 背景

设置里的重页面，以及聊天里的角色编辑/背景设置页，在 iOS 风格的转场期间会同时做动画和较重的首帧工作，主观感受是“点进去有点卡”。

## 2026-04-01 调整

- 根据最新真机反馈，模型管理相关页面的“先轻壳，后重内容”会带来明显撕裂感，因此已撤回以下页面的延后加载：
- `lib/src/ui/features/settings/pages/model_list_page.dart`
- `lib/src/ui/features/settings/pages/default_model_settings_page.dart`
- `lib/src/ui/features/settings/pages/provider_detail_page.dart`
- 角色卡详情入口 `lib/src/ui/features/character/widgets/horizontal_role_card.dart` 的 `onTapDown` 图片预热也已移除，改为直接进入详情页。
- 角色编辑页与聊天背景设置页的轻壳策略暂时保留，因为它们仍主要服务于重预览/重解码场景。

这次分三个小单元推进：

- `lib/src/ui/features/character/pages/contact_edit_page.dart`
- `lib/src/ui/features/chat/pages/chat_background_settings_page.dart`
- `lib/src/ui/features/settings/pages/model_list_page.dart`
- `lib/src/ui/features/settings/pages/default_model_settings_page.dart`
- `lib/src/ui/features/settings/pages/provider_detail_page.dart`

## 处理策略

统一采用“先轻壳，后重预览”的策略：

- 转场期间先展示轻量占位壳，避免大图、模糊、复杂预览和整页编辑树与 `ParallaxSlidePageRoute` 抢帧。
- 等转场窗口过去后，再挂载完整编辑内容或背景缩略预览。
- 对 data url 图片的解码从首帧挪到延后阶段，减少进入页面瞬间的同步开销。
- 静态模糊层的准备仍保留，但不在进入页面的第一时间触发。

## 当前效果

### 角色编辑页

- 首帧只显示导航和若干轻量壳卡片。
- 延后窗口结束后，再挂载完整的编辑区、插件区、聊天背景区和绘图提示区。
- 模糊背景在延后窗口结束后再启动。

### 聊天背景设置页

- 首帧先显示轻量预览壳，不立刻渲染完整聊天缩略图。
- 延后窗口结束后，再渲染背景图、静态模糊层、遮罩和模拟聊天 UI。
- `data:image/...` 的解码从首帧移到延后阶段。

### 模型管理页

- 首帧先显示默认模型入口和供应商列表壳，不立刻挂载 `ReorderableListView`。
- 供应商摘要改为先收敛成轻量条目，再交给列表渲染，减少进入页面瞬间的重复字符串拼装。
- 转场窗口结束后，再挂载完整供应商列表和拖拽排序能力。

### 默认模型设置页

- 首帧先显示三个设置分组的轻量壳，不立刻做聊天模型收集和整组行渲染。
- 聊天模型的筛选与显示名称解析延后到转场窗口后执行。
- 历史消息条数输入框仍会提前初始化本地状态，但重分组内容不和转场动画同帧落下。

### 渠道详情页

- 首帧先显示顶部信息卡壳和底部切换框壳，不立刻挂载 `PageView`、配置表单和模型拖拽列表。
- 表单控制器同步、顶部卡片完整内容、模型排序列表都延后到转场窗口后激活。
- 这样可以避开进入详情页时“顶部卡片 + 双 Tab + 模型列表”一起抢主线程。
- 同一个渠道在当前 App 进程内二次进入时，会命中轻量内存缓存，直接复用排序后的模型视图条目并跳过轻壳。

## 后续建议

当前普通设置重页还剩 `log_viewer_page.dart` 没处理，它更像是性能专项，建议继续单独拆成下一单元：

- 先定位首屏文件读取、日志解析、排序和过滤各自的占比。
- 优先把日志页入口转成“轻壳先出，重解析后置”。
- 如果解析量仍大，再考虑把格式化/筛选进一步移到 isolate。
