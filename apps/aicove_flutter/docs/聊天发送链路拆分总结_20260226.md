# 聊天发送链路拆分总结（2026-02-26）

> 适用范围：`lib/src/features/chat/`
>  
> 目标：把“上帝类”拆成可维护的协作结构，降低改动连锁风险。

---

## 1. 这次做了什么

把原先集中在 `chat_send_service.dart` 的重逻辑拆开，让每个文件只做一类事。

- 以前：像“一个人既当调度又当执行还要记账”
- 现在：变成“总调度 + 专职执行 + 专职翻译 + 专职插件协调”

---

## 2. 功能 ↔ 文件（排查入口）

| 功能 | 文件 | 出问题先看哪里 |
|------|------|----------------|
| 发送总流程编排（组装参数、串联调用、交付消息） | `lib/src/features/chat/services/chat_send_service.dart` | 发送流程顺序不对、状态流转异常 |
| 模型调用 + 工具循环 + 流式回退 | `lib/src/features/chat/services/chat_send_api_runner.dart` | 工具没执行、tool loop 异常、流式中断 |
| 历史消息转请求消息（图文/文件/非视觉回退） | `lib/src/features/chat/services/chat_request_message_builder.dart` | 图片消息理解错误、文件内容喂给模型异常 |
| 插件筛选、插件 prompt、工具定义收集 | `lib/src/features/chat/services/chat_plugin_context_builder.dart` | 插件未生效、工具列表缺失、prompt 异常 |
| 失败消息重试（retry） | `lib/src/features/chat/chat_actions.dart` | 重试行为和正常发送不一致 |

---

## 3. 为什么这次必须拆

- 风险问题：一个超大文件承载太多职责，任何小改动都可能误伤其他流程。
- 协作问题：排查成本高，不清楚“这个 bug 应该去哪个文件找”。
- 测试问题：难做针对性单测，回归范围大。

拆分后的好处是“定位更快、影响面更小、测试更准”。

---

## 4. 关键修复点（与这次拆分配套）

- `retry()` 流式参数透传补齐  
  现象：重试路径和正常发送路径行为不一致。  
  修复：`chat_actions.dart` 的 `retry()` 补齐 `enableStreaming` 与流式回调透传。

- Windows 单测依赖补齐

## 7. 2026-02-27 补充：流式文本被图片后补“整段撤回”修复

### 7.1 现象

- 用户看到文本已经流式显示出来，随后检测到图片/工具结果时，文本占位气泡被删掉，表现成“刚出来的字又没了，再一次性重发”。

### 7.2 根因（对应文件）

- `lib/src/features/chat/services/chat_send_api_runner.dart`
  - 工具调用被观测到后会触发“流式重置”链路，导致占位文本被清空。
- `lib/src/features/chat/chat_actions.dart`
  - 流式 finalize 过于依赖 `finalText`，当最终文本为空但已有流式文本时，没有兜底，容易走到“删占位重发”。
- `lib/src/features/chat/services/chat_tts_handler.dart`
  - 多模态后补插槽在“无锚点”时不够明确，图片可能不是尾插，影响语序稳定性。

### 7.3 修复策略

- 工具调用观测只打标，不再清空已流出的文本。
- finalize 增加“最终文本为空时回退到已流式文本”的兜底。
- 多模态后补新增“强制尾插”插槽规则：后方无文本锚点时，图片/非文本补充直接插到末尾。

### 7.4 对应测试

- `test/features/chat/services/chat_tts_handler_insert_slot_test.dart`
  - 新增 `resolveSupplementInsertSlot` 用例，验证强制尾插和普通字符槽位两种路径。

### 7.5 调试入口补齐（阶段4）

- 页面：`lib/src/ui/features/debug/pages/stream_monitor_debug_page.dart`
- 入口：`调试中心 -> 流式监控`
- 能看到什么：
  - 流式尝试次数 / 成功次数 / 回退次数 / 成功率
  - 最近失败时间、失败原因、错误详情
  - 失败原因分布（按类型计数）
- 什么时候用：
  - 用户反馈“看起来没流式”时，先看这里是否发生大量回退，再决定排查模型端还是前端展示端。

## 8. 2026-02-27 补充：稳定模式二轮调用把图片误喂给无视觉模型（本次修复）

### 8.1 现象

- **快速模式（单轮）正常**。
- **稳定模式（两轮）报错**：第一轮工具生成图片后，第二轮继续请求时把图片内容也带上了；
  对不支持视觉输入的模型会直接报错（常见错误是“不支持 image content / image_url”）。

### 8.2 根因（对应文件）

- `lib/src/features/chat/services/chat_send_api_runner.dart`
  - 稳定模式会执行“第一轮模型 -> 工具 -> 第二轮模型”。
  - 第二轮拼接消息时，会把第一轮 assistant 原始消息和 tool result 一起追加回 `messages`。
  - 若 assistant 原始消息里含有图片片段（`image_url` / `image` / `inlineData(image/*)`），就会被再次发送给当前模型。

### 8.3 修复策略

- 在 `chat_send_api_runner.dart` 增加**非视觉模型消息清洗**：
  - 进入每一轮请求前，对 `currentMessages` 做一次图片片段剔除；
  - 追加 `toolResultMessages` 时再次清洗，防止第一轮 assistant 原始响应里的图片“带入第二轮”；
  - 只删除图片输入片段，保留文本、`tool_calls`、`tool_result` 结构，确保工具链路不受影响。

### 8.4 复现与回归测试

- 新增测试：`test/features/chat/services/chat_send_api_runner_non_vision_test.dart`
  - 模拟稳定模式两轮：
    1. 第一轮返回 `tool_calls` 且 assistant `content` 含 `image_url`；
    2. 第二轮若请求里仍含图片，伪服务端返回 400；
  - 断言：修复后第二轮请求不再包含图片片段，调用成功。

## 9. 2026-02-27 补充：流式完成阶段“重排重发”修复（本次修复）

### 9.1 现象

- 流式阶段已经按句子逐条显示；
- 但在模型完成瞬间，已显示的分段会出现“回退后再重发”的观感，像被重新整理了一次。

### 9.2 根因（对应文件）

- `lib/src/features/chat/chat_actions.dart`
  - `_StreamPlaceholderDelivery.finalize()` 在启用 `streamSegmentDelaySeconds` 时，会走 `_finalizeWithDelayedChunks()`。
  - 该路径会先清空已流出的分段缓存，再按最终文本重新逐段推送，导致已显示分段在收尾阶段发生回退/重播。

### 9.3 修复策略

- 在 `chat_actions.dart` 将收尾逻辑改为“完成阶段不重播”：
  - 保留流式阶段已展示结果；
  - 完成时只做一次最终对齐并落库，不再进行二次逐段回放。

### 9.4 复现与回归测试

- 新增测试：`test/features/chat/chat_actions_test.dart`
  - 用例：`send 在分段延迟模式下完成时，不会撤回已流出的文本段`
  - 断言：
    1. 流式过程中已出现的文本分段数量在收尾阶段不允许回退；
    2. 最终结果包含全部分段文本。

## 10. 2026-02-28 补充：消息分段“引号保护失效”修复（本次修复）

### 10.1 现象

- 已开启 `protectQuotes` 时，中文弯引号 `“”` / `‘’` 内的内容仍被按标点拆分；
- 用户观感是“引号里的完整一句话被截断成两条消息”。

### 10.2 根因（对应文件）

- `lib/src/core/utils/message_formatter.dart`
  - `MessageFormatter._quotePattern` 仅覆盖了 `「」`、`『』`、`""`、`''`、`《》`、`【】`；
  - 未覆盖 `“”` / `‘’`，导致保护占位步骤漏掉该类引号文本，后续标点切分直接命中引号内部。

### 10.3 修复策略

- 在 `_quotePattern` 中补齐 `“.*?”` 与 `‘.*?’` 两类匹配；
- 不改分段主算法，仅扩展“引号保护识别范围”，保持最小影响面。

### 10.4 复现与回归测试

- 测试文件：`test/core/utils/message_formatter_test.dart`
  - 新增：
    - `should not split inside Chinese double quotes`
    - `should not split inside Chinese single quotes`
  - 结果：
    - 修复前：两条用例均失败（可稳定复现）
    - 修复后：两条用例通过
