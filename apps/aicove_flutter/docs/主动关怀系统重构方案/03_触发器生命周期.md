# 03 触发器生命周期

> 本文档描述触发器的状态机和转换规则

---

## 状态机图

```
                                    ┌─────────────┐
                                    │   deleted   │
                                    │   已删除    │
                                    └─────────────┘
                                          ▲
                                          │ 用户删除
                                          │
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   created   │────►│  preparing  │────►│  prepared   │
│   刚创建    │     │  预生成中   │     │  已预生成   │
└─────────────┘     └─────────────┘     └─────────────┘
      │                   │                   │
      │                   │ 预生成失败        │
      │                   ▼                   │
      │             ┌─────────────┐           │
      └────────────►│   pending   │◄──────────┘
                    │   等待中    │
                    └─────────────┘
                          │
          ┌───────────────┼───────────────┐
          │               │               │
          ▼               ▼               ▼
    ┌─────────────┐ ┌─────────────┐ ┌─────────────┐
    │   expired   │ │    fired    │ │   paused    │
    │   已作废    │ │   已触发    │ │   已暂停    │
    └─────────────┘ └─────────────┘ └─────────────┘

                                          ▼
                                    ┌─────────────┐
                                    │   pending   │
```

---

## 状态说明

| 状态 | 说明 | 可转换到 |
|------|------|---------|
| `created` | 刚创建，准备开始预生成 | `preparing`, `pending`, `deleted` |
| `preparing` | 正在调用 AI 预生成内容 | `prepared`, `pending`, `deleted` |
| `prepared` | 预生成完成，等待触发时间 | `fired`, `expired`, `paused`, `deleted` |
| `pending` | 等待触发（无预生成或预生成失败） | `fired`, `expired`, `paused`, `deleted` |
| `fired` | 已触发，消息已发送 | （终态） |
| `expired` | 已作废，不再触发 | （终态） |
| `paused` | 用户手动暂停 | `pending`, `deleted` |
| `deleted` | 已删除 | （终态） |

## 状态转换规则

### 1. created → preparing

**触发条件**：触发器创建后立即开始预生成

```dart
Future<void> _onTriggerCreated(AutoReplyTrigger trigger) async {
  // 更新状态为 preparing
  await _updateStatus(trigger.id, AutoReplyTriggerStatus.preparing);

  // 开始预生成
  await _prepareContent(trigger);
}
```

### 2. preparing → prepared

**触发条件**：预生成成功

```dart
Future<void> _prepareContent(AutoReplyTrigger trigger) async {
  try {
    final content = await _generateProactiveContent(trigger);

    await _updateTrigger(
      trigger.id,
      status: AutoReplyTriggerStatus.prepared,
      cachedContent: content,
      preparedAt: DateTime.now(),
    );
  } catch (e) {
    // 预生成失败，转为 pending
    await _updateStatus(trigger.id, AutoReplyTriggerStatus.pending);
  }
}
```

### 3. preparing → pending

**触发条件**：预生成失败（网络错误、API 超限等）

**后续处理**：触发时实时生成内容

### 4. prepared/pending → fired

**触发条件**：
1. 触发时间到达
2. 作废检查通过

```dart
Future<void> _fireTrigger(AutoReplyTrigger trigger) async {
  // 1. 作废检查
  // 获取“当前最后一条用户消息”（实现方式见 05_作废与优先级.md 的代码片段）
  final lastUser = _getCurrentLastUserMessage(trigger.conversationId);
  final shouldExpire = trigger.shouldExpire(
    currentLastUserMessageId: lastUser?.id,
    currentLastUserMessageAt: lastUser?.createdAt,
    isChatActive: _isChatActive(trigger.conversationId),
  );

  if (shouldExpire) {
    await _expireTrigger(trigger, reason: '用户已发送新消息');
    return;
  }

  // 2. 发送消息
  if (trigger.hasCachedContent) {
    await _sendCachedContent(trigger);
  } else {
    await _generateAndSend(trigger);
  }

  // 3. 更新状态
  await _updateTrigger(
    trigger.id,
    status: AutoReplyTriggerStatus.fired,
    lastFiredAt: DateTime.now(),
  );
}
```

### 5. prepared/pending → expired

**触发条件**：作废检查不通过

```dart
Future<void> _expireTrigger(AutoReplyTrigger trigger, {required String reason}) async {
  await _updateTrigger(
    trigger.id,
    status: AutoReplyTriggerStatus.expired,
    expireReason: reason,
  );

  AppLogger.info('TriggerController', '触发器已作废', metadata: {
    'id': trigger.id,
    'title': trigger.title,
    'reason': reason,
  });
}
```

### 6. prepared/pending → paused

**触发条件**：用户手动暂停

```dart
Future<void> pauseTrigger(String triggerId) async {
  await _updateStatus(triggerId, AutoReplyTriggerStatus.paused);
}
```

### 7. paused → pending

**触发条件**：用户恢复触发器

```dart
Future<void> resumeTrigger(String triggerId) async {
  final trigger = await _getTrigger(triggerId);

  // 如果恢复时已经过了触发时间，重新计算
  if (trigger.nextFireAt.isBefore(DateTime.now())) {
    // 可以选择立即触发，或者作废
    // 这里选择作废
    await _expireTrigger(trigger, reason: '恢复时已过期');
    return;
  }

  await _updateStatus(triggerId, AutoReplyTriggerStatus.pending);
}
```

### 8. any → deleted

**触发条件**：用户删除触发器

```dart
Future<void> deleteTrigger(String triggerId) async {
  await _updateStatus(triggerId, AutoReplyTriggerStatus.deleted);
  // 或者直接从列表中移除
  await _removeTrigger(triggerId);
}
```

## 轮询检查逻辑

系统每隔一定时间（建议 30 秒）检查是否有触发器需要处理：

```dart
Future<void> _pollDueTriggers() async {
  final triggers = state.valueOrNull;
  if (triggers == null || triggers.isEmpty) return;

  final now = DateTime.now();

  for (final trigger in triggers) {
    // 只处理活跃状态的触发器
    if (!trigger.isActive) continue;

    // 检查是否到达触发时间
    if (!trigger.shouldFire(now)) continue;

    // 执行触发逻辑
    await _fireTrigger(trigger);
  }
}
```

## 作废检查时机

作废检查在以下时机执行：

### 1. 触发时检查

```dart
// 触发时间到达后，先检查是否应该作废
Future<void> _fireTrigger(AutoReplyTrigger trigger) async {
  if (trigger.shouldExpire(...)) {
    await _expireTrigger(trigger, reason: '...');
    return;
  }
  // ...
}
```

### 2. 用户发消息时检查（可选优化）

为了更及时地作废，可以在用户发消息时主动检查：

```dart
// ChatActions.send()
Future<void> send(String text) async {
  // 用户发了新消息，检查是否有需要作废的触发器
  await _checkAndExpireLowPriorityTriggers();

  // ... 正常发送逻辑
}

Future<void> _checkAndExpireLowPriorityTriggers() async {
  final triggers = ref.read(autoReplyTriggersProvider).valueOrNull ?? [];
  final activeConvId = ref.read(activeConversationIdProvider);

  for (final trigger in triggers) {
    if (!trigger.isActive) continue;
    if (trigger.conversationId != activeConvId) continue;

    // 低优先级立即作废
    if (trigger.priority == AutoReplyTriggerPriority.low) {
      await _expireTrigger(trigger, reason: '用户发送了新消息');
    }
    // 中优先级：不需要立即处理（触发时再比对“最后一条用户消息”）
  }
}
```

## 生命周期事件

可以定义事件监听，方便 UI 响应：

```dart
/// 触发器生命周期事件
abstract class TriggerLifecycleEvent {}

class TriggerCreated extends TriggerLifecycleEvent {
  final AutoReplyTrigger trigger;
  TriggerCreated(this.trigger);
}

class TriggerPrepared extends TriggerLifecycleEvent {
  final AutoReplyTrigger trigger;
  TriggerPrepared(this.trigger);
}

class TriggerFired extends TriggerLifecycleEvent {
  final AutoReplyTrigger trigger;
  final String content;
  TriggerFired(this.trigger, this.content);
}

class TriggerExpired extends TriggerLifecycleEvent {
  final AutoReplyTrigger trigger;
  final String reason;
  TriggerExpired(this.trigger, this.reason);
}

// 使用 StreamController 广播事件
final _lifecycleController = StreamController<TriggerLifecycleEvent>.broadcast();
Stream<TriggerLifecycleEvent> get lifecycleEvents => _lifecycleController.stream;
```

## 定时器与后台任务

### 前台定时器

App 在前台时，使用 Dart Timer 轮询：

```dart
Timer? _pollTimer;

void _startPolling() {
  _pollTimer?.cancel();
  _pollTimer = Timer.periodic(
    const Duration(seconds: 30),
    (_) => _pollDueTriggers(),
  );
}

void _stopPolling() {
  _pollTimer?.cancel();
  _pollTimer = null;
}
```

### 后台任务（Android）

App 在后台时，使用 WorkManager：

```dart
// 创建触发器时同时注册后台任务
Future<void> _registerBackgroundTask(AutoReplyTrigger trigger) async {
  await BackgroundService.scheduleOneOffTask(
    uniqueName: 'trigger_${trigger.id}',
    delay: trigger.nextFireAt.difference(DateTime.now()),
    inputData: {
      'triggerId': trigger.id,
      'apiKey': apiKey,
      'apiBase': apiBase,
      // ...
    },
  );
}
```

> 安全提醒：尽量不要把 `apiKey` 直接塞进 WorkManager 的 `inputData`（它会落地到本地持久化里）。  
> 更稳的做法是只传 `triggerId`，在任务执行时再从安全存储/配置中读取密钥；或把生成/发送走后端网关。

### 后台任务（iOS）

iOS 后台限制较多，可以考虑：
1. 推送通知触发
2. Background Fetch（不精确）
3. 用户下次打开 App 时补发
