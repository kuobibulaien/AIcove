# 文档治理规则

本文档规定 AIcove 文档怎么放、怎么更新、怎么归档。这里面向人阅读；`docs/项目记忆/`（仓库根目录）面向 AI 协作时快速加载，两边口径一致。

## 文档分层

| 位置 | 定位 | 示例 |
|---|---|---|
| `docs/项目记忆/` | 长期有效的项目规范、架构决策、需求日志、经验教训 | 分层边界、踩坑硬约束、Agent Context 规则、用户原始需求 |
| `apps/aicove_flutter/docs/` | Flutter 与项目开发文档库 | 架构说明、功能模块、UI 组件、历史归档 |
| `cloud_backend/` | 云端服务专题文档 | 云同步协议、测试与运行配置 |
| `scratch/` / `.codex-temp/` | 临时草稿、诊断输出、一次性报告 | 排查日志、生成草稿、临时交付物 |
| `opusdocs/` / `data/*.md` | 个人头脑风暴笔记与旧规则历史快照，不作为规范真相源 | 需求草稿、任务备忘、旧版 CLAUDE.md 备份 |

## 新文档放哪里

| 内容 | 放置位置 |
|---|---|
| 不可违反的长期规则 | `docs/项目记忆/经验教训.md`、`docs/项目记忆/README.md` |
| 面向开发者的模块说明 | `apps/aicove_flutter/docs/04_功能模块规范/` |
| 前端 UI 组件说明 | `apps/aicove_flutter/docs/03_前端开发规范/` 或 `公共组件总览.md` |
| 前后端边界、上下文、Agent 架构 | `apps/aicove_flutter/docs/02_前后端分离与架构规范/` |
| 云同步 API / 运行配置 | `cloud_backend/README.md` 或云端专题文档 |
| 一次性排查 | `scratch/diagnostics/` |
| 过时方案 | `apps/aicove_flutter/docs/05_历史归档/` |

## 更新要求

1. 改公共组件，更新 `公共组件总览.md`。
2. 改页面布局，更新 `界面布局说明.md` 或对应页面说明。
3. 改聊天上下文、Agent Runtime、同步/备份/记忆等核心链路，同步更新 `docs/项目记忆/` 和 docs。
4. 新增大任务，先在对话中确认目标、边界、验收，完成后把长期结论回写 `docs/项目记忆/`。
5. 根 README 只做面向用户的产品介绍；架构约束、项目宪法与开发入口在根 DEVELOPMENT.md，不承载详细模块文档。

## 归档规则

- 已完成且不再代表当前设计的施工方案，加日期前缀后归入 `05_历史归档/`。
- 临时诊断报告不归入正式 docs，除非已经提炼成长期规范。
- 不复制同一份文档到多个位置；需要引用时使用相对链接。
