# 文档治理规则

本文档规定 AIcove 文档怎么放、怎么更新、怎么归档。它与 `.trellis/spec/project/documentation.md` 保持同一口径：这里面向人阅读，Trellis spec 面向 AI 协作时快速加载。

## 文档分层

| 位置 | 定位 | 示例 |
|---|---|---|
| `.trellis/spec/` | 长期有效的项目规范和架构决策 | 分层边界、Flutter 规则、云端规则、Agent Context 规则 |
| `.trellis/tasks/` | 单个任务的 PRD、研究、验收 | 大重构、新模块、跨端改造 |
| `apps/aicove_flutter/docs/` | Flutter 与项目开发文档库 | 架构说明、功能模块、UI 组件、历史归档 |
| `cloud_backend/` | 云端服务专题文档 | API、部署、Agent Context Web 管理端 |
| `scratch/` / `.codex-temp/` | 临时草稿、诊断输出、一次性报告 | 排查日志、生成草稿、临时交付物 |
| `opusdocs/` / `data/*.md` | 个人头脑风暴笔记与旧规则历史快照，不作为规范真相源 | 需求草稿、任务备忘、旧版 CLAUDE.md 备份 |
| `毕业设计论文/` | 毕设材料 | 论文、答辩、模板、过程文件 |

## 新文档放哪里

| 内容 | 放置位置 |
|---|---|
| 不可违反的长期规则 | `.trellis/spec/` |
| 面向开发者的模块说明 | `apps/aicove_flutter/docs/04_功能模块规范/` |
| 前端 UI 组件说明 | `apps/aicove_flutter/docs/03_前端开发规范/` 或 `公共组件总览.md` |
| 前后端边界、上下文、Agent 架构 | `apps/aicove_flutter/docs/02_前后端分离与架构规范/` |
| 云端 API / 部署 / Web 管理面板 | `cloud_backend/README.md` 或云端专题文档 |
| 一次性排查 | `scratch/diagnostics/` |
| 过时方案 | `apps/aicove_flutter/docs/05_历史归档/` |

## 更新要求

1. 改公共组件，更新 `公共组件总览.md`。
2. 改页面布局，更新 `界面布局说明.md` 或对应页面说明。
3. 改聊天上下文、Agent Runtime、同步/备份/记忆等核心链路，同步更新 `.trellis/spec/` 和 docs。
4. 新增大任务，优先在 `.trellis/tasks/` 建 PRD，完成后把长期结论提炼回 `.trellis/spec/`。
5. 根 README 只保留项目总览和权威入口，不承载详细模块文档。

## 归档规则

- 已完成且不再代表当前设计的施工方案，加日期前缀后归入 `05_历史归档/`。
- 临时诊断报告不归入正式 docs，除非已经提炼成长期规范。
- 不复制同一份文档到多个位置；需要引用时使用相对链接。
