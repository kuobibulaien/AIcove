# 图片渠道适配说明

> 更新日期：2026-09-22

这次把图片请求从聊天协议里拆开了。现在图片生成单独走图片协议判断，不再复用 `Claude/Gemini` 的聊天端点。

## 当前支持

### 1. NovelAI

- `requestFormat = novelai`
- 走 `POST /ai/generate-image`
- 保留 ZIP 解包逻辑

#### 受控模型目录（零网络）

NovelAI 没有稳定的图片模型列表端点（`GET /oa/v1/models` 只服务 OpenAI 兼容文本 API；
`/ai/models` 等探测均 404）。因此模型目录随客户端版本受控维护，**预览/导入绝不请求
`/models` 端点**。目录顺序同时表达默认优先级，New 在前、Legacy 在后：

| 分组 | 模型 ID |
|---|---|
| New | `nai-diffusion-5-full` |
| New | `nai-diffusion-5-curated` |
| Legacy | `nai-diffusion-4-5-full` |
| Legacy | `nai-diffusion-4-5-curated` |
| Legacy | `nai-diffusion-4-full` |
| Legacy | `nai-diffusion-4-curated-preview` |
| Legacy | `nai-diffusion-3` |
| Legacy | `nai-diffusion-furry-3` |

目录常量：`kNovelAiDefaultModels`（`ui_models_store_support.dart`），被默认渠道、
模型预览、导入 fallback 与既有渠道迁移共同复用。目录顺序是硬约束，NovelAI 模型的
normalize 走「受控目录优先 + 未知模型原顺序」，**禁止通用字母排序**打乱目录。

inpainting 模型不进入目录（当前只支持文生图）。

#### 请求体分支（按模型族）

| 模型族 | params_version | 默认 scale | 结构化 prompt | V3 legacy 字段 |
|---|---:|---:|---|---|
| V5（Full / Curated） | 4 | 7.0 | `v4_prompt` / `v4_negative_prompt` | 否 |
| V4 / V4.5 | 3 | 5.0 | `v4_prompt` / `v4_negative_prompt` | 否 |
| V3 / Furry V3 | 3 | 5.0 | 无 | `qualityToggle / legacy / sm / sm_dyn / noise_schedule / ...` |

- V5 默认 `steps = 23`、`sampler = k_euler_ancestral`；显式传入的
  `steps / guidanceScale / sampler / seed` 优先于默认值。
- V5 与 V4 共用「结构化提示词模型」判定，共用禁止覆盖核心字段的 reserved key 集合：
  `image_parameters` 不能覆盖 `params_version / 尺寸 / steps / scale / sampler /
  v4_prompt / v4_negative_prompt`，也不能重新注入 V3 专属的
  `legacy / qualityToggle / sm / sm_dyn` 等字段。
- 旧 ID `nai-diffusion-4-5-curated-preview` 仍规范化到正式 ID
  `nai-diffusion-4-5-curated`（仅确定性别名，不是跨模型降级）。

#### 错误处理：不做跨模型静默降级

所有显式选择的 NovelAI 模型（V5 / V4.5 / V3 等）在枚举错误或其他失败后**只请求一次**，
保留所选模型上下文并直接返回错误；不自动换另一个模型重试。

#### 新安装与既有渠道默认值

- 新安装内置 NovelAI 渠道：`defaultImageModel = nai-diffusion-5-full`，可见模型
  首项为 V5 Full；持久层使用 `custom_config` 键。
- 既有 NovelAI 渠道（按 id / base URL / `requestFormat` 识别）通过一次性迁移
  `kNovelAiV5FullDefaultMigrationId` 补齐目录、把 V5 Full 放到可见模型首位，并把
  缺失或历史内置默认值（V4.5 Curated / V4.5 Full / 旧 Curated Preview 别名）升级为
  V5 Full；明确的 V3 / Furry V3 / V4 / 自定义默认值保持不变，API Token、地址、启用
  状态、capabilities 与未知 `custom_config` 字段全部保留。迁移幂等，之后用户的新选择
  不再被自动覆盖。

### 2. OpenAI 兼容图片接口

- `requestFormat = openai`
- 默认走 `POST /v1/images/generations`
- 返回同时兼容：
  - `data[].b64_json`
  - `data[].url`
- 如果返回的是 URL，客户端会自动下载图片再落本地

## 设置页调整

- 新增渠道时：
  - 对话渠道可选 `OpenAI / Claude / Gemini`
  - 图片渠道可选 `OpenAI / NovelAI`
- 渠道详情页的 `API 格式` 也按渠道用途动态显示

## 新增约定

OpenAI 兼容图片渠道可额外使用这些 `customConfig`：

- `imageEndpoint`
  - 自定义图片生成路径
- `imageResponseFormat`
  - 可选 `b64_json` 或 `url`
- `image_parameters`
  - 追加到请求体里的渠道特有参数

## ComfyUI 原生工作流（2026-09-22）

已新增 `ComfyUIImageAdapter`，复用 `<image>` / `draw_image`、角色绘图预设、图片保存与重画链路。

### 配置步骤

1. 设置 → 模型 → 添加渠道，API 格式选 `ComfyUI`。
2. 填写服务根地址，例如 `http://127.0.0.1:8188`；手机连接电脑时填电脑的局域网地址。API Key 可留空；填写时作为 Bearer Token 发给同一服务。
3. 打开「ComfyUI 工作流」，导入或粘贴从 ComfyUI 导出的 **API 格式 JSON**，普通画布 JSON 不适用。
4. 选择正向提示词的节点输入；按需绑定负面词、尺寸、种子、步数、引导强度、数量等输入。未绑定的字段保留工作流原值；模型、LoRA、采样流程由工作流定义，不自动猜节点用途。
5. 可指定图片输出节点；留空时读取已保存的输出图片，忽略临时预览。工作流需包含 `SaveImage` 或等价的图片文件输出。
6. 保存渠道后，在绘图预设中选择该渠道的 `comfyui-workflow`。这是工作流入口，不是服务器 checkpoint 名称。较慢的工作流可把绘图预设的超时调到 300 秒（现有范围 5–600 秒）。

每个渠道保存一个工作流，可建立多个命名渠道切换。已有渠道的详情页 →「工作流与参数绑定」可重新编辑。配置保存和模型列表刷新不会执行生图；「测试连接」只读取 `/system_stats`。

### 请求与配置

- `customConfig.requestFormat = comfyui`。
- `comfyWorkflow` 保存 API 工作流对象；`comfyBindings` 为参数名到 `节点ID.输入名` 的映射；`comfyOutputNode` 是可选输出节点 ID。
- 参数名支持 `prompt`、`negative_prompt`、`width`、`height`、`seed`、`steps`、`cfg_scale`、`batch_size`、`sampler_name`。也支持对应 `%参数名%` 占位符；独占字符串的数值占位符会替换为 JSON 数字。未提供的采样器沿用工作流值。
- `POST /prompt` 提交工作流 → 按 `prompt_id` 轮询 `/history/{id}` → `GET /view` 下载图片。URL 支持反向代理路径前缀。
- 全链路共用绘图预设超时；失败不会重新提交或改用其它供应商。等待超时后服务端任务可能继续执行，不调用会影响其他使用者的全局 `/interrupt`。
- 普通工作流的参数快照保存在图片元数据，重画复用原工作流和绑定；渠道地址与 API Key 仍从当前渠道读取。含凭证字段的远端 API 节点工作流不保存重画快照，避免把这些字段写入聊天历史。

### 验证边界

本地协议模拟覆盖任务提交、排队、失败、超时、取图、无 Key、渠道保存，以及插件生成与快照重画；设置编辑器已做窄／宽源码渲染检查。用户尚未部署 ComfyUI，按用户要求未做真实引擎出图验收，未安装或更新运行中的应用。

本批为工作流文生图接入，不含参考图片上传、局部重绘画布、视频输出及服务器任务取消管理。
