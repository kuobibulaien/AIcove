## 1. 目标与现状差距

目标：用户只描述日常 BUG 现象，agent 在已授权、可访问的手机上自行获取诊断包，找到对应操作，给出证据与候选根因，再通过复现测试验证。不要求用户读日志、筛选类别、找 traceId 或事发前打开调试模式。

当前已实现的前端事件只是入口：阶段、累计耗时、部分状态及编号可以落盘；错误主要保留类型与最多 12 个 package/dart 位置；内存关联表有界，但没有应用运行编号/可定位的构建指纹，没有统一状态转移、故障前后快照、可靠的日志健康报告或自动抓取工具。现有七天清理只有时间规则，没有覆盖全部日志与 payload 的统一字节预算。只能证明发生过部分事件，不能充分解释为什么。

详细诊断与友好界面并不冲突：完整结构化数据用于机器分析，中文摘要是数据投影；不能为了列表简短，在采集时就把关键证据删掉。ADR0005 的低频入口与关联能力保留，扩大异常正文、状态采样或存储边界须经本方案确认，不把新政策默认为已批准。

## 2. 一次操作的证据模型

所有事件采用统一 envelope；现有 AppLogger/ApiLogger/TraceStore 逐步通过适配器输出，不一次性推倒替换。

| 字段组 | 必要信息 |
|---|---|
| 运行身份 | schemaVersion、不可歧义的 buildId、appRunId、进程/isolate、设备/OS、刷新率；开发构建包含工作树内容指纹，不能只记 versionName 或 Git commit |
| 时间和顺序 | 墙钟用于检索；单调时间用于耗时；每个写入源的递增序号用于发现缺失。跨进程不假装共享同一个单调时钟/序号，使用明确父子关系 |
| 因果关系 | operationId / parentOperationId / traceId / generationSeq / round / rawMessageId / bubbleId / pageInstanceId / projectionRevision，字段按场景使用而非全部强填；异步任务在创建时固定上下文 |
| 行为与决策 | eventName、phase(start/end/error/cancel/skip)、before、after、reasonCode、duration、结果统计。包括“不执行”的原因，不能只有成功/失败摘要 |
| 错误与健康 | 脱敏后的错误说明、错误码、异常类型、完整有界堆栈及已知 cause；截断标记、采样率、丢弃数量、写盘检查点、存储不可用及重启后的未完成操作 |

状态从正在执行的路径读取，不为日志额外查库，不用诊断快照改变业务真相源。错误说明改为字段级/内容级脱敏，不能继续只留下笼统的 StateError；也不能把完整 HTTP 响应或 SQL 参数无差别当错误正文存盘。

### 首批覆盖五类证据

1. 操作与页面：有效点击、路由/前后台切换、请求取消、页面销毁。点击到真正提交之间的等待与取消也纳入，而非从确认框之后才开始计时。
2. 生成链路：配置与模型、请求开始/首包/结束、解析统计、分段序号、TTS 排队/合成/回填、投影安装、落库、界面消费与播放器状态；收齐 start/end/cancel/skip。
3. UI 状态转移：用户/程序谁控制滚动，偏移与范围，前后可见锚点，气泡来源与投影版本，动画是否已播放以及为什么启动，回填/投影为什么被丢弃。
4. 错误与退出：业务错误、Flutter/异步错误、插件通道失败；Android 自有应用退出原因按系统能力采集。上次运行没有结束标记只能称“不完整结束”，不能直接认定崩溃。
5. 性能与诊断健康：刷新率对应的帧预算、build/raster 耗时分布、窗口内重建/投影次数；日志本身的开销、队列水位、丢弃/截断/存储故障。

## 3. 日常记录与故障保留

两级细节，不做全量逐帧写盘：

- 常驻低频：状态转移、阶段耗时、异常、结束原因。以分段 JSONL 批量写盘，重启仍保留；大字段独立 payload 引用，不能重复存多份全文。
- 高频上下文：有界内存环形缓冲，目标保留最近 60 秒且最多 4MB（先碰到哪个上限就停止保留更旧数据）；帧/流增量只记数值摘要、计数和必要状态，不记录每个 token 的正文。
- 故障冻结：异常、超时、持续卡顿/关键状态长时间不前进等可观测条件触发，合并相近故障，保存前置缓冲及后续约 15 秒，形成 incident。未被规则识别的错位仍须能通过常驻状态记录回查，不能依赖用户事后重开详细模式。
- 初始存储预算建议：普通日志与 payload 合计最多 128MB/7天，故障包另限 32MB、每包最多8MB；容量与期限先到先轮转。具体预算必须用真实典型会话测量后调整，不能称为已经验证的开销指标。
- 异步写入不阻塞 UI；诊断 UI 按批通知，不逐事件重建。重要结束/错误尽快写入，退出有机会则 flush；强杀或断电无法保证最后一条保存。启动时检查尾部完整性，并明确报告采样/缺段/进程终止情况。

所有阈值是候选初值。常驻摘要与触发缓冲需要开/关对照测量，验收性能开销，而不是仅凭“用了异步”认定没有开销。

## 4. agent 自助抓取流程

拟新增电脑端 `tool/collect_diagnostics.py`（当前不存在），标准库＋ADB，默认只读应用诊断数据；命令形态示例：

```text
python3 tool/collect_diagnostics.py --device auto --since 2h
```

流程：自动识别已授权设备与安装构建→读取故障索引→候选时间窗→拉取关联运行/操作的完整事件与必要 payload→校验序号和引用→输出分层诊断包。不先把所有聊天数据库拷出来。

诊断包包含：

```text
manifest.json       构建/设备、覆盖时间窗、时钟域、采样和缺失声明
summary.json        故障候选、异常/慢操作、索引与来源位置
operations.jsonl    相关操作的结构化记录
snapshots/          必要的前后状态与经过脱敏的细节
native/             权限允许的本应用退出信息与相关系统日志
```

agent 先读 summary，再按 ID/范围读取正文，避免成百 MB 原始日志塞进模型上下文。诊断输出必须区分事实、推断和待验证项，并引用事件位置/编号；优先复用实际出错构建的源代码定位，不拿最新工作树的行号冒充设备版本。

采集边界：

- 目前安装的是可调试 Android 构建，授权 ADB 可用 run-as 读取应用私有日志。多设备时不得猜设备；已记录当前调试设备可作为默认，否则按安装构建/时间证据定位再确认。
- 正式 release 包不能依赖 run-as；需要应用内受控的诊断快照/导出出口。导出只读取快照，不和活跃写入竞争；无法触发快照时取现有文件，并标记末尾不完整。
- 手机断开且没有授权同步通道时，agent 不能凭一句描述远程读私有数据。先以“接上手机或授权本地调试连接”为最低前提；跨网络的加密、鉴权与单次授权诊断通道属于后续独立方案，不默认建设、不后台上传。

## 5. 隐私、验收与实施顺序

### 隐私

常驻状态日志不能含 API Key、Authorization、Cookie、音频/base64 或聊天全文。正常使用不录屏、不记录键盘输入。请求记录保留脱敏的端点/状态、供应商与模型、配置摘要/哈希、数据规模和结构。

当前项目已有模型原文 payload，不能误称“之前从不记录正文”。本方案不自动扩大这部分采集/分享范围；统一限额与脱敏时应清点现有路径。确实需要文本排版/解析原文复现时，按候选消息明确征得授权后，从对应版本的本地数据获取最小必要范围，不默认导出整库。无原文时应坦白这类问题的复现限制，不能保证所有 BUG 仅靠状态日志还原。

### 验收

使用真实入口注入固定故障：分段后旧气泡跳动、TTS 成功但回填被拒绝、历史读取慢、切后台请求未完成、日志写入失败。不给分析过程额外测试内部变量，只提供用户式描述与诊断包。应能定位到错误阶段和相关状态/代码路径，说明缺失证据，并写复现测试验证，不必然承诺每例直接确定唯一根因。

同时验证跨角色/重试/进程隔离、重启仍可读、触发前置记录存在、隐私脱敏、磁盘与内存上限、断写恢复、采集开关对帧耗时影响、debug/release 的各自抓取路径。

### 分批交付（确认后实施）

第一批约 1 个工作日：统一运行/构建身份和状态事件；选聊天分段与 TTS 两条已知故障链补齐；提供可调试 Android 的电脑端自动采集器，完成描述→抓取→证据→复现测试的闭环。不优先改日志页面。

第二批：故障前后冻结、帧摘要、自有应用原生退出原因、release 的受控导出入口。远程通道若有需求再单独确认。

回滚：新采集策略可禁用；旧日志读取和现有界面保留。不迁移/删除聊天数据库，不更改生成、滚动或播放器业务裁决，不以扩大日志为名默默采集敏感正文。
