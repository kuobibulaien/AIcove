# 本地持久缓存机制

更新时间：2026-04-23

## 目标

统一约定项目里的“持久缓存”定义：

- **持久缓存**：退出应用、重启应用后仍然可用，必须落到本地文件或本地数据库。
- **内存缓存**：仅当前进程有效，应用退出后失效，不算持久缓存。

本项目后续所有标记为“持久缓存”的能力，都必须满足：

1. 退出应用不丢失；
2. 重启应用不丢失；
3. 能明确说明存储位置、失效规则与更新时机。

---

## 当前缓存分层

### 1. 内存缓存

适合解决“同一次 App 生命周期内反复打开”的速度问题。

典型案例：

- Flutter `ImageCache`
- 各类页面 warm cache / LRU cache
- Riverpod / 控制器当前进程内状态

特点：

- 命中快；
- 退出应用即失效；
- 不满足“持久缓存”定义。

### 2. 本地持久缓存

适合解决“重启应用后仍然希望秒开/直出”的问题。

典型存储位置：

- `SharedPreferences`
- Drift / SQLite
- `ApplicationDocumentsDirectory` 下的 JSON / 图片 / 二进制文件

特点：

- 退出/重启后仍然存在；
- 可作为页面恢复、草稿恢复、资源复用的长期缓存。

## 角色信息页持久快照缓存

### 适用路径

`聊天页 -> 更多 -> 聊天设置 -> 角色信息`

对应页面：

- `lib/src/ui/features/character/pages/contact_edit_page.dart`

### 设计目的

角色信息页之前每次进入都像“重新打开一个重页面”：

- 页面通过 `Navigator.push(...)` 每次新建；
- 原先还存在“轻壳 -> 正式表单”的延后挂载；
- 背景图和表单内容都容易产生“又在重新加载”的观感。

这次改造后，角色信息页新增 **本地持久快照缓存**，用于把“已准备好的表单状态”直接存本地，下次进入优先直接恢复。

### 缓存内容

按 `conversationId` 存储一份本地 snapshot，至少包含：

- `displayName`
- `description`
- `personaPrompt`
- `selfAddress`
- `addressUser`
- `avatarUrl`
- `characterImage`
- `chatBackgroundImage`
- `voiceFile`
- `enabledPlugins`
- `sourceUpdatedAtMs`
- `cachedAtMs`

### 存储位置

使用本地 JSON 文件，目录：

- `ApplicationDocumentsDirectory/contact_edit_snapshots/`

实现文件：

- `lib/src/ui/features/character/services/contact_edit_snapshot_store.dart`

### 打开策略

进入角色信息页前：

1. 先读取/刷新当前角色的本地 snapshot；
2. 命中后将 snapshot 作为 `initialSnapshot` 传给 `ContactEditPage`；
3. 页面首帧直接挂完整表单，不再先显示轻壳等待；
4. 背景层继续走模糊背景缓存链路。

### 更新策略

- **保存角色信息后**：立即重写对应 snapshot；
- **角色保存为新模板 / 新建角色后**：为新 `conversationId` 写入 snapshot；
- **删除角色后**：删除对应 snapshot；
- **进入页面发现 `sourceUpdatedAtMs` 过期**：自动用最新角色数据覆盖旧 snapshot。

### 失效规则

若本地 snapshot 的 `sourceUpdatedAtMs` 小于当前角色 `updatedAt`：

- 判定该 snapshot 已过期；
- 不再直接复用；
- 改用当前角色最新数据重建并回写 snapshot。

## 背景模糊图缓存

角色信息页背景不是整页截图缓存，而是独立的资源缓存。

当前分两类：

### 1. 内置静态模糊图

若角色图片存在配套的 `_blur` 资源，例如：

- 原图：`assets/characters/images/nahida.jpg`
- 模糊图：`assets/characters/images/nahida_blur.jpg`

则优先直接使用静态模糊资源。

### 2. 动态生成模糊图

对于 data url / 网络图 / 本地图，使用：

- `lib/src/core/utils/blurred_background_service.dart`

将生成后的模糊图持久化到本地目录：

- `ApplicationDocumentsDirectory/blurred_backgrounds/`

这同样属于**持久缓存**，退出/重启应用后仍可复用。

---

## 为什么不做“整页截图式缓存”

角色信息页是一个可编辑表单页，不适合直接把整页渲染结果缓存成 bitmap：

- 主题变化后旧截图容易失真；
- 字号/缩放变化后布局会错位；
- 插件列表、表单项结构变化后容易展示旧 UI；
- 用户看到截图时，真实输入控件可能还没 ready，交互割裂感强。

因此当前策略是：

- **背景资源独立缓存**
- **表单数据做持久快照缓存**
- **页面结构照常实时构建**

这样既能保留可编辑性，又能接近“设置页一样直出”的体验。

---

## 后续约定

后续如果项目里再提“页面持久缓存”，默认按下面顺序选型：

1. 先判断能否通过页面保活解决；
2. 不能保活时，优先做“数据快照持久缓存”；
3. 背景图/图片资源单独做文件缓存；
4. 非必要不做整页 bitmap 持久化。
