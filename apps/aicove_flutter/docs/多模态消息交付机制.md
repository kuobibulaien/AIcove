# 多模态消息交付机制

> 更新日期：2026-02-21
>
> 关键词：消息分段、TTS 语音、表情包、多模态、语序保持

---

## 1. 背景与问题

### 1.1 什么是"多模态消息"

AI 的一条回复可能同时包含多种内容类型：
- **文本**：普通文字
- **TTS 语音**：用 `<tts>...</tts>` 标签标记的语音内容
- **表情包**：用 `[标签名]` 标记的表情图片

例如 AI 回复：
```
早安呀~ [早安] <tts>今天天气很好呢</tts> 出去走走吧
```
这条回复包含 4 个片段：文本("早安呀~") → 表情包(早安) → 语音(今天天气很好呢) → 文本(出去走走吧)。

### 1.2 为什么需要"按位置拆分"

如果不拆分，插件处理后会变成：
- 文本消息："早安呀~ 出去走走吧"（两段文字被拼在一起）
- 语音消息：「今天天气很好呢」
- 表情包消息：[早安]

**语序完全乱了**！用户看到的是"先文字、再语音、最后表情"，而 AI 原本想表达的是"先打招呼、发个表情、说句话、再补一句"。

### 1.3 与前端标点分段的区别

| 特性 | 多模态拆分（本文档） | 前端标点分段（enableChunking） |
|------|---------------------|-------------------------------|
| 层级 | 数据层（存储时拆分） | UI 层（渲染时拆分） |
| 目的 | 保证多模态内容语序正确 | 让长文本按标点换行显示 |
| 触发条件 | 存在 TTS/表情包标签 | enableChunking = true |
| 是否影响消息数量 | 是（一条变多条） | 否（一条消息多段展示） |
| 相关文件 | `chat_message_processor.dart` | `message_formatter.dart` |

## 2. 整体架构

### 2.1 消息交付流程

```
AI 原始回复 (replyText)
    │
    ▼
ChatSendService.buildAssistantMessages()
    │ 检测是否有多模态事件 (tts_convert / sticker_convert)
    │
    ├─ 无多模态 → 保持消息完整，直接存储
    │
    └─ 有多模态 → 调用 _parseMultimodalSegments()
         │ 按标签位置拆分为 [text, tts, sticker, text, ...] 片段
         │
         ├─ text 段 → 直接创建文本 Message
         ├─ sticker 段 → 直接创建 EmojiBlock Message
         └─ tts 段 → 跳过（交给 ChatTtsHandler）
              │
              ▼
         ChatTtsHandler.deliverSegmentedMessages()
              │ 重新调用 parseMultimodalSegments() 获取完整片段列表
              │ 按顺序逐段发送：
              ├─ text → 直接追加到对话
              ├─ sticker → 直接追加到对话
              └─ tts → 生成语音后追加（失败则回退为文本）
```

### 2.2 两条交付路径

| 路径 | 条件 | 处理方式 |
|------|------|---------|
| 直接交付 | TTS 未启用 / 无 TTS 事件 / 已有工具音频 | `buildResult.messages` 直接存储 |
| TTS 交付 | TTS 已启用且有 TTS 事件 | `ChatTtsHandler` 重新解析并按段顺序发送 |

**为什么 TTS 路径要重新解析？** 因为 TTS 生成是异步的，需要等语音生成完才能发送。直接交付路径只处理文本和表情包，TTS 段被跳过。

## 3. 核心算法：位置标记解析

### 3.1 解析流程

文件：`chat_message_processor.dart` → `_parseMultimodalSegments()`

```
1. 清理文本：移除非多模态标签（如 <create_trigger>）
2. 收集表情包数据：从 sticker_convert 事件中提取 tag → data 映射
3. 标记 TTS 位置：用正则 <tts>(.*?)</tts> 找到所有 TTS 段的 start/end
4. 标记表情包位置：用正则 \[tag\] 找到已确认的表情包标签位置
5. 去重叠：移除被 TTS 标记包含的表情包标记（嵌套场景）
6. 按位置排序：所有标记按 start 升序排列
7. 切分文本：标记之间的文本作为 text 段，标记本身作为 tts/sticker 段
```

### 3.2 嵌套处理

如果表情包标签出现在 TTS 标签内部：
```
<tts>好开心呀 [开心]</tts>
```
`[开心]` 属于语音内容的一部分，**不会被单独拆分为表情包**。

### 3.3 示例

输入：
```
早安呀~ [早安] <tts>今天天气很好</tts> 出去走走吧
```

PluginEvents：
```
[sticker_convert: {tag: "早安", assetPath: "...", stickerId: "..."}]
[tts_convert: {text: "今天天气很好"}]
```

解析结果：
```
[
  _Seg(text, "早安呀~"),
  _Seg(sticker, "早安", stickerData: {...}),
  _Seg(tts, "今天天气很好"),
  _Seg(text, "出去走走吧"),
]
```

## 4. 关键文件

| 文件 | 职责 |
|------|------|
| `lib/src/features/chat/services/chat_message_processor.dart` | 消息构建、多模态解析、文本处理 |
| `lib/src/features/chat/services/chat_tts_handler.dart` | TTS 语音生成与多模态消息顺序交付 |
| `lib/src/features/chat/services/chat_send_service.dart` | 消息发送编排（调用上面两个服务） |
| `lib/src/core/utils/message_formatter.dart` | 前端标点分段（与本机制无关） |

### 4.1 关键类型

```dart
// 公开类型（供 ChatTtsHandler 使用）
enum MultimodalSegmentType { text, tts, sticker }

class MultimodalSegment {
  final MultimodalSegmentType type;
  final String content;
  final Map<String, dynamic>? stickerData; // 表情包专有数据
}
```

### 4.2 关键方法

| 方法 | 所在文件 | 说明 |
|------|---------|------|
| `buildAssistantMessages()` | chat_message_processor.dart | 构建消息列表，有多模态时自动拆分 |
| `parseMultimodalSegments()` | chat_message_processor.dart | 公开方法，返回多模态片段列表 |
| `_parseMultimodalSegments()` | chat_message_processor.dart | 内部实现，位置标记解析 |
| `deliverSegmentedMessages()` | chat_tts_handler.dart | 统一交付入口，自动选择交付策略 |
| `_deliverWithTtsSegments()` | chat_tts_handler.dart | TTS 路径的顺序发送实现 |

## 5. 扩展指南

### 5.1 新增多模态类型

如果未来需要支持新的多模态内容（如视频、链接卡片等），需要：

1. **在 `MultimodalSegmentType` 中新增枚举值**
2. **在 `_parseMultimodalSegments()` 中新增标记收集逻辑**：
   - 从对应的 PluginEvent 中提取数据
   - 用正则找到标签在原文中的位置
   - 创建 `_Marker` 添加到标记列表
3. **在 `buildAssistantMessages()` 的 switch 中处理新类型**
4. **在 `ChatTtsHandler._deliverWithTtsSegments()` 中处理新类型的交付**

### 5.2 注意事项

- 新标签格式不应与现有标签冲突
- 嵌套场景需要考虑（新标签出现在 TTS 内部时如何处理）
- `_Marker` 的 `data` 字段可携带任意插件数据
